# 청주 대표필지 선택 근거 및 복수 건물 집계 정책 검토

2026-10-05. 기존 결과를 유지한 로컬 읽기 전용 근거 조사와 병행 정책 실험이다. 운영 DB·제품 대표필지·회귀·기존 T/P/K-apt 속성은 수정하지 않았다.

## 대표 PNU 차이 4개에서 확인한 원인

앞 조사에서 가격 마트 대표 PNU와 최신 통계 주소가 다른 연립다세대 키 4개를 찾았다. 이번에는 각 키의 최신 통계 기간에 맞춰 유효하고 단가가 양수인 실제 거래 주소를 조회했다. 4개 모두 해당 기간에 엄격히 해석 가능한 서로 다른 PNU 2개가 관측됐다.

**4개 중 3개의 최신 통계 법정동·지번 조합은 해당 기간의 유효 거래에서 함께 관측되지 않았다.** `build_collective_building_stats.py`의 ROLLING_SQL은 법정동과 지번을 각각 `MAX`로 선택한다. 이번 4개 모두 현재 거래 주소에서 각 열의 MAX를 별도로 계산하면 저장된 통계 주소가 재현됐다. 따라서 주소 필드 조합의 생성 문제를 실제로 확인했다. 실제로 함께 관측된 주소를 보존하는 선택 방식으로 개편할 필요가 있다. 이번 표본을 도시 전체의 오류율로 사용하지 않는다.

이름이 있는 집합의 `building_key`는 자산 유형·주소 1~3·건물명으로 생성되며 지번은 포함하지 않는다. 같은 이름 키가 여러 PNU를 갖는 것이 가능하다. 이름 키가 같다는 사실만으로 물리적으로 하나의 건물·단지라는 인증이 되지는 않는다.

4개의 기존 가격 마트 PNU는 모두 해당 기간 거래에서도 관측됐고, 저장된 과거 통계 주소에서도 발견됐다. 가격 마트의 적재 시각은 모두 최신 통계 계산 시각보다 앞섰다. 현재 통계 PNU 4개 중 3개는 같은 기준연도의 양수 가격을 로컬 `parcel_land_price`에서 찾지 못했다.

현행 가격 import는 최신 통계 주소에서 가격을 찾지 못하면 그 키를 갱신 기록에 넣지 않는다. 기존 마트 행은 유지된다. 이는 이번 차이가 남을 수 있는 경로와 일치하지만, 당시 import 실행 로그가 없으므로 모든 차이의 역사적 실행 원인을 인증하지 않는다. 기존 주소 쪽에 건물이 있거나 가격이 있다는 사실만으로 올바른 단지 대표필지라고 확정하지도 않는다.

## 대표필지 선택 초안

1. 법정동·대지구분·본번·부번을 실제 함께 관측된 주소 쌍에서 해석한다. 서로 독립된 MAX/MODE 결과를 합쳐 새 필지를 만들지 않는다.
2. 단지 키에 연결된 관측 주소 목록, 원천·시점·거래 분포와 기존 대표필지 근거를 함께 저장한다. 빈 지번/길이 초과/미확인 구분은 후보를 만들지 않는다.
3. 관측 주소가 여러 개면 대표필지 확정과 전체 단지 필지 구성 확인을 별도 작업으로 둔다. 거래가 많거나 가격이 존재한다는 이유만으로 자동 확정하지 않는다.
4. 기존 대표필지와 새로운 후보가 다르면 기존값을 보존하고 검토 상태를 기록한다. 기존값도 현재 거래에서 관측되지 않으면 별도 충돌 이유를 남긴다. 새 주소에 가격이 없을 때 기존 가격을 새 주소의 가격으로 치환하지 않는다.
5. 대표필지 선택과 연간 가격 갱신은 별도 버전/판본으로 기록한다. 집합 지역회귀의 단지별 평균가격·최신 대표필지 공시지가 소비 목적은 유지한다. 과거 개별 거래 보강을 추가하지 않는다.

`ledger_relationship_policy_shadow.py`는 4개의 저장 근거에 이 규칙을 병행 적용했다. 모두 `review_required`, 그중 3개는 `stats_address_pair_not_observed` 사유를 반환했다. 새 대표필지 할당은 모두 null이고 기존 값은 그대로 남았다. 이는 제품 선택기를 교체한 것이 아니다.

## 복수 건물 40개 표본의 원본 구성

기존 복수 후보에서 구별·제품별 최대 5개를 SHA-256 순서로 골랐다. 복합 거래 키 20개와 집합 키 20개, 총 40개다. 동일 필지가 여러 제품 키에 등장할 수 있으므로 고유 필지 40개로 해석하지 않는다.

이 표본 및 대표필지·산 counterpart 관련 최신 건물 관리 PK 252개를 전국 원본 표제부에서 확인했다. 같은 주소 총괄표제부도 조회했다. 표제부 및 총괄 파일 전체 SHA-256과 행수가 앞 조사와 같고, 대상 PK 중복/원본 누락은 없었다.

- 주건축물과 부속건축물이 함께 있는 제품 키 표본: **29개**.
- 주건축물이 여러 개 있는 표본: **11개**.
- 같은 주소에 총괄표제부가 있는 표본: **22개**.
- 선택 주소와 원본 표제부 PNU가 다른 표본: **0개**.

이 구성은 주·부속/다동 관계를 보존할 필요가 있다는 근거다. 같은 PNU의 모든 건물이 특정 거래·단지 소속이라는 증거는 아니다. 총괄이 있다는 사실도 직접 부모 PK 연결이 아니다. 현재 원본에는 그 부모 관계/추가 필지 식별 목록이 확인되지 않았다.

## 복수 건물 집계 초안

먼저 소비 객체의 범위를 확정한다. 복합 거래 대상 건물/지분과 집합 단지 구성은 다른 관계다. 소속 근거가 확인된 관리 PK 목록과 판본, 근거 ID, 집계 규칙 버전을 고정한다. 같은 판본의 관리 PK를 한 번만 포함하며 총괄 집계와 표제부 동별 값을 동시에 더하지 않는다.

세대수·호수는 원천의 동별 값인지 단지 전체 값인지 확인한 뒤 합산한다. 주·부속 구분과 주거 유형을 별도로 보존하고 부속시설을 이름만 보고 단지 주동으로 확정하지 않는다. 오피스텔의 세대수 결측시 호수 소비는 현재 정책처럼 별도 파생 필드에 기록한다.

층수는 소속이 확인된 대상의 최대값으로, 구조·준공연도는 분포와 대표값 규칙으로 표현한다. 층수/연도/범주를 무의미하게 합산하지 않는다. 주차는 공유 시설·총괄값·동별값의 범위를 확인하지 않으면 중복 합산할 수 없으므로 수량 범위 근거가 필요하다. 필지면적·가격 단가는 동일 PNU를 동 수만큼 더하지 않는다. 거래 귀속 지분/면적이나 전체 부지가 확인되지 않으면 총액을 생성하지 않는다.

이번 병행 게이트는 소속 확인, 원천 주소 식별, 같은 판본, 고유 구성원, 수량 범위 확인을 따로 검사했다. 40개 모두 원천 주소는 일치하지만 소속·수량 범위는 독립 확인되지 않아 **새 합산을 보류**했다. 현재 제품의 기존 T/K-apt 집계를 삭제하거나 회귀에서 40개를 새로 제외한 것이 아니다.

비주거 집합은 도로명 군집을 유지한다. 출처·품질·집계 범위 계약은 주거와 함께 정리하되 단지 소속이 없는 군집을 K-apt 단지처럼 합산하지 않는다.

## 복합 산 counterpart 2건

두 거래의 원문 지번은 마스킹되어 있고 기존 A1 보강이다. 일반 토지 주소에는 각각 원본 표제부 1개가 있었고, 같은 본번/부번의 산 주소에는 각각 1개·2개가 있었다. 일반 토지 쪽 주소는 원본과 일치했다. 산/일반 토지를 구분하지 않는 기존 복원 키의 한계를 보존하고 양쪽을 별도 후보로 남겼다. 원문 검토만으로 거래 대상의 정확도를 인증하거나 기존 A1을 교체하지 않았다.
