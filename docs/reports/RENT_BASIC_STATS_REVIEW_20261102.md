# 임대 기본통계 화면 리뷰 · 2026-11-02

## 범위와 결론

- 대상: 로컬 `http://localhost:5178/rent/`, 충청북도 음성군 아파트, 2026년 9월말 기준.
- 실제 화면 조작과 현재 소스를 대조했다. 제품 코드 수정·커밋·배포는 하지 않았다.
- 기본 조회(5년 96동), 건물명 열 필터, 필터 초기화, 지도 접기, 환산 열 펼치기는 동작했다. 확인 시점 브라우저 warn/error 로그는 없었다.
- 우선 수정: 기간 변경 시 읍면동 선택 유실. 다음으로 검색 동작 안내와 기본 표 너비를 개선할 필요가 있다.
- 전국·모든 주택유형의 데이터 정합성, 거래 원장 수치 대조, 상세 회귀·AI·상권 모달은 이번 검증 범위 밖이다. 관측한 평균·비율 자체가 잘못 계산됐다고 판정하지 않았다.

## 1. [P2 · 재현 오류] 롤링 기간을 바꾸면 읍면동 선택이 해제됨

재현:

1. 아파트 → 충청북도 → 음성군 → 대소읍 선택.
2. 5년에서 3년으로 변경.
3. 대소읍 선택이 풀리고 읍면동이 전체로 바뀜. 3년 대소읍 1,087건이 있으므로 거래 부재 때문이 아님.
4. 대소읍을 다시 선택하고 7년으로 변경해도 해제됨. 7년 대소읍은 1,843건 존재.

영향: 사용자가 기간만 변경했다고 생각하고 통계분석을 다시 누르면 음성군 전체가 조회된다. 화면에는 조건 변경 안내가 있지만 지역 선택 유실을 별도로 알리지 않는다.

원인: `frontend-rent/src/App.tsx:195`의 effect가 `leafOptions`가 바뀔 때마다 선택을 교집합으로 축소한다. 기간 변경으로 새 query가 로딩되면 옵션이 임시로 빈 배열이 되고, 기존 선택이 삭제된다. 데이터가 도착해도 복구하지 않는다.

권고: 해당 기간의 지역 query가 성공한 뒤에만 유효성 검사를 수행한다. 재조회 중에는 기존 지역 선택을 보존하고, 실제로 사라진 지역만 명시적으로 해제한다.

## 2. [P2 · 재현 UX 문제] 검색이 강조 전용인데 이를 알 수 없고 열 필터와 충돌함

재현:

1. 음성군 5년 목록에서 `건물명 포함`에 `쌍용` 입력 → 표시 1/96.
2. 위쪽 `검색`에 `음성아이파크` 입력.
3. 쌍용예가 한 행만 남고, 아이파크로 이동하거나 검색 결과 없음/필터에 숨겨짐 안내가 나타나지 않음.

원인: 상단 검색은 `App.tsx:224`에서 전체 items를 대상으로 일치 여부를 계산하고, 표에는 `highlightQuery`만 넘긴다. 실제 표시 행은 표 내부 필터가 결정한다. 스크롤 대상이 없으면 `scrollIntoView`도 조용히 끝난다.

영향: 일반적인 검색/필터로 기대하고 입력하면 반응이 없다고 느끼기 쉽다. 검색어가 일치하지 않아도 기존 전체 목록이 그대로 보인다.

권고: `건물 찾기(강조)`처럼 동작을 명시하고, 표시 중 일치 건수·결과 없음·현재 필터로 숨겨짐을 안내한다. 검색을 필터로 통합할지는 제품 의도에 따라 결정한다.

## 3. [P2 · 화면 개선] 기본 표가 지나치게 넓어 핵심 열 비교가 어려움

관측: 약 1803px 너비의 현재 화면에서도 기본 표의 월세 일부와 준공·지번주소가 오른쪽으로 밀린다. 지도 기본 상태에서는 표에 보이는 행도 약 9개 수준이다. 지도 접기 자체는 정상 동작한다.

원인: `frontend-rent/src/index.css:89`에서 기본 표의 최소 너비가 `56cm`(약 2,117 CSS px), 확장 표가 `76cm`(약 2,872 CSS px)로 고정되어 있다. 사이드바와 여백을 제외한 표 영역보다 훨씬 넓다.

영향: 임대 화면의 핵심인 전세·매매·월세를 한 번에 비교하기 어렵고, 오른쪽 열을 볼 때 건물명이 사라진다.

권고: 기본 표는 내용에 맞춘 열 너비로 축소하고 건물명 고정을 검토한다. 지도와 표의 기본 높이 배분도 조정한다. 공통 형식 변경으로 진행할 경우 AGENTS.md의 5앱 패리티 규칙을 함께 적용한다.

## 4. [P2 · 통계 한계 노출 개선] 매매 소표본은 전세가율 경고에 반영되지 않음

실제 표시 예:

- 음성아이파크: 전세 42건, 매매 4건, 전세가율 71.6%, `n<15` 표시 없음.
- 음성푸르지오마크베르: 전세 44건, 매매 1건, 전세가율 46.3%, `n<15` 표시 없음.
- 반면 음성지평더웰은 전세 3건, 매매 45건으로 `n<15` 표시가 있음.

원인: `RentBuildingStatsTable.tsx:464`의 경고는 전세 n만 검사한다. `backend/app/rent/sale_join.py:81`의 전세가율 노출 기준도 전세 n≥3만 검사한다.

판정: 현재 용어 설명도 전세 n만 경고한다고 명시하므로 구현과 명세의 불일치는 아니다. 다만 분모인 매매 평균이 1건이어도 별도 경고가 없어, 헌법의 표본 한계 노출 취지에서 개선이 필요하다. 비율 계산 오류로 단정하지 않는다.

권고: 전세와 매매 표본을 각각 설명하고, 매매 소표본도 구분해 경고한다. 비율 숨김 기준 변경은 통계 정책으로 결정한다.

## 추가 정적 확인

`App.tsx:639`의 빈 결과 안내는 “칩 숫자는 선택한 유형의 건물 수”라고 쓰지만, 실제 지역 칩과 선택 안내는 “거래 건수”라고 표시한다. 빈 결과 화면에서는 같은 숫자를 서로 다른 단위로 설명하게 된다. 해당 빈 결과 분기는 이번 UI 조작으로 재현하지 않았으며 문구 모순만 소스로 확인했다.
