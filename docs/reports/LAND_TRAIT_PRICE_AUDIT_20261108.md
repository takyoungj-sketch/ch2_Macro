# 거래목록 공시지가 표시 개선 및 원천 대조

검증일: 2026-11-08. 운영 DB는 읽기 전용 트랜잭션으로 조회했다. 매칭 규칙 V1, 원장, 연결표와 권한 정책은 변경하지 않았다.

## 화면 변경

- 체크박스를 `공시지가 표시`로 바꾸고 옆 물음표로 안내를 다시 열 수 있게 했다.
- 연결 상태·특성기준일 열을 제거했다. 공시지가 한 칸에 금액(원/㎡)과 실제 기준연도를 표시한다. 금액이 없으면 원인과 무관하게 `—`로 표시한다.
- 기존 71.4% 시험 비율과 긴 인라인 설명을 없앴다. 안내에는 연결 방식, 미표시 이유, 거래연도 우선·전년도 대체 원칙, 관측일과 가격 기준시점의 차이, 적정가격과의 구별을 담았다.
- 공통 안내 CSS의 옅은 노란색 바탕·진한 글씨·내부 스크롤·고정 확인 버튼을 재사용했다. 네이티브 모달과 공통 포커스 훅으로 Tab 순환과 포커스 복귀를 처리한다. X·ESC·배경 클릭은 안내만 닫는다.
- 네트워크/서버 실패는 오류로 알리고, 로딩 중에는 이전 응답 때문에 실패 안내가 잘못 나타나지 않게 했다.
- API 응답·CSV의 연결 상태, 기준연도, 관측일 및 회귀분석 입력은 보존했다. 이 변경은 토지의 도메인 열과 도움말에 한정하며 다른 앱의 공통 형식은 변경하지 않았다.

## 충돌 전건 검증

운영 연결표 2,684,877행 중 `price_conflict`는 **16,622건**이다. 이 전건을 로컬 동결 원천 대장 `land_trait_observations.sqlite`의 정상 관측과 표기 정규화 관측에 대조했다. PNU 기본키 범위 조회를 사용했고 원천 파일은 SQLite `mode=ro&immutable=1`, `query_only=ON`으로 열었다.

- **16,282건 / 16,129필지:** 같은 연도의 **1월·7월 가격 차이만** 존재한다. 각 기준월 안에서는 가격이 하나다. 연도 단위 금액 집합이 둘 이상이어서 현재 V1이 충돌로 처리한다.
- **339건 / 329필지:** 같은 기준월에도 관측 시점에 따라 다른 금액이 있다. 이 중 333건은 1월만, 6건은 1월·7월 자료가 함께 있다. 기준월을 추가하는 것만으로는 해소할 수 없다. 정정·변경 이력을 확인해야 하며 원천 오류로 단정하지 않는다.
- **1건:** 연결표 행은 있으나 현재 `land_transactions`에는 같은 해시의 거래가 없어 계약연도를 대조할 수 없었다. 원장 수정·삭제 이력을 추가 확인해야 한다. 이를 다른 두 범주에 추정 배분하지 않았다.
- 대조 가능한 16,621건에서 **같은 관측일·같은 기준연월 안의 서로 다른 금액은 0건**이다. 관측 시점이 다른 변경과 동일 관측 내 실질 충돌을 구별해야 한다.

따라서 기준월이 다른 정상 자료를 연도만으로 묶어 보류하는 운영 사례가 실제 존재한다. **16,282건을 바로 가격 표시 가능 건수로 해석하지 않는다.** 어느 기준월을 선택할지, 계약일 이전에 유효했는지, 정정 이력을 어떻게 다룰지 별도 정책이 필요하다.

## 기존 연결 200건 검증

저장 상태별로 정상 해당연도 80건, 표기 정규화 해당연도 40건, 전년도 가격 40건, 가격 충돌 40건을 추출했다. 각 층에서 법정코드 시도 접두어별 해시 순위로 순환 추출했다. 현행·과거 코드가 함께 있어 접두어는 19개이며 실제 시도 19곳이라는 뜻은 아니다. 무작위·모집단 가중 표본이 아닌 재현 가능한 진단 표본이다.

각 거래에 대해 다음을 확인했고 **모두 200/200건 일치**했다.

1. 저장된 가격 상태·금액·기준연도를 원천 관측과 V1의 거래연도→전년도 선택 규칙으로 재현.
2. 지목·0.1㎡ 단위 면적·용도지역·계약 전 특성 관측일 대조.
3. 원래 마스킹 지번과 연결 필지의 산 여부·본번 대조.
4. 해당 법정코드와 지번 마스크 범위의 다른 원천 필지를 함께 검색하여 기존 규칙상 단일 후보인지 확인. 면적 SQL 조건은 넓게 검색한 뒤 Decimal 기반 V1 규칙으로 최종 판정.

200건 중 **185건은 저장된 특성 관측보다 이후의 관측이 있어**, 최신 자료를 무조건 정답으로 삼지 않고 계약 전 후보 선택을 재검증했다. 이 가운데 **2건은 선택한 정상 관측보다 최신인 계약 전 충돌 관측**이 있었으나, 둘 다 코드·면적·가격이 같은 **표기 차이**였다. 계약 전 최신 실질 충돌을 무시한 오연결은 이 표본에서 발견하지 못했다. 해당 경로의 전국 발생 건수가 0이라고 결론 내리지는 않는다.

## 해석과 후속 기준

- 현행 `거래연도 우선, 없으면 전년도` 정책은 코드로 확인했으므로 안내에 반영했다. 충돌이면 전년도로 자동 대체하지 않는 현재 처리도 유지했다.
- 기존 `trait_asof`는 토지특성 관측일이며 공시지가 기준일이 아니다. 가격의 기준일로 재사용하지 않는다.
- 동결 원천에는 기준연도와 기준월이 보존돼 있다. 이번 감사의 비공개 대조 파일도 연월을 유지했다. **현재 운영 연결표에는 기준월·정확한 기준일·가격 출처 관측일 열이 없다.** 없는 날짜를 1월 1일로 만들어 표시하지 않았다.
- 후속 V2에서는 `필지 + 기준연도·월(원천이 제공하는 실제 기준일) + 금액 + 관측일/정정 이력`을 분리 보존해야 한다. 선택 기준월과 동기간 변경 우선순위를 확정한 후 새 결과를 V1과 별도로 생성·비교하는 것이 적절하다. V1을 덮어쓰지 않는다.
- 원천 대조 대상은 수집 당시 자료를 보관한 **동결 SQLite 원천 대장**이다. 전체 원본 ZIP 재파싱, 현재 외부 공시지가 사이트 조회, 공부 원본의 실제 필지와의 독립적인 실사 검증은 하지 않았다. 마스킹 거래의 진짜 필지 식별 정확도 100%를 입증한 검증은 아니다.
- 공개 집계: `LAND_TRAIT_PRICE_AUDIT_20261108.json`. 재현 도구: `pipeline/parcel_master/audit_land_trait_prices.py`. 식별정보 입력·대조 결과는 사용자 허용하에 Git 제외 logs에 임시 저장했으며, 검증 완료 후 두 비공개 파일을 삭제했다. 소스 커밋과 공개 보고서에는 집계만 포함했다.

## 검증 기록

- 공시지가 표시 단위 테스트 3개 통과. 기존 backend 연결·CSV 및 매칭 규칙, 감사 분류 테스트 합계 22개 통과.
- TypeScript 검사 및 Vite 프로덕션 빌드 통과.
- 로컬 브라우저의 실제 가경동 거래목록에서 금액·기준연도·미표시 대시와 열 제거를 확인했다. 다크·라이트 모드, X·ESC·배경 클릭, 부모 상세창 유지, Tab 순환·포커스 복귀, 본문 내부 스크롤을 검증했다. 1280×720에서 팝업 높이는 612px(85%)이었다. 모바일 전용 화면은 변경하지 않았으며 이번 거래목록 검증 대상이 아니다.
- 구현 커밋 `6c0fbde`를 main에 푸시하고 런북의 land 배포를 완료했다. VPS TypeScript·Vite 빌드 및 backend 재시작 성공, 서비스 active·health 200 확인.
- 운영 서버 내부 HTTP 스모크: 지역 검색 200, 비로그인 토지 5년 기본통계 200, 기본 조건 matrix-yearly 롤링 200, 비로그인 거래목록 401, 주거·비주거 집합 meta/filters 각각 200. 사용자 세션·JWT 없이 기존 인프라 API 토큰만 서버 내부에서 사용했다. 토큰은 출력·저장하지 않았다.
- 운영 index가 참조하는 `/land/assets/index-DQpqe7fx.js`에서 새 공시지가 안내 본문을 확인했다. 운영 브라우저에서 인증 후 전체 유료 거래목록을 조작하는 테스트는 수행하지 않았다. 로컬 UI 검증과 운영 API·배포 번들 검증을 구분한다.
