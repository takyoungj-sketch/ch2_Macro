# KB 보강 운영 반영 사전 확인 — 2026-11-09

**상태: 운영·로컬 모두 이미 반영됨(시공사 3,498 / 주차 3,673), 추가 실행 불필요. KB 적용 4단계는 운영자 지시로 취소.**

운영에도 이미 KB 보강 플래그와 CSV 값이 있다. 현재 CSV·빈칸 조건으로 추가로 바뀔 운영 행은 **0건**이다. 최초 예상인 ‘로컬에는 보강값이 있고 운영에는 없음’과 달라 요청한 중단 조건에 따라 적용 단계로 넘어가지 않았다. 보강 스크립트·CSV 복사, DB 백업·UPDATE, 캐시 비우기·백엔드 재시작, 화면 변경 검증은 수행하지 않았다.

## 1. 로컬·운영 DB 현황

두 DB 모두 `collective_stats`의 `collective_building_attributes`를 READ ONLY 트랜잭션으로 조회했다. `MAX(snapshot_ym)`는 테이블 전체 기준이고, 나머지 건수는 `snapshot_ym='202607' AND asset_type='apartment'` 기준이다.

로컬 결과:

- MAX(snapshot_ym): **202607**.
- 해당 스냅샷 아파트 속성: **45,058행**.
- `kb_internet_builder` 플래그: **3,498행**.
- `kb_internet_parking` 플래그: **3,673행**.
- `builder_raw`가 NULL·공백이 아닌 행: **24,186행**.

운영 결과:

- MAX(snapshot_ym): **202607** — 최신 스냅샷 조건 통과.
- 해당 스냅샷 아파트 속성: **45,058행**.
- `kb_internet_builder` 플래그: **3,498행**.
- `kb_internet_parking` 플래그: **3,673행**.
- `builder_raw`가 NULL·공백이 아닌 행: **24,186행**.

로컬 PostgreSQL은 18.6, 운영은 16.14로 서로 다른 서버를 조회했음을 보조 확인했다. 운영 조회는 SSH로 VPS에서 운영 backend 설정을 읽어 수행했고, 로컬은 기존 로컬 backend 설정으로 접속했다. 접속 URL·비밀번호는 결과에 저장하지 않았다.

이는 현재 보강값이 이미 존재한다는 확인이다. 누가 언제 반영했는지, 어떤 과거 작업으로 들어왔는지는 이번 조사에서 특정하지 않았다.

## 2. promote 시 속성 테이블 덮어쓰기 여부

**덮어쓰는 경로가 있다. 운영에만 채운 값이 다음 원본 덤프에 없으면 사라질 수 있다.** 다음 네 스크립트는 운영 서버에도 존재하고, 줄바꿈을 정규화한 해시가 현재 main과 일치함을 확인했다. 읽기만 했고 실행하지 않았다.

- `deploy/scripts/vps_promote_collective_pg18.sh:30`: `collective_stats`를 DROP/CREATE한 뒤 덤프를 복원한다. 기존 운영 속성 값을 병합·보존하는 과정이 없다.
- `deploy/scripts/vps_promote_db_sql.sh:21`: 지정 DB를 DROP/CREATE하고 SQL 덤프를 복원한다. `collective_stats` 대상으로 사용하면 같은 위험이 있다.
- `deploy/scripts/vps_restore_collective_stats.sh:32`: `pg_restore --clean --if-exists`를 사용한다. 덤프에 `collective_building_attributes`가 포함되면 해당 테이블은 덤프 기준으로 교체된다. 덤프에서 제외한 테이블까지 무조건 교체한다는 뜻은 아니다.
- `deploy/scripts/vps_promote_7y_marts.sh:70`: 단지 속성 덤프를 지정하는 경로에서 `collective_building_attributes`를 TRUNCATE한 다음 덤프를 적재한다. 단지 덤프를 지정하지 않고 건너뛰는 경로는 이 초기화를 수행하지 않는다.

추가로 `vps_sync_collective_building_attributes.sh:40`은 속성 생성기를 `--replace`로 실행한다. 단지 속성 재생성 뒤에도 KB 값·플래그를 다시 검증할 필요가 있다.

현재는 로컬에도 같은 보강값이 있으므로 **현재 로컬 속성 테이블을 그대로 포함한 새 덤프**라면 그 값이 함께 반영될 수 있다. 반대로 보강 전 덤프, KB 값이 빠진 재생성 결과, 다른 스냅샷 원본으로 교체하면 운영에 있던 값의 보존을 보장하지 못한다. 다음에 실제 사용할 덤프의 내용과 실행 경로는 별도 확인해야 한다.

화면의 속성 조회는 최신 스냅샷을 사용하므로, 향후 더 최신 스냅샷을 만들면 과거 `202607`의 KB 값만 존재하는 것으로는 충분하지 않을 수도 있다. 이번 운영 최신값은 요청 조건과 같은 `202607`이다.

## 3. 같은 CSV·빈칸 조건의 운영 미리보기

`apply_kb_complex_fill.py`를 import하거나 실행하지 않았다. 별도 미리보기 도구에서 CSV를 읽고, 입력을 `jsonb_to_recordset`으로 넘긴 **SELECT CTE**로만 변경 예상 건수를 집계했다. 실제 UPDATE·임시 테이블 생성은 하지 않았다. SQL은 READ ONLY 및 REPEATABLE READ 트랜잭션 안에서 실행했다.

조건은 원본과 동일하게 유지했다:

- 완료 행·유효 building_key만 사용, 중복 키는 마지막 입력 우선.
- 시공사 길이 200자 제한, 유효한 정수 주차대수, 세대당 주차 우선순위와 소수 셋째 자리 반올림.
- 속성 행이 없으면 제외, 기존 시공사·주차 값은 덮어쓰지 않음.
- Python의 공백 제거 판정과 실제 UPDATE WHERE의 `btrim` 조건을 모두 고려.
- `asset_type='apartment'`, `snapshot_ym='202607'` 한정.

입력 확인:

- 1단계 CSV: 1,268행, 완료 619행.
- 2단계 CSV: 1,700행, 완료 758행.
- 3단계 CSV: 7,263행, 완료 2,511행.
- 완료 키: **3,888개**, 중복 완료 키 0개.
- 현재 속성에 연결되는 키: **3,674개**.
- 속성 행이 없어 건너뛰는 키: **214개**. 원본 스크립트도 새 속성 행을 생성하지 않는다.

운영 변경 예상:

```text
주차만 변경:       0행
시공사만 변경:     0행
주차·시공사 모두:  0행
총 변경:           0행
주차 변경 합계:    0행
시공사 변경 합계:  0행
```

기존 운영 보강값과 CSV 일치 여부도 집계했다:

- KB 시공사 플래그가 있고 시공사 원문이 CSV와 같은 행: **3,498행**.
- KB 주차 플래그가 있고 주차대수·세대당 주차가 원본 계산과 같은 행: **3,673행**.

로컬에 같은 SELECT 미리보기를 수행한 결과도 변경 0행 및 기존 값 일치 건수가 동일했다. 따라서 미리보기 0행과 과거 로컬 보강 결과 3,498/3,673의 차이는 ‘현재 운영에 값이 없음’이 아니라 **현재 두 DB 모두 해당 값이 이미 채워진 상태**로 설명된다.

최신 스냅샷은 유효하지만, 새로 바뀔 건수는 초기 예상과 다르므로 적용을 진행하지 않았다. 현재 확인 결과로는 추가 적용 대상이 없다.

## 보호 파일·임시 자료

스크립트와 CSV 3개의 SHA256을 시작 전에 기록하고, 확인 종료 시 동일함을 검증했다. release 워크트리와 기본 체크아웃의 해당 파일 바이트도 같았다. 보호 파일 내용은 수정하지 않았다.

모든 미리보기 입력·SQL·도구·집계는 Git 제외 `logs/kb-fill-precheck-20261109/`에 두었다:

- `input-manifest.json`, `input-summary.json`: 보호 파일 해시·입력 집계.
- `local-state.log`, `production-state.log`: DB 현황.
- `local-preview.log`, `production-preview.log`: SELECT 변경 예상·기존 값 일치 집계.
- `promote-server-check.log`: 운영 promote 스크립트 존재·main 일치 여부.
- `preview.sql`, `prepare_preview.py`, `preview_core.py`, `preview_runner.py`: 적용 스크립트를 실행하지 않는 별도 SELECT 미리보기 도구.

운영 DB 원행을 로컬로 내려받지 않았다. 원본 스크립트·CSV를 운영 서버에 복사하지 않았고, 미리보기 입력은 SSH 표준입력으로 전달해 서버 메모리에서만 사용했다.

## 종료 상태

1~3번 읽기 전용 확인 결과, 운영·로컬 모두 이미 반영돼 추가 실행이 불필요하다. **KB 적용 4단계는 취소됐으며 실행하지 않는다.** 운영 DB용 pg_dump 백업 생성, 보강 스크립트 실행, 캐시 갱신/재시작, KB 적용 후 화면 확인은 수행하지 않았다. 이 보고서만 docs 전용 커밋으로 기록한다. promote의 속성 테이블 초기화·교체 위험은 위 2번과 같이 유지된다. Git 제외 logs 아래 임시 자료는 커밋하지 않는다.
