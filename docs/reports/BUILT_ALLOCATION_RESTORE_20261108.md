# 복합 간이 토지 배분단가 복원

2026-11-08 (한국 시간).

## 원인과 복구 범위

기능은 작업 브랜치의 `9fa3202`(11월 3일 추가), `dc326cc`(11월 4일 개선), `ba21f7b`(설명 정비)에 존재했으나 main 통합에서 빠졌다. 11월 8일 00:20 배포 전 백업의 실제 제공 자산 `index-CDYWwcty.js`에는 배분단가 버튼과 계산 설명이 있었고, 이후 통합 배포에서는 빠졌다. 관련 파일을 잔존 파일로 분류했던 것은 잘못된 판단이었다.

원래 작업 브랜치에서 다음 도메인 파일을 복원했다. 해당 브랜치 전체를 병합하거나 현재 App을 과거 버전으로 되돌리지 않았다.

- `frontend-built/src/components/AllocationUi.tsx`
- `frontend-built/src/components/BuiltTransactionAggregate.tsx`
- `frontend-built/src/components/BuiltTransactionListModal.tsx`
- `frontend-built/src/components/BuiltTransactionTable.tsx`
- `frontend-built/src/utils/allocationCost.ts`
- `frontend-built/src/utils/allocationDefaults.ts`
- `frontend-built/src/utils/builtTransactionHelp.ts`
- `frontend-built/src/utils/builtTxAggregate.ts`
- `frontend-built/src/utils/builtTxDisplay.ts`

대장 사용승인연도 대체 계산에 필요한 `approve_year` 필드만 프론트 타입·백엔드 거래 응답·보강 SELECT에 추가했다. 운영 복합 전용 DB에 해당 열이 이미 존재함을 읽기 전용으로 확인했다. DB 구조·거래 원장·기존 매칭 규칙·회귀와 추천 로직은 변경하지 않았다.

현재의 `실거래자료 / 대장자료` 구획, 구조·개별공시지가 최초 선택 시 안내 후 해당 변수만 연결하는 흐름, 기존 추천2 타입은 유지했다. 복합의 배분 계산과 거래 집계 복원에 한정하며 공통 모달 셸과 다른 앱은 변경하지 않았다.

## 검증

- TypeScript 검사·Vite 프로덕션 빌드 통과.
- 프론트 계산·집계 테스트 6개: 원가 상하한과 잔가율, 거래연도/승인연도 우선순위, 거래별 잔존연수 수정의 격리, 음수 보존·면적 누락, 목록/집계 범위 일치, 대체 연도 표식.
- 백엔드 보강·응답·기존 정책 테스트 16개 통과. 실제 응답 모델에 사용승인연도가 보존되는지도 검증.
- 로컬 실제 거래 1,360건 목록에서 배분단가 버튼·원가표·계산 열과 집계 표시 확인.
- 거래별 잔존연수 9→5년 수정에 따라 단가 범위 80~118→125~146으로 변경되고 초기화로 복귀함을 확인.
- 공통 원가표의 한 원가 하한을 변경하자 해당 거래 범위가 80~118→80~126으로 갱신되고 집계에도 반영됨을 확인.
- 상세창을 닫고 다시 열면 배분 표시·원가표 변경이 초기화되고 기본 범위 80~118로 복귀함을 확인.
- 구조 최초 선택의 안내·확인·선택 흐름이 유지됨을 같은 화면에서 확인.

임시 UI 조정은 브라우저 내 상태로만 수행했다. 실제 거래 원장·원가표 기본 파일에는 저장하지 않았다. 운영 브라우저의 로그인 후 유료 화면 전체 조작은 별도이며, 배포 후 운영 소스·번들·서비스와 보강 응답 경로를 확인한다.

## 운영 반영 결과

- 복원 커밋 `64713c3`를 main에 푸시하고 런북의 built 배포를 완료했다. VPS TypeScript·Vite 빌드, 서비스 재시작·active, health 200 확인.
- 운영의 복원 핵심 소스 9개 SHA-256이 검증한 로컬 파일과 일치했다. 실제 index가 참조하는 `/built/assets/index-B4aFQSyQ.js`에 배분단가 버튼·집계가 포함됐음을 확인했다.
- 운영 복합 DB를 읽기 전용으로 연결해 실제 거래목록 핸들러를 실행했다. 가경동 보강 응답 25건 모두 사용승인연도 필드를 유지했고 이 중 19건에 값이 있었다. 식별정보는 출력하지 않았다. 이는 HTTP 로그인 세션을 통한 전체 화면 테스트와 구별한다.
- 사용자 세션 없이 운영 HTTP 거래목록 요청은 기존대로 401이었다. 권한을 해제하거나 테스트 계정을 생성하지 않았다.
- 운영 App에 변수 직접 선택 흐름이 유지됨을 확인했다. 원래 작업 브랜치 전체·격리 폴더·운영 백업·거래 DB는 변경하지 않았다.

## 재발 방지

배포용 main에 없는 파일이라는 사실이나 현재 진입점에서 참조되지 않는다는 사실만으로 기존 운영 기능을 폐기된 코드로 판단하지 않는다. 배포 전 정적 자산과 원래 작업 브랜치의 기능 차이를 함께 확인한다. 이번 복원 파일은 모두 main에 커밋하고 원가·집계 테스트도 함께 보존한다.
