# 토지 거래목록의 토지특성 대장 보강 검토

검토일: 2026-11-08. 코드·기존 시험 기록·운영 DB 집계만 읽었다. 매칭 규칙, 동결 원장, 운영 데이터는 수정하지 않았다.

> 후속 원천 대조와 UI 개선 결과는 [공시지가 감사 보고서](LAND_TRAIT_PRICE_AUDIT_20261108.md)를 따른다. 아래는 최초 코드 검토 기록이다. 계약 후 관측이나 과거 정상 후보 우선 선택 자체를 오류로 확정한 것이 아니다. 실제 1월·7월 기준 차이에 따른 과도한 충돌 16,282건과 동일 기준월의 관측 간 차이 339건을 후속 검증에서 구분했다. 기존 연결 규칙과 동결 표는 보존했다.

## 현재 동작

1. 사용자가 거래목록의 보강 체크박스를 켜고 동의하면 `trait_enrich=true`로 목록을 다시 요청한다. CSV도 같은 설정을 전달한다.
2. 요청 시 외부 대장을 실시간 조회하거나 재매칭하지 않는다. 사전에 생성한 `land_transaction_trait_link`를 `transaction_hash`로 LEFT JOIN한다. 기본 원장과 기존 통계 필터는 유지한다.
3. 오프라인 매칭은 계약 2019년 이후 거래를 대상으로 한다. 취소·무효·지분거래, 미지원 용도지역·지번 형식, 면적 누락 등을 제외한다. 법정코드 이력을 반영하고 지목·0.1㎡ 반올림 면적·용도지역·마스킹 본번·산 여부를 조합해 후보를 찾는다.
4. 계약일 이전 최신 정상 관측에서 후보가 하나이면 exact, 표기 정규화를 통해 조건이 맞으면 label_normalized로 처리한다. 여러 후보·실질 충돌·계약 전 자료 없음 등에는 연결 상태만 남긴다.
5. 유일하게 연결된 필지만 공시지가를 선택한다. 계약연도 우선, 없으면 전년 값을 사용한다. 같은 기준연도에 서로 다른 금액이 있으면 충돌 처리하며 다른 연도로 내려가지 않는다.
6. 연결 상태·공시지가·특성기준일을 추가 표시한다. 추정한 지번은 원래 표시를 덮어쓰지 않고 호버로 제공하며 검증 전임을 표시한다. 모든 저장 행은 unverified=true이다.

## 주요 확인 사항

### 1. 공시지가의 관측 시점 조건이 없다 — 우선 검토

`attach_price_detail(rows, contract_year)`에는 계약일 인수가 없고, 관측일(row[0])을 거르지 않는다. materializer는 해당 필지의 전체 정상·정규화 관측을 전달한다. 한편 화면의 `trait_asof`는 계약일 이전 특성을 기준으로 계산한다. 따라서 표시된 특성기준일과 공시지가를 가져온 실제 관측 시점이 다를 수 있다.

재현: 계약일 2019-02-01, 2019-01-01 관측에 2018년 가격 900, 2019-12-01 관측에 2019년 가격 1000을 주면 `same_year, 1000, 2019`가 반환된다.

이것만으로 실제 저장된 모든 금액이 틀렸다고 판단할 수는 없다. 해당 연도 확정 공시지가를 사후 설명 변수로 쓰려는 것인지, 계약 당시 확인 가능한 가격만 붙이려는 것인지 정책을 명확히 해야 한다. 후자라면 가격 관측일을 계약일 이하로 제한해야 하고, 전자라도 가격 출처 기준일을 특성기준일과 구분해야 한다.

근거: `pipeline/parcel_master/cheongju_land_label_rule_probe.py:155`, `pipeline/parcel_master/land_trait_link_materialize.py:203`, `:221`.

### 2. 단일 정상 후보가 있으면 충돌 검사 전에 exact 반환 — 우선 검토

`classify_link_v1`은 prior 후보가 하나이면 즉시 exact를 반환한다. 별도로 적재한 `conflict_asofs`, `substantive_asofs`는 이 경로에서 사용하지 않는다. 정상 관측과 충돌 관측은 별도 표에 보관되므로 오래된 정상 관측보다 최신인 계약 전 충돌이 있어도 판정에 반영되지 않을 수 있다.

재현: 정상 관측 2019-01-01, 실질 충돌 관측 2019-01-15, 계약일 2019-02-01, prior 단일 후보를 전달해도 결과는 exact이다.

최근 계약 전 관측 전체에서 어떤 판이 최신인지 확인한 뒤, 최신 판이 실질 충돌이라면 금액을 보류하는 방식을 검토해야 한다. 단, 아직 운영에서 이 경로에 해당하는 필지·거래의 건수나 실제 오매칭을 집계하지 않았으므로 확인된 운영 오류 건수로 해석하면 안 된다.

근거: `pipeline/parcel_master/cheongju_land_label_rule_probe.py:130`, `pipeline/parcel_master/national_land_link_shadow.py:107`, `pipeline/parcel_master/land_trait_link_materialize.py:99`.

### 3. 연결표는 동결 스냅샷이며 자동 갱신되지 않는다 — 운영 범위 명시 필요

운영 DB 확인 결과 연결표 2,684,877행, 생성 시각은 2026-10-16 08:02~09:32 UTC이다. 특성 관측일 범위는 2017-10-17~2026-07-20이다. 필수 recovered_lot 열은 존재한다.

흥덕구의 계약일 2026-10-17 이후 정상·비지분 거래 16건을 집계했을 때 연결표 행은 0건이었다. 이 16건은 지원 용도·지번 등 모든 매칭 자격까지 판정한 표본은 아니다.

동결 문서는 같은 V1의 재적재를 금지하고 새 버전 또는 증분 설계를 요구한다. materializer도 완료 시군구를 건너뛰고, 기존 해시는 ON CONFLICT DO NOTHING으로 남긴다. 단순 재실행이나 버튼 클릭만으로 새 거래·수정 자료가 갱신되지는 않는다.

화면에 자료 범위·연결표 생성일을 표시하고, 미계산·대상 제외·미연결을 구분하는 것이 좋다. 71.4%는 과거 전국 시험의 '비교 가능 거래 중 단일 필지 연결 비율'이며 전체 거래의 연결률이나 정확도가 아니다.

근거: `docs/lab/LAND_TRAIT_LEDGER_V1_FREEZE.md`, `pipeline/parcel_master/land_trait_link_materialize.py:67`, `:345`.

### 4. 보강 적용 플래그와 조회 비용

`trait_enrich_applied`는 테이블이 존재해 JOIN을 수행했다는 의미다. 요청 거래의 실제 연결률이나 금액 보강 성공률을 의미하지 않는다. 표 존재 여부만 검사하므로 별도 환경에서 076 마이그레이션이 빠져 recovered_lot 열이 없으면 JOIN이 실패할 수 있다. 현재 운영에는 해당 열이 있어 이 장애는 관측되지 않았다.

목록은 먼저 total 탐색 요청을 하고 다시 최대 10,000건을 요청한다. 서버는 각 요청에서 해당 셀 거래 전체를 읽고 필터링한 뒤 Python에서 페이지를 자른다. 보강 JOIN도 두 번 실행된다. 큰 셀에서는 조회 통합·취소 가능한 요청·페이지 처리 또는 캐시 전략을 검토할 수 있다. 이 비용은 보강 버튼에만 새로 생기는 문제가 아니라 기존 목록 조회 구조에 포함돼 있다.

근거: `backend/app/routers/paid.py:1856`, `:2036`, `frontend/src/api/client.ts:152`.

## 검증과 제한

- 기존 backend/test_land_trait_link, trait_link_helpers, cheongju_land_label_rule_probe, cheongju_land_link_probe 관련 테스트 18개 통과.
- 추가 합성 입력으로 위 시점 조건·충돌 우회 동작을 재현했다. 운영 데이터를 재매칭하거나 동결 표를 갱신하지 않았다.
- 운영 DB에서 표·열 존재, 총 건수·생성일·관측일 범위와 흥덕구 최근 거래의 연결표 존재 건수만 읽었다. 개별 필지와 거래는 출력하지 않았다.
- 전국 재매칭 정확도, 위 두 경로의 실제 발생률, 대표성 검증 및 실시간 외부 원천 자료 확인은 수행하지 않았다.

## 권장 순서

먼저 가격의 시간 기준을 확정하고, 최신 관측의 충돌 검사를 설계한 후 새로운 규칙 버전에서 표본 비교를 한다. 동결 V1은 그대로 보관하고 새 연결 결과를 분리해야 한다. 그 다음 증분 갱신 및 화면의 자료 기준일·보강 상태 표시를 정비한다.
