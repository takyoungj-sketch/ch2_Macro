# 토지 실거래–토지특성 대장 연결 검토 (1단계)

작성 2026-11-10. 범위: 작업 지시서 요약의 1단계(재판정 경로)와 4항(65.1% 분모). 지시서 원문 `CLAUDE_CODE_LAND_LINK_TASK_20261110.md`를 찾지 못해 2·3단계(오연결률 측정, 개선안 A~D)는 진행하지 않았다.

운영 연결 결과는 바꾸지 않았다. 로컬 `land_stats`와 운영 DB는 읽기 전용으로만 조회했다. 두 DB의 연결 테이블 수치는 같다(2,701,573행, 최신 `trait_asof` 2026-07-20).

## 요약

1. **이미 판정된 거래는 다시 판정하지 않는다.** 월간 경로에는 미연결 거래만 다시 보는 단계가 없다.
2. **새 대장 판이 들어와도 V1 판정은 거의 바뀌지 않는다.** V1은 계약일 이전의 마지막 판으로만 필지를 정하기 때문이다. 마지막 판(2026-07-20)을 빼고 판정해도 27,934건 중 54건만 달라졌다.
3. **2026-07 이후 연결률 하락의 주원인은 광주·전남 코드 개편이다.** 2026-07-01부터 광주·전남 거래는 새 코드(`12`)로 필지를 찾는다. 그런데 대장에는 `12`로 시작하는 필지가 하나도 없다. 그래서 이 지역의 7월 이후 거래 9,085건이 모두 `other_unmatched`가 됐다. 대장이 아직 옛 코드(29·46)를 쓰는 동안 옛 코드로 찾게 하면 exact가 7,448건 늘어난다(shadow). 이 지역 월 연결률은 24%에서 78~82%가 되어 6월 수준(82%)으로 돌아온다.
4. 9·10월 연결률이 낮은 것을 "최신 판이 2026-07-20이라서"로 보던 추정은 맞지 않는다. 하락은 07-20이 아니라 07-01에 시작한다.

## 1. 재판정 경로 (코드 확인)

| 위치 | 동작 |
|---|---|
| `pipeline/parcel_master/land_trait_link_materialize.py` | 첫 전국 적재. `INSERT … ON CONFLICT (transaction_hash) DO NOTHING`. 진행 파일(`land_trait_link_progress.json`)에 있는 시군구는 건너뛴다. |
| `pipeline/monthly_ledger_supply.py` `publish` | `capture` 이후 새로 생긴 거래 키(`after - before`)만 `prepare`에 넘긴다. |
| `pipeline/parcel_master/land_trait_link_missing.py` `FETCH` | `NOT EXISTS (… land_transaction_trait_link …)`. 연결 행이 아예 없는 거래만 읽는다. |
| `pipeline/ledger_supply_store.py` `append` | `ON CONFLICT DO NOTHING`. 넣은 수가 요청 수와 다르면 전체를 되돌린다. 기존 행은 "published values"로 유지한다고 적혀 있다. |

**결론:** `other_unmatched`, `no_precontract_observation` 같은 미연결 상태도 연결 행으로 저장된다. 그러므로 한 번 판정된 거래는 이후 어떤 월간 실행에서도 다시 판정되지 않는다. 새 대장 판을 적재하는 단계에도 재판정을 부르는 코드가 없다. `UPDATE`가 바꾸는 것은 `reconcile_orphans`의 `orphaned` 표시뿐이다.

## 2. 마지막 판 제외 vs 전체 판 (shadow)

스크립트: `pipeline/parcel_master/land_link_rejudge_shadow.py`. 읽기 전용이고 JSON만 쓴다. 각 거래를 V1 그대로 세 번 판정한다.

- `full`: 대장 전체 판
- `drop_last`: `asof ≥ 2026-07-20`인 판과 충돌 행을 뺀 판정. 07-20 판이 들어오기 전의 판정을 대신한다.
- `code_gen`: 전체 판. 새 시도 코드로 된 필지가 대장에 하나도 없으면 1:1 코드 대응의 옛 코드를 쓴다.

대상: 계약 2026-04-01~2026-10-31, 시도 `12`(광주·전남)와 `43`(충북), 판정 27,934건. 결과: [`docs/lab/land_link_rejudge_shadow_12_43_20261110.json`](../lab/land_link_rejudge_shadow_12_43_20261110.json)

| 확인 | 결과 |
|---|---|
| `full`과 운영 저장값 | 27,844건 동일. 88건은 아직 연결 행 없음. 2건 다름(저장값 `multiple_candidates`). |
| `drop_last` → `full` | `exact → other_unmatched` 52건, `multiple_candidates → exact` 2건 |
| `full` → `code_gen` | `other_unmatched → exact` 7,448건, `other_unmatched → multiple_candidates` 847건. 모두 시도 `12`. |
| 대장에 필지가 없는 새 시도 코드 | `12`만 해당 (강원 51, 전북 52는 대장에 있음) |

시도 `12`·`43` 합산 월별 연결률(exact + label_normalized ÷ 판정 건수):

| 월 | drop_last | full (현재 운영) | code_gen |
|---|---:|---:|---:|
| 2026-06 | 82.2% | 82.2% | 82.2% |
| 2026-07 | 23.9% | 23.7% | 78.4% |
| 2026-08 | 23.6% | 23.1% | 79.8% |
| 2026-09 | 24.8% | 24.2% | 79.3% |
| 2026-10 | 25.1% | 24.9% | 81.9% |

(표의 월별 값은 `12`와 `43`을 합친 값이다. `43`은 세 방식 모두 거의 같으므로 차이는 `12`에서 온다.)

### 왜 새 판이 판정을 거의 바꾸지 못하나

V1은 계약일 이전의 마지막 판이 거래의 지목·면적·용도지역과 같고 후보가 하나일 때만 연결한다. 계약일 뒤에 나온 판은 `later` 후보가 되어 미연결 사유만 바꾼다. 미연결 사유는 `clean_precontract_traits_differ`, `no_precontract_observation` 등이다. 예외는 `label_normalized` 하나다. 그래서 7-20 이후 계약은 이미 07-20 판으로 판정된다. 다음 판이 들어와도 exact로 바뀔 수 없다. 재판정 경로를 만들어도 V1 규칙에서 얻는 연결은 작다. 바뀌는 것은 대부분 미연결 사유의 이름이다.

`drop_last`에서 exact였다가 `full`에서 `other_unmatched`가 된 52건의 원인은 이렇다. 07-20 이후 계약은 07-20 판으로 비교되는데, 그 판의 특성이 거래와 다르다. 그런데 뒤에 오는 판이 없어서 `later` 후보도 생기지 않는다. 그래서 사유가 `clean_precontract_traits_differ`가 아니라 `other_unmatched`로 잡힌다. 최근 계약일수록 `other_unmatched` 비중이 커지는 것도 이 구조 때문이다.

### 전국 영향 추정 (광주·전남 코드 문제)

로컬 DB 기준 2026-07~10 전국 판정 57,162건 중 연결은 36,299건(63.5%)이다. `code_gen`의 7,448건을 더하면 43,747건(76.5%)이 된다. 6월은 79.6%였다. 2019년 이후 전체 연결률에는 +0.25%p 정도다.

## 3. 화면 연결률 65.1%의 분모

코드에서 65.1을 고정해 쓰는 곳은 찾지 못했다. 그래서 정의별로 다시 계산했다. 2019년 이후 계약, 로컬과 운영 같음.

| 분모 | 건수 | 연결(exact+label_normalized) | 공시지가 있음 |
|---|---:|---:|---:|
| 전체 토지 거래 | 4,112,649 | 46.9% | 46.4% |
| 지분 거래 제외 | 2,936,112 | **65.6%** | **64.9%** |
| 유효·미해제 | 3,850,598 | 50.0% | 49.5% |
| 유효·미해제·지분 제외 | 2,766,025 | 69.7% | 68.9% |
| V1 판정 대상(연결 행 있음) | 2,700,205 | 71.4% | 70.6% |

65.1%에 가장 가까운 정의는 "지분 거래만 뺀 전체"다. 회귀 화면의 "공시지가 연결 n건 / 미연결 m건"이 이 방식이다(`backend/app/land_regression.py`). 지분이 아닌 행 중 공시지가가 0보다 크면 연결로 센다. 이 분모에는 판정 대상이 아닌 거래가 함께 들어 있다.

- 해제 거래 167,010건
- 지원하지 않는 용도지역 65,902건
- 무효 거래 3,077건
- 판정 대상이지만 연결 행이 없는 거래 1,491건

V1이 실제로 판정한 거래만 보면 연결률은 71.4%다. 화면의 정확한 위치(지역·기간 필터)를 알면 65.1을 그대로 재현할 수 있다.

## 4. 한계

- shadow는 시도 `12`와 `43`, 2026-04~10만 돌렸다. 서울(11)·인천(28)은 추가로 돌리는 중이다. 전국 `drop_last` 비교는 하지 않았다. 2개 시도에 12분이 걸렸으므로 전국은 약 2시간으로 본다.
- `code_gen`은 V1을 바꾸지 않고 코드 대응의 적용 시점만 대장의 실제 코드 세대에 맞춘 것이다. 대응은 기존 `load_pairs`(시군구·읍면동·리 이름 1:1)를 그대로 쓴다. 이 대응이 맞는지 따로 검증하지는 않았다.
- 대장이 새 코드(`12`)로 적재되기 시작하면 한 필지의 이력이 두 PNU로 나뉜다. 그때 코드 대응을 PNU 쪽에도 적용해야 한다.

## 운영 반영에 필요한 결정 (승인 전 미실행)

1. 코드 세대 보정을 운영 규칙에 넣을지 결정해야 한다. 넣으면 규칙 버전을 올려야 한다. 예: `LAND_CODE_HISTORY_LAYER_V2`.
2. 이미 저장된 시도 `12` 미연결 행을 다시 판정할 경로가 필요하다. 현재 `append`는 기존 행을 바꾸지 않는다. 대상 행을 지우고 다시 넣거나, 상태가 바뀐 행만 `UPDATE`해야 한다. 어느 쪽이든 운영 DB 쓰기다.
3. 월간 경로에 미연결 재시도 단계를 둘지 결정해야 한다. 위 분석상 V1 그대로라면 효과가 작다. 규칙을 바꿀 때만 의미가 있다.
