# 복합 쌍둥이 확장 화면 선택 복원

2026-11-08. 원래 작업 브랜치 `b94512c`(2026-10-31 23:25 KST)에 있던 화면 개선이 main 통합에서 빠졌다. 11월 8일 00:20 배포 전 백업 소스와 현재 운영 소스를 대조하여, 당시에는 비교창이 맨 아래에 있고 전체 지역명·유사도 전달이 구현돼 있었음을 확인했다.

## 변경

- `MacroTwinResults.tsx`: Local·Twin1·Twin2 비교를 최하단 접이식 영역으로 복원. 추가지역 선택표는 기본 펼침으로 바꾸고 유사도 열과 도움말을 복원.
- `RecommendationModal.tsx`: 후보 선택표와 선택 지역 표시에 전체 지역명을 전달하고 `similarity_score`를 그대로 연결.
- `RecommendStagePanel.tsx`: 후보의 선택적 유사도 타입 복원.
- `profileLink.ts`: 원래 전체 이름 조합 함수 복원. 제공된 시도·시군구·동/리 이름을 연결하고 이미 포함된 상위 이름은 중복하지 않음.

회귀·추천·Twin 계산 및 후보 선택 요청은 변경하지 않았다. 원래 커밋 전체를 병합하지 않았고, 현재 대장 변수 직접 선택·배분단가·모형추천2 화면 제거·AI2 숨김은 유지했다.

## 검증

- TypeScript 검사·Vite 빌드 통과. 전체 이름·중복 제거·법정리 제공 이름 처리 테스트 3개 통과.
- 로컬 실제 복대동 분석과 일반 Macro 탐색을 실행한 뒤 쌍둥이 확장 탭에서 검증했다. 후보 5개에 전체 지역명과 유사도(예: 가경동 91.8%)가 표시됐으며 가경동을 선택하자 현재 선택에도 `충청북도 청주시 흥덕구 가경동`이 표시됐다.
- DOM의 직접 자식 순서가 추가지역 → Local → Twin1 → Twin2 → 표본·검증 안내 → 비교창임을 확인했다. 마지막 비교창을 펼쳐 기존 응답의 지표 표시도 확인했다.
- 유사도는 지역프로필 응답의 0~1 값을 기존 작업 방식대로 백분율 소수 한 자리로 표시한다. 결측·비정상 값은 대시이며 임의 점수는 만들지 않는다.
- 이번 작업은 화면 복원이다. Twin1·Twin2의 추가 회귀를 실행하거나 기존 통계 엔진의 정확성을 새로 검증한 작업은 아니다. 운영 로그인 후 유료 화면 전체 조작은 별도이며 로컬 화면 검증과 운영 소스·번들 검증을 구분한다.

## 운영 반영

- 복원 커밋 `abadae2`를 main에 푸시하고 런북의 built 배포를 완료했다. 운영 TypeScript·Vite 빌드, 서비스 재시작·active, health 200 확인.
- 네 복원 파일의 SHA-256이 로컬 검증본과 일치했다. 실제 index가 참조하는 `/built/assets/index-C9WPclV_.js`에 전체 이름·유사도 표시가 포함됐고 비교창이 Twin2 아래로 배치된 운영 소스를 확인했다.
- 배포 번들에서 배분단가 유지, 모형추천2 프론트 제거 및 AI2 숨김 상태를 재확인했다. 현재 대장 변수 직접 선택 흐름도 유지됐다.
