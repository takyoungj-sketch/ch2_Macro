# KB 시공사 보강 스크립트 사전 검토 — 2026-11-08

원본 커밋: `05fa48fdc707e64f417fefdec2eb05fa96032745`.

## 실행 여부

`pipeline/apply_kb_complex_fill.py`는 **운영 DB에 UPDATE 후 COMMIT하는 스크립트**다. 이번 반영에서는 운영·로컬 DB 어느 쪽에도 실행하지 않았다. 아래는 실행 전 변경 범위와 백업 방법의 보고이며, 백업이나 DB 반영을 이미 완료했다는 의미가 아니다.

## 무엇을 바꾸는가

- 연결: `get_collective_engine()`이 읽는 collective DB 설정.
- 테이블: `collective_building_attributes`.
- 고정 대상: `asset_type='apartment'`, `snapshot_ym='202607'`.
- 입력: `docs/lab/naver_complex_fill/1단계_명단.csv`, `2단계_명단.csv`, `3단계_명단.csv`.
- `상태='완료'`이며 `building_key`가 있는 행만 읽는다. 같은 키가 중복되면 나중에 읽은 입력이 앞의 입력을 덮는다.
- 원본 CSV 3개의 완료 행 수는 각각 619, 758, 2,511건이다. 총 3,888건은 **중복 제거 전 완료 입력 수**이며, 실제 UPDATE 대상 수가 아니다. DB와 대조한 실제 변경 건수는 이번에 산출하지 않았다.
- DB 속성 행이 없는 단지는 새로 만들지 않고 건너뛴다.
- 시공사: `builder_raw`가 NULL 또는 공백일 때만 KB 시공사 원문을 넣는다. 기존 시공사는 유지하고, 기업집단·정규화 필드는 바꾸지 않는다. 200자를 초과하는 KB 시공사 원문은 사용하지 않는다.
- **주차도 함께 처리한다.** `parking_total`과 `parking_per_household`가 둘 다 NULL일 때만 유효한 KB 주차대수와 세대당 주차를 넣는다. 기존 주차 값이 한쪽이라도 있으면 주차 보강은 건너뛴다.
- 세대당 주차는 KB 입력값을 우선 사용하고, 없으면 총주차/세대수로 계산할 수 있다. DB 세대수, 입력 세대수, KB 세대수 순으로 계산 가능한 값을 찾는다. 소수 셋째 자리 반올림이며 0대는 0.000으로 처리한다.
- `attr_quality_flags`에 `kb_internet_builder`, `kb_internet_parking`, 필요한 경우 `parking_implausible`을 기록한다. 기존에 읽은 플래그 문자열을 바탕으로 다시 저장한다.
- 후보 읽기 후 `eng.begin()`의 한 트랜잭션에서 UPDATE한다. SQL WHERE에서 빈칸 조건을 다시 확인한다.
- dry-run 옵션이나 자동 백업 단계가 없다. **일반 실행은 조회 전용이 아니며, 시공사만 넣는 모드도 없다.** 시공사만 보강하려는 작업에 원본 스크립트를 그대로 실행하면 주차도 변경될 수 있다.

## 실행 전에 준비할 백업

1. 중복 실행과 동시 속성 보강 작업을 멈추고 입력 CSV 3개의 SHA256·완료 키 목록·중복 키 처리 결과를 고정한다.
2. 실제 운영 DB 설정을 확인한 뒤, 비밀번호를 출력하지 않는 접속 방식으로 `pg_dump -Fc --table=public.collective_building_attributes`를 수행해 **테이블 스키마·전체 데이터·인덱스가 포함된 custom-format 백업**을 만든다.
3. 백업은 서버의 `/opt/ch2_release_backups/<작업시각>-kb-fill/` 같은 전용 디렉터리에 저장하고 권한 600, SHA256, 파일 크기, 생성 시간, `pg_restore --list` 점검 결과를 기록한다.
4. 실제 후보 키에 해당하는 변경 전 행도 별도로 보존한다. 복구 키는 `building_key`, `asset_type`, `snapshot_ym`; 최소 보존 필드는 `builder_raw`, `parking_total`, `parking_per_household`, `attr_quality_flags`다. 다른 필드와의 대조를 위해 가능하면 전체 행을 보존한다.
5. 백업은 별도 검증 DB에 복원해 조회 가능 여부와 대상 행 수를 확인한다. 백업을 운영 테이블에 단순 추가 로딩하거나 테이블 전체를 비우는 방식으로 복구하지 않는다.
6. 문제가 있으면 변경한 대상 키에 한해 변경 전 네 필드를 복구하고 건수·값·플래그를 대조한다. 백업 이후 다른 작업이 바꾼 값이 있는 경우 무조건 덮어쓰지 않는다.

이미 있는 코드·정적 파일 배포 백업은 이 DB 테이블 백업을 대신하지 못한다. 대상 건수 사전 산출·DB 백업·복구 검증·실제 UPDATE는 이번 작업 범위에서 실행하지 않았다.

## main에 가져올 범위

빈 시공사 표시·내부 출처 플래그 처리, 해당 운영 스크립트와 스크립트가 참조하는 입력 CSV를 선별한다. 원본 커밋의 랩 계획표·일지·과거 실행 결과 JSON은 이번 출시 코드 반영에서 제외한다. 데이터 입력이 포함돼도 스크립트는 자동 실행되지 않으며 기존 서비스 시작 경로에서도 호출하지 않는다.
