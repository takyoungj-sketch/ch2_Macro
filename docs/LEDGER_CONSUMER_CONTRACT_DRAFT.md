# 공통 대장 소비 계약 초안 v1~v2

후속 [제품 숫자 공급·실제 엔진 재현](CHEONGJU_PRODUCT_NUMERIC_SUPPLY_RESULT.md)에서 통합 원문의 속성 893개 키·대표 가격 1,302개를 기존 입력과 일치하도록 공급했다. K-apt 등 기존 출처 승계와 통합 원문 재공급을 구분한다. `legacy_replay_audit`는 고정 입력의 연구 비교에 한정하며 원천 계약의 제품 보강·합산·회귀 권한을 승격하지 않는다.

2026-10-05 통합 원천 공급 구현: [소비 계약 v2.2](LEDGER_SOURCE_CONSUMER_CONTRACT_V2_2.json), [4,000 PK 통합 결과](CHEONGJU_INTEGRATED_LEDGER_V2_4000_RESULT.md), [청주 전체·병행 공급 결과](CHEONGJU_INTEGRATED_LEDGER_V2_CITY_RESULT.md)를 따른다. 원천·기준시점·신뢰상태·last-seen·사용 허용을 각 값에 함께 반환한다. 이는 아래 v1~v2 실험을 보존하면서 원천 공급 계약을 고정한 것이며 제품 연결·회귀 사용 권한의 자동 승격이 아니다.

작성: 2026-10-05. 계약 ID: `ledger-consumer-input-draft-v1`. 청주 실험을 바탕으로 정리한 개편 설계다. 운영 API·테이블·회귀의 현재 계약을 교체한 문서가 아니며, 제품 전환 전 확정할 항목을 아래에 남긴다.

## 소비 단위를 먼저 고정한다

공통 대장은 건물·필지·가격의 원천 관측과 관계 근거를 제공한다. 제품은 이를 거래 또는 단지에 연결한 별도 결과를 소비한다. 표제부 1행이 거래 자산이나 단지 1개라는 전제를 두지 않는다.

- 복합: `transaction_hash`를 소비 키로 유지한다. 계약일·거래 입력 판본·정정/해제 상태를 함께 받으며, 연결 건물 PK와 필지 PNU는 근거가 있는 별도 목록으로 저장한다. 기존 확정 보강과 새로운 후보를 병행 비교한다.
- 주거 집합: `(building_key, asset_type)`을 유지한다. 지역회귀는 기존 단지별 가격 집계 1행에 속성과 최신 대표필지 공시지가를 붙인다. 단지 키↔표제부/대표 PNU는 별도 관계다. 공통 대장의 관리 PK를 단지 키로 자동 치환하지 않는다. 과거 개별 거래마다 토지정보를 보강하지 않는다.
- 비주거 집합: 도로명 `cluster_key` 및 `resolution_mode`를 유지한다. 출처·시점·품질 표시 계약은 주거와 공유하지만 K-apt 단지 속성이나 대표 PNU를 억지로 부여하지 않는다. 현행 분석 단위에서 확보 가능한 항목만 전달한다.

집합 공시지가의 기존 회귀 소비 열은 `assessed_land_price`, `assessed_land_price_year`, `assessed_land_price_pnu`다. 향후 공급 경로를 바꾸더라도 값·연도·대표 필지의 뜻을 유지한다. 현재 `collective_building_assessed_land_price`와의 키 결합도 두 열을 모두 사용한다.

## 서로 다른 판정을 합치지 않는다

각 결과에서 원천 식별, 제품 연결, 가격 품질, 시점 적합성, 회귀 적격성을 따로 반환한다.

1. `identity_status`: `canonical_address`, `unknown_land_type`, `invalid_district`, `invalid_bjd`, `invalid_main_lot`, `invalid_sub_lot`. 이는 선택한 표제부 주소를 해석한 결과다. `canonical_address`도 거래·단지 매칭 인증은 아니다.
2. `consumer_assignment`: 원천 미리보기는 `unassigned`. 제품 연결 단계에서만 소비 키를 부여한다. 연결 결과는 `unmatched`, `candidate`, `confirmed`, `conflict`로 구분하고 근거·판정 규칙·독립 검증 상태를 남기는 안이다. 현행 A1/A2 또는 A~Z 등급은 별도 원래 등급 필드에 보존한다. 새 상태와 기존 등급의 대응은 자동 추정하지 않는다.
3. `price.status`: `identity_blocked`, `not_observed_in_selected_snapshot`, `source_overflow`, `missing_or_nonpositive`, `unknown_price_year`, `positive_known_year`. 미리보기의 상태는 조회한 판본 안에서만 의미가 있다. `identity_blocked`일 때 다른 추정 PNU의 가격을 붙이지 않는다.
4. `temporal_policy`: 어떤 날짜 정책으로 선택했는지 명시한다. 현재 미리보기는 `same_year_research_only`다. 과거 거래 당시 공개·이용 가능했던 자료의 인증을 뜻하지 않는다.
5. `regression_eligibility`: 원천 미리보기는 `not_evaluated`. 향후 목적별 정책에서 선택 변수, 연결 근거, 품질 플래그, 결측·표본 조건을 평가하고 이유를 반환한다. 주소 또는 가격 양수 여부만으로 회귀 사용을 확정하지 않는다.

가격 단위는 원/㎡다. 면적을 곱한 전체 공시지가 금액과 다르다. 공시지가와 토지특성은 둘 다 제공할 수 있지만 동시에 회귀 기본변수로 채택하는 결정은 별도 비교 검증을 거친다. 토지이용계획은 선택 확장 원천이며 기본 공통 입력의 필수 조건으로 넣지 않는다.

## 원천 입력의 필수 내용

실험에서 실제 만든 원천 입력은 `(mgmt_pk, title_snapshot)`별 1행이다. 제품 소비 키는 아직 없다.

- 계약/변환 버전: `contract_version`, 정규화 규칙 버전.
- 건물 관측: `mgmt_pk`, `title_snapshot`, 원문 버전 해시.
- 주소 관계: `identity_status`, nullable `address_pnu`, `relation_kind=title_address` 또는 null.
- 출처: 표제부 배치 내용 해시, 토지 입력 SHA-256, 토지 기준일. 원본 파일 SHA-256과 파일명은 해당 배치 manifest로 추적한다.
- 가격: `price_year`, 원문 연도·가격·원천 상태, 사용 가능한 nullable `value_krw_per_m2`와 품질 상태. 미확정·오버플로·비양수·기준연도 미상은 임의 수치로 바꾸지 않는다.
- 평가 상태: 제품 연결 및 회귀는 `not_evaluated`로 유지한다.

원문 지번·특수지명·블록·로트·주부속 및 관계 개수는 연결된 원문 버전에서 조회한다. 외필지 수·부속건물 수만으로 식별 목록을 만들지 않는다. 토지특성 코드/명칭 및 이용계획 목록의 전체 소비 필드와 정정 판본은 다음 확장 계약에 정의한다. 현재 미리보기는 그 전체 계약의 구현물이 아니다.

## 시점 선택 계약

복합의 현행 `time_fallback`과 사전 가용 자료만 쓰는 연구 방식은 서로 다른 모드로 남긴다. 선행 판본, 최초 이후 판본 사용 여부, 판본 간 충돌을 반환하고 계약 당시 속성 복원이라고 표시하지 않는다. 엄격한 사전 가용 모드에서는 확인된 공개/가용 시점이 필요하다. 판본월·파일명·같은 연도만으로 가용 시점이나 법적 효력일을 인증하지 않는다.

집합 지역회귀는 평가 기준일과 가격 기준연도·정정 판본을 명시한 최신 대표필지 가격을 선택한다. 건축대장 관측월과 가격 연도는 별도다. 최신 자료에서 가격이 없을 때 이전 가격을 묵시적으로 최신값으로 표시하지 않는다. 이전 양수값 유지가 필요하면 사용 연도·기준일·stale 상태를 함께 반환하는 별도 옵션으로 정한다. 이 최신 선택기는 이번 미리보기에서 구현하지 않았다.

토지특성·건축대장·가격이 동일 날짜에 관측됐다고 가정하지 않는다. 2019~2022년 토지 원천만으로 당시 건물 속성을 생성하지 않는다.

## 행수와 중복 계약

제품 입력은 거래 또는 단지/군집 키별 1행이다. 여러 건물·필지 관계는 별도 목록/관계 테이블에 저장하고 원장 LEFT JOIN으로 행수가 늘어나지 않게 한다. 대표 필지, 추가 필지, 전체 대지 확인 여부, 거래 대상 범위를 서로 구분한다.

같은 필지가 여러 표제부와 연결될 수 있다. 가격 단가를 표제부 수만큼 더하거나 필지면적을 중복 합산하지 않는다. 복수 필지 집계는 고유 PNU와 판본을 기준으로 하되, 거래 귀속 면적·지분 및 전체 부지가 확인되지 않으면 총액을 만들어내지 않는다. 집합에서는 여러 후보 PNU가 있다는 이유로 임의 평균을 대표값으로 정하지 않는다.

## 기존 보강 보호와 개편 순서

기존 확정 건물/필지 매칭과 신규 후보는 별도 버전으로 둔다. 원천 코드 2 발견을 이유로 현재 제품 보강을 일괄 삭제·교체하지 않는다. 전환시 영향 목록과 기존값 유지/검토 상태를 먼저 만든다.

건물 연결의 갱신과 최신 공시지가 갱신을 별도 작업으로 나눈다. 실패 배치는 공개하지 않고, 검증한 이전 결과를 재현할 수 있어야 한다. v1에서 시험한 현재 상태 복구 기능은 아직 v2로 이관하지 않았으므로 그 검증을 운영 전환 조건으로 남긴다.

집합 회귀 등급은 엔진의 현행 A/B/C/D/F/T/P 허용과 E/Z/공란·`kapt_same_pnu` 제외를 기준선으로 기록한다. T/P에 대한 목록 안내 불일치를 공통 목적별 정책으로 해소할 예정이며 이번 계약 초안에서 엔진 허용 범위를 바꾸지 않는다. 비주거도 표시·품질 계약을 함께 정리하되 현행 군집 분석에 없는 단지별 지역회귀를 새로 적용하지 않는다.

복합은 거래별 건물 PK 근거, 계약 이후 판본·대표 용도지역·검증 지역 안내, 전체 이관 검증과 월간 신규/미연결 계산 분리를 함께 개편한다. 고정 75%를 새 지역/시점의 매칭 정확도로 제시하지 않는다.

## 이번에 구현한 부분과 남은 결정

`ledger_consumer_input_preview.py`는 두 로컬 SQLite를 읽기 전용으로 열어 원천 식별과 가격 품질을 분리한 입력 파일을 만들었다. 단지 키/거래 해시를 부여하지 않고 회귀 적격성을 평가하지 않았다. DB 파일 해시가 실행 전후 같음을 확인했다. 공개 결과는 [집계 JSON](lab/ledger_consumer_input_preview.json)에 있고, 식별자를 포함하는 입력은 연구 폴더 gzip에만 저장했다.

후속 v2 실행은 [`CHEONGJU_TRAIT_AND_PRODUCT_LINK_REVIEW.md`](CHEONGJU_TRAIT_AND_PRODUCT_LINK_REVIEW.md)를 따른다. 캐시 19열과 원본 DBF 27열을 보존하고 기존 제품 키의 최신 동주소 후보/충돌을 검토했다. 소비 키 확정 연결이나 회귀 적격성 승격은 하지 않았다.

`ledger-consumer-input-draft-v2`는 v1 원천 입력에 `traits`를 추가한다. `traits.status`는 `observed`, `not_observed_in_selected_snapshot`, `identity_blocked`다. 관측일 때만 캐시 원문 `raw`, `raw_record_hash`, 기존 `attribute_version_hash`와 정규화 규칙을 반환한다. `original_dbf`는 `payload_version=traits-raw-dbf-v1`, A0~A26 문자열 `raw_fields`, 원본 행 해시, ZIP 해시·파일명·DBF member·인코딩을 포함한다. 미관측·식별 보류는 `raw`와 `original_dbf`를 null로 둔다. 추가 원필드를 회귀에 자동 채택하지 않는다.

제품 후보 파일은 실제 소비 입력과 별도다. 동주소 후보 관리번호 목록, 원천 v2 판정 후보 수, 가공 추출만의 후보 수, 차단 후보, 기존 대표 PNU와 최신 통계 주소 차이를 보존한다. `independent_match_verification=unverified`, `new_assignment=none`을 유지한다. 복수 후보를 단일 대표 건물로 임의 변환하지 않는다.

대표필지/집계 후속은 [`CHEONGJU_REPRESENTATIVE_AND_AGGREGATION_REVIEW.md`](CHEONGJU_REPRESENTATIVE_AND_AGGREGATION_REVIEW.md)를 따른다. 대표 PNU 차이 4개 중 3개는 해당 통계 기간의 거래에서 함께 관측되지 않은 주소 조합이었다. 각 주소 열의 MAX가 4개 모두 현재 통계를 재현했다. 대표 주소는 함께 관측된 쌍에서 선택하고, 복수 PNU·기존 대표와의 차이는 검토 상태로 전달하는 안이다. 가격 존재 여부만으로 대표를 확정하지 않는다.

집계 조건은 소속 확인·원천 식별·동일 판본·고유 구성원·수량 범위 확인을 분리한다. 주부속/총괄 동주소 관측만으로 소속이나 수량 범위를 인증하지 않는다. 표본 40개는 새 집계를 보류했으며 기존 제품 집계·회귀는 유지했다.

남은 실행 단위는 주소 쌍 선택의 전체 영향 범위, 대표필지/소속의 독립 근거 확인, v2 현재 상태·이력/정정 복구 통합, 코드 2의 의미 확인이다. 제품 전환 전에 최신 결측시 처리, 연결 확정 근거, 회귀 목적별 허용 정책, 독립 검증 기준을 확정한다. 현재 탐색 결과를 보고 사후 합격선을 만들지 않는다.
