# 대장 통합 계획과 청주 실험 종합 리뷰

검토일: 2026-10-05. 검토 기준 코드는 `df7216a`와 현재 로컬 작업 파일이다. 계획·결과 문서, 집계 JSON, 핵심 정규화 코드, 연구 SQLite 3개를 대조했다. 운영 VPS 상태는 조회하지 않았고, 전국 원본 재스캔·회귀 재학습은 하지 않았다. 이 문서는 수정 권고이며 새 운영 정책의 확정·제품 전환을 뜻하지 않는다.

## 판단

**계획의 큰 방향은 유지할 수 있다. 다만 현재 상태를 ‘원천 보존과 이력 관리가 각각 검증된 시제품’으로 보고, 이를 하나의 공급 경로로 통합하는 단계가 먼저다.** 제품 키와 실제 객체의 소속 문제, 회귀 채택 문제는 별도 완료 조건으로 둬야 한다. 모든 관계를 인증할 때까지 대장 구축을 멈추거나, 기술적 테스트 통과만으로 제품 연결을 확정하는 양쪽 해석을 모두 피해야 한다.

기존 건축물 판본과 2019~2026년 토지특성·가격 자료로 공통 원천·이력·복구를 구현할 재료는 확보돼 있다. 건축물은 2024-09·2025-07·2026-07 세 판본뿐이며, 2019년부터의 건물 변동을 전부 복원할 수 있다는 의미는 아니다. API 신청이나 추가 부속지번 수집을 공통 대장 통합 전체의 선행 조건으로 둘 필요가 없다.

추가로 이번 리뷰에서 **본번 0000이 정식 주소로 인정되는 원천 식별 문제**를 재현했다. 이 항목은 다음 통합 전에 처리해야 한다. 기존 실험은 그대로 보존하고 수정 규칙을 새 판본으로 비교하는 방식이 적합하다.

## 1. 유지할 설계

근거: [대장 일원화 로드맵](LEDGER_UNIFICATION_ROADMAP.md), [청주 통합 검토](CHEONGJU_BUILDING_PARCEL_INTEGRATION_REVIEW.md), [v2 운영 설계](CH2_LEDGER_V2_OPERATING_POLICY.md), [기존 구현 계획](PARCEL_MASTER_IMPLEMENTATION.md).

- 원장, 공통 대장, 연결 결과, 분석 결과를 분리한다. MOLIT 원장과 원장만 사용하는 기본통계는 보존한다.
- 공통 대장은 로컬 배치 재료이며, 제품에는 검증한 작은 보강 결과를 전달한다. 요청마다 DB 간 조인을 하지 않는다.
- 필지 PNU, 건축대장 PK, K-apt 관리코드, 제품 키, 거래 해시를 별개 식별자로 둔다.
- 원본·파일 해시·규칙 버전·판본·원문을 보존한다. 관측 시점과 법적 효력일, 실제 입수일을 구분한다.
- 토지·복합은 거래 단위 연결을 검토하고, 집합은 단지/건물 단위 최신 공시지가와 속성 공급을 유지한다. 집합 과거 거래별 보강을 새로 확대하지 않는다.
- 토지이용계획은 선택 확장 자료다. 주거의 단지 규칙을 비주거 도로명 군집에 적용하지 않는다.
- 미연결·미관측·가격 결측·품질 보류를 각각 전달한다. 대장 누락을 말소로, 유일 후보를 정답으로 해석하지 않는다.

## 2. 실제 실험이 입증한 범위

### 토지 원천과 회귀

[청주 실험 계획](PARCEL_LEDGER_CHEONGJU_PILOT_PLAN.md) 및 `lab/cheongju_trait_links_20261004.json`, `lab/cheongju_historical_regression_20261004.json`을 대조했다.

2019~2026년 거래 입력은 62,499건이다. 연도 대표·거래 전 관측 정책별 후보 하나는 28,162건·24,758건이며, 양수 면적·단가·공시지가를 갖춘 회귀 표본은 28,157건·24,754건이다. 두 정책의 표본은 다르다. 연도 대표는 사후 참고 분석이고, 거래 전 관측도 당시 실제 공급·입수 가능성을 인증하지 않는다.

시간 순서 검증 모형 80개에서 공시지가 추가 효과가 확인됐다. 이 결과는 연결된 양수 가격 표본 안의 효과이며, 독립 매칭 정확도나 전체 시장 대표성을 증명하지 않는다. 가격으로 매칭 후보를 고르지 않았고, 동일 정책·범위·검증연도 안에서 모형별 표본을 같게 비교한 것은 적절하다.

2026년 거래 전 관측 검증 표본 1,610건의 결과는 목적별 판단이 필요함을 잘 보여준다.

- 기본 모형: 로그 RMSE 0.7800, 20건 이상 집단 평균의 가중 절대오차 4.2008만 원/㎡.
- 공시지가 모형: 로그 RMSE 0.7068, 집단 평균 오차 3.9205만 원/㎡.
- 공시지가·특성 결합: 로그 RMSE 0.7035, 집단 평균 오차 4.2591만 원/㎡.

결합 모형은 개별 로그 오차를 더 줄이지만, 계획의 주목적인 집단 평균 오차는 기본 모형보다 크다. 공시지가 모형의 실제 평균 25.4388만 원/㎡ 대비 예측 평균은 30.0077만 원/㎡로 약 17.96% 높다. 정보 추가의 가치와 평균 추정의 보정은 별도 과제다.

평균 편향 진단 162개는 탐색으로 가치가 있다. 그러나 최근 학습연도의 학습 내 적합값을 쓰는 비율 보정은 독립 보정 표본 검증을 대신하지 않는다. 같은 검증연도들을 여러 방식의 선택에 사용했으므로 이후 최종 평가를 독립적으로 마련해야 한다. 새 필지 검증과 구별 결과를 이미 보고했으므로 이를 ‘미실행’으로 쓰기보다 목적별 최종 채택 기준이 미확정이라고 쓰는 것이 정확하다.

평균 CI는 연결·시점·로그 역변환 보정의 불확실성을 모두 포함한 구간이 아니다. 현행 근사 구간이 좁아졌다는 이유만으로 성공을 판단하면 안 된다.

### 건물 주소와 토지특성의 연결 범위

[연결 범위 보고](CHEONGJU_BUILDING_TRAIT_COVERAGE_RESULT.md)에서 2026년 건물 관측 141,252개 중 133,931개(94.817%), 대표 주소 필지 94,365개 중 90,087개(95.467%)에 토지특성이 연결됐다. 이는 주소 필지의 자료 교집합이며 거래 대상 또는 전체 부지 정확도가 아니다.

이 광범위 연결은 대장 통합의 효용을 뒷받침한다. 다만 도시 전체 수치는 기존 가공 추출을 사용한다. 원문 v2 검증은 관리 PK 4,000개 표본까지이므로 도시 전체를 원천 검증 완료로 쓰면 안 된다. 표본은 주소 변경 사례를 의도적으로 포함해 예외율 추정용 무작위 표본도 아니다.

### 이력과 원문 보존

[건물·필지 staging](CHEONGJU_BUILDING_RELATION_STAGING_RESULT.md)은 관리 PK 4,000개에서 건물 관측 11,696개, 토지특성·공시지가 관측 각 10,867개를 보존하고 반복 실행·실패 롤백·이전/최신 current 복구를 시험했다. 가격을 토지특성 내용 버전에서 분리한 구조는 적합하다.

[원문 v2 확대](CHEONGJU_BUILDING_SOURCE_V2_FULL_RESULT.md)는 같은 관리 PK 4,000개의 관측 11,696개와 원문 버전 7,986개를 보존했다. 주소 관계 11,673개, 코드 2 보류 23개다. 토지특성 입력에는 캐시 19열과 원본 DBF 27열을 보존했다. 그러나 건축 원문은 선택 필드 보존이며 76/77열 전체 이관은 아니다.

이 두 성과는 합산해서 ‘통합 v2 완료’라고 할 수 없다. 현재 원문 v2에는 가격·토지특성·current 복구가 없고, 이전 관계 staging에는 그 기능이 있지만 가공 건물 속성을 사용한다. 입력 미리보기는 두 자산을 읽는 외부 조합이며 일관된 한 배치의 공개·복구 경로를 완성한 DB가 아니다.

전체 건축 원문 76/77열을 전부 운영형 테이블에 복제하는 것을 완료 조건으로 강제할 필요는 없다. 원본 파일·해시·판본과 행 식별 근거를 유지하고, 소비·판정에 필요한 필드의 대응과 의미·변환·결측을 확정하면 된다. 별도 원문 payload나 원본 참조로 나머지 필드를 재현하는 방식도 가능하다. 현재 선택 필드 보존의 한계와 원본 자체의 보존 여부는 구분해서 관리한다.

이번 읽기 전용 확인에서 SQLite 3개의 테이블 행수는 해당 집계와 일치했고 `quick_check=ok`, 외래키 오류 0건이었다. 파일 해시는 확인 전후 동일했다. 관련 `test*.py` 전체 발견 실행은 119개 통과했다. 이전 보고서의 19·25·82·76 같은 테스트 수는 서로 겹치는 실행 묶음이므로 더해 누적 성과로 쓰지 않는다.

### 주소·제품 키·실제 소속

[주소 감사](CHEONGJU_ADDRESS_PAIR_IMPACT_RESULT.md)와 [이름 키 혼합 감사](CHEONGJU_NAMED_OBJECT_MIX_RESULT.md)에서 분양권 포함 1,471개 키 중 28개가 거래에서 관측되지 않은 통계 주소 쌍을 사용했고, 43개가 여러 법정동 거래를 묶었다. 이 28개는 모두 43개에 포함된다. 열별 MAX를 함께 관측된 주소 쌍으로 바꾸는 것만으로 키의 객체 혼합은 해결되지 않는다.

우선 가격 마트 6개의 숫자는 원본과 맞았지만 객체에 귀속할 근거가 부족했다. 가격 숫자의 정확성과 가격을 적용할 객체의 정확성이 다른 문제라는 중요한 발견이다.

[아파트 17개 검토](CHEONGJU_APARTMENT_SITE_REVIEW.md)는 28개 주소 쌍 중 23개에서 서로 다른 단지임을 뒷받침하는 독립 주소·관리·승인일 근거를 확인했다. 모든 개별 거래의 소속이나 관리코드 승계 이력을 인증한 것은 아니다. 같은 필지의 복수 코드도 자동 분할하지 않아야 한다.

[선택기 실험](CHEONGJU_OBJECT_SELECTOR_SHADOW_RESULT.md)은 52개 검토 큐와 같은 법정동 복수 PNU 33개의 중복 없는 85개 키, 177개 주소 파티션, 13,975거래를 보존했다. 객체 범위 보류 74개, 같은 필지 관리코드 검토 9개, 사업 블록 2개다. 새 대표 선택·객체 할당·가격 승계는 0개다. 이것은 **보존·보류 선택기의 완료**이며 실제 대표필지 선택기의 완료는 아니다.

비주거 306개 군집은 기존 키 보존 대조군이다. 주소 조합 미관측 0개를 비주거 전체 연결 정확도 인증으로 확대하지 않는다. 85개 메모리 내 처리 0.00587초 역시 운영 DB·API 성능 지표가 아니다.

## 3. 이번 리뷰에서 확인한 우선 보완 사항

### A. 본번 0000의 정식 PNU 승격 — 통합 전 수정

`building_source_staging_v2.identity(['43111','12000','0','0000','0000'])`는 `canonical_address`와 19자리 PNU를 반환한다. 숫자 자릿수만 확인하고 본번 0을 별도 예외로 처리하지 않는다.

실제 저장된 v2 표본에서도 본번 0000의 정식 주소 관계는 **44개 관측·16개 고유 관리 PK**다. 판본별 14·14·16개다. 별도로 코드 2의 본번 0 관측 23개는 이미 보류됐다. 즉 여기서 새로 문제 삼는 것은 코드 2를 정식 필지로 변환했다는 주장이 아니라 **코드 0의 본번 0도 정식 주소로 승인하는 규칙**이다.

이 44개에 정상 지번과 같은 정규화 승인을 줄 근거가 현재 규칙에 없다. 개별 행의 실제 지번 의미를 원문·공식 정의로 확인하고, 그 전에는 원문을 유지하며 `noncanonical_zero_main_lot` 같은 별도 식별 보류로 분리해야 한다. 본번 0을 허용할 명시적 예외가 확인되면 그 예외 규칙과 근거를 기록한다. 이번 리뷰로 이 44개의 거래 연결·가격 피해까지 확인한 것은 아니다.

이전 v1과 같은 PNU라는 대조만으로 정규화 타당성이 검증되지 않는 사례다. 기존 v2·보고서·해시는 수정하지 말고 새 규칙으로 영향 목록과 입력 차이를 만들 것을 권고한다. 새 건축HUB 검증기는 본번 0에서 PNU를 생성하지 않아 두 입력 경로의 정책 일치도 필요하다.

### B. 출처·정정 판본·PK 공간을 통합 스키마에 반영

현재 원문 v2의 `source_batch` 기본키는 월 문자열 `snapshot` 하나이고 같은 월의 다른 내용은 거절한다. 실험 보호에는 적합하지만, 서로 독립적으로 공급되는 토지·건축·가격 자료와 정정판의 공통 레지스트리로는 부족하다.

새 통합 모델은 원천종류·지역/범위·원천 판본·수집 배치·파일 해시·변환 규칙 버전을 참조해야 한다. 원본 정정판과 정규화 규칙 변경을 구분하고, 공개 배치 ID가 어떤 토지·건축·가격 버전을 묶는지 고정한다. 재처리 때 같은 월 자료를 조용히 덮지 않는다.

건축HUB PK 이관이 존재하므로 PK 공간도 출처와 함께 명시한다. 실제 구·신 PK 대응이 확보되기 전에는 문자열 같음으로 승계하지 않는다. PNU 변경과 법적 필지 계보도 분리한다.

### C. current와 마지막 관측을 구분

마지막 관측 보존은 올바른 방식이다. 그러나 최신 원천에 없는 건물을 `current`라고만 반환하면 현재 존재·유효 상태로 오해할 수 있다. `selected_source_snapshot`, `last_seen_snapshot`, `observed_in_selected_snapshot`, 가격 기준연도와 미관측 사유를 함께 제공해야 한다. 새로운 원천이 없을 때 이전값을 사용할 목적과 허용 조건도 소비 계약에 기록한다.

토지·건축·가격을 서로 독립적으로 적재하더라도 소비자가 읽는 공개 배치와 복구 지점은 함께 고정해야 한다. 한 부분만 최신으로 전환한 조합이 자동 공개되지 않도록 한다.

### D. 지역 전체 후보와 저장 범위를 구분

기존 D-050 문서는 수요 필지 적재를 고정했고, 청주 계획은 도시 전체 필지를 후보로 사용하는 방향을 검토한다. 둘은 후보 조회 범위와 영구 저장 범위를 나누면 조화될 수 있다.

청주 마스킹 후보의 모집단은 도시 전체 원천으로 유지해야 한다. 거래 있는 필지만 남겨 유일 후보를 만들어서는 안 된다. 한편 전국 전체 필지 선적재는 계속 범위 밖이다. 청주 전체 후보 인덱스를 로컬 대장에 저장할지, 지역 원천 캐시로 참조할지 결정하고 용량·처리시간을 실측한다. 기본 대장 축과 후보 인덱스를 같은 테이블로 강제할 필요는 없다.

### E. 객체 검증과 공급 허용을 목적별로 나눔

대장 원문 조회, 주소 관측, 후보 반환, 실제 객체 소속, 대표 선택, 속성 합산, 회귀 사용은 서로 다른 허용 단계다. 모두를 하나의 `membership_verified`에 매달면 조회 가능한 원문까지 막히고 관계 조사가 무한히 늘어날 수 있다.

대장 자체의 관측·품질 보류는 바로 저장·조회할 수 있다. 제품 키에 새 보강을 승계하는 단계는 별도 근거를 요구한다. 대표 주소만 필요한 소비와 전체 부지·합산 수량이 필요한 소비의 증거 요구도 구분한다. 애매한 85개가 끝날 때까지 모든 통합을 대기하는 구조로 만들지 않는다.

단, 85개 밖의 키가 모두 정확하다는 뜻은 아니다. 일반 단일주소 사례·다동·다필지·이름 없음·비주거 등 일반화에 필요한 층화 검증과 거래 보존 검사를 별도로 한다. 기존 마트 값 보존은 재현 기준이지 재인증이 아니다.

### F. 평균 추정 목적에 맞춘 회귀 채택 기준

주 평가 항목은 집단 평균 오차·평균 편향·구/지목/용도별 안정성으로 정하고 개별 로그 RMSE·R²는 보조로 둔다. 표본 수·범위와 구간의 불확실성 범위도 함께 평가한다. 특성 변수는 조회 제공과 회귀 기본 채택을 분리한다.

다음 평가 전에 허용 오차와 구별 악화 기준을 정해야 한다. 이 리뷰에서는 이미 본 2026년 결과에 맞춰 수치 문턱을 새로 만들어 합격시키지 않는다. 시간 분리된 학습·보정·최종 검증, 기존/신규 필지 구분, 선택 표본과 전체 거래 구성 비교를 포함한다. 월별 계절·검증기간 길이와 실제 관측 범위도 비교 대상으로 명시한다.

## 4. 단계별 진행 판정

- **0단계 기준 고정:** 연구 입력·출력은 상당 부분 고정됐고 해시가 있다. 향후 실제 제품 개편 직전 코드·입력·현행 마트 기준점을 별도로 고정해야 한다. 현재 작업 파일의 미커밋 변화까지 포함해 모든 제품 기준이 고정됐다고 할 수 없다.
- **1단계 원천 사전:** 토지 원천과 건축 선택 필드 조사에 충분한 성과가 있다. 본번 0, 건축 전체 필드의 보존 정책, 출처별 PK 공간, 과거 기본개요 보유 기록과 현재 위치 차이는 남아 있다. 마지막 항목이 기본 통합의 중단 조건은 아니다.
- **2단계 정규화·복구:** 표본 v1 이력·복구와 v2 원문 보존은 검증됐으나 통합 경로는 미완료다. 지금의 최우선 구현 단계다.
- **3단계 연결 검증:** PNU 자료 교집합과 후보·키 혼합 범위는 측정했다. 거래·객체 소속과 새 대표 선택은 미완료다. 통합과 별도로 필요한 관계를 층화해 진행한다.
- **4단계 정책 확정:** 소비 계약 초안은 있지만 목적별 허용과 정정·공개 배치·회귀 채택 규칙은 확정 전이다. 일부 원천 저장 규칙은 먼저 고정하되 제품 사용 정책을 실험 완료로 간주하지 않는다.
- **5단계 제품 개편:** 전체 재계산/증분 구분, 허용 등급·목록 설명의 일치, 복합 출처·시점 안내, 키 대응표·회귀 영향 확인이 남아 있다. 공통 공급 경로와 검증 기준을 갖춘 후 진행한다.
- **6단계 운영 전환:** 아직 진행할 단계가 아니다. 로컬 병행 결과·갱신 비용·키/거래 보존·이전 결과 복구와 사용자 설명을 갖춘 뒤 별도 전환한다. 배포는 요청 시 수행한다.

## 5. 권고 작업 순서와 완료 조건

1. **식별 규칙 수정 실험:** 본번 0 및 코드 2·미상·산 구분을 한 계약으로 정의한다. 원본 보존, 기존 v2 대비 변화 목록, 영향 입력의 가격·특성 연결 보류를 확인한다. 기존 실험 파일은 덮지 않는다.
2. **4,000 PK 통합 v2:** 기존 원문·특성·가격·관측·주소 관계를 한 배치 레지스트리로 연결한다. 독립 원천 날짜·정정판·PK 공간을 보존한다. 3판본 반복, 중간 실패의 모든 계층 원상 유지, 이전/최신 배치 복구, 기존값과 차이 사유를 확인한다.
3. **청주 범위와 비용 확대:** 고정 표본 다음에 전체 청주 건축물·토지 후보 범위로 확대한다. 원문 이관 범위, 행수·유일키·원천 미관측, 저장량·인덱스·적재/복구 시간과 증분 비용을 실제 측정한다. 지금의 메모리 선택기 시간으로 대체하지 않는다.
4. **제품 공급 병행:** 복합 거래와 집합 단지용 입력을 따로 만들고 거래/키 보존, 누락·중복, 가격/속성 차이, 보류 사유를 비교한다. 문제 85개를 보존하며 정상 비교군도 검증한다. 객체 분할 시 옛 키↔새 키↔거래 대응표를 먼저 만든다.
5. **관계 근거와 회귀 평가:** 추가 관계 수집은 필요한 사례와 소비 목적에 한정한다. 원천 부모 관계가 거래 소속을 대신 인증하지 않는다. 회귀는 독립 보정·최종 평가 기준을 고정한 뒤 평균 목적의 채택 여부를 결정한다.
6. **정책·월갱신·표시 개편과 전환:** 승인된 소비 규칙으로 제품의 목록·CSV·필터·회귀 안내를 일치시킨다. 전체 이관 검증과 신규/미연결 계산을 나누고, 판본 변경 시 재검토 대상만 산출한다. 이전 결과의 복구 경로를 확인한 뒤 단계적으로 전환한다.

완료의 첫 도착지는 ‘소속이 전부 인증된 전국 대장’보다 **청주에서 재현·갱신·복구가 가능한 공통 입력 공급 경로**로 정하는 것이 현실적이다. 두 번째 도착지는 소비 목적에 맞게 검증된 연결 결과와 품질 상태를 제품에 전달하는 것이다. 이 구분은 원래 계획의 원장 보존·출처 추적·검증 후 전환 원칙과 일치한다.

## 6. 계획 문서에 반영할 수정안

계획의 0~6단계는 유지하되 2단계를 ‘원천 식별 교정 → 표본 통합 → 청주 확대’로 나누고, 3단계 소속 검증은 소비 목적별로 병행할 것을 권고한다. 추가 API 권한을 전체 단계의 관문으로 두지 않는다.

`PARCEL_MASTER_DESIGN.md`의 ‘집합 매칭 정확도 개념 없음’, ‘키와 필지 거의 1:1’은 당시 PNU 조회의 용이성을 설명한 관측이다. 새 실험에서는 객체 키 혼합과 대표 주소 문제가 확인됐으므로 현재 공통 연결 정책의 보장 문장으로 사용하면 안 된다. D-050의 로컬 저장·원장 분리·전국 선적재 금지는 유지하되 수요 저장과 청주 전체 후보 모집단은 분리해서 설명한다.

`CH2_LEDGER_V2_OPERATING_POLICY.md`·소비 계약의 당시 ‘코드 2 미확인’, 완료 항목 및 다음 작업은 날짜별 기록과 현재 상태를 구분해야 한다. 새 현재 상태 표에는 ‘코드 2 의미 확인/정식 지번 미해결’, ‘본번 0 추가 식별 보류 필요’, ‘통합 v2 복구 미완료’를 명시한다.

`PARCEL_LEDGER_CHEONGJU_PILOT_PLAN.md`의 최초 ‘원천 조사 전’ 상태와 월간 문서의 ‘운영 0행’ 같은 오래된 표현은 각각 당시 상태 기록으로 표시해야 한다. 운영 0행은 이번 리뷰에서 VPS를 조회한 사실이 아니므로 현재 운영 상태로 재확정하지 않는다.

현재 로드맵의 긴 진행 내역은 증거 일지로 보존하되 맨 앞에 단계별 현황·다음 완료 조건을 둔다. 조사 결과가 생길 때마다 다음 원천 조사로만 이어지는 흐름을 줄이고, 핵심 통합 산출물을 기준으로 진행을 관리한다.

이번에는 종합 리뷰와 검증 집계만 작성했다. 기존 계획·정책의 확정 내용을 자동 변경하거나 원천 식별 코드·DB·제품을 수정하지 않았다. [검증 집계](lab/ledger_plan_experiment_review_20261005.json)에는 이번 읽기 전용 점검과 수치 근거를 보존한다.
