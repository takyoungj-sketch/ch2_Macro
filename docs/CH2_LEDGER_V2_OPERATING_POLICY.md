# CH2 Ledger v2 운영 설계 — 청주 검증 후속

작성: 2026-10-04. 상태: 로컬 연구·표본 SQLite 갱신 시험 구현. 운영 정책 전환·운영 DDL·자동 갱신 미실행.

## 목적과 현재 경계

실거래와 대장을 독립적인 원자료 자산으로 유지하고 연결·분석 결과를 재생성한다. 기존 `parcel_master`를 보존하며 청주부터 병행 검증한다. D-050/D-051의 원장 미덮기, 로컬 대장 보관, 확정 보강 동결, 결과만 운영 반영, 동의·출처 표시를 유지한다. 전국 선적재와 공개 토지 회귀 활성화는 이번 작업에 포함하지 않는다.

## 저장 계층

- 원본: ZIP/CSV와 파일 SHA-256, 공급기관·파일명·지역 범위·판본·입수일. 원본은 보존한다.
- 대장: 필지 기본정보, 토지특성, 복수 토지이용 지정, 연도·판본별 공시지가, 건물 속성을 별도 관리한다.
- 연결: 거래 식별자, 후보 PNU 목록·수, 규칙 버전, 사용 원천 판본, 판정 사유와 독립 검증 상태를 보존한다.
- 분석: 연결 버전·특성 버전·모형 버전·거래 입력 판본을 참조하는 고정 결과를 생성한다. 원장이나 MOLIT-only 기본통계 마트를 덮지 않는다.

처음부터 별도 PostgreSQL 서버를 추가하지 않는다. 기존 DB 안의 테이블/스키마 경계와 로컬 연구 자산을 우선 사용한다. 연구 gzip 파일은 운영 이력 DB의 완성본이 아니다.

## 권장 스키마와 시점

`ledger_source_snapshot`에는 원천종류, 판본 ID, 지역 범위, `source_base_date`, `collected_at`, `loaded_at`, 파일 해시, 검증 상태를 둔다. 과거 파일을 지금 확보했다면 과거에 CH2가 보유했던 것으로 기록하지 않는다.

`parcel_attribute_history`는 내부 필지 식별자·PNU·속성 해시·원천 판본을 보관한다. 변경 없으면 관측 기록만 추가하고 동일 속성 전체를 복제하지 않는다. 변경시 새 이력을 추가한다. current는 검증된 공개 판본의 조회 뷰 또는 명시적으로 승인한 포인터다.

`parcel_land_use_history`는 복수 지정을 보존하고 포함·저촉·접함을 구분한다. `parcel_land_price_history`는 PNU·기준연도·정정 판본을 구분한다. `building_snapshot`과 `parcel_building_link`로 다대다 관계를 표현한다.

`parcel_identity`와 `parcel_lineage`는 PNU의 영구 불변을 가정하지 않는다. 분할·합병 관계는 원천 근거가 확인된 경우에만 추가한다. 주소나 면적 유사성만으로 관계를 생성하지 않는다.

`transaction_parcel_link`와 `transaction_feature_version`을 분리한다. 필지가 같은데 속성만 바뀌었다면 다시 필지를 찾지 않고 새 특성 버전을 생성한다. 기존 확정 연결은 자동 교체하지 않는다. 정정·해제 거래는 원장 상태를 따른다.

`effective_date`는 원천이 실제 효력일을 제공할 때만 기록한다. 관측일 사이에 값이 바뀌었다는 사실로 법적 변경일을 추정하지 않는다. ‘거래 전 관측자료’는 원천 내부 기준일 기준의 사후 연구이며 당시 실제 입수 가능성을 보장하지 않는다. 미래예측 검증에는 공급·입수 시점도 통제한다.

## 갱신 절차

매월 거래 갱신은 기존 해시 유지 UPSERT·정정·해제 정책을 따른다. 신규 거래 연결, 미연결 재시도, 확정 연결의 수정 제안을 별도 처리한다. 모든 기존 거래를 무조건 재매칭하지 않는다.

분기마다 대장 공급 여부를 확인한다. 새 판본이 있을 때 원본 확보 → staging 검사 → 이전 판본과 비교 → 변화 이력 추가 → 완전성 검증 → 새 공개 판본 지정 순서로 처리한다. 분기 점검은 원천기관이 분기마다 신본을 공급한다는 뜻이 아니다. 공시지가 기준연도와 정정 판본은 따로 관리한다.

수집 누락·지역 누락·파일 손상은 필지 삭제로 해석하지 않는다. 전체 공급 범위가 검증되고 말소 근거가 확인될 때만 말소 상태를 기록한다. 실패한 배치는 current나 운영 분석 결과를 변경하지 않는다.

연결 수정·규칙 변경은 새 버전에서 비교하고 검증 후 반영한다. 과거 확정 결과는 유지한다. 전체 재생성 명령은 별도로 제공하되 일상 월갱신 경로로 사용하지 않는다.

## 청주 전환 순서와 검증 게이트

1. 현재 연구 입력·결과를 해시와 함께 고정한다. 기존 운영 DB는 보존한다.
2. 구·연도·지목별 독립 근거 표본과 정책 충돌 3건을 검토한다. 후보 하나를 정확도로 보고하지 않는다. 정답 근거가 없으면 미검증으로 남긴다.
3. 연결/미연결 집단의 분포 차이, 새 필지 검증, 구별 평균 오차를 함께 제시한다.
4. 청주 전용 staging에서 이력·연결·특성 버전을 시험한다. 중복 실행 멱등성, 누락 배치 중단, 실패 복구, 기존 결과 재현을 확인한다.
5. 같은 입력에서 기존 결과와 새 결과의 차이를 검토한 뒤 운영 정책 개정·제품 적용 범위를 결정한다.

현재 통과: 읽기 전용 연결, 과거 확대 80개 회귀, 평균 편향 162개 비교, 새 필지·구별 검증, 입력 해시, 식별자 없는 관리자 집계, 4,000 PNU 로컬 표본의 판본·속성 이력·멱등성·실패 원상 유지·과거 복구 시험. 미통과: 독립 연결 정확도 인증, 전체 청주 운영 DB 전환, 자동 원천 수집, 건물·복수 지정 이력 및 월간 거래 보강 연결.

새 검증 게이트의 수치 기준은 추가 성능 결과를 보기 전에 별도로 고정한다. 이번 탐색 결과를 보고 사후에 정확도 합격선을 만들어 운영 인증하지 않는다.

후속 표본 시험: [`CHEONGJU_BUILDING_RELATION_STAGING_RESULT.md`](CHEONGJU_BUILDING_RELATION_STAGING_RESULT.md). 관리 PK 4,000개에서 건물/토지 속성·공시지가 관측·대표 주소 관계 이력을 분리하고 누락 유지·재실행·실패 롤백·이전/최신 복구를 확인했다. 전체 부지 관계, 운영 PostgreSQL 전환, 제품 보강 수정이 완료됐다는 뜻은 아니다.

원천 보존 후속 시험: [`CHEONGJU_BUILDING_SOURCE_V2_RESULT.md`](CHEONGJU_BUILDING_SOURCE_V2_RESULT.md). 검토 대상 관리 PK 118개의 관측 298개를 원본에서 재확인했다. 291개 주소 관계는 v1과 동일하고, 고유 PK 3개의 관측 7개는 미확인 대지구분 코드 2라 정식 PNU 연결을 보류했다. 원문 주소·주부속·개수 근거를 유지하며, 개수만으로 관계를 만들지 않는다. 선택 필드 보존 실험으로 전체 필드·가격 이력·복구 기능의 v2 이관과 운영 정책 확정을 대체하지 않는다.

4,000 PK 확대 시험: [`CHEONGJU_BUILDING_SOURCE_V2_FULL_RESULT.md`](CHEONGJU_BUILDING_SOURCE_V2_FULL_RESULT.md). 원본 관측 11,696개 중 11,673개의 정식 주소가 기존 v1과 동일했고, PK 18개의 관측 23개는 원코드 2라 보류했다. [`LEDGER_CONSUMER_CONTRACT_DRAFT.md`](LEDGER_CONSUMER_CONTRACT_DRAFT.md)는 원천 식별·제품 연결·가격/시점 품질·회귀 적격성을 별도로 전달하는 초안이다. 읽기 전용 가격 입력 미리보기는 구현했으며 실제 소비 키 매칭·운영 공급·회귀 정책 전환은 아직 실행하지 않았다.

토지특성/제품 키 후속 시험: [`CHEONGJU_TRAIT_AND_PRODUCT_LINK_REVIEW.md`](CHEONGJU_TRAIT_AND_PRODUCT_LINK_REVIEW.md). 공통 입력에 캐시 19열과 원본 DBF 27열을 보존했고, 기존 복합 13,293거래와 주거 집합 1,381개 키의 동주소 후보를 읽기 전용으로 검토했다. 집합 대표 PNU 차이 4개와 복합 산 counterpart 2건은 검토 근거로 남겼으며 기존값은 유지했다. 복수 후보를 확정 관계로 승격하지 않았고 테스트 25개가 통과했다. 현재 가격/특성 입력은 로컬 미리보기이며 제품 공급 경로 전환은 아니다.

대표필지/집계 근거 후속: [`CHEONGJU_REPRESENTATIVE_AND_AGGREGATION_REVIEW.md`](CHEONGJU_REPRESENTATIVE_AND_AGGREGATION_REVIEW.md). 대표 차이 4개 중 3개는 통계 기간 거래에 없는 주소 조합이었고 4개 모두 법정동·지번 각각의 MAX로 재현됐다. 대표 주소는 함께 관측된 쌍에서 검토하는 안을 세웠다. 복수 후보 표본 40개는 주부속 혼합 29개·여러 주건축물 11개이며, 소속·수량 범위 미확인 상태에서 새 합산을 차단했다. 테스트 28개가 통과했고 제품 선택기·기존 대표 및 집계값은 유지했다.

## 용량과 처리량

건축·토지 대장의 통합 검토와 다음 청주 연결 실험은 [`CHEONGJU_BUILDING_PARCEL_INTEGRATION_REVIEW.md`](CHEONGJU_BUILDING_PARCEL_INTEGRATION_REVIEW.md)를 참조한다. 기존 `parcel_master.building`을 재사용하고 토지특성·공시지가 이력을 확장하는 제안이다. 필지 연결과 건물 연결을 구분하고 대표 필지만으로 전체 부지를 확정하지 않는다. 해당 검토는 운영 DDL·기존 확정 보강·제품 회귀 정책의 전환을 실행한 것이 아니다.

집합은 단지별 평균가격 기반 지역회귀·신축 아파트 예측에 최신 대표필지 공시지가를 사용하는 경로를 유지한다. 이번 통합에서 집합 과거 개별 거래별 공시지가·토지특성 보강은 제외한다. 공통 대장과 단지 키의 연결·출처·갱신 경로를 정리하되, 거래 단위 토지정보 보강 실험은 토지·복합에 집중한다.

현재 4개 연도 속성 gzip 합계는 약 38.4MB다. 이는 연구용 선별 속성 압축값이며 원본 ZIP·공간도형·DB 인덱스·관계 테이블을 포함한 운영 용량 추정이 아니다. 분기 처리 비용은 실제 신본 한 개의 staging 적재·해시 비교·변경률 실측 후 산정한다. 전국 비용은 청주 결과만으로 확정하지 않는다.


## 과거 범위 확대 — 2019~2022년 토지특성

2019~2022년 청주 4개 구 SHP는 2026-10-04 추가 입수했다. 원천 내부 기준연도·공시지가·코드·인코딩을 검사해 `traits_YYYY.csv.gz`에 별도 정리한다. 이 입수는 거래 연결·회귀 검증 완료와 구분한다.

2019~2022년에는 AL_D155 이용계획 자료가 없으므로 특성의 용도지역 1·2로 후보를 선별하는 별도 연구 규칙을 사용해야 한다. 복수 지역·지구·구역 전체가 확보된 것으로 해석하지 않는다. 2023~2026년에서도 같은 규칙을 실행해 기존 이용계획 필터 방식과 비교한 뒤 과거 연도 성능을 해석한다.

과거 DBF는 명칭이 비어 있고 코드만 존재할 수 있다. 코드의 원값을 보존하고 사전의 연도·근거를 검증한다. 다른 연도의 명칭을 그대로 덮어쓰거나 빈 명칭을 실제 특성 부재로 단정하지 않는다.

회귀 확대는 연도별 실제 확보 범위·연결 품질 확인 뒤 진행한다. 특히 2019년 계약일 이전 판본이 없으면 사전 관측 정책으로 연결 불가하며, 2019년 후반 판본을 연초 계약 당시 자료로 표시하지 않는다. 연도 대표 판본 정책의 사후 참고 분석은 별도 표시한다.
