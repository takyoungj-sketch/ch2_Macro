## 1. 재검토 결론과 문서의 역할

유형별로 화면을 따로 고치기 전에 **분석 결과의 표시 계약·상태 처리·비교 가능 조건**을 함께 확정한다. 이후 같은 기준으로 각 엔진과 화면을 단계적으로 연결한다. 일괄 작업은 한 번의 거대한 변경이나 한 커밋을 뜻하지 않는다.

이번 재검토의 결론은 다음과 같다.

1. 선행 정합성 수정은 이미 로컬에 일부 적용돼 있다. 미구현 제안 전체를 처음부터 다시 구현하지 않는다.
2. 남은 최우선 항목은 복합 계수 해설의 변환 오류, 주거 단지의 실제 변수/FE 상태와 이전 추정값, 지역회귀의 지역 더미·블록 정합성, 검증 대상이 다른 결과의 비교 제한이다.
3. 공통 UI는 같은 단위·표본·검증을 의미할 때만 같은 이름을 쓴다. 단가와 금액, 거래와 단지, 무작위 CV와 시간 검증을 형식상 통일하지 않는다.
4. ‘비교할 수 없음’ 표시를 먼저 완성하고, 같은 표본에서 다시 평가하는 기능을 후속으로 구현한다. 없는 검증을 UI가 대신 추론하지 않는다.
5. 토지 지분거래의 공시지가 보강 불가는 분석 대상의 구조적 제약이다. 결측 보충·대장 재보강 과제로 되돌리지 않는다.
6. 기존 공통 추천·도움말을 확장하고, 도메인 엔진을 하나로 합치는 대규모 리팩터는 범위에서 제외한다.

이 문서는 **공통 결정·실행 순서·완료 판정**의 기준이다. 아래 개별 문서는 원래 관찰·사례·유형별 요구의 근거로 유지한다. 구현 상태가 섞인 항목은 이 문서 §3을 먼저 확인한다.

- [복합 개선안](BUILT_REGRESSION_UX_IMPROVEMENT_PLAN.md): B-01~03, M-01~05, U-01~04.
- [주거 단지 개선안](COLLECTIVE_RESIDENTIAL_REGRESSION_UX_IMPROVEMENT_PLAN.md): R-01~10.
- [주거 지역회귀 개선안](COLLECTIVE_REGIONAL_REGRESSION_UX_IMPROVEMENT_PLAN.md): RG-01~08.
- [비주거 도로명 개선안](COLLECTIVE_COMMERCIAL_REGRESSION_UX_IMPROVEMENT_PLAN.md): C-01~11.
- [토지 개선안](LAND_REGRESSION_UX_IMPROVEMENT_PLAN.md): L-01~09.

§1~8은 최초 계획이다. 실제 반영 범위와 검증은 §9~13의 차수별 기록을 기준으로 읽으며, 최신 잔여 목록은 §13.3이다. 선행 테스트 건수는 당시 기록이며 중복 합산하지 않는다.

## 2. 유지할 차이와 공통화 범위

### 2.1 다섯 분석 화면의 차이

- **토지:** 한 행은 개별 거래, 종속변수는 단가(만원/㎡). 용도×지목 셀·면적 변환·연도 추세·법정동 FE·지분 정책을 보존한다. 현재 추천은 선택 변수/척도 안의 AIC 및 학습 MAPE 비교다.
- **복합:** 한 행은 개별 건물 거래, 종속변수는 거래금액. 기본회귀·기존 Macro 탐색·상위지역 재적합은 별도 모형이다. 현재 지역 기준·Twin1 같은 변수 재적합·Twin2 변수 재탐색을 구분한다.
- **주거 단지:** 한 행은 개별 거래, 종속변수는 거래금액. 단지·동·층·반기 및 단지 특성의 식별 제약을 보존한다. 거래 무작위 CV는 새로운 단지 일반화 검증이 아니다.
- **주거 지역회귀:** 한 행은 단지의 기간 중앙단가. 표본 단위는 단지이며 학습/검증 분할·거래수 가중·유형 더미·지역 더미를 보존한다. 개별 거래 예측범위라는 이름을 그대로 사용하지 않는다.
- **비주거 도로명:** 한 행은 도로 범위의 개별 거래, 종속변수는 거래금액. 상가/공장 층 구간·도로 변수·추가 도로 FE·반기 조건을 보존한다.

### 2.2 함께 구현할 형식

분석 범위 요약, 표본 흐름, 학습/검증 지표 표시, 계수 열·단위, 기준 범주, 경고 등급, 결과 상태, 추정 입력/범위, 후보 선택 상태, 도움말 문체를 공통화한다.

[5앱 형식 패리티](../.cursor/rules/five-app-format-parity.mdc)는 별도의 적용 범위다. 모달 크롬·탭·필터 같은 형식 변경은 **토지·복합·집합·임대·지역프로필의 같은 위젯**에서 함께 검증한다. 임대·지역프로필에 이 계획의 회귀 엔진을 새로 만들지는 않는다. 랩은 제외한다.

[집합 주거/비주거 패리티](../.cursor/rules/collective-residential-commercial-parity.mdc)에 따라 공통 회귀 결과·추정·추천 변경은 두 화면을 한 변경 단위로 관리한다. 단지 전용 특성·지역회귀를 비주거에 형식적으로 복제하지 않는다.

## 3. 재검토한 현재 상태

### 3.1 선행 적용 — 유지하고 회귀 검증할 항목

- **RG-01:** `(asset_type, building_key)` 정렬로 지역회귀·추천·예측의 동일 조건 재현성을 확보한 수정이 있다. 공통 평가 대상 고정까지 완료된 것은 아니다.
- **R-01 / C-02 일부:** 집합 공유 엔진·결과 UI에 학습 MAPE와 CV-MAPE 분리, 유효 행 기준 CV, 부분 fold 실패 시 CV 미제공이 적용됐다. 검증 표본 해시·방법·유효 fold·실패 사유의 전체 계약은 남았다.
- **C-01·03·04:** 비주거 날짜 필터, 거래 ID 정렬, 시나리오 반기 선택·적용 시점, 필수 입력 검증이 적용됐다.
- **C-05:** 비주거의 요청/입력 변경 시 이전 추정 결과 차단이 적용됐다. 주거 단지의 같은 문제까지 해결됐다고 보지 않는다.
- **C-06 / R-07 일부:** 반기·상가 층·공장 층·도로 FE의 범주 해석 수정이 공유 코드에 반영됐다. 기준 범주를 계수마다 표시하는 UI와 전체 계수 포맷 통일은 남았다.
- **L-01~05:** 로그 탄력성·원면적 효과·상수 설명, 공시지가 모형/해당 탐색의 지분 제외, 추천의 별도 표본 안내, 원단가 평균 역변환, 이전 결과 차단, 거래 ID 정렬이 적용됐다.

위 항목은 **현재 로컬 워킹트리 반영**을 뜻한다. 커밋·배포 완료나 모든 지역/유형 검증 완료를 뜻하지 않는다. 선행 변경을 삭제하고 새 구현으로 교체하기보다 보호 테스트와 함께 점진적으로 공통화한다.

### 3.2 계획 수립 당시 남은 항목 (구현 진행은 §9 참조)

- 복합 `backend/app/recommendation/coef_narrative.py`에는 로그-로그 면적을 `β×100%`로 설명하는 경로가 남아 있다. 표·해설의 척도 차이와 절편 기여도도 우선 대상이다.
- 주거 `BuildingRegressionPanel.tsx`는 체크·척도 중심의 변경 감지와 `predictM.data` 직접 표시 경로를 사용한다. 전체 조건·입력·늦은 응답의 공통 상태 처리로 이관해야 한다.
- 지역회귀 `_block_contrib`의 기본 블록 설계에는 현재 지역 더미 구성이 전달되지 않는다. RG-06은 미완료다.
- 지역회귀 응답은 로그 R²와 원단가에서 다시 계산한 조정 지표의 의미를 충분히 구분하지 않는다. RG-02는 남았다.
- 토지 추천은 학습 MAPE이며 독립 검증이 아니다. ‘학습’ 표기를 붙였다는 이유로 검증 기능을 완료 처리하지 않는다.
- 서로 다른 후보·기본/확장·초점/상위 모형의 표본·검증 대상 동일 여부를 n만으로 판정할 수 없다. 공통 비교 메타데이터가 필요하다.

### 3.3 문서 초안 간 조정

- 추정 영역의 여러 이름은 §4의 한 규칙으로 정리한다.
- 같은 p 임계치를 모든 엔진에 새로 강제하지 않는다. 회귀식 표시 기준·유의 계수 집계·추천 해설의 실제 임계치를 각각 표시한다.
- ‘95% 개별 거래 예측범위’는 거래 단위 모형에서만 사용한다. 지역회귀는 단지 기간 중앙단가 관측값의 범위로 표시한다.
- 주거/비주거를 같은 UI로 만든다는 이유로 설명형 기준을 AIC로 교체하거나 모든 검증을 시간 CV로 바꾸지 않는다. 현재와 목표를 구분한다.
- 소표본·식별·외삽·이전 결과는 서로 다른 상태다. 공통 노란 경고 한 종류로 합치지 않는다.

## 4. 구현 전에 고정할 공통 표시 계약

### 4.1 화면 이름과 정보 순서

상위 기능명은 **회귀 분석**, **Macro 모형 탐색**, **상위지역 재적합**을 사용한다. 추정 영역은 **조건별 통계적 추정**, 버튼은 **추정값 계산**으로 통일한다. 토지는 단가, 복합/집합 거래 모형은 금액, 지역회귀는 단지 중앙단가를 부제에 명시한다.

읽는 순서:

1. 분석 대상·기간·필터·종속변수·단위.
2. 현재 결과의 상태와 해석 제한.
3. 표본 흐름·실제 포함 변수.
4. 학습/검증 지표.
5. 회귀식·계수·진단.
6. 조건별 추정·범위.
7. 후보·확장·상위지역 결과와 비교 가능 여부.

### 4.2 API 메타데이터와 화면 어댑터

다음은 **추가할 논리적 계약**이다. 모든 기존 API를 한 번에 같은 응답으로 바꾸거나 다음 필드명을 구현 완료로 취급하지 않는다. 기존 응답을 보존하고 메타데이터를 추가한 뒤 유형별 어댑터로 공통 화면 모델을 만든다.

- **분석 조건:** 요청 범위·실제 포함 지역·기간·필터·데이터 기준 월·속성 기준 시점·종속변수·단위·변환·가중 방식.
- **모형 식별:** 요청 식별자·실행 식별자·실제 변수/계수·기준 범주·모형 서명. 정규화된 조건과 데이터/표본을 구분한다.
- **표본:** 조회·구조적 제외·결측/품질 제외·최종 분석·학습·검증 수, 각 단위, 제외 순서·중복 여부, 대상별 건수.
- **변수 상태:** 요청됨·포함됨·상수여서 생략·자료 없음·결측 후 생략·다른 효과와 식별 제한. UI 체크에서 실제 모형을 추측하지 않는다.
- **지표:** 값·계산 척도·표본/가중 기준·학습/선정용 검증/독립 확인 역할·방법·평가 수·fold/기간·미제공 사유.
- **비교 근거:** selection/fit/evaluation 표본 서명, split 서명·버전, 대상 단위, 평가 목적. 같은 n과 같은 시드만으로 동일 표본이라 판정하지 않는다.
- **추정:** 적용 모형·입력·기준 지역/범주/반기·원척도 평균 등 추정 대상·역변환 방식·구간 대상·수준·근사 여부·외삽.
- **상태 근거:** 표본 제한·식별 제한·외삽·비교 불가·실패를 구조화한다. 문장 파싱으로 상태를 판정하지 않는다.

실제 거래 ID 목록 전체를 브라우저/AI에 노출할 필요는 없다. 서버에서 비교 가능한 해시·범위·건수와 실패 이유를 제공한다. `mape` 같은 기존 혼합 필드는 호환용으로 유지하되 새 화면은 명시적 학습/검증 필드를 우선한다.

### 4.3 결과 상태와 계산 조건

현재 설정, 마지막 성공한 적합, 추정에 사용한 입력을 구분한다. 모형의 건강 상태와 요청의 진행 상태는 별도로 관리한다.

- 조건 변경 시 이전 적합 결과에는 상태 표시를 붙이고 추정은 재실행 전까지 막는다.
- 입력만 바뀌면 호환되는 입력값은 유지하고 이전 추정 출력·AI 사실을 무효화한다.
- 늦은 응답은 실행/입력 식별자로 확인한다. 오래된 요청이 최신 결과를 덮지 못하게 한다.
- 객체 참조나 JSON 속성 순서만으로 같은 모형을 다른 모형으로 판정하지 않는다. 내용 기반 정규화와 안정된 서명을 사용한다.
- 예측 API가 재적합하는 구조에서는 당시 데이터·표본·변수 서명을 검증한다. 달라졌으면 새 결과로 조용히 계산하지 말고 재적합 필요 상태를 반환한다. 이번 계획 때문에 모형 저장 서버를 새로 만들지는 않는다.
- 서버 취소가 없는 기능은 ‘계산 취소’라고 약속하지 않는다. 수신 중단과 서버 계산 중단을 구분한다.

### 4.4 계수·숫자·문체

- 계수 표: **변수 / β / 효과 해석 / SE / t / p**. 그룹별 실제 기준 범주·단위를 표시한다.
- 효과 해석은 y/x 변환·변화량·입력 단위에서 생성한다. 변수명 접두어만으로 단위를 추론하지 않는다.
- 로그-로그 1% 변화는 `(1.01^β−1)×100`, 선형 y/로그 x는 `β×ln(1.01)`, 로그 y/원 x 1단위는 `(exp(β)−1)×100`을 기준으로 한다.
- 작은 계수/SE는 유효숫자를 보존하고, p<0.001은 `<0.001`로 표시한다. 반올림으로 0만원·0.00000을 만들지 않는다.
- 실제 임계치를 붙여 ‘유의한 계수’라고 부른다. 변수 블록 수와 범주 계수 수를 혼용하지 않는다. 절편은 효과·중요도 순위에서 제외한다.
- 설명은 `~입니다/합니다`, 안내는 `~을 확인하세요`, 버튼은 동작명으로 쓴다. 인과·우수성·안정성을 근거 없이 단정하지 않는다.
- 공통 범위명은 **95% 평균 추정범위**와 **95% 개별 거래 예측범위**다. 지역회귀의 후자는 **95% 단지 중앙단가 예측범위**로 구분한다. 실제 산식이 해당 해석을 뒷받침하는지 먼저 검증한다.

### 4.5 비교 가능 판정

- 검증 오차의 우열/유사 판정은 같은 대상 관측·검증 분할·기간·계산 척도·가중·오차 정의에서만 제공한다. 평가 목적도 같아야 한다.
- AIC/BIC는 같은 종속변수·관측 표본·우도 척도에서 비교한다. 선형/로그를 직접 비교하는 우도 보정이 검증되지 않았다면 서로 다른 척도 간 AIC 차이를 제공하지 않는다.
- 정보가 없으면 ‘미확인’, 명확히 다르면 ‘직접 비교 불가’로 표시한다. 숫자만 같다는 이유로 ‘성능 유사’라고 하지 않는다.
- 부호 일치·높은 R²·낮은 학습 MAPE는 모형 안정성이나 확장의 검증 성능 개선을 대신하지 않는다.

### WP-4. 같은 평가 대상의 후보·지역 확장 비교

**선행:** WP-1/2/3. **해결:** M-02/04/05, U-03, R-04/10, RG-04/05, C-10, L-08.

1. 우선 비교 근거가 다른 기존 결과의 순위 차이·성능 유사·개선 판정을 제한한다. 기존 후보 수치와 실패 사유는 보존한다.
2. 동일 scope의 변수 후보는 후보 변수 합집합의 공통 유효 표본에서 평가한다. 공시지가의 구조적 제외 집단은 일반 결측 집단과 분리한다.
3. 지역/단지/도로 추가 비교는 기준 대상의 검증 관측을 먼저 고정한다. 양쪽 학습에서 그 관측을 제외하고 추가 집단은 학습에만 더한다. 혼합 지역 전체의 참고 오차는 별도로 표시한다.
4. 분할 이후 학습해야 할 결측 처리·범주 선택·변환 보정은 검증 행을 학습하지 않도록 한다. 특히 로그 역변환 보정은 학습 잔차에서 계산한다.
5. 후보 선정용 검증과 마지막 연도/독립 확인을 구분한다. 마지막 연도 결과를 보고 다시 후보를 고르면 독립 확인이라고 부르지 않는다.

토지의 첫 비교 기능은 같은 공시지가 연결 비지분 표본에서 공시지가 유무를 평가하는 방식으로 한정한다. 비지분 전체 모형도 보여줄 수 있지만 25건과 122건 지표를 우열로 결론내리지 않는다. 작은 표본에서 억지로 fold를 늘리지 않고 기존 제공 기준과 평가 불가 사유를 따른다.

단지 단위 Holdout·무작위 거래 CV·복합의 시간 검증은 각각 유지한다. 모든 엔진을 한 종류 검증으로 바꾸는 장기 목표는 이번 UI 통일과 분리한다.

**검증:** 같은 n/다른 ID, 같은 ID/다른 split, 기간·척도·가중 차이, 기준 검증 관측의 학습 유입, 일부 fold 실패, 표본 부족, 데이터 기준 변경.

**완료:** 우열 판정마다 근거를 확인할 수 있고, 같은 기준 대상에서만 ‘추가 후 개선’을 표시한다. 구현되지 않은 비교는 명시적으로 보류한다.

4. **WP-5/6 잔여:** 모든 회귀식/계수 상세의 유의수준·기준 범주·숫자 표기 교차 감사, 변수/표본 세부 목록, 후보 검색과 범위 표시, Macro/Twin/상위지역 흐름, 고급 특성 출처/확인값 연동, 진단·영향 거래 연결, 공시지가 기준연도·동별 연결 수.

## 10. 예약 재개 후 2차 구현 기록 — 2026-10-26

**전체 완료가 아니다.** §9.3은 1차 종료 시점의 잔여 목록이다. 이번에 해결한 부분과 실제 남은 부분은 아래로 갱신한다. 기존 로컬 변경을 보존했고 push·운영 배포는 하지 않았다.

### 10.1 비교·재적합 계약

- **집합 주거/비주거 후보:** 실행 가능한 후보의 실제 설계행렬을 먼저 만들고, 양의 금액과 유한한 설명변수를 모두 갖춘 공통 거래만 남겨 비교한다. 후보마다 결측 제외 후 다른 표본을 쓰던 문제를 수정했다. 공통 표본·평가 관측 서명, 적합/평가 수, 거래/단지 단위와 선정 목적을 함께 제공한다. 전체 CV를 마치지 못한 결과를 성공으로 표시하지 않는다.
- **지역회귀 후보:** 후보 공통 유효 단지와 학습/평가 분할을 고정했다. 범주 결측 정책도 실제 실행과 일치시킨다.
- **지역 확장 비교:** 원래 지역의 같은 평가 단지를 기본/확장 적합 양쪽 학습에서 제외하고, 인접지역을 학습에 추가했을 때 같은 평가 대상의 오차를 비교한다. 실제 주소로 대상 지역을 확인한다. 표본 부족·실패는 비교 불가로 제공한다. 이 별도 선정용 실험을 최종 확대 모형의 검증이나 독립 확인으로 표현하지 않는다.
- **5개 회귀의 추정 API:** 화면의 `expected_model_signature`와 서버 재적합의 실제 자료·계수·척도·대상을 대조한다. 다르면 409와 재실행 안내를 반환한다. 기존 클라이언트를 위해 필드는 선택형이지만 수정한 화면은 서명을 전달한다. 지역회귀의 두 번째 자료 조회/재적합도 다시 확인한다.
- **실제 관측 식별:** 주거 거래의 run/predict/코호트 조회에 실제 거래 ID를 사용하고 정렬을 고정한다. 값이 같아도 거래 정체가 바뀌면 다른 모형으로 구분한다. 이름/화면 표시 변경이나 추정 시나리오 입력만으로 적합 모형 서명을 바꾸지 않는다.

### 10.2 결과·입력·설명 표시

- 공통 분석 기준에 실제 기준 범주, 적합 거래 연도·연결 공시지가 연도(자료가 있는 경우), 표본 단계, 실제 포함 변수와 생략 이유를 연결했다. 주거 고급 특성은 상수/자료 없음/결측 제외 후 차이 없음/단일 단지 식별 불가를 실제 계산 단계에서 기록한다. 경고 문장 검색으로 상태를 추측하지 않는다.
- 지역회귀 계수 상세도 `변수 / β / 효과 해석 / SE / t / p`로 맞추고 대상과 단위를 **단지 중앙단가·만원/㎡**로 바로잡았다. 지역/법정동 더미는 범주 효과로 설명한다. 원 로그 상수를 가상의 0조건 가격으로 바꾸지 않는다. 작은 효과를 0으로 지우지 않으며 계수 크기로 중요도를 정렬하지 않는다.
- 원래 유의수준은 유지했다. 복합 p<0.05, 그 외 해당 화면 p<0.1을 화면에 명시하고 ‘유의 계수’로 표시한다. 눈에 덜 띄게 하려고 비유의 회귀식 항 전체를 불투명도 40%로 낮추던 처리를 제거했다.
- 토지·주거·비주거에서 재적합 후 호환 수치 입력은 보존하고 사라진 범주는 새 모형의 기준으로 바꾼다. 이전 추정은 무효화한다. 주거/비주거의 모형에 없는 범주·FE 제외 대상을 기준 범주로 조용히 계산하지 않고 거절한다. 주거 FE 제외 단지 선택도 막았다. 지역회귀의 필수 실제 수치 누락/잘못된 범위도 계산 전에 검증한다.
- 주거·비주거 추가 대상 영역의 문체·색을 맞추고 ‘함께 분석할 단지/도로’, ‘원래 단지/도로’, 목록 거래수와 실제 적합 수의 차이를 표시했다. 비주거의 어두운 테마에서 연한 배경과 흐린 글자가 겹치던 추가 도로 영역을 수정했다.
- 집합 AI 화면 context에 현재/이전 조건 결과 상태를 명시했다. `analysis_explain.py`, AI 제품 지식, 공통 추정/회귀 용어 설명에 실제 포함 변수·FE·단위·변환·선정용 지표의 뜻을 동기화했다. 전체 AI 지식/도움말 교차 감사는 아직 남아 있다.

### 10.3 모달·접근성

- 실제 1280×720 화면에서 모달 제목/닫기가 앱 헤더 뒤에 가려지는 문제를 재현했다. 공통 화면 경계 계산을 만들어 토지·복합·집합·임대의 로컬 셸과 지역프로필을 포함하는 공통 도움말/AI 창에 적용했다. 헤더 아래로 위치·크기를 제한하고 작은 창에서는 요청 최소 크기보다 실제 가용 영역을 우선한다.
- 제목 아래 긴 탭/추가 대상 영역에 별도 스크롤을 두어 제목·닫기가 사라지지 않게 했다. 확대 후 복원·Esc 복원에 현재 화면 경계를 다시 적용한다. 상태 갱신 함수 안에서 복원 참조를 지우던 부작용도 제거해 React 개발 모드에서 두 번 평가되어 복원 크기를 잃는 문제를 수정했다.

## 11. 유형별 상세 UI 후속 구현 — 2026-10-27

§10.5는 2차 종료 시점 기록이다. 이번 반영으로 해결한 부분을 아래에 기록한다. 최종 완료 체크는 아직 올리지 않으며 기존 다른 작업 파일을 유지했다. 시작 시 수정 예정 17개 파일의 내용과 SHA256을 `logs/regression-third-baseline/manifest.json`에 보관했다. push·운영 배포는 하지 않았다.

### 11.1 Macro·상위지역·잔차

- **기존 Macro 유지:** 예측형/설명형/쌍둥이 확장 탭을 그대로 사용한다. 지역 내 탐색 → 쌍둥이 확장 재적합 → 확장 재탐색의 미실행/계산 중/실패/완료/이전 조건 상태를 구분한다. 재계산·실패 중 이전 성공 결과가 남아 있음을 명시한다. 계산 중 중복 실행과 후보 추정을 막는다.
- 실행 범위·기준월·롤링 기간·조회/적합 수와 실행 당시 선택 지역을 표시한다. 현재 쌍둥이 선택과 결과의 선택이 다르면 확장 결과를 이전 조건으로 표시하고 추정을 숨긴다. 기본 회귀 비교 척도는 마지막 통계분석 요청을 사용한다. 현재 탐색 설정과 다르면 그 차이를 알린다. 기존 Macro는 이 창에서 후보를 비교하고 기본 회귀 설정은 바꾸지 않는다는 문체를 유지한다. 집합의 후보 설정 반영 동작과 혼동하지 않는다.
- **Twin 재실행 보호:** Twin2 계산 후 Twin1을 다시 실행할 때 연구 실행 플래그·자동 추정 대상을 초기화한다. 실패 후 Twin2 재시도도 새 실행으로 처리한다. 한 번 실행한 플래그가 남아 다음 재탐색을 막는 경로를 제거했다.
- **상위지역:** 버튼을 ‘결과 보기/접기’로 바꾸고 이미 계산된 결과를 펼친다는 사실을 명시했다. 실제 포함 변수·기준 범주·기간·계수 식별 상태를 공통 분석 기준에서 확인한다. 펼치기만 했을 때 추정을 자동 실행하지 않는다.
- **잔차:** ‘전체 대비’로 남아 있던 본문·도움말·AI 지식을 ‘나머지 대비’ 산식으로 수정했다. 영향 거래의 위치를 누르면 적합 당시 실제 거래 ID·연도·실제/추정금액·오차·면적·Cook 거리·레버리지를 확인한다. 식별자가 없는 입력에 행 번호를 대신 제공하지 않는다. 기존 전체 거래목록은 별도 행동으로 남긴다. 단순 영향도가 자동 제외 근거는 아니라는 설명을 붙였다.
- 복합 요약의 유의 계수는 기존 p<0.05, 회귀식의 기본 표시 기준은 기존 p<0.1을 각각 명시한다. 통계 기준 자체를 몰래 바꾸지 않았다.

### 11.2 집합 주거·비주거 및 지역회귀

- **쌍 작업:** 추가 단지/도로 선택을 공통 `TargetPicker`로 맞췄다. 조회된 전체 후보를 이름·주소로 검색한다. 첫 80개 표시 제한과 전체 검색 결과 수를 명시해 나머지 후보를 찾을 수 있게 했다. 주거는 지번/도로명 주소, 비주거는 동·면적 구간을 이름 옆에 보여 준다.
- **대상별 표본:** 주거/비주거 공통 분석 기준에서 대상별 조회 수·실제 적합 수·고정효과 기준/계수 포함/미포함/적합 거래 없음을 확인한다. FE 미포함과 거래 제외를 혼동하지 않게 설명한다. 이미 조회한 DataFrame에서 집계하며 추가 DB 조회를 만들지 않는다.
- **주거 확인값 불러오기:** 현재 선택 단지의 적합 거래 전체에 값이 있고 모두 같을 때만 세대수·세대당 주차·공시지가를 명시적 버튼으로 입력한다. 일부 결측이나 연도별 차이가 있으면 값을 만들지 않는다. 미포함 변수는 채우지 않고 면적·층·연식은 사용자 입력을 유지한다. 비주거에는 단지 단위의 동일한 확인값이 없으므로 이 도메인 행동을 복제하지 않으며, 대상 검색/표본/추정 UI는 같은 패턴을 유지한다.
- **지역회귀:** 학습 단지별 중앙단가를 만든 거래수와 실제/적합 단가를 별도 표로 제공한다. 단지 주소를 제공해 확장 지역을 구분한다. 회귀 관측 수와 거래수를 구분하고 별도 평가 단지를 학습 표에 섞지 않는다. 표시 건수/전체 학습 단지 수와 표시 한도를 명시한다.

### 11.3 토지·평가·설명

- **토지 동별 연결:** 법정동별 조회/적합 수, 보강 불가 지분 수, 비지분의 공시지가 연결/미연결 수를 나눠 표시한다. 새 보강 요청이나 임의 보충을 하지 않는다. 부분회귀도는 다른 변수 영향을 제거한 두 잔차의 관계이며 모형 전체 잔차 진단과 다르다고 화면과 도움말에 명시했다.
- **검증 연도:** Macro 후보 응답에 평가 예정 연도·성공 연도·실패 사유·가용/일부/미제공 상태를 추가했다. 예를 들어 ‘3/4개 · 2022년 미제공: 학습 표본 또는 평가 거래 부족’으로 표시한다. 한 연도 안에서 일부 예측이 비유한 값이면 그 연도를 통째로 제외하고 이유를 남긴다. 정상 거래 일부만 골라 성공한 검증처럼 표시하지 않는다.
- **AIC 감사:** 기존 설명형은 같은 log(y)인 log/log-log 계열만 비교하고 토지 후보는 요청의 같은 종속변수 척도/고정 표본에서 비교한다. 집합 후보는 원척도 오차로 정렬한다. 복합 척도 선택에서 원척도 오차가 모두 없는 극단적 경우 원값/로그 AIC로 우열을 대신 정하던 fallback을 제거했다.
- 잔차 도움말/AI의 ‘평균은 항상 중위보다 음수’라는 일반화와 오래된 운영 수치 인용을 제거했다. 오차 부호의 의미·분모가 작은 거래에 대한 민감도를 정확히 설명한다. Twin은 상위지역 붙임이 아니라 유사 지역 확장으로 수정했다.

## 12. 검증 실패 계약·비동기 상태·공통 창 후속 수정 — 2026-10-27

§11.5를 이어서 작업했다. 기존 변경을 보존하고 수정 전 파일은 `logs/regression-fourth-baseline/manifest.json`에 기록했다. 이번 기록은 로컬 반영 범위이며, push·운영 배포는 하지 않았다. §7.3 전체 완료 체크는 아직 올리지 않는다.

### 12.1 검증의 실제 실행 기록

- 공통 `validation`에 검증 방식·관측 단위·예정/시도/완료 분할·유효/정상 예측/검증 전 제외 수·사유 코드·분할별 실패를 제공한다. 정상, 일부 제공, 미제공, 미실행을 구분한다.
- **집합 주거/비주거:** 거래 5겹 검증의 최소 표본 부족, 분할의 학습 거래 부족, 적합/예측 실패, 비유한 예측, 최종 지표 계산 실패를 나눈다. 한 분할의 일부 예측만 실패해도 그 분할 전체를 실패로 기록한다. 전체 5개 분할이 완료되지 않으면 CV-MAPE를 제공하지 않되 완료 횟수·정상 예측 수와 구체 사유를 보존한다. 검증 대상으로 선정되지 않은 후보는 미실행으로 표시한다.
- **지역회귀:** 단지 분리 검증에서 예측 실패가 나도 학습 적합 결과는 유지한다. 검증 표본 부족과 예측/지표 실패를 구분하고, 검증 없는 후보는 학습 지표 역할로 표시한다. ‘Holdout’을 ‘분리 검증’으로 맞췄으며, 적합도 바로 아래 실제 검증 상태를 표시한다.
- **복합 기본회귀:** 기존 Macro와 같은 연도별 검증에 실패 연도와 구체 원인을 연결했다. 기존 정책상 일부 연도만 완료한 오차는 유지하되 ‘일부 제공’과 완료/예정 연도·정상 예측 수를 명시한다. 거래 5겹의 전체 완료 정책과 혼동하지 않는다. 검증 미요청과 계약연도 없음도 분리했다.
- 공통 분석 기준·집합 결과 지표 아래·선택 후보에 같은 표시 컴포넌트를 사용한다. 상세를 펼치면 분할/연도별 실패를 확인한다. 같은 실패 이유를 분석 기준 안에서 두 번 반복하지 않는다. 추천의 내부 등급 ‘깊이: 표준+’는 ‘변수·척도 탐색’ 등 실제 탐색 행동으로 바꿨다.

### 12.2 이전 응답·재시도 보호

- 토지 조건별 추정에 요청 순서 가드를 연결했다. 입력·모형·비활성 상태 변경이나 닫기 이후 도착한 이전 응답은 결과·오류·로딩 상태를 바꾸지 않는다. 이전 요청이 끝났다고 새 요청의 로딩을 끄지 않으며, 실패 후 새 요청의 성공은 정상 표시한다.
- 비동기 성공/실패·진행 상태·무효화·재시도 회귀 테스트를 통과했다. 이어 별도 루프백 검증 서버에서 실제 API 응답을 12초 지연했다. 100㎡ 이전 성공 뒤 101㎡ 새 결과(338.86만원/㎡), 102㎡ 이전 오류 뒤 103㎡ 새 결과(338.41만원/㎡)가 유지됐다. 현재 요청의 503 오류가 표시된 뒤 같은 조건 재시도 성공과 오류 해제도 확인했다. 원본 자료나 실제 API의 계산값을 변조하지 않았다. 요청 결과의 무효화와 실제 서버 계산 중단은 다른 기능이며 서버 계산 취소 기능을 추가한 것은 아니다.

### 12.3 실제 발견한 중첩 창 오류

- 집합 단지 도움말에서 Esc 한 번에 도움말과 부모 단지 창이 함께 닫히는 오류를 재현하고 수정했다. 포털의 다른 대화상자에서 시작한 키 이벤트를 부모가 소비하지 않도록 토지·복합·집합·임대 셸에 동일하게 적용했다.
- 공통 분석 도움말에 최초 포커스·Tab 순환·닫기 후 복귀를 연결했다. 용어 창·AI 창은 모델리스 특성을 유지하며 최초 포커스/복귀를 제공한다. AI 입력 자동 포커스 때문에 복귀 대상이 사라지는 문제는 실제 열기 버튼을 보존해 해결했다.
- 실제 집합 화면에서 도움말 열기(대화상자 2개) → Tab/Shift+Tab 순환 → Esc(부모 1개 유지) → 도움말 버튼 포커스 복귀를 확인했다. 토지·복합·임대·지역프로필에서도 AI 닫기 후 AI 버튼으로 복귀하는 것을 확인했다.

### 13.3 원문 기준 실제 남은 작업 — 최신 잔여 목록

**‘QA만 남았다’는 뜻이 아니다.** §12.5는 최근 구현 묶음의 QA 목록이었고, 아래 원문 제안의 미반영 세부 요구까지 포함하지 못했다. 구현 미완료와 검증 미완료를 나눠 추적한다. 다음은 코드·화면에서 확인한 잔여이며 원문 전체의 최종 항목별 판정표는 아직 작성 중이다.

1. **토지 동일 대상 비교 실험 — L-08 / WP-4 (구현 잔여).** 공시지가 연결 비지분 거래를 고정해 공시지가 사용/미사용을 비교하는 기능, 같은 원래 지역 검증 거래에서 인접지역 추가 전후를 평가하는 실험은 아직 없다. 현재는 다른 표본 결과를 직접 비교하지 않도록 안내하고 후보를 같은 요청 범위에서 비교하는 단계다. CV를 새로 제공한 것으로 해석하지 않는다.
2. **토지·집합 전체 잔차 진단 — L-09·C-09 및 주거 공통화 (구현 잔여).** 토지의 공시지가 부분회귀도와 복합의 영향 거래 상세는 반영했다. 토지·주거/비주거에 같은 전체 모형 잔차 진단 진입점·표본 요약·세부 화면을 제공한 것은 아니다. 부분회귀도가 전체 진단을 대신하지 않는다.
3. **경고 정보 구조 — B-01·R-06·C-08·L-09 (일부 구현 잔여).** 소표본/식별·검증 실패의 구조화는 반영했다. 화면의 반복되는 warnings 배열·용도지역 주의·면책 문구를 핵심 상태/조건별 주의/상세로 통합하고 중복을 줄이는 작업은 남아 있다. 중복 제거 시 실제 경고를 숨기지 않아야 한다.
4. **사용 흐름과 표시 세부 — M-01/04/05·R-10·각 모달 요구 (일부 구현 잔여).** 후보별 현재 설정과의 변수 차이·적용 전 요약, 추가 단지/도로 영역 접기와 요약, 결과 구역 바로가기·계수 크게 보기, Macro 탭 유지/후보 선택 시 상세 이동과 번호 체계 정리가 남아 있다. 토지 회귀 탭에서 모달 제목이 여전히 ‘롤링 구간별 평균 변동’인 점(L-06)도 미반영이다. 통계 계약·후보 적용 후 재실행·대상 검색은 이미 반영한 부분이다.
5. **최종 화면·상태 QA — WP-8 (검증 잔여).** 지금 확인한 오류/재시도 외에 재적합 중 입력 복원·창 닫기/재열기, 주거 단지 특성 각각/전체·미확보, 토지·복합·지역회귀의 개별 상세/차트/추정 입력에서 좁은 창·배율·테마·키보드·대비 조합을 끝까지 대조한다. 공통 AI 창/일부 계수 표 통과를 모든 화면의 접근성 완료로 바꾸지 않는다.
6. **설명·AI 및 원문 대응 완료 판정 — WP-7/8 (감사 잔여).** 활성 화면·도움말·AI context의 대상/척도/표본/현재·이전·미실행 상태를 전수 대조하고 B/M/U/R/RG/C/L 항목별 완료·부분·보류·검증 근거를 확정한다. 원문에 미체크인 항목을 전부 미구현으로 보거나, 후속 구현 기록만으로 전부 완료로 보지 않는다.

우선순위는 **동일 대상 비교 설계 확정 → 잔차 진단 범위/구현 → 경고·조작 UI 세부 → 최종 QA·설명 대응 판정**이다. 기존 정합성 수정과 상태 보호는 유지한다. 지분거래 공시지가 보강·임의 보충과 기존 Macro를 추천2로 대체하는 작업은 계속 범위 밖이다. 운영 배포는 구현 잔여와 별도이며 요청 시에만 수행한다.


## 14. 최종 UX 작업과 통합 반영 — 2026-10-29

사용자가 작업 방향을 화면·문체 개선으로 재설정했다. §13.3 등 이전 차수에 적힌 새로운 동일 표본 실험, 추가 잔차 진단, 장기 통계 감사는 이번 완료 조건에서 제외한다. 이미 반영한 계산·정합성 보호는 유지한다.

- 복합 기본회귀: 지표·유의변수 회귀식·기준 범주를 요약에 모으고, 계수/VIF/표본 상세와 보조 예측범위는 펼쳐서 확인하도록 정리했다.
- 잔차 진단: 금액대별 오차·조건별 오차·주요 영향 거래로 정리했다. 축 눈금, 음수 오차 설명과 비교 기준 문구를 수정했다.
- 설정·물음표: 자연스러운 존댓말, 필요한 제목만 표시, 내부 식별자 숨김, 계산 기준과 FAQ 접기를 적용했다. 집합 주거·비주거 도움말도 같은 표시 원칙을 사용한다.
- Macro 예측형·설명형: 추천 요약 → 기존 후보 비교 → 선택 모형 상세 → 조건별 추정 순서를 통일했다. 추천 기준과 실제 계산은 유지했다.
- 쌍둥이 확장: Local·Twin1·Twin2의 실제 제공 지표를 상단 비교표에 모았다. 현재 지역 선택, 마지막 완료 결과의 선택, 모형의 실제 사용 지역을 구분한다. 상세 검증·회귀계수·각 모형의 추정창은 기본적으로 접는다.
- 배포 통합에서 발견한 비주거 표본 상세의 행 불일치를 수정했다. 지원하지 않는 공시지가 요청 옵션을 표본 상세에서 다시 적용하지 않고 실제 적합 행을 사용한다. 계산·보강 정책은 변경하지 않았다.

기존 Macro를 추천2로 대체하지 않았다. 토지 지분거래의 공시지가를 보강하거나 임의로 보충하지 않았다. AI 응답 정책 개선은 별도 과제로 남긴다. 모든 유형의 최종 UX가 완성됐다는 선언은 아니다.

검증: 분리한 운영 main 기준 소스에서 백엔드 244개·프런트 15개 테스트, 토지·복합·집합·임대·지역프로필 5앱 타입 검사와 빌드를 확인했다. 완전적합 fixture의 기존 statsmodels 경고와 큰 번들 경고는 남아 있다. 쌍둥이 최종 UI는 로그인 모드인 로컬 API를 변경하지 않고 예시 자료로 접기·지역 선택·기존 입력창 연결을 확인했다. 실제 거래자료의 새 추정 계산을 확인한 것으로 기록하지 않는다.
