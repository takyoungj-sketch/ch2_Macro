## 우선 복원할 항목

### 1. 복합: 추천 때와 채택·재추정 때의 표본 고정 — 높음

원래 브랜치의 `_lock_recommendation_sample`, `_with_recommendation_missing_policy`와 `sample_lock_blocks` 전달이 main에 없다. 추천 검색에 사용한 전체 변수의 공통 표본과, 선택된 변수만으로 다시 적합하는 표본이 달라질 수 있다. 추천 당시와 채택 후의 표본 수·계수·성능이 달라지는 원인이 된다.

관련: `backend/app/built/regression/engine.py`, `backend/app/built/schemas.py`, `frontend-built/src/components/RecommendationModal.tsx`.

기존 테스트 파일은 main에서 필요한 함수를 import하지 못해 수집 오류가 발생했다. 원래 브랜치에서는 이 파일의 3개 테스트가 통과했다.

### 2. 복합: Twin 분석 필터·선택 범위와 불완전 CV 순위 — 높음

- Twin 표본 조회에 현재 분석 요청의 도로조건·용도지역·건물용도·면적·연식 및 IQR 필터를 전달하는 경로가 빠져 있다. 기간·유형 필터는 남아 있지만 상세 조건은 동일하게 유지되지 않는다.
- `research_full_twin_pool`은 원래 통과한 선택 지역들을 묶었으나 main은 `passed[0]`만 사용한다. 선택 지역 전체를 비교한다는 UI 의도와 계산 범위가 달라질 수 있다.
- `_rank_candidates`는 일부 검증 연도만 성공한 모형도 CV 오차가 있으면 순위에 넣는다. 실패 연도를 제외하고 얻은 낮은 오차가 정상 검증을 완료한 모형보다 높게 평가될 수 있다.

관련: `backend/app/built/regression/candidates/factory.py:199`, `backend/app/built/regression/selection/pooling.py:133`, `backend/app/built/regression/selection/best_subset.py:44`.

수집 오류와 독립적으로 두 테스트를 실행하도록 원본 테스트에서 import와 표본고정 테스트만 제외한 별도 probe를 만들었다. 원래 브랜치 2/2 통과, main 2/2 실패했다. 한 테스트는 부분 CV 후보가 잘못 1위가 됐고, 다른 테스트는 상세 필터 요청 인자를 받지 못했다. 실제 SQL 호출부에서도 해당 요청 전달이 없는 것을 확인했다.

### 3. 토지: 결측치·최소 표본·퇴화 모형 처리 — 높음

- 표시된 회귀 적합과 가격 추정에서 범주형 결측치 처리 경로가 다르다. 동일 요청에서도 추정이 409로 거절되는 사례가 재현됐다.
- 지분거래 표기가 비어 있는 정상 전체거래를 모형추천의 완전자료 선택 과정에서 제외한다. 시험 표본은 기대 60건 대신 20건이 남았다.
- 빈 거래 결과에서 정해진 표본 부족 응답 대신 KeyError가 발생한다.
- 공시지가만 선택한 추천 요청, 요청한 최소 표본 수, 상수 설명변수 모형에 대한 보호 처리가 원래 브랜치보다 부족하다.

관련: `backend/app/land_regression.py:79`, `:542`, `:723`.

13개 기존 테스트 중 원래 브랜치는 전부 통과, main은 7개 통과·6개 실패했다. 이는 공시지가 연결 V1 정책이나 과거 후보 우선 연결을 변경하자는 의미가 아니다.

### 4. 집합 주거·비주거: 희소 표본과 효용지수의 해석 보호 — 높음

- 희소 동·단지·도로명·반기·층 표본을 제외하거나 추정 불가로 처리하는 개선이 누락됐다. 작은 범주가 기준 범주에 섞여 계수·지수를 바꾸는 사례가 재현됐다.
- 공선성이 있는 연식의 표준오차, 관측하지 않은 층과 기준층 정보, 검증이 불가능한 경우의 CV 표시 등이 원래 브랜치와 다르다.
- 효용지수의 표본 부족 시 참고값 전환, 신뢰구간·기준층 표시, 건물별 동 기준, 지하층·관측 최상층 구분 개선이 빠져 있다.
- 비주거 효용지수 API가 `contract_date_from/to`를 받지 않아 롤링 구간의 정확한 날짜를 전달하는 개선도 누락됐다. main은 연도 범위만 받는다.

관련: `backend/app/collective/regression/engine.py`, `backend/app/collective/floor_index_regression.py:527`, `backend/app/collective_commercial/router.py:1005`, `frontend-collective/src/components/FloorIndexPanel.tsx`, `CommercialFloorIndexPanel.tsx`.

회귀 표본 보호 테스트 main 12개 실패, 효용지수 테스트 6개 통과·12개 실패, 비주거 회귀 테스트 20개 통과·1개 실패. 다만 별도의 집합 예측 정합성 테스트 8개는 main에서도 전부 통과했다. 따라서 집합 예측 보호가 전부 사라진 것은 아니다. 복원 시 주거·비주거를 함께 검증해야 한다.

### 5. Macro Insight 13·14: AI 전용 해석 등록 누락 — 중간

보고서 페이지와 프런트의 `Insight13`, `Insight14` 컨텍스트 발행은 main에 있다. 반면 AI의 bundle registry, extractor, panel capability에는 두 보고서의 등록이 없다. 등록이 없는 패널은 `regression_diagnostic` 및 기본 capability로 넘어간다. 보고서가 없어진 문제가 아니라 해당 보고서의 핵심 수치·해석 한계를 AI에 구조적으로 전달하는 지원이 빠진 것이다.

관련: `frontend-insight/src/pages/Insight13.tsx:27`, `Insight14.tsx:114`, `backend/app/ai/bundles/registry.py:378`, `backend/app/ai/bundles/extractors.py`, `backend/app/ai/panel_capabilities.py:589`.

세 AI 파일 모두 배포 전 백업은 원래 브랜치, 현재 운영은 main과 일치한다. 실제 유료 모델 호출은 수행하지 않았으므로 모든 질문이 실패한다고 단정하지 않는다. 프런트가 제공하는 다른 facts의 활용 가능성은 별개다.

## 추가 복원 후보와 구분 사항

### 집합 장기추세의 결측 연도 표시 — 중간

원래 `YearlyTrendChart`는 빠진 연도도 축에 표시하고 관측이 연속된 구간만 연결한다. main은 존재하는 관측치를 같은 간격으로 배치하고 누락 연도를 가로질러 선을 연결한다. 시간 간격을 잘못 읽을 수 있다. 원래 브랜치의 `trendComparison` 유틸리티와 연계해 복원할 필요가 있다. 이 항목은 코드 대조만 수행했고 브라우저 시각 검증은 하지 않았다.

### 임대 회귀 탭의 비공개 설정 — 추가 확인 후 복원

원래 브랜치는 성능 개선 전까지 `SHOW_REGRESSION_TAB=false`로 숨겼지만 main은 회귀 탭을 항상 표시한다. 탭 공개 상태가 되돌아간 차이는 확인했다. 다만 이 파일은 후속 안내문 편집도 섞여 백업과 브랜치 전체 해시가 일치하지 않는다. 마지막 공개 의도를 확인한 뒤 이 플래그만 선택 복원하는 것이 적절하다.

### 토지 모형추천 UI — 전면 소실로 보지 않음

새 `LandModelRecommend` 컴포넌트와 후보 채택 UI 개선은 main에서 빠졌지만, 이전 방식의 모형추천 버튼·결과는 남아 있다. 따라서 ‘토지 모형추천 기능 전체 삭제’라고 보고하면 부정확하다. 계산 정합성을 먼저 복구한 다음 UI 개선분을 별도로 대조해야 한다.

- 관리·구독·사용량 정책의 main 전용 개선. 과거 브랜치로 되돌릴 대상이 아니다.
