# 청주 실제 SQL·FastAPI 요청 병행 검증

2026-10-05. [가격 마트·응답 함수 검증](CHEONGJU_PRODUCT_MARTS_API_REPLAY_RESULT.md)의 후속으로 실제 FastAPI 앱과 PostgreSQL에 기존 입력·통합 공급 입력을 각각 실행했다. 비교 범위 안에서 상태 코드와 전체 JSON 본문이 동일했다. 운영 API 프로세스·제품 테이블·라우터 코드는 이번 작업에서 수정하지 않았다.

## 실측 결과

각 입력에 122개, 총 **244개 요청**을 실행했다. 응답 차이는 **0건**이다. 입력별 상태 코드는 200 104건, 401 6건, 422 8건, 400 4건이다. SQL 추적은 입력별 집합 618회·복합 398회이며 조회뿐 아니라 읽기 전용 상태 확인·savepoint 제어문도 포함한다. 쿼리 해시와 실행 횟수는 상세 연구 산출물에 보존한다.

- 주거 `/api/collective/buildings`: 거래 수·평균·이름·주소·세대수 정렬, 1/2 페이지, 자산 유형별 조회, 구/동·주소 단위 필터, 연도 지정 live 조회, 속성·가격·분석 게이트·동일 지번 유형 sibling을 포함한 실제 응답.
- 비주거 `/api/collective/commercial/clusters`: 거래 수·평균·표시명 정렬, 페이지, 상가/공장, 구/동·주소 단위 필터, 연도 지정 live SQL과 기존 도로명 군집 응답. 주거 단지 속성 합산은 적용하지 않는다.
- 복합 `/api/built/transactions`: 원장/보강 표시, 자산 유형·연면적 범위·용도지역 필터, 날짜/ID 정렬, 실제 enrichment LEFT JOIN과 표시용 용도지역·복구 지번 변환.

토큰 누락·오류는 실제 앱 미들웨어에서 401, page=0/page_size=501/잘못된 sort는 422, 시군구 누락/역전 연도는 400으로 확인했다. 없는 지역과 마지막 페이지 이후는 빈 목록이다. 자산 필터·연면적 범위·복합 정렬의 의미도 별도 확인했다. 500개씩 전체 페이지를 끝까지 읽고 총수·키 중복·누락을 확인했다.

## 최신 목록과 이전 마트 판본

동결 주거 마트는 1,471개지만 2026-09 최신 판본은 **1,470개**이고 2026-08 판본 1개가 남아 있다. 8월 판본에는 2019년 거래 2건이 있으며 최신 목록은 최신 마트 월만 조회하므로 이 키는 반환하지 않는다. 이전 판본은 동결 자료에 보존한다. 이를 통합 공급의 유실로 판정하거나 최신 목록에 자동 복구하지 않았다.

전체 목록의 실제 반환은 최신 주거 1,470개·비주거 306개·복합 13,293건(원장/보강 각각)이다. 최신 주거·비주거 키 집합은 최신 마트 판본과 일치하는지 검사한다. 판본 월이 다른 과거 관측의 보존과 현재 노출은 서로 다른 계약이다. 건축 원문 2026-07 판본과 제품 마트 2026-09 기준월도 구분한다.

## DB·앱 격리

각 입력의 집합/복합에 별도 로컬 PostgreSQL 연결을 사용했다. 공개 제품 테이블에서 열 타입만 복사한 연결 전용 TEMP 테이블에 검증된 동결 행을 넣었다. 데이터 INSERT는 `pg_temp`로 한정하며 공개 기본값·sequence·제약을 복사하지 않는다. 요청 단계에서는 PostgreSQL 트랜잭션을 READ ONLY로 전환하고 모든 대상 테이블의 이름이 TEMP OID로 해석되는지 검사한다. 요청별 읽기 전용 상태도 확인한다.

실제 앱의 DB 의존성만 이 연결에 지정했다. SQL 문장을 흉내 낸 어댑터가 아니며 실제 WHERE·ANY·DISTINCT ON·집계·LEFT JOIN·페이지 쿼리가 PostgreSQL에서 실행된다. 작업 종료 시 DB 세션/물리 연결을 닫아 TEMP 테이블을 제거한다. 앱 의존성·메모리 내 테스트 토큰도 복구한다. 외부에서 실행 중인 로컬 서버의 설정과 토큰은 바꾸지 않는다.

연간 거래 수는 동결 7년 거래에서 계산해 분석 게이트 조회에 사용한다. 비주거 `commercial_clusters` 메타데이터는 로컬 DB에서 읽기 전용으로 한 번 확보하여 양쪽 입력에 동일하게 제공하고 내용 해시를 보존한다. 공개 스키마·지역 메타데이터 조회는 가능하므로 전체 운영 DB를 당시 시점으로 복제한 실험은 아니다.

## 실행·재현

공급 → 실제 회귀 → 가격 마트 → 응답 함수 → 실제 FastAPI/PostgreSQL 요청 → 코드·보고서·상세 산출물 해시 검증을 기존 한 명령에 추가했다. 최종 manifest ID는 `cheongju-fixed-product-input-acceptance-v2`다.

최신 전체 실행은 약 113초에 통과했다. 로컬 고정 자료의 배치 실행 시간이며 운영 API 응답 속도나 동시 사용자 부하 성능을 뜻하지 않는다.

```powershell
pipeline\.venv\Scripts\python.exe pipeline/parcel_master/run_cheongju_product_acceptance.py
```

기존 성공 공급을 재사용하여 SQL/요청만 실행할 수도 있다.

```powershell
backend\.venv\Scripts\python.exe pipeline/parcel_master/replay_cheongju_supply_http.py
```

관련 테스트 **155개**가 통과했다. 추가 검사는 임시 테이블 이름 허용 목록, 자산별 연간 수 구분, 공급값 변경 시 동결 입력 불변, 페이지 수 부족/중복 차단을 포함한다. 현재 작업폴더의 실제 엔진 코드 해시를 기록했고 기존 dirty 제품 파일은 보존했다. 원본·거래·응답 상세 gzip은 커밋하지 않는다.

## 완료 범위와 다음 단계
