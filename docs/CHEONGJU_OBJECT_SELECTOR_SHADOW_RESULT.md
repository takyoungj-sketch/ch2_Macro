# 청주 객체·주소 선택기 — 관측 보존과 보류 단계 병행 검증

2026-10-05. [객체·소속 계약 초안](LEDGER_OBJECT_MEMBERSHIP_CONTRACT_DRAFT.md)을 검토 큐 52개 및 같은 법정동 복수 PNU 33개에 병행 적용했다. 기존 키와 자산 유형 기준으로 두 집합의 중복이 없어 **85개 키**를 검증했다.

구현한 범위는 **관측 후보 보존·입력 검증·보류 판정**이다. 실제 거래 소속을 검증하는 원천별 검증기와 대표 주소 선택 규칙은 아직 구현하지 않았다. 따라서 85개 모두 새 객체·대표 PNU·가격·속성 승계 없이 보류한다. 이는 제품 데이터를 차단하거나 85개를 모두 오류로 확정한 결과가 아니다.

## 거래와 기존 보강 보존

검토 큐 52개는 106개 주소 파티션·10,620거래, 같은 법정동 복수 PNU 33개는 71개 파티션·3,355거래다. 전체 **177개 파티션·13,975거래**를 그대로 보존했다. 원문 `(법정동 코드, 지번)` 쌍은 거래수와 함께 유지하고 열별 MAX로 새 주소 조합을 생성하지 않는다. 지번 표기 별칭은 같은 PNU 후보에 묶더라도 원문 쌍을 따로 남긴다.

기존 가격 마트가 있는 **54개 키**, 건물 속성 보강이 있는 **70개 키**는 기준값을 원형과 내용 해시로 보존했다. 이번 실험에서는 새 후보에 이 보강값을 복사하지 않는다. 기존 운영 가격·속성은 그대로 유지한다.

## 상태와 근거

- **객체 범위 검토 보류 74개:** 서로 다른 필지·법정동의 거래가 한 키에 포함돼 소속을 확인해야 한다. 같은 단지의 여러 필지일 가능성도 보존한다.
- **같은 필지의 관리코드 관계 검토 9개:** 복수 관리코드만으로 분할·병합하지 않는다.
- **개발사업 블록 주소 미확정 2개:** 비정규 블록 주소 4개를 원문으로 유지하고 PNU를 만들어내지 않는다.

보류 사유는 복수로 기록한다. 기존 거래 미관측 통계 주소 28개, 법정동 교차 43개, 복수 관리코드 26개를 재현했다. 최신 표제부 원천 범위 부족은 13개 키의 추가 사유다. 사유별 건수를 합쳐 독립 키 수로 해석하지 않는다.

원천별 소속 검증기가 없는 상태에서 외부 호출자가 `membership_verified` 등의 표시만 넘겨도 승격되지 않는다. 현재 구현은 `unverified` 입력만 받으며 다른 검증 상태를 오류로 거절한다. `membership_verified`의 실제 허용 경로는 독립 관계 원천과 검증 규칙을 갖춘 뒤 추가한다.

## 복수 PNU 33개의 추가 원본 범위 확인

2026-07 원본 표제부 전체 8,060,932행을 읽어 **71개 PNU**를 확인했다. 60개 PNU에서 관련 표제부 297행을 확보했으며 11개 PNU에는 선택 판본의 표제부가 없었다. 관련 관리 PK 중복은 없고 원천 SHA-256은 이전 감사와 일치한다.

추가 원천 부재가 있는 키 11개 중 10개는 분양권, 1개는 연립다세대다. 분양권에는 과거 사업 지번·신규 지번 관계가 포함될 수 있으므로 최신 대장 부재를 거래 오류나 건물 부재로 확정하지 않았다.

전체 177개 파티션의 원천 범위는 표제부 관측 160개, 최신 판본 부재 13개, 비정규 주소 4개다. 앞 52개의 원문 근거는 보호된 이전 감사 파일을 재사용했다. 이번 작업은 현재 DB를 다시 조회한 감사가 아니며 거래 기간·기준 보강은 기존 고정 입력을 사용했다.

## 검증

신규 선택기 테스트 15개와 기존 67개, **총 82개 테스트 통과**. 미관측 주소 조합, 중복 관측·파티션, 잘못된 거래수, 다른 유형·통계 기간의 그룹, 원문 지번 별칭, 입력·출력 기준값 분리, 근거 없는 검증 표시 및 원천 부재와 미검토 구분을 검사했다.

85개 키를 독립 재계산하면서 키·파티션·내부 그룹 순서를 뒤집어도 같은 후보와 보류 결과가 나왔다. 원문 주소별 거래수와 기준값 해시를 각각 대조했고, 보호한 앞 단계 근거 파일은 변경되지 않았다. 비주거 **306개 기존 군집 키**도 정확히 유지했으며 주거 분할 규칙을 적용하지 않았다. 비주거 값은 보호된 이전 감사의 대조군이며 신규 DB 조회가 아니다.

선택기 처리 시간은 85개 키의 메모리 내 검증만 측정했다. 파일 읽기·원본 스캔을 제외하므로 제품 API·DB 조회 성능으로 해석하지 않는다. 실제 제품 성능과 통계·회귀 변화는 운영 연결 경로가 준비된 뒤 별도 측정한다.

## 다음 단계

소속 검증에 사용할 원본 관계의 실제 식별자·스키마·판본을 확인하고, 원천별 검증기를 구현한다. 표제부 주소·K-apt 대표주소가 실제 거래 소속을 대신 인증하지 않도록 한다. 분양권의 과거 사업 지번과 신규 지번 관계도 별도 근거를 갖춘다.

검증된 소속이 확보되면 대표 주소 선택과 기존 키 전환 대응표를 만들고, 통계·가격·회귀 차이와 조회 성능·복구 절차를 검증한다. 현재는 사용자가 직접 화면을 열어 판정할 사항이 없다. 운영 전환·푸시·배포는 수행하지 않았다.
