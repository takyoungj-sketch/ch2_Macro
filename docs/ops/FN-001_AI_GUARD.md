# FN-001 운영 메모

FieldNote AI 남용 방지. 설계는 PLAN v3. 이 메모는 배포 전의 운영 한계다. main 병합과 배포는 하지 않았다.

## 설정 출발값

| 설정 | 출발값 |
|---|---|
| `FIELDNOTE_AI_ANON_MONTHLY_QUOTA` | 0. 0보다 커도 기기 ID 한도로 돌아가지 않는다 |
| 유료 월 한도 | 사진 500장, 주소표 100회, 문구 100회 |
| 체험 월 한도 | 사진 125, 주소표 25, 문구 25. 체험 등급 자체는 FN-002 |
| 관리자 월 한도 | 사진 1000, 주소표 200, 문구 200 |
| `FIELDNOTE_AI_DAILY_CAP_CALLS` | 300 |
| `FIELDNOTE_AI_DAILY_CAP_USD` | 5.0 |
| `FIELDNOTE_AI_WORST_CALL_USD` | 0.025 |
| 속도 | 계정 분 10·시간 120, IP 분 20·시간 240 |
| `FIELDNOTE_AI_ACCEPT_LEGACY_FORMAT` | true. 끄면 구 앱 형식은 400 |
| 출력 토큰 | 주소표 8000, 사진 분석·문구 4000. 클라이언트 값은 무시 |

`ai_subscription_quota_enabled`는 Macro AI용으로 남아 있다. FieldNote 접근은 이 스위치와 무관하다.

## 운영할 때 알아 둘 한계

- 속도 제한은 프로세스 메모리다. 워커가 늘면 워커 수만큼 한도가 곱해진다. Redis는 넣지 않았다.
- 하루 금액은 `ai_provider_calls`를 기능 행과 맞춰 센다. `created_at` 인덱스는 없다. 호출이 쌓이면 FN-003에서 인덱스를 검토한다.
- 금액이 비어 있는 호출과 진행 중 예약은 건당 0.025달러로 센다. 상한을 넘으면 그 호출은 OpenAI로 나가지 않고 예약을 푼다.
- 유료 1명이 월 한도를 최악으로 쓰면 약 6.7달러다. 하루 상한이 전체 규모를 막는다. 실측 전에는 이 차이를 위험으로 남긴다.
- 주소표 사진 상한은 앱 `f496ff2`의 6장으로 확인했다. 예전 서버 검사는 12장까지 허용했다.
- 사진 분석의 비전 detail은 low다. 주소표는 4장 이하면 high, 5장 이상이면 low다.
- 구독 표의 `source` 검사에는 `admin`이 있으나, 그 값으로 이용권을 주는 경로·문서·런북은 없다. 테스터 부여 도구는 만들지 않았다.
- 동시 호출 상한은 SQLite에서 12요청 중 5건만 예약되는 것으로 확인했다. 전용 Postgres 시험 주소가 없고 운영 DB는 열지 않아서 Postgres에서는 돌리지 않았다.

## 배포하지 않은 이유

검수는 Codex가 한다. 운영 서버와 운영 DB에는 접근하지 않았다.
