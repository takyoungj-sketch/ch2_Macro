# 청주 전체 이름 키 — 법정동·K-apt 혼합 범위

2026-10-05. [우선 6개 검토](CHEONGJU_PRIORITY_PRICE_MART_SOURCE_REVIEW.md)를 청주 전체 최신·최장기간 키로 확대했다. 원천 근거와 조사용 파티션을 만드는 읽기 전용 감사이며, 운영 객체 키·대표필지·가격·통계·회귀는 변경하지 않았다.

## 전체 측정 결과

아파트·오피스텔·연립다세대 **1,381개 이름 키 중 40개(2.90%)**가 서로 다른 법정동의 거래를 묶는다. 아파트 24개, 오피스텔 1개, 연립다세대 15개다. 해당 키의 기간 거래수 합계는 7,680건이다. 분양권 90개를 포함하면 1,471개 중 43개(2.92%), 8,179거래다.

기존 키 1,471개는 모두 현행 `attach_building_identity`로 원문 주소 그룹에서 재현됐다. 분양권에는 분양권 정규화 규칙만 사용했고 다른 유형에 적용하지 않았다. 따라서 이번 범위는 실제 현재 키 생성 규칙과 거래 구성에서 관측한 결과다.

서로 다른 법정동이 포함됐다는 사실만으로 모든 키가 잘못됐다고 확정하지 않는다. 단지의 여러 필지, 행정코드 변경, 동명 건물 등을 원천 근거로 구분해야 한다. 거래수 합계도 오매칭 거래수나 가격 오차의 건수가 아니다.

## K-apt 원문으로 구분한 근거

법정동을 넘는 43개는 다음처럼 나뉜다.

- **17개:** 관측 PNU에서 여러 K-apt 단지 코드가 발견된다. 모두 아파트다. 실제 단지명·법정동주소 원문을 확보했으며 객체 범위 검토의 우선 대상이다.
- **4개:** 관측 주소에서 K-apt 코드가 하나만 발견된다. 그 코드가 모든 주소의 소속을 인증하는 것은 아니다. 주거 3개·분양권 1개다.
- **22개:** 관측 PNU에 K-apt 대표주소 근거가 없다. 주거 20개·분양권 2개다. 미등록·관리대상 차이 등을 확인하지 않고 부적합으로 확정하지 않는다.

법정동을 넘는 키 중 **22개는 가격 마트**, **38개는 기존 건물 속성 보강**이 있다. 한 대표필지나 단지 속성이 여러 객체의 거래 묶음에 적용되는지 검토해야 한다. 기존 확정 보강은 유지했다.

반면 **같은 법정동에서 복수 PNU가 관측된 키는 33개**다. 주거 23개·분양권 10개로, 단지 다필지인지 별개 건물인지 독립 확인이 필요하다. 11개에는 일부 주소에만 K-apt 코드가 있고 22개에는 K-apt 대표주소 근거가 없다. **모든 관측 PNU가 공통 K-apt 코드로 연결된 사례는 이번 원문 대표주소 자료에서 없었다.** 이는 다필지 단지가 없다는 뜻이 아니라, 대표주소 파일만으로 전체 부지를 인증할 수 없다는 뜻이다.

**하나의 PNU에 여러 K-apt 코드가 있는 키 9개**도 별도로 남겼다. 이를 법정동을 넘는 동명 거래와 합쳐 같은 원인으로 분류하지 않았다. 한 필지에 여러 관리 단지 코드가 있을 수 있으므로 코드 개수만으로 객체를 분할하지 않는다.

전체 1,471개에는 이름 없는 키가 없었다. 이 결과를 전국의 이름 없는 주소 키까지 일반화하지 않는다.

## 이전 주소 조합 오류와의 관계

앞 감사의 거래 미관측 통계 주소 **28개는 모두 이번 법정동 교차 43개 안에 포함**됐다. 열별 MAX로 새 주소가 만들어지는 현상은 객체 키가 여러 법정동의 거래를 묶는 문제와 함께 다뤄야 한다.

주소 조합이 거래에서 관측된 키라도 객체 혼합이 없다고 인증할 수 없다. 법정동 교차 43개 중 나머지 15개는 관측 주소가 통계 주소로 남지만 여러 법정동의 거래가 한 키에 포함돼 있다.

분양권 포함 구별 검사 키/법정동 교차 키는 상당구 385/11, 서원구 310/7, 흥덕구 491/19, 청원구 285/6이다. 관측월은 키별 최신이며 대부분 2026-09, 연립다세대 1개는 2026-08이다.

## 검토 큐와 병행 파티션

법정동 교차 43개와 단일 PNU·복수 K-apt 코드 9개, **52개 키**를 검토 큐에 저장했다. 조사용 주소 파티션은 **106개**, 해당 큐의 거래수 합계는 **10,620건**이다. 주소 미해석 그룹도 버리지 않고 원문 주소 버킷으로 보존했다. `12`와 `12-0`처럼 같은 PNU로 해석되는 주소는 하나의 관측 버킷으로 묶지만 실제 객체 소속은 미검증으로 둔다.

이 파티션은 새 객체 키가 아니다. 기존 키별 거래수와 기준 가격·속성을 보존하며 신규 객체 키·대표 PNU는 모두 null, 운영 적용은 false다. 같은 법정동 복수 PNU 33개는 전체 근거 파일에 별도 분류로 보존했으며, 별도 소속 증빙이 필요하다.

## 검증

현재 DB에서 유효·양수 단가·기간 조건을 일치시켜 주소·이름 그룹 1,660개를 조회했다. 키별 거래수와 PNU 후보가 이전 고정 입력과 같음을 확인했고, 이전 우선 6개의 법정동 및 K-apt 코드 개수도 재현했다.

신규 분류·주소 파티션·nullable 키 재현 테스트 8개와 기존 45개, **총 53개 테스트 통과**. 별도 직접 SQL의 `COUNT(DISTINCT beopjungri_code)`와 거래수로 법정동 교차 **43개를 독립 대조**했다. 반복 실행의 근거 내용 해시 일치, 52개 큐·106개 파티션·10,620거래 보존, 새 객체·대표필지 할당 없음도 확인했다.

K-apt 대표 PNU XLSX와 기본정보 XLSX의 SHA-256이 이전 우선 검토와 같았다. 관련 대표주소 378행과 기본정보 404행을 원문 그대로 보존했으며 관련 코드의 기본정보 누락은 없었다. 원천의 중복 코드·행을 임의로 제거하지 않았다. 원문 행수는 단지 개수와 구분한다.

비주거는 도로명 군집이므로 주거 이름 키의 분할 기준을 적용하지 않았다. 보호된 이전 감사의 비주거 306개·미관측 주소 조합 0개 결과를 함께 보존했다. 이번 비주거 값은 신규 원천 조회 결과가 아니다.

## 다음 실행 단위

법정동 교차·복수 K-apt 코드 **17개 아파트 키**부터 단지명·법정동주소·관측 시점·원본 표제부를 대조해, 별개 단지 혼합과 행정코드/다필지 관계를 검토한다. 그 근거로 객체 식별자·주소 쌍을 보존하는 선택기를 병행 실험한다. 실측에서 발견한 코드 개수나 거래수가 운영 전환의 자동 합격선이 되지 않도록 한다.
