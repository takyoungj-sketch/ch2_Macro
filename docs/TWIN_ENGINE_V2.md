# Twin Engine V2

> **상태:** 랩 구현 (D-044, 2026-08-16). 제품 Twin 카드 V1 대체는 보류.  
> **결정:** [`DECISIONS.md`](./DECISIONS.md) D-044 · 카드 [`lab/decisions/D-044.json`](./lab/decisions/D-044.json)  
> **선행:** D-029(카탈로그·가중 YAML) · D-041(Twin≠회귀 X) · D-026(지목군 7)

V1 마트·카탈로그를 **폐기하지 않는다.** V2는 그 데이터를 읽는 **거리 엔진**이다.  
클러스터링 · ML Twin · 자동 가중 학습은 **넣지 않는다.**

제품 목표: 사람이 설명할 수 있고, 데이터 없음과 낮은 유사도를 구별하는 기준선.

---

## 1. 두 직업

| | 비교 Twin | 풀 Twin |
|--|-----------|---------|
| 질문 | 이 지역을 **설명할 때** 참고할 곳 | 이 지역 **가격을 분석할 때** 참고할 곳 |
| 무게 | 구조 중심 | 가격까지 |
| 쓰는 곳 | 지역프로필 카드 | 회귀 Stage2 검토 (D-041, 자동 채택 없음) |

같은 엔진. **후보 우주와 구조/시장 가중**만 다르다.

```text
              Twin Engine V2
                    │
          ┌─────────┴─────────┐
          │                   │
     후보 생성              후보 평가
     행정·인구·거래량        ① 구조  ② 시장
     최소 데이터
          └─────────┬─────────┘
                    │
              Twin Score + 신뢰도
                    │
           ┌────────┴────────┐
           │                 │
      비교 Twin           풀 Twin
```

## 2. 코딩 전 고정 3항 (D-044)

설정값이다. 신성이 아니다. YAML에 두고 검증으로 고친다.

### 2.1 인구 문

```text
|log(Pa) − log(Pb)| ≤ log(2)
```

인구가 최대 **2배** 안. ±50% 하드컷·인구수 가산점은 쓰지 않는다.  
인구 NULL이면 **탈락** (V1처럼 통과시키지 않음).

### 2.2 구조 : 시장 가중 (초기값)

| 직업 | 구조 | 시장 |
|------|------|------|
| 비교 Twin | 0.60 | 0.40 |
| 풀 Twin | 0.40 | 0.60 |

키 예: `compare_structure_weight` / `compare_market_weight` / `pool_structure_weight` / `pool_market_weight`.  
풀 Twin은 Stage2에서 「넣었더니 CV-MAPE가 좋아지는가」가 장기 근거가 된다.

### 2.3 후보 우주

| 직업 | 우주 |
|------|------|
| 비교 Twin | **같은 권역** 중심 (`region` scope) |
| 풀 Twin | **같은 시군 + 인접 + n-hop**. 권역 밖·너무 먼 곳은 제외 |

리=같은 시군만(V1)은 비교 Twin에 쓰지 않는다.

## 3. 평가

### 3.1 구조

| 항 | 재료 | 비고 |
|----|------|------|
| 8대 거래구성 | `yearly_mix.count_share_by_type` | 벡터 거리(코사인). **새 통계 없음** |
| 토지 이용 | `jimok_group_composition` 7벡터 | **주력.** agri/forest/dev/infra/water/special/other |
| 아파트 시장구조 | 거래량 등 | 표본 적으면 항만 축소·제외 |
| 용도×지목 Top3 Jaccard | 기존 land_top | **보조.** 주력 아님 |

대지·공업·상업·공공은 **용도지역**이다. 지목군과 섞지 않는다.

### 3.2 시장

| 항 | 재료 |
|----|------|
| 토지 가격 | 대표 셀·지목군 단가 수준 |
| 아파트 가격 | P50 만원/㎡ |
| 아파트 분포 | (P75 − P25) / P50 |

P25/P50/P75 세 값의 단순 평균은 쓰지 않는다.

### 3.3 없음 ≠ 0점

두 층을 섞지 않는다.

| 층 | 없는 유형 | 점수 |
|----|-----------|------|
| **구성 벡터** | 비중 **0** (좌표) | 코사인은 이 벡터 그대로. 「오피스텔 없음」은 구조의 일부 |
| **가격·시장 블록** | 마스크 실패 | 그 블록을 **평균에서 제외**. 0점을 남기고 가중치를 유지하지 않음 |

아파트 데이터가 한쪽만 있으면 아파트 **가격** 항을 뺀다. “아파트가 다르다”가 아니다.

최종 Twin Score = **이번에 쓴 항만**의 가중평균.

### 3.4 신뢰도 (별도)

```text
신뢰도 = (실제로 쓴 가중치 합) / (설계 가중치 합)
```

점수와 한 줄에 섞지 않는다. 예: Twin Score 82 · 신뢰도 74.

## 4. 하지 않는 것

- V1 `regional_profile` / twin 마트 / 카탈로그 폐기
- 지목 7대를 Twin용으로 다시 정의
- 구성 벡터에서 없는 유형을 “가격 0점”처럼 취급
- 구조:시장 가중치를 코드 상수로 고정하고 검증 없이 신성화
- 클러스터링 · 학습형 Twin · 자동 가중
- Twin score를 회귀 X에 넣기 (D-041)
- 풀 Twin 자동 채택

다음 검증은 수식 튜닝이 아니라 **사람이 봤을 때 Twin이 맞는가**이다.
