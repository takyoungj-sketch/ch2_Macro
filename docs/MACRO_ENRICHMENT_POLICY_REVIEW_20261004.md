# Macro 복합·집합 데이터 보강 정책 리뷰

2026-10-04. 현재 로컬 코드·정책 문서 리뷰. 앞선 청주 읽기 전용 인벤토리를 참고했다. 운영 VPS의 적재 상태·실제 화면·스케줄 실행 여부는 확인하지 않았다. 정책이나 제품 코드를 변경하지 않았다.

사용자가 정한 후속 순서: 공통 대장 일원화·정규화 실험과 정책을 먼저 세우고, 이 리뷰의 보완점을 포함하여 복합·집합 보강을 전반 개편한다. 지금 발견 사항을 개별 제품 수정으로 실행하지 않는다. 계획: [`LEDGER_UNIFICATION_ROADMAP.md`](LEDGER_UNIFICATION_ROADMAP.md).

## 결론

원장과 보강을 분리하고 불확실한 연결을 억지로 채우지 않는 방향은 적합하다. 복합은 거래 해시별 별도 보강, 집합은 단지/건물 속성 및 최신 대표필지 공시지가 소비가 중심이다. 공통 대장을 통합해도 두 소비 단위를 유지한다. 집합 과거 개별 거래별 토지정보 보강은 이번 범위에서 제외한다.

주요 개선점은 회귀 허용 등급·안내 문구의 일치, 복합 동의의 출처·시점 한계, 월간 보강의 실제 증분 계산, 건물 연결 근거 보존이다.

## 확인한 문제

### P2 — 집합 대표 주소의 열별 MAX가 실제 거래에 없는 조합을 만듦

2026-10-05 후속 근거: [`CHEONGJU_REPRESENTATIVE_AND_AGGREGATION_REVIEW.md`](CHEONGJU_REPRESENTATIVE_AND_AGGREGATION_REVIEW.md). `build_collective_building_stats.py`의 ROLLING_SQL은 법정동과 지번을 각각 MAX로 선택한다. 대표 PNU 차이 4개 중 3개에서 해당 기간의 유효 거래에 없는 조합을 확인했고, 4개 모두 현재 거래의 열별 MAX가 저장 통계 주소를 재현했다. 가격 import는 이 통계 주소로 조회하며 가격이 없으면 기존 마트 행을 유지한다. 과거 적재 실행 원인은 로그가 없어 인증하지 않았다.

권고: 실제 관측 주소 쌍과 대표필지 관계를 보존하고 복수 주소/기존 대표 충돌을 분리한다. 이름 키가 지번을 포함하지 않는 구조도 함께 검토한다. 현재 코드·대표필지·가격 마트는 유지했으며 공통 정책 정리 후 개편할 항목이다.

### P2 — 집합 지역회귀 허용과 목록 설명이 다름

`backend/app/collective/regional_regression/engine.py:47`은 A/B/C/D/F/T/P를 허용하고 E/Z/공란을 제외한다. `kapt_same_pnu` 규칙은 등급과 별도로 제외한다. 허용은 선택 변수·품질·결측·거래수 조건을 통과할 자격이며 모든 행의 최종 사용을 보장하지 않는다.

반면 `backend/app/collective/danji_attributes.py:36` 및 37은 P/T의 `usable=False`를 반환하고, 109~129의 PNU·표제부 설명은 지역회귀 hard 표본에 넣지 않는다고 안내한다. 540~553에서 해당 설명을 실제 응답에 붙인다. 사용자는 표제부/PNU 연결 단지가 제외된다는 설명을 보면서 지역회귀에서 사용되는 상황을 만날 수 있다. 월간 정책·D-048 일부 문구도 A/B/C만 허용한다는 과거 설명을 유지한다.

권고: 회귀 목적별 허용 정책을 명시적으로 정의하고 목록의 `usable_for_regression`·설명·지역회귀 엔진이 이를 공유하도록 정리한다. 최신 허용 범위를 검증 없이 A/B/C로 되돌리는 것은 해결책으로 확정하지 않는다.

### P2 — 복합 동의에서 정책상 핵심 한계가 빠짐

D-051은 계약 이후 건축대장 사용, 복수 용도지역의 대표값 선택, 서울·충북 중심의 매칭 검증 범위를 설명하도록 정했다. 현재 프런트 `frontend-built/src/utils/enrichmentConsent.ts:3`과 백엔드 `backend/app/built/enrichment_policy.py:8`은 일반 설명 2문장과 75.0% 매칭률만 제공한다. `EnrichConsentModal.tsx`는 이 상수를 그대로 표시한다.

과거 거래의 당시 상태가 복원됐다고 오해할 수 있다. 75.0%는 D-050 고정 게이트 값이며 지역·유형별 현재 정확도 또는 항상 최신인 매칭률이 아니다. 새 스냅샷을 추가한다면 과거 문서의 최대 시차 숫자도 재검증해야 한다.

권고: 출처·관측 시점·대표값 처리·검증 범위를 동의에 복원하고 비율에 기준일·분모를 명시한다. 길게 경고하기보다 사용자가 선택의 의미를 알 수 있는 짧은 설명으로 정리한다.

### P2 — 복합 월간 보강은 INSERT만 증분이고 계산은 전체

`pipeline/built/recover_from_parcel.py:230`은 지역·2019년 이후 대상 거래를 읽고, 246에서 판본별로 전체 `match_all(tx,...)`를 호출한다. 가져오는 `recover_address.TX_SQL`에는 기존 보강을 제외하는 조건이 없다. 기존 결과를 읽어 비교 게이트를 만들고 최종 INSERT는 `ON CONFLICT DO NOTHING`으로 동결한다.

기존 값을 덮지는 않지만, 월간 문서의 "없는 hash만 enrich"가 계산 범위에서는 구현되지 않았다. 거래 누적에 따라 전체 재매칭 비용이 증가하고 월간 증분 경로와 이관 인증 경로가 섞인다.

권고: 전체 SQL 이관 게이트와 신규·미연결 증분 계산을 별도 실행 경로로 나눈다. 이관 검증용 전체 분모·등급 비교를 증분 결과로 대체하면 안 된다. 미연결 재시도와 신규 해시도 구분한다.

### 통합 전 보완 — 건축물 식별 근거가 부족함

청주 로컬 보강행 10,799건에서 `bldrgst_pk`는 모두 비어 있었고 `pipeline/built/enrichment_rows.py`도 None으로 생성한다. 현행 구조·용도지역 조회는 작동할 수 있지만 거래가 어느 건물 PK·대표/추가 필지에서 왔는지 재검증하는 데 한계가 있다. 복수 건물/필지 관계를 보존할 새 연결 실험의 과제다. 빈 PK를 주소만으로 자동 채우지 않는다.

## 복합 정책과 실제 적용

- 원천: 건축 표제부·총괄, 토지대장 대지면적 보조, AL_D155 용도지역. 건축HUB 지역지구구역은 용도지역 원천에서 배제한다.
- 연결: 마스킹 지번·법정동·연면적 등으로 A1/A2 후보를 판정한다. A1은 연면적 일치, A2는 대지면적 동률 해소다. 지분거래는 복원 매칭에서 제외한다.
- 시간: 실제 SQL 경로는 `time_fallback`. 거래월에 가장 가까운 과거 판본을 우선하고 없으면 최초 이후 판본을 쓴다. 선택 판본 실패시 다른 판본을 확인하며 대안 필지가 갈리면 미상이다. 과거 당시 속성이 입증됐다는 정책은 아니다.
- 저장: 거래 해시별 `built_transaction_enrichment`, 원장 무수정. 미확정은 보강행을 만들지 않고, 확정행은 충돌시 유지한다. 정정으로 해시가 달라지면 새 연결 대상이며 옛 보강은 고아로 남을 수 있다.
- 제품: 기본 off, 동의 후 LEFT JOIN. 목록·CSV·회귀가 같은 표시 용도지역과 필터를 사용한다. 원장에 유효한 세부 용도지역이 있으면 우선하며 없을 때 보강 대표값을 쓴다. 복수 라벨은 원자료에 보존하고 제품은 대표 1개를 표시한다.
- 회귀: 구조 더미는 보강을 켰을 때 사용 가능하다. 공시지가·D194 토지특성은 이번 청주 연구 결과이며 현재 복합 공개 회귀에 반영됐다고 볼 근거는 없다. 기본통계 마트는 원장만 사용한다.
- 갱신: 월간 러너 기본 skip. opt-in enrich 구현은 존재하나 위 전체 계산 문제가 있다. 분기 대장 갱신, 연간 공부 갱신은 계획된 운영 달력이며 자동 다운로드가 실행된 증거는 아니다.

## 집합 정책과 실제 적용

- K-apt로 시공사·규모·층수·주차 등 단지 속성을 보강한다. 브랜드는 거래 단지명과 사전에서 추출하며 K-apt에서 바로 가져온 브랜드로 설명하지 않는다.
- A/B/C는 이름 또는 지번 일치, D/F는 복수 단지 집계, E는 이름 부분일치, P는 PNU 기반, T는 표제부 동 합산, Z는 미연결이다. 합산 속성은 개별 건물 값과 구분해야 한다.
- 표제부에는 시공사가 없으므로 T 보강에서 시공사를 추정하지 않는다. 오피스텔은 세대수가 비면 호수를 사용하며 원천 세대수·호수를 서로 덮지 않는다.
- 신규 키 보강 러너는 기존 속성행을 유지한다. 표제부 채움은 K-apt 및 P 연결을 보호하고 기존 T는 대장 달의 명시적인 `--refresh-t`로 갱신한다. 불안전한 T/P를 미연결로 되돌리는 전용 정리 경로도 존재하므로 모든 등급이 영구 불변인 것은 아니다.
- 최신 공시지가 마트는 `(building_key, asset_type)`당 대표 PNU 1개, `DO UPDATE`로 갱신한다. 건축/K-apt 매칭 동결과 최신 공시지가 갱신은 서로 다른 정책이다. 원천 이력 보관과 제품 최신 마트도 구분한다.
- 지역회귀는 `collective_building_stats`의 단지 가격 집계와 속성을 연결하여 단지당 한 행으로 분석하고 최신 공시지가를 변수 선택에 따라 사용한다. 현재 엔진의 사용 등급은 위 문제 항목과 같다. 품질 플래그의 세대수·층수·주차 이상값은 회귀 입력에서 결측 처리하고 원본 표시값은 별도로 보존한다.
- 사용자가 정한 목적: 현재 단지 가격 수준과 신축 아파트 지역회귀에 집중. 과거 거래별 공시지가·토지특성 연결을 추가하지 않는다.
- 비주거 집합은 도로명 군집 단위이며 같은 K-apt/표제부 단지 속성 보강 경로를 타지 않는다. 정책 통일은 동일한 출처·품질 계약을 뜻하며 주거와 동일한 원천이 확보됐다는 뜻이 아니다.

## 유지할 점과 정리 순서

원장 분리·확정 결과 보호·품질 플래그·현재 단지별 최신 공시지가 소비는 유지한다. 우선 등급·설명 불일치와 복합 동의를 정리하고, 다음으로 건축·토지 관계를 청주에서 검증한다. 월간 증분화는 전체 이관 검증 경로를 보존하며 진행한다. 문서의 '운영 0행'·'지역회귀 A/B/C' 등은 당시 상태 기록과 현재 정책을 구분해야 한다. 이번 조사만으로 VPS 현재 상태를 확정하지 않는다.
