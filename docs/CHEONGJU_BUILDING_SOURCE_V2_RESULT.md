# 청주 원천 보존 정규화 v2 — 검토 표본 실험

실행일: 2026-10-05. 운영 DB 연결·제품 수정·배포 없이 원본을 읽고 별도 SQLite를 만들었다. [집계 JSON](lab/cheongju_building_source_v2.json), [실행 코드](../pipeline/parcel_master/pilot_cheongju_building_source_v2.py), [변환 코드](../pipeline/parcel_master/building_source_staging_v2.py).

## 무엇을 확인했나

기존 관계 검토 큐 160행에 등장하는 관리 PK 118개를 골라 2024-09, 2025-07, 2026-07 전국 원본 표제부에서 다시 찾았다. 큐 행수와 고유 건물 수는 다르다. 세 파일 전체 SHA-256과 행수가 이전 원본 조사와 같고 대상 PK 중복이 없음을 확인한 뒤 적재했다. 원본 전국 파일을 검사한 것이지 전국 데이터를 실험 DB에 적재한 것은 아니다.

2024-09에는 113개 관측 중 110개, 2025-07에는 105개 중 103개, 2026-07에는 80개 중 78개의 PNU가 v1과 같았다. 합계 298개 관측 중 291개는 동일한 주소 관계이고, 7개는 대지구분 원코드 `2`라 PNU 확정을 보류했다. 7개는 고유 관리 PK 3개에 걸친 반복 관측이다. 앞 조사에서 검토 행의 예외 3건을 확인한 뒤, 이번에는 해당 관리번호의 모든 판본을 확인해 관측 수가 늘었다. 정상 판정 PNU의 v1/v2 불일치는 0건이다.

예외 중심으로 선정한 표본이므로 이 수치로 청주 전체 예외율이나 연결 정확도를 추정하지 않는다. 최신 원본에 없는 건물은 최신 관측을 새로 만들지 않는다. 누락을 멸실로 해석하지 않는다.

## v1에서 달라진 점

v1은 기존 가공 DB의 PNU를 입력으로 받았다. v2는 원본의 시군구·법정동·대지구분·본번·부번을 보존하고 직접 판정한다. 관리 PK가 있어도 PNU를 확정할 수 없으면 건물 관측은 저장하되 정식 주소 관계는 만들지 않는다.

확인된 코드 0/1만 각각 일반 토지/산 PNU로 변환한다. 빈 지번을 0으로 채우거나 긴 지번을 잘라내지 않는다. 법정동과 시군구 일치, ASCII 숫자 및 길이를 검사한다. 코드 2의 의미는 아직 확인하지 않았으며 일반 토지로 간주하지 않는다. 제품의 기존 PNU 생성기는 이번 작업에서 수정하지 않았다.

원문 주소, 특수지명·블록·로트, 주·부속 코드/명, 외필지 수, 부속건물 수, 확인한 면적 및 대장 종류를 원문 문자열로 저장한다. 선택한 공통 필드를 보존한 프로토타입이며 76/77열 전체 필드 이관은 아니다. 외필지 수와 부속건물 수는 개수 근거만 보존한다. 같은 주소만으로 총괄–표제부 부모 관계나 추가 필지 목록을 생성하지 않는다.

## 실험 구조와 검증

로컬 `data/research/cheongju_ledger/building_source_staging_v2.sqlite`에 원천 배치 3개, 건물 식별 118개, 원문 버전 240개, 판본 관측 298개, 정식 주소 관계 291개를 저장했다. 건물 식별·원문 버전·시점별 관측·주소 관계를 분리했다. 별도 비공개 원문/대조 파일은 `building_source_v2_raw_review.json.gz`다. 공개 집계에는 관리 PK·PNU를 넣지 않았다.

- 판본별 재실행 3회가 추가 행 없이 같은 상태를 유지했다.
- 새 배치 적재 중 고의 실패를 넣어 모든 테이블이 이전 상태로 돌아가는 것을 확인했다.
- 선택한 원문 필드가 저장된 버전과 완전히 같고, 미확정 관측에 정식 주소 링크가 없음을 확인했다.
- 외래키 위반이 없고 기존 v1 DB의 전체 논리 상태가 유지됐다.
- v2 테스트 3개와 기존 원천 식별·관계 staging·토지 연결 테스트를 합쳐 17개가 통과했다.

v2는 원천 관측의 보존을 검증하는 별도 소규모 프로토타입이다. v1의 공시지가·토지 속성·현재 상태 복구 전체 기능을 v2로 옮겼다는 뜻은 아니다. 원본 주소의 확인은 거래 연결의 독립 정확도 인증이나 법적 부지 범위 확정이 아니다.
