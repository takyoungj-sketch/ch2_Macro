## 2. AI 역할 정의 (정책)

AI는 질문 의도를 스스로 파악해 아래 역할을 자연스럽게 오간다. 사용자가 역할을 고르는 메뉴는 만들지 않는다.

1. **통계 해설자** — 현재 화면의 건수·평균·중앙값·분위수·추이를 쉽게 설명하고 특징을 짚는다.
2. **분석 연구 조수** — 이상치 기준, 기간 선택, 지역 비교, 필터 조합 등 분석 방법의 대안을 제시한다. 결과에 대한 가능한 가설과 그 가설을 확인할 추가 분석을 제안한다.
3. **지식 안내자** — 통계학, 부동산 시장, 감정평가 이론, 경제지표, 데이터 특성에 관한 일반 질문에 답한다.
4. **보고서 작성 보조자** — 화면에서 확인된 수치로 시장동향·거래사례·통계 특성 문단 초안을 쓴다. 수치는 반드시 화면 참조로 넣는다.

## 3. 근거 자료 3분류 (정책)

| 자료 | 사용 원칙 | 검증 |
|---|---|---|
| A. CH2 화면 수치 | 서버가 전달한 값만, `{{current.fN}}` 참조로만 쓴다 | 서버 코드가 참조 존재·값 일치 확인 (LLM 검증 없음) |
| B. 일반 지식 (통계·부동산·감정평가·경제) | 자유롭게 쓴다. 예시 숫자·공식 허용 | 검증 없음. 단, 특정 지역·CH2 관측처럼 말하면 A로 취급 |
| C. 외부 최신 자료 (금리, 정책, 뉴스) | 조회 기능 없이 확인했다고 주장하지 않는다. 일반적 관계는 설명 가능 | 문장 패턴으로 "확인됨/발표됨" 류 단정 차단 |

원인 질문(예: "거래 감소가 금리 때문?")은 **B의 일반 관계 + A의 화면 추세 + "가설"임을 명시**하는 형태로 답한다. 인과를 검증한 것처럼 말하지 않는다.

## 4. 가격·투자 관련 경계 (정책)

**허용**
- 화면 통계와 사용자가 준 조건으로 하는 **산술 계산** (예: 중앙값 × 면적)
- 통계적 비교, 분석 방법, 가격형성요인 설명
- 매수·매도 질문에 대해 "자료로 결론을 낼 수 없다"는 답과 판단에 필요한 요소 설명

**제한**
- 개별 부동산의 적정가격을 **확정**하는 표현 ("적정가격은 ○원입니다")
- 직접적인 매수·매도 권유, 미래 가격 단정

**산술 계산 구현 규칙**
- 계산은 LLM이 하지 않는다. 답변에 `{{calc:current.f3*5000}}` 형식으로 식을 쓰면 서버가 계산해 삽입한다 (§5.4).
- 단일 점값보다 **범위**를 우선한다: 가능하면 25%~75% 분위수 × 면적을 함께 제시.
- 계산 결과 문장에는 "지역 통계에 따른 산술값이며 해당 토지의 적정가격이 아님"과 개별요인(접근성·경사·형상·이용상황) 한 줄을 붙인다. 이 경우에 한해 주의 문구는 습관적 면책이 아니라 필수다.

## 5. 구현 작업

### 5.1 [최우선] 화면 문맥 전달 완성 (P1, P2, P5)

**원칙:** 스크린샷 이미지가 아니라 **구조화된 데이터**를 보낸다. 원시 거래 행은 보내지 않는다.

모든 토지 화면 문맥에 공통 `scope`:
- `region_label` (예: "충청북도 단양군 영춘면"), `region_level`, `region_codes`(길면 개수만)
- `period`: 롤링이면 `period_start`/`period_end`/`window_years`, 만년력이면 `years`
- `filters`: 도로·면적구분·면적범위·지분제외·거래유형·이상치(on/off, k)·`matrix_mode`
- `as_of_month`, `stats_reference_date`

**(a) 기본통계 화면** — `FreeStatsPanel.tsx`
- `buildLandMatrixOverviewContext` 를 확장: 매트릭스 **전체 칸**을 보낸다.
- 칸별: `zone_type`, `land_category`, `count`, `mean`, `median`, `p25`, `p75`, `min`, `max`, `ci_lower`, `ci_upper`, `is_reliable(n≥15)`
- 행·열 합계(`by_zone`, `by_land_category`), 연도별 총계표(`by_year`)도 포함.
- 크기 관리: `count ≥ 1` 칸만, 칸이 120개 초과면 거래수 상위 120칸 + "나머지 N칸 생략" 메타.

**(b) 필터 분석 결과 화면** — `PaidAnalysisPanel.tsx`
- 현재 AI 문맥 게시가 없다. (a)와 같은 형식으로 `PublishAiContext` 추가. `panel: "LandMatrix"`, `facts.result_kind: "filtered"`.
- 반드시 **실행된 요청**(`paidAnalysisResult.request`) 기준으로 필터를 넣는다. 화면의 현재 필터 입력값이 아니다.

**(c) 셀 모달** — `PaidMatrixYearlyModal.tsx`
- `aiRegionLabel` 이 비어 "지역 미선택"으로 표시됨. 부모에서 지역명을 전달.
- 추이(`TrendCard`) 행마다 `count`, `mean`, `median`, `p25`, `p75` 와 함께:
  - `is_partial_period`: 만년력에서 기준월이 속한 해(예: 2026년, 10월까지) → `true`, `covered_months` 표시
  - `is_small_sample`: `count < 15`
- 롤링 버킷도 `period_start`/`period_end` 그대로 전달.

**(d) 백엔드 `dialogue._screen`**
- 새 `panel: "LandMatrix"` 분기 추가. 칸 라벨은 `"{용도} × {지목}"` 로 `identifiers` 에 등록 (숫자 포함 라벨 오인 방지 로직 재사용).
- `is_partial_period`, `is_small_sample` 은 `notes` 로 넣어 모델이 해석 시 반드시 보게 한다.
- 화면 문맥이 비어 있으면 "지역 미선택" 대신 실제 상태("이 화면의 통계가 AI에 전달되지 않았습니다")를 헤더·답변에 표시.

### 5.2 [최우선] 호출 구조 단순화 (P3, P4)

목표: **일반적인 질문은 LLM 1회.**

`dialogue.answer_land` 흐름을 다음으로 교체:

1. LLM 1회 호출 → `{"kind", "answer"}` 초안
2. **서버 코드만으로** 검증 (`_render` 기반):
   - 참조 `{{current.fN}}` 존재·형식 확인 (현행 유지)
   - 참조 없는 숫자 문장 처리 규칙 변경:
     - 사용자 질문 원문에 나온 숫자 → 허용
     - `product_knowledge` 문서에 나온 숫자 → 허용
     - 지역명·칸 라벨·"화면/현재/이 지역" 등 관측 지시어와 **같은 문장**에 있는 미참조 숫자 → 위반
     - 그 밖의 숫자(일반 설명·가상 예시) → 허용
   - 이 판정에 `_check_general_numbers`(LLM 검증 호출)를 쓰지 않는다. 함수 삭제.
3. 위반이 있을 때만 재작성 1회 (`staged_chat("repair")`). 재작성도 실패하면 위반 문장만 제거하고 나머지를 보여준다. 전체 실패 메시지는 남은 문장이 없을 때만.
4. 재작성 프롬프트에서 "참조 밖 아라비아 숫자를 쓰지 말라"는 문구 삭제 (어색한 한글 숫자의 원인).

추가:
- **스트리밍**: 1단계 초안을 생성 중에 바로 표시하지 않는다(검증 전 숫자 노출 위험). 대신 진행 상태("화면 자료 확인 중 → 답변 작성 중")를 SSE로 보낸다. 2차로, 참조 치환을 토큰 단위로 처리하는 스트리밍을 검토한다.
- `_unasked_causes`/`_drop_causes`(가설 문장 자동 삭제) 제거. 대신 시스템 프롬프트에서 "가설은 '가설'로 표시"만 요구.
- `_wrong_agreement`, `_buy_lecture` 정규식 의미검사는 유지하되, 위반 시 재작성 호출 대신 해당 문단만 제거하는 방식 검토.

### 5.3 해석 품질 (P5)

시스템 프롬프트(`dialogue._SYSTEM`) 보완. 고정 템플릿은 만들지 않는다.
- 사용자가 간단히 물으면 간단히. 해석·요약·비교를 요청하면: **주요 특징 → 해석상 주의점 → (필요 시) 추가 비교 제안** 순으로.
- 숫자를 표처럼 나열하지 말고 범위·최고·최저·변화 방향으로 요약.
- `is_partial_period`, `is_small_sample`, 넓은 신뢰구간이 있으면 반드시 언급.
- 평균과 중앙값이 크게 다르면 분포 치우침을 언급.

참조 삽입 문체 개선 (`_render.insert`):
- 현재 "2021 단가 평균 2.7만원/㎡" 처럼 라벨 전체가 반복 삽입됨. 모델이 문장에 이미 라벨을 썼으면 **값+단위만** 삽입하는 옵션 `{{current.f3|value}}` 추가.

기준 예시 (영춘면 계관×전, 추이 질문에 대한 기대 답):
> 2021~2026년 평균 단가는 2.6~3.2만원/㎡ 범위에서 움직였어요. 가장 높은 해는 2026년(3.2만원/㎡), 가장 낮은 해는 2024년(2.6만원/㎡)입니다. 다만 2026년은 10월까지 18건, 2024년은 15건뿐이라 연도별 평균 차이를 가격 상승·하락으로 바로 해석하기는 어렵습니다. 거래건수와 중앙값을 함께 보는 게 좋습니다.

### 5.4 서버 계산 참조 (§4 구현)

- `{{calc:<식>}}` 지원. 식에는 화면 참조(`current.fN`)와 사용자 질문에 나온 숫자, `+ - * /`, 괄호만 허용. `ast` 로 파싱해 안전하게 계산 (eval 금지).
- 결과는 원 단위면 천 단위 구분, 억·만 단위 변환 함수 제공.
- 계산 결과가 포함된 문장에는 §4 주의 문구가 없으면 서버가 붙인다.

### 5.5 [출시 전 필수] 보안·비용 (P7, P8, P9)

- `/api/lab/` 를 `product_gate._ALWAYS_OPEN_PREFIXES` 에서 제거하고 관리자(`role == "admin"`) 전용으로. `/api/lab/ai2/*` 는 운영에서 라우터 자체를 등록하지 않는 설정(`AI2_LAB_ENABLED=false` 기본) 추가.
- `/api/admin/*` 전체를 관리자 세션 필수로 통일. `QA_AUDIT_TOKEN` 미설정 시 **거부**(현재는 통과).
- `/api/admin/land-twin` 인증 추가.
- `rate_limit._client_key`: 로그인 사용자는 `user.id`, 비로그인은 nginx가 넣는 `X-Real-IP`(신뢰 프록시일 때만) 사용. XFF 첫 값 사용 중지.
- 세션·요청제한 저장소: 현 단일 워커 유지 시 문서에 명시. 워커 증설 전 Redis 또는 플랫폼 DB로 이전 (이번 작업에서는 인터페이스만 분리).

### 5.6 사용량 측정 → 정책 재검토 (P10)

이번 작업에서 **제공 횟수는 바꾸지 않는다.** 먼저 측정한다.
1. 질문 단위 로그 추가 (질문 문장은 저장하지 않음): `request_id`, 앱, 패널, LLM 호출 수, 입력·출력 토큰, 추정 원가, 소요 시간, 검증 결과(통과/재작성/부분제거/실패).
2. 관리자 AI 사용량 화면에 질문당 평균 호출 수·원가·p50/p90 지연 표시.
3. 서비스 전체 한도(`AI_MONTHLY_CALL_LIMIT`, `AI_MONTHLY_BUDGET_KRW`)를 운영 `.env` 에서 확인하고, 개인 한도 합계와 모순되면 운영자에게 경고 로그. 전체 한도 단위를 "LLM 호출"에서 "원가(원)"로 일원화하는 안 제시.
4. `usage_log.month_snapshot` 이 호출마다 월 JSONL 전체를 읽음 → 월별 누계 캐시로 교체.

- 핵심 문장 (문서 맨 위):
  > CH2 Macro AI는 사용자가 선택한 통계 데이터와 분석 조건을 이해하고, 결과를 설명하며, 추가 분석을 제안하는 연구 보조자다. CH2 화면 수치는 정확하게 인용하고, 일반 통계·부동산 지식은 자유롭게 활용한다. 확인된 사실과 가설을 구분하며, 질문을 불필요하게 거절하지 않는다. 개별 부동산의 가격을 확정하거나 투자 판단을 대신하지 않지만, 산술 계산·통계적 비교·분석 방법 설명은 제공한다. 불필요한 면책문구나 반복 검증으로 사용자 경험을 해치지 않는다.
- `constitution._REFUSAL_PATTERNS`, `is_refusal_message` 등 현 경로에서 쓰지 않는 거절 로직에 `# legacy: not used by dialogue.answer_land` 주석. 삭제는 5.8에서.
