# CH2 AI 어시스턴트 대화 개선 계획

2026-11-04 · 1차 구현 계획

## 목표와 범위

사용자가 CH2 Macro의 기능과 통계를 편하게 질문하면, 기존 AI 어시스턴트가 질문의 핵심을 파악하고 필요한 근거로 짧고 정확하게 답한다. 같은 대화 안에서 사용법, 일반 통계 개념, 현재 결과 해석, 이전 분석과의 비교를 자연스럽게 이어간다. 질문 하나에 여러 의도가 있으면 필요한 내용을 함께 다룬다.

1차 구현은 기존 `/api/ai`의 답변 생성과 데이터 전달을 대상으로 한다. 토지 회귀 화면을 중심으로 구현하고, 산점도·장기추세는 각각의 화면 자료를 대상으로 연결과 자료 누락 처리를 검증한다. 복합·집합 등은 공통 구조의 다음 적용 대상으로 둔다. AI 2·AI 3는 실험 종료 상태로 두며, 기존 모델과 사용량 제한을 유지한다. 화면 레이아웃과 통계 계산 엔진의 변경은 후속 범위다.

기존 근거·실행 정책은 [CH2 AI 헌법](CH2_AI_CONSTITUTION.md), 이력과 경로 정책은 [AI 어시스턴트 확장 계획](CH2_AI_ASSISTANT_EXPANSION_PLAN.md)을 따른다. 현행 헌법의 제품 안내용 코드 응답 정책과 모델이 문장을 작성하는 이번 제안의 차이, 별도 동의형 외부조사와 이번 주제 제한의 관계는 구현 전 문서에 명시한다. 이번 대화의 허용 주제는 CH2 Macro와 일반 통계이며, 적정가·투자 판단·가격 전망에 대한 제한을 유지한다.

## 답변의 기본 흐름

1. **질문에서 답할 내용을 정한다.** 현재 질문과 직전 대화를 보고 사용자가 어떤 대상과 지표를 가리키는지 파악한다. 제품 안내·통계 해석·비교를 서로 배타적인 분기로 만들지 않는다. “면적 계수가 뭘 뜻하고, 산점도는 어디서 봐?”라면 두 가지에 각각 답한다. 대상이 모호하고 선택에 따라 답이 달라지는 경우에만 짧게 되묻는다.
2. **대상에 맞는 자료를 선택한다.** 제품 질문에는 전체 앱의 제품 지식에서 관련 기능과 사용 조건을 찾는다. 현재 화면 해석에는 해당 패널의 결과를 쓰고, 후속 질문에는 앞선 답변이 참조한 분석을 찾는다. 사용자가 비교를 요청한 경우에는 각 결과를 별도 대상으로 유지한다.
3. **핵심부터 자연스럽게 답한다.** 버튼 위치에는 실제 클릭 순서, 계수 질문에는 변수와 계수의 의미를 먼저 말한다. 해석을 바꾸는 표본·모형 조건은 그 답과 함께 설명한다. 표, 관련 질문, 추가 분석 제안은 질문에 도움이 될 때 사용한다. 기존 응답의 근거·신뢰도는 보존하되 모델 본문에 고정 제목이나 근거 개수를 요구하지 않는다.
4. **검증을 통과한 답변을 전달한다.** 출처가 틀리거나 화면 수치가 섞이면 해당 주장을 제거하거나 확인된 자료로 짧게 다시 구성한다. 자료 부족, 모델 오류, 한도 도달 시에는 확인 가능한 정보만 전달하고, 필요한 자료가 있으면 그 항목과 확인 위치를 알려준다. 관련 없는 회귀 종합 요약을 공통 대체 답변으로 사용하지 않는다.

## 세 가지 정보의 관리

### 제품 지식

기존 Product Knowledge·Playbook을 활용해 앱, 화면, 기능, 메뉴명, 용어, 계산 방식, 사용 조건을 찾을 수 있게 한다. 현재 앱은 검색에 참고하되, 질문에 다른 앱이나 기능이 명시되면 그 대상을 먼저 조회한다. 앱별 기능과 메뉴는 제품 문서·실제 화면 구현을 확인해 출처를 붙이고, 확인이 어려운 경로나 계산 방식은 확인 가능한 범위까지만 설명한다. 일반 통계 개념은 모델 지식을 활용하고, CH2의 구현이나 화면 결과에 관한 주장은 제품 자료나 해당 분석에 연결한다.

### 현재 화면의 분석 데이터

기존 `ActiveAiView → AiContext → Bundle` 경로를 살려 화면 결과를 전달한다. 화면에서 이미 받은 분석 응답을 바탕으로 서버가 지표별 근거를 구성한다. 근거에는 분석 결과 참조, 패널, 지역·기간·필터, 지표 ID, 값, 단위와 필요한 모형 정보를 담는다. 토지 회귀에서는 종속변수와 독립변수의 변환, 변수 단위, 더미 기준 범주, 표본 수, 계수와 진단값을 우선 확인한다. 기존 화면 스냅샷과 서버에서 출처를 확인할 수 있는 결과의 신뢰 수준도 구분한다.

숫자 토큰의 일치만으로 답변을 승인하는 현재 검증을 보완한다. 화면 수치와 정량 비교는 선택한 결과의 지표 참조를 통해 표시하고, 서버에서 지표·단위·대상·기간의 연결을 확인한다. 상승·하락이나 이상치 같은 정성적 관찰도 해당 차트의 점 또는 확인된 요약 근거에 연결한다. 모형 내 관계, 실제 거래 분포, 인과 해석을 구분한다. 필요한 역변환 수치가 검증된 형태로 제공되지 않으면 계산식과 적용 조건을 설명하고, 화면에서 확인된 값만 인용한다.

### 대화와 분석 이력

이전 대화는 “그럼 면적은?”의 대상과 변수명을 해석하는 데 활용한다. 이전 답변에 나온 숫자는 참조가 가리키는 분석 이력에서 다시 확인한다. 각 응답이 참조한 결과와 변수를 세션에 연결해 화면이 바뀐 뒤에도 후속 질문을 이어갈 수 있게 한다.

화면이 A에서 B로 바뀌면 “이 표”는 B를 가리킨다. “아까 모형의 면적 계수는?”은 A를 참조하며 답변에 A의 범위를 표시한다. 비교에서는 A·B의 근거를 각각 명시한다. 어떤 결과인지 불분명하거나 이전 결과가 만료됐으면 확인 가능한 범위에서 답하거나 필요한 대상을 묻는다. 최종 검증에 세션 전체 수치를 합쳐 넣는 방식은 이 경로에서 제거한다.

## 구현 순서

1. **변경 전 기준을 기록한다.** 대표 토지 회귀·산점도·장기추세 스냅샷과 질문 세트를 준비한다. 현재 답변과 참조한 화면, 모델·설정, 대체 응답 여부를 기록한다. 정상·누락·화면 전환·이전 분석 비교 사례를 포함한다.
2. **질문 해석과 근거 선택을 함께 적용한다.** 기존 `orchestrator.py`의 고정 답변 선행 분기와 `llm.py`의 출력 형식 요구를 점검한다. 제품 지식 검색, 화면 근거 선택, 이력 참조를 분리하고, 질문에 필요한 자료를 조합하는 공통 경로를 추가한다. 범위 제한과 실행 승인, 사용량 제한은 서버에서 일관되게 적용한다.
3. **토지 화면에 근거 검증을 연결한다.** 기존 응답 스키마와 화면 동작을 유지하면서 회귀 결과에 적용한다. 산점도·추세는 기존 자료가 전달되는 범위를 확인하고, 자료가 있는 경우의 해석과 누락된 경우의 응답을 각각 검증한다. 복합·집합은 화면별 근거 추출만 추가해 동일한 대화·검증 경로를 사용할 수 있게 한다.
4. **동일 조건에서 전후 답변을 비교한다.** 우선 기존 모델을 사용해 데이터 전달과 답변 구조의 효과를 분리한다. 자동 테스트는 참조와 검증 규칙을 확인하고, 실제 모델 비교에서는 대화 품질을 별도로 평가한다. 모델 자체의 자연스러움·속도·비용 비교는 구조 개선 이후 필요한 경우 진행한다.

주요 점검 지점은 [질문 처리와 최종 검증](../backend/app/ai/orchestrator.py), [응답 합성과 프롬프트](../backend/app/ai/llm.py), [제품 지식](../backend/app/ai/knowledge/product.py), [화면 컨텍스트](../shared/ai-assistant/ActiveAiView.tsx), [세션과 이력](../backend/app/ai/sessions.py)이다.

## 검증과 완료 기준

- **질문 적합성과 간결성.** “조정 R² 0.528의 의미”, “각 변수와 계수”, “설명력이 제한적인 이유”, “방금 설명 중 핵심”, “다른 지역과 비교하는 방법”을 묻는다. 답변 첫 문장에서 요청한 항목을 다루고, 설명력 질문에서는 자료가 보여 주는 진단과 가능한 원인을 구분한다. 조정 R²는 변수 수와 자유도를 고려한 지표로 설명한다.
- **근거 정확성.** 표본 수와 MAPE를 교환하거나, 단위를 바꾸거나, 다른 지역의 과거 수치를 현재 답변에 넣는 경우를 테스트한다. 세 경우 모두 잘못된 주장이 표시되면 실패다. 자료가 있는 산점도·장기추세에서는 관찰된 관계나 방향을 설명하고, 자료가 없으면 확인 위치를 안내한다.
- **연속성과 통계적 판단.** 한 대화에서 “면적 계수는 무슨 뜻이야?”, “면적이 커지면 땅값이 떨어진다는 거야?”, “실제 거래에서는 큰 토지가 더 비싸지 않아?”, “그럼 규모의 경제가 있는 거네?”를 순서대로 묻는다. 모형과 변수는 일관되게 유지하면서 단가와 총액, 조건부 관계와 실제 관측, 통계적 연관과 인과적 결론의 차이를 질문에 맞춰 설명한다. 같은 의미를 여러 표현으로 물었을 때 답변은 자연스럽게 달라지고 해석은 일관되어야 한다.
- **화면 전환과 제품 지식.** 지역 A 분석 뒤 지역 B로 화면을 바꾸고 “이 표”, “아까 모형”, “둘을 비교”를 각각 묻는다. 이어 토지 화면에서 집합·임대 기능의 위치를 묻고, 현재 제품의 실제 메뉴와 조건을 안내하는지 확인한다. 일반 통계 질문에는 직접 답하고, 무관한 질문에는 짧게 거절한다.
- **대화 품질.** 변경 전후를 질문 적합성, 수치·출처 정확성, 통계적 타당성, 대화 연속성, 자연스러움, 분량과 반복으로 평가한다. 실제 답변 예시와 실패 사례를 함께 남긴다. 잘못된 화면·이력 인용과 사용자의 부정확한 결론에 대한 무조건적인 동의는 문체 평가와 별개로 실패 처리한다.

1차 완료 보고에는 전후 답변 비교, 자동 테스트 결과, 검증에 사용한 모델과 설정, 누락된 화면 데이터, 다른 분석 화면 적용에 필요한 작업을 포함한다.


## 네거티브 대화 원칙 보완 (2026-11-04)

최신 사용자 지시가 위 초기 범위 설명보다 우선한다. CH2와 통계 외에도 관련 부동산 시장·데이터 분석·경제 개념을 허용한다. 개별 적정가 결정·매매 권유, 무관한 주제, 근거 없는 사실 생성을 제한한다.

이번 수정은 자기소개·가격 질문의 코드 고정 응답, 통계 정의 템플릿 폴백, 실패 시 임의 지표 나열을 제거한다. 현재/이전 자료를 키워드로 숨기지 않고 모델에 별도로 제공한다. 일반 지식의 숫자·수식은 화면 자료가 있다는 이유로 차단하지 않는다. 실제 화면 수치 참조와 재작성 검증은 유지한다.

미완료 범위: 전체 제품 지식의 검색 도구화, 다수 분석 스냅샷 보관, 모든 토지 패널의 데이터 누락 조사, 개발용 사용량 분리. 현재는 제품 지식 묶음과 직전 참조 분석 하나를 제공한다. 모든 창에서 공통 대화 경로를 쓰는 것과 모든 창의 데이터가 완전히 연결된 것은 구분한다. 비용 정책은 이번 변경으로 완화하지 않는다.


### 후속 답변 검증 수정

실제 모델 재현에서 일반 대수식의 상수와 탄력성 설명의 단위변화까지 화면 숫자로 차단했고, 문장별 복구는 핵심 부정·조건을 누락시켰다. 문장별 복구를 제거하고 실패 원인을 전달해 전체 답변을 재작성한다. 실제 숫자는 해당 문장에서 인용한 지표값과 대조한다. 대수 항등 상수와 참조를 동반한 1% 단위변화는 구분한다. 새 계산 결과와 다른 문장에서 빌린 수치는 허용하지 않는다. 짧은 질문에는 두세 문장을 기본으로 하되 상세 요청의 분량은 제한하지 않는다.

수치 일치는 의미적 정확성을 보장하지 않는다. 동일 수치를 잘못된 지표·방향에 연결하는 의미 오류, 경제·통계 설명의 정확성은 실제 모델 평가를 계속해야 한다. 자동 테스트는 이러한 의미 검증을 대체하지 않는다.


### 로컬 API 다중 턴 재검증

`gpt-5-mini`와 가상 지역 A/B의 계수 -0.24/0.35를 사용해 `/api/ai/chat`을 순차 호출했다. 면적 계수, 이전 분석의 경제적 의미, 현재 화면 계수, 유의수준, 주식 예측 요청의 다섯 질문은 모두 응답했다. 이전 질문은 previous, 현재 화면 질문은 current 참조를 사용했고 범위 밖 주식 예측은 거절했다. 소요 시간은 각각 27.9/20.8/21.1/15.4/7.9초였다. UI 직접 조작 검증은 아니며, 자동 테스트 76개 통과와 구분한다.

후속 답변이 단가 하락과 생산비용 감소를 혼동할 소지가 있어, 개념의 정의에 필요한 변수와 실제 관측변수를 대조하고 가격·비용·수익을 대체하지 않도록 공통 원칙을 보완했다. 질문·출력 키워드로 의미를 판정하던 p값/총액 차단은 제거했다. 정확성은 실제 응답 평가로 확인하며, 한 번의 성공을 모든 질문에 대한 정확성 보장으로 취급하지 않는다.


### 실제 토지 회귀 화면의 적정성 질문 실패 수정

사용자 화면(흥덕구, 자녹 × 임)에서 동일 질문을 직접 재현했다. 최초 답변과 재작성 답변 모두 도로조건 범주명 `12미만`, `25이상`의 숫자 12/25를 관측값으로 오인해 검증에서 차단된 것을 로그로 확인했다. 범주 식별자와 측정값을 구분하도록 데이터 전달과 검증을 수정한다. 범주명은 실제 계수·기준범주에서 추출하며 질문별 허용 목록을 추가하지 않는다. 알려지지 않은 범주명은 허용하지 않는다.

정상 반올림은 인용한 근거값에 대해 소수 둘째 자리 이상의 정밀도로 검증한다. 모형의 계수 수·설계행렬 rank·잔차 자유도·지표 제공 여부도 분석 결과에서 전달한다. 사용자에게 내부 JSON 경로를 안내하지 않도록 공통 문체 원칙을 보완했다. 자동 테스트 87개 통과.
