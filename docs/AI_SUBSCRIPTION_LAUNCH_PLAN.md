# CH2 Macro · Fieldnote AI 출시 이용량 정책 및 구현 계획

작성일: 2026-11-07  
상태: 사용자 승인 정책 확정 및 로컬 구현 진행. 운영 활성화·상품 공지는 별도.  
범위: 계정별 AI 제공량, 차감·정산, 원가 기록, 이용량 안내 및 단계적 전환.

## 1. 목표와 원칙

Macro는 통계분석 도구이고 AI는 분석과 해석을 돕는 보조 기능이다. 집중 분석 중 여러 질문을 이어갈 수 있도록 제공량을 넉넉하게 설정한다. 비용은 질문 주제·답변 형식을 좁히는 대신 입력량, 불필요한 호출, 재시도와 동시 실행을 관리해 통제한다.

- Macro의 네거티브 제한과 자유로운 답변 형식은 유지한다. 실제 관측값의 근거 검증을 비용 절감 목적으로 제거하지 않는다.
- 사용자 이용량과 공급자 모델 호출·비용을 별도 집계한다. 한 질문의 내부 검증·재작성은 추가 질문으로 차감하지 않는다.
- 사용자가 공지된 제공량 안에서 정상 이용 중일 때, 숨겨진 개인 원가 상한으로 제한하지 않는다.
- 사진 촬영·보관·기존 결과 열람은 AI 분석 이용량과 분리한다. 사진 보관의 용량·동기화 정책 자체는 이번 계획에서 무제한으로 변경하지 않는다.
- 가격·통계 엔진·기존 제품 접근 권한·결제 처리 방식은 이번 AI 한도 작업의 대상으로 변경하지 않는다. 기존 구독 정보를 읽어 AI 정책을 적용한다.
- 사용자 권한은 서버가 검증한다. 기기 ID·클라이언트가 지정한 기능명·단위 수·요금제는 권한과 차감의 근거로 신뢰하지 않는다.

## 4. 사용자 이용량 차감 규칙

### 4.1 Macro 질문

- 정상 답변이 서버에 영속 저장되어 사용자가 조회할 수 있게 완료되면 1회 차감한다.
- 한 질문에 포함되는 생성·검증·재작성·자동 재시도는 모두 같은 요청 ID에 묶고 사용자에게 추가 차감하지 않는다.
- 사전 권한·주제·입력 검사 거절, 공급자 오류, 최종 답변 검증 실패 및 결과 저장 실패는 차감하지 않거나 예약을 반환한다. 이미 발생한 공급자 비용은 내부 원가로 남긴다.
- 대화 기록 재열람·내보내기·사용량 조회는 차감하지 않는다. 새 답변 생성 요청은 별도 질문이다.
- 결과를 정상 완료한 뒤 사용자가 다시 질문하거나 의도적으로 재생성을 요청하면 새 요청으로 계산한다. 네트워크 중복 전송은 같은 멱등 키로 처리한다.

### 4.2 사진 AI 분석

- 호출 횟수가 아니라 새 분석에 포함된 사진 장수를 기준으로 한다. 예: 사진 3장을 묶어 한 답변을 정상 완료하면 3장 차감한다.
- 하나의 요청에 동일 사진이 중복 첨부되면 서버가 정규화해 중복 제거한다. 첨부 수는 서버 검증 결과로 산정한다.
- 같은 사진의 저장된 분석 결과를 열람·저장·재사용하면 차감하지 않는다.
- 사용자가 새 조건 또는 새 분석을 명시적으로 요청해 모델을 다시 호출하면 재분석 장수로 계산한다. 실행 전에 차감 장수를 알린다.
- 실패·자동 재시도·동일 작업의 중복 전송에는 추가 차감하지 않는다.
- 일괄 작업의 일부만 성공하는 경우 성공 결과와 사진의 대응을 확인할 수 있을 때만 성공 장수를 정산한다. 하나의 묶음 답변이면 묶음 전체의 성공·실패로 처리하고 임의로 부분 차감하지 않는다.
- 사진 분석에 포함된 요약 문장을 별도 문구 작성 1회로 다시 차감하지 않는다.

### 4.3 문구 작성·주소표 보정

- 별도 요청으로 정상 완료한 작업 1건을 1회로 계산하는 것을 기본안으로 한다.
- 실제 앱의 short/long/sheet와 고객 기능의 관계를 먼저 확인한다. 현재 장문 사진 분석을 독립된 문구 작성으로 단정하거나 `long` 한도를 그대로 새 기능 한도로 치환하지 않는다.
- 1회당 사진·페이지·주소 행 수·입력 문자·출력 크기와 파일 크기 상한을 정한다. 무제한 크기의 문서를 한 번으로 처리하는 상품을 만들지 않는다.
- 고객 기능과 실제 모델 호출의 대응표 및 화면별 차감 예시를 작성한다. 하나의 사용자 작업에 내부 단계가 여러 개여도 공지하지 않은 중복 차감을 하지 않는다.
- 실행 전 필요한 단위를 표시하고, 상한을 넘으면 분할 범위를 안내한다. 임의 분할·자동 실행으로 이용량을 소모하지 않는다.

### 4.4 취소·중복·동시 실행

- 실행 전 취소는 예약 반환. 모델 실행 중 취소는 공급자 비용 발생 여부와 사용자 제공 완료 여부를 분리 기록한다.
- 서버가 취소를 확인하고 결과를 제공하지 않으면 사용자 차감을 반환한다. 취소와 완료가 경합해 결과가 이미 정상 저장·제공됐다면 1회 정산하고 그 결과를 재조회할 수 있게 한다.
- 브라우저 연결 종료 자체를 공급자 취소나 무조건 환불로 해석하지 않는다. 최종 작업 상태가 기준이다.
- 사용자·기능·기간별 예약과 정산은 DB 트랜잭션으로 처리한다. 마지막 1회를 두 기기에서 동시에 예약해 초과하지 않도록 한다.
- 계정별 모델 작업 동시 실행은 초기 기본 1건으로 설계한다. 초과 요청은 `busy`와 재시도 안내를 반환하고 차감하지 않는다. 하루 10회 같은 별도 일일 한도는 두지 않는다.

## 5. 계정·기간·요금제

- 두 서비스는 같은 플랫폼 계정의 중앙 장부를 사용하되 `macro_question`, `photo_analysis_image`, `text_writing`, `address_sheet_job` 잔여량은 각각 표시한다. 서로 자동 환산하거나 빌려 쓰지 않는다.
- 유료 제공량은 로그인 계정의 검증된 구독으로 부여한다. 기기를 바꿔도 동일 잔여량을 사용한다. 기존 비로그인·기기 기반 이용자는 별도 호환 정책을 확인하고 조용히 차단하거나 유료 권한을 새로 부여하지 않는다.
- 월 구독은 결제 시스템이 확정한 이용 기간 `[start, end)`에 맞춘다. 기간 ID를 영속 저장하고 중복 결제 통지·재시작으로 재충전하지 않는다.
- 현재 웹 구독은 `period_end_monthly()`에서 31일을 더한다. AI 작업에서 이를 달력 한 달로 바꾸지 않는다. 검증된 실제 기간을 읽어 사용하고 UI에는 정확한 다음 초기화 날짜를 표시한다. 기간 시작·앵커 정보가 부족하면 해당 저장 구조를 보완하는 설계를 먼저 확정한다.
- 연간 상품은 12배를 한 번에 지급하지 않는 월별 제공을 기본 설계로 한다. 기존 연간 약정·스토어 기간과 일치하는 하위 이용 기간을 정의한 후 활성화한다.
- 만료·해지 예약·갱신 실패 시 기존 구독 유효기간을 따른다. 해지 예약만으로 남은 기간을 박탈하지 않는다.
- 기본안: 이월 없음. 해당 조건은 출시 안내에 명시하고 기존 약정에 불리하게 소급 적용하지 않는다.
- 기간 중 상향 시 기존 사용량을 유지하고 상향된 한도와의 차이만 제공한다. 하향은 다음 갱신부터 적용하는 것을 기본안으로 하되 기존 상품 전환 규칙과 대조한다. 한도 갱신만을 위해 결제 금액·일할 계산·청구 날짜를 변경하지 않는다.
- 관리자·개발자 테스트는 별도 원가 구분을 사용한다. 관리자 권한이 익명·일반 사용자에게 전파되지 않도록 한다.

## 6. 현행 구현과 필요한 변경

### 6.1 현재 확인된 구조

- Macro: `backend/app/ai/usage_log.py`의 서버 전체 월 모델 호출 200회 또는 추정 10,000원 제한. 사용자별 질문 제공량이 아니다.
- Macro: `llm.py`의 완료된 공급자 호출 기록과 `dialogue.py`의 최대 4회 생성·검증·수정 경로가 존재한다. 호출 단계·부모 요청 ID가 부족하다.
- Fieldnote: `backend/app/platform/fieldnote_ai_router.py`는 기기별 short/long/sheet 요청을 사전 차감한다. 사진 장수와 다르며 실패 복원과 공통 원가 기록이 없다.
- Fieldnote 프록시는 성공 응답의 토큰 정보를 공통 비용 장부에 연결하지 않고 반환한다. 클라이언트 `max_tokens` 등의 상한은 서버에서 검증해야 한다.
- 사용량 안내에는 실험용 월 200회·1만원 문구가 고정되어 있다.
- 플랫폼에 구독·권한 구조가 존재하지만 제품 권한의 true/false만으로 AI 요금제·이용 기간 전체를 판단할 수는 없다.

상세: [사용량 정책 리뷰](reports/AI_USAGE_POLICY_REVIEW_20261107.md).

### 6.2 권장 데이터 구조 — 구현 시 스키마 확정

기존 플랫폼 DB에 추가하는 논리 구조다. 이름은 구현 시 확정하며 아래는 제안이다.

- `ai_policy_versions`: 요금제·기능별 한도, 차감 단위, 요청 상한, 적용 버전·시작일. 아직 확정되지 않은 항목은 비활성으로 둔다.
- `ai_allowance_periods`: 계정, 구독 참조, 기간 시작·종료, 정책 버전, 기능별 한도·정산 사용량·예약량. 기능·계정·기간의 유일성을 보장한다.
- `ai_requests`: 계정, 앱·고객 기능, 기간, 멱등 키, 요청 단위 수, 상태, 생성·완료 시각, 결과 참조, 오류 유형, 취소 상태. 사용자·기능 범위의 멱등 키와 입력 지문을 검증한다.
- `ai_provider_calls`: 부모 요청, 생성/검증/재작성 등의 단계, 실제 모델, 공급자 요청 ID, 입력·캐시·출력·가능한 추론 토큰, 단가 버전·환율, 추정 비용, 완료·오류·미확정 상태.
- `ai_usage_adjustments`: 장애 복원·운영 보정의 이유, 담당자, 대상 요청·단위 및 중복 보정 방지 키.

사용자 한도는 JSONL 파일이 아닌 영속 DB를 기준으로 한다. 기존 JSONL은 부가 감사 자료로 보존하며, 과거 기록에 없는 사용자·기능·성공 여부를 추측해 신규 잔여량에서 소급 차감하지 않는다.

사진 원본·주소·질문·답변 본문·인증 정보는 비용 장부에 복제하지 않는다. 결과 보관은 기존 권한을 따르는 별도 참조로 연결한다. 사진 재사용 판정은 계정 경계 안에서 수행한다.

### 6.3 처리 흐름

1. 계정·구독·서버 기능 매핑·입력 범위 검사.
2. 멱등 키 조회. 동일 키의 입력이 다르면 충돌 오류. 완료됐으면 기존 결과 반환.
3. 유효 기간·정책 버전을 고정하고 원자적으로 잔여량 예약, 계정 동시 실행 검사.
4. 요청 ID를 전파하며 공급자 호출. 필요한 내부 검증·수정은 같은 요청에 연결.
5. 공급자별 실제 토큰·비용을 기록. 결과 검증·영속 저장 성공 후 사용자 단위 정산.
6. 실패 시 예약 반환, 원가와 실패 상태 기록. 트랜잭션과 외부 호출 사이의 미확정 상태는 복구 작업으로 대조.
7. 만료된 예약을 단순 삭제하지 않는다. 작업 생존·공급자 완료·저장 결과를 확인해 정산 또는 반환하고 중복 실행을 방지한다.

외부 API 호출 동안 DB 행 잠금을 오래 유지하지 않는다. 예약·호출·정산을 분리하고 정산 전후 장애를 복구할 수 있게 한다. 기간 경계 중 완료한 요청은 예약한 기간에 정산한다.

## 7. 원가와 운영 안전장치

- 알려진 모델의 입력·캐시 입력·출력 단가와 버전을 기록한다. 알 수 없는 모델을 조용히 mini 가격으로 계산하지 않고 `cost_unknown`과 관리자 경고로 분리한다.
- 출력·입력·사진 수·사진 크기·문서 크기·내부 호출 횟수에는 서버 측 상한을 둔다. 수치는 실측과 기능 검증 후 정책 파일에서 관리한다.
- 일반 질문은 1회 호출을 목표로 하되 필요한 검증은 유지한다. 전체 원자료·전체 대화의 무조건 반복 전송을 줄인다.
- 서버 전체 비용·공급자 호출 안전장치는 계정 제공량과 별개로 운영한다. 현행 전체 월 200회 실험 상한을 출시 기준으로 그대로 사용하지 않는다.
- 예상 활성 사용자·제공량·단가 및 비상 여유를 근거로 운영 예산을 산정한다. 고객 80% 안내와 내부 원가 80% 경고를 혼동하지 않는다.
- 일반 운영은 비용 경고·확장으로 처리한다. 비정상 호출·공급자 장애에 대한 전체 비상 중지 기능은 유지하되, 개인 제공량 소진으로 위장하지 않고 서비스 장애와 복구 상황을 안내한다.
- 원가 기록 실패는 영속 재처리 대상으로 남긴다. 사용량 예약이 불가능한 요청을 무제한 실행하지 않는다. 최종 결과와 정산 상태가 어긋나지 않게 복구한다.
- 공급자 비용 CSV와 주기적으로 대조한다. 집계 지연·반올림·다른 환경 테스트·미확정 호출은 별도 설명한다.

## 8. 사용자·관리자 화면

### 사용자

- 예: `이번 이용 기간 AI 질문 127 / 200회 · 73회 남음 · 다음 초기화 12월 7일`.
- 동시 구독은 Macro 질문·사진 장수·문구 작성·주소표를 기능별로 표시한다. 운영 활성화 전에 변경된 혜택을 기존 사용자에게 적용됐다고 표시하지 않는다.
- 80% 도달 시 기간·기능별 한 번 안내한다. 100%에서는 해당 기능의 새 작업만 제한한다. 다른 기능의 남은 제공량은 유지한다.
- 이미 예약·수락한 작업은 완료한다. 통계분석·기존 결과·물음표 설명·사진 촬영·보관은 AI 잔여량 소진만으로 차단하지 않는다.
- 한도 초과 시 남은 양·다음 초기화 날짜·상향 문의 경로를 안내한다. 초기에는 자동 추가 과금하지 않는다.
- Macro의 공통 AI 패널과 Insight에서 같은 값을 사용한다. 기존 모바일 제공 앱 범위는 유지한다. 집합 주거·비주거는 동일 UX를 적용한다.

### 관리자

- 사용자 정상 완료 작업 수, 사진 장수, 실제 모델 호출 수, 단계별 비용을 구분한다.
- 전체·계정·요금제·앱·기능·모델·정책 버전별 집계, 실패·복원·미확정·재시도·원가 대조 차이를 제공한다.
- 일반 사용자는 본인 이용량만 조회한다. 관리자 장부·보정 API는 서버의 관리자 권한과 기존 외부 인증 경계를 함께 검증한다.
