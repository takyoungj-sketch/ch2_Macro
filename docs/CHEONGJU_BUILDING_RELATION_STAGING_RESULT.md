# 청주 건물–필지 정규화·이력 갱신 시험

2026-10-04. 로컬 SQLite 표본 실험 완료. 운영 PostgreSQL·제품 보강 코드·확정 연결은 변경하지 않았다. 재현: `python pipeline/parcel_master/pilot_cheongju_building_relation_staging.py`. 집계: `docs/lab/cheongju_building_relation_staging.json`.

## 실험 구조

기존 고정 건축대장 추출과 감사된 토지특성 캐시를 사용했다. 구별 최초 관측 주소를 기준으로 관리 PK 1,000개씩 총 4,000개를 선택했다. 인접 판본에서 발견한 PNU 변경 관리 PK는 모두 포함하고 나머지는 PK 해시 순서로 선택했다. 변경 사례를 의도적으로 포함했으므로 표본의 변경률을 도시 전체 비율로 해석하지 않는다.

로컬 DB `data/research/cheongju_ledger/building_relation_staging.sqlite`의 계층:

- `source_snapshot`: 건축·토지 고정 입력 해시, 표본 해시, 원천 범위, 토지 기준일·연도, 정규화 규칙과 내용 해시.
- `building_entity`, `parcel_identity`: 관리 PK와 주소 필지 PNU의 독립 식별 집합.
- `building_version`, `parcel_version`: 건물 속성과 토지특성의 내용 버전. 같은 내용은 재사용한다.
- `building_observation`, `parcel_observation`: 판본별 속성 버전 관측. 관측을 추가하고 과거 버전을 덮지 않는다.
- `assessed_price_observation`: 공시지가 원값, 기준연도, 원문 연도, 양수/미상/오버플로 상태. 토지특성 버전과 분리한다.
- `address_relation_observation`: 판본별 관리 PK↔PNU의 대표 주소 관계와 해당 토지 판본 존재 여부. 전체 부지나 거래 대상 관계를 뜻하지 않는다.
- `current_building`: 마지막으로 관측한 건물 상태의 파생 포인터. 최신 원천에서 빠진 경우 마지막 관측 판본이 남아 있어 stale을 구분할 수 있다.

건물 PNU만 바뀌면 주소 관계가 변한 것으로 기록한다. 면적·용도 등 건물 속성 변화와 구분한다. 같은 판본 이름에 내용이 달라지면 거절하고, 복구 이후에도 새로운 과거 판본을 조용히 끼워 넣지 않는다. 원본 효력일이 없어 관측 사이의 법적 변경일을 추정하지 않았다.

## 실제 적재 결과

- 2024-09: 표본 관측 3,850건. 토지자료가 있는 주소 관계 3,527건, 없는 관계 323건.
- 2025-07: 관측 3,933건. 처음 관측된 PK 107개, 건물 속성 변경 59개, 주소 PNU 변경 170개. 과거 관측 PK 중 이번에 없는 24개는 삭제하지 않았다.
- 2026-07: 관측 3,913건. 처음 관측된 PK 43개, 건물 속성 변경 60개, 주소 PNU 변경 131개. 마지막 관측 상태로 유지된 누락 PK는 87개다.

속성 변경과 주소 변경은 서로 배타적인 숫자가 아니므로 합산하지 않는다. 처음 관측은 신축, 누락은 멸실, 주소 변경은 분할·합병을 인증한 것이 아니다.

누적 관리 PK 4,000개, PNU 3,931개, 건물 속성 버전 4,119개, 토지특성 버전 5,028개다. 건물 관측 및 주소 관계 관측은 각각 11,696건, 토지특성 관측과 공시지가 관측은 각각 10,867건이다. 관측 전체를 매번 새 속성으로 복제하지 않았다.

공시지가 원본 숫자 오버플로 표시는 2024년 17건·2025년 24건이다. 2026년 결측/비양수는 6건이다. 기준연도 미상 관측 47건도 원문 상태로 보존했다. 값이나 연도를 다른 판본/파일 연도로 채우지 않았다. 이 범주들은 중첩될 수 있어 단순 합산하지 않는다.

## 안전성 검증

단위 테스트 7개 통과: 같은 판본 재실행, 내용 변조 거절, 주소/속성 변경 분리, 누락 보존, 전 테이블 실패 롤백, 정체성 충돌 차단, 복구 뒤 과거 판본 삽입 거절, 공시지가 기준연도 미상·별도 관측 보존을 테스트 묶음으로 확인했다.

실제 표본 검사 9개 통과: 판본별 멱등 재실행, 강제 실패 후 모든 테이블 보존, 최초 판본 포인터 복구, 최신 전체 상태 정확 복구, 외래키 무결성, 건물 관측당 주소 관계 하나, 관측과 버전의 객체 일치, 변경 사례 포함, 토지 관측당 가격 관측 하나. 전체 러너도 같은 입력으로 재실행하여 중복 적재 없이 검토 큐를 생성했다.

과거 복구는 이 실험 DB의 파생 current만 재구성한다. 관측·내용 버전·관계 이력은 유지한다. 이는 운영 서버 복원 시험을 대신하지 않는다.

## 다음 검토와 남은 범위

`building_relation_review_queue.csv`는 구·사유별 최대 10개씩 뽑은 로컬 검토 큐다. 주소 변경, 토지자료 미연결, 최신 건축물 관측 누락, 가격 오버플로/결측을 분리했다. 독립 검증 상태는 미검증이며 근거 칸은 비어 있다. 집계 보고서에는 개별 PNU·관리 PK를 넣지 않았다.

다음은 큐의 원천 근거를 확인하고 대표/추가 필지, 총괄·주부속 관계의 확보 범위를 조사하는 작업이다. 지금 구조는 대표 주소 하나만 담으며 전체 부지 다대다 관계의 완성본이 아니다. 건축물 속성은 기존 DB의 가공 추출값으로, 원문 문자·전체 필드·원천 가공 사유 보존은 추가 보완이 필요하다.

운영 정책 확정, 전체 청주 이관, 거래 대상 건물 정확도 인증, 제품 보강 개편은 아직 남아 있다. 집합은 단지별 최신 공시지가 경로를 유지하며 과거 거래별 보강을 추가하지 않는다.
