# 대장 DB 일원화·정규화 및 제품 보강 개편 계획

작성: 2026-10-04. 사용자와 합의한 작업 순서 기록. 현재 제품 보강 정책·코드는 유지하며, 실험과 공통 정책을 세운 뒤 복합·집합 보강을 함께 개편한다. 아래 스키마 명칭·전환 절차는 제안이고 운영 적용 완료를 뜻하지 않는다.

## 목적과 범위

기존 로컬 `parcel_master` 건축대장과 청주 토지특성·공시지가 연구 자산을 공통 원천·키·이력 체계로 통합한다. 원본 보존, 출처 추적, 판본 재현, 안전한 갱신을 먼저 검증한다. 공통 대장을 하나의 평평한 테이블로 만들거나 제품 DB를 물리적으로 하나로 합치는 작업으로 해석하지 않는다.

제품별 소비 목적은 구분한다.

- 토지: 필지·거래 연결과 연도별 특성·공시지가 분석.
- 복합: 거래 대상 필지·건축물 관계를 확인하고 공시지가·토지특성을 거래 단위로 보강.
- 집합: 단지/건물 단위 기존 속성 및 최신 대표필지 공시지가 공급. 단지 평균가격 기반 지역회귀와 신축 아파트 예측 목적을 유지한다. 과거 개별 거래별 토지정보 보강은 이번 범위에서 제외한다.
- 토지이용계획: 선택 확장 자료로 보존. 기본 대장 구성·연결의 필수 조건으로 두지 않는다. 기존 제품 보강값을 지금 삭제·교체하지 않는다.

## 0단계 — 현재 상태를 기준으로 고정

완료: 청주 토지 연구 입력·회귀 결과·표본 SQLite 갱신 시험, 건축대장/제품 키 읽기 전용 인벤토리, 현행 보강 정책 리뷰. 아직 독립 연결 정확도 인증이나 전체 청주 운영 전환은 완료하지 않았다.

기준 문서:

- `MACRO_ENRICHMENT_POLICY_REVIEW_20261004.md`: 현행 복합·집합 방식과 정책/구현 불일치.
- `CHEONGJU_BUILDING_PARCEL_INTEGRATION_REVIEW.md`: 건축·토지 관계 검토.
- `CH2_LEDGER_V2_OPERATING_POLICY.md`: 원천·이력·연결·갱신의 초안.

집합 허용 등급/안내 불일치, 복합 동의 문구, 전체 재계산, 비어 있는 건축물 PK는 후속 개편 목록에 보존한다. 이 로드맵 단계에서 제품 동작을 바꾸지 않는다. 코드 기준 상태의 Git 기준점은 실제 개편 직전에 확보하고, 그때 다른 진행 작업과 변경 범위를 구분한다.

## 1단계 — 청주 원천·식별 단위 인벤토리

원천별 확보 연도·판본·지역 범위·필수 컬럼·결측·코드 체계를 정리한다. 토지특성은 2019~2026년, 조사된 건축대장은 2024-09·2025-07·2026-07이라는 차이를 명시한다. 필지 PNU, 건축물 관리 PK, 단지 키, 비주거 군집 키, 거래 해시를 구분한다.

산출물: 원천 사전, 원본→표준 컬럼 대응표, 단위/그레인 정의, 동일 값·중복·충돌 목록. 관측 기준일·효력일·입수일을 구분하며 과거에 입수했다고 소급 기록하지 않는다.

완료 조건: 각 표준 필드의 원천·의미·단위·키·결측 정책을 추적할 수 있다. 모르는 코드와 근거가 없는 시점은 미상으로 유지한다.

## 2단계 — 공통 대장 정규화와 이력 갱신 실험

기존 건축물 판본을 재사용하면서 필지 식별, 토지특성 이력, 공시지가 연도/정정 판본, 건축물 판본, 원천 레지스트리, 관측 기록, 필지↔건물 관계를 분리하는 로컬 실험 스키마를 만든다. 동일 속성은 관측만 추가하고 변경된 속성은 새 버전을 만든다. latest/current는 명시적인 판본 선택 규칙을 갖는다.

표제부의 대표 주소 필지와 전체 대지 집합을 구분한다. 현재 주소만으로 추가 필지, 분할·합병 계보, 동일 건물 승계를 만들어내지 않는다. 총괄·주건축물·부속건축물·집합 표제부 집계 단위를 확인한다.

산출물: 작은 로컬 DB, 변환 규칙 버전, 원천별 이관 대조 보고서, 갱신/복구 실험 결과.

완료 조건: 원본 의미·행수/키가 보존되거나 제외 사유가 설명된다. 반복 실행 멱등성, 실패시 이전 상태 유지, 원천 누락시 잘못된 말소 방지, 이전 판본 재현을 확인한다. 기존 SQLite 4,000 PNU 시험은 출발점이며 건물·관계 통합 시험을 대체하지 않는다.

## 3단계 — 건축·토지·거래 연결 검증

청주 동일 판본의 건축물 PNU ↔ 토지특성 연결 범위를 먼저 측정한다. 다음으로 복합 거래를 단일/복수 필지와 단일/복수 건물 후보로 구분한다. 기존 확정 보강을 보존하면서 새 연결 규칙의 결과를 별도로 비교한다.

산출물: 연결 후보 및 근거 큐, 독립 검증 상태, 유형/구별 연결 범위, 기존 결과와의 충돌 보고서, 거래별 특성 실험 파일.

완료 조건: 후보 하나와 정확한 연결을 구분한다. 독립 근거가 없으면 미검증으로 남긴다. 조인 후 거래행수 증가, 필지면적·공시지가 금액 중복, 전체 부지를 거래 대상이라고 잘못 취급하는 경우를 검사한다. 날짜 가용성과 연결/미연결 표본 차이를 함께 평가한다. 회귀는 같은 표본에서 비교하되 정확도 기준은 추가 결과를 보기 전에 정한다.

집합은 기존 단지 키↔건축물/대표 PNU 관계 및 최신 공시지가 공급 경로를 검토한다. 과거 거래별 보강 파일은 만들지 않는다.

## 4단계 — 공통 운영 정책 확정

앞 단계의 실측을 바탕으로 출처 우선순위, 코드 정규화, 이력/정정, 대표/복수 필지, 연결 확정과 수정, 품질 등급, 판본 선택, 갱신/재시도, 복구 정책을 사용자와 정리한다. 원천 관측 변경과 실제 법적 효력 변경은 구분한다.

산출물: 확정 정책, 스키마/변환 계약, 제품별 보강 인터페이스, 운영 전환 게이트. 실험 수치만으로 사후 합격선을 만들지 않는다. 새 정책의 적용 범위·기존 확정 결과 처리·사용자 설명을 개편 전에 구체화한다.

## 5단계 — 복합·집합 보강 전반 개편

공통 정책이 확정되면 현행 파이프라인·결과 테이블·갱신 러너·API·회귀·출처/동의 안내·품질 검증을 함께 정리한다. 제품별 소비 단위는 위 범위를 유지한다.

- 복합: 건물/필지 연결 버전과 근거를 보존하고, 거래별 토지정보 보강을 구현한다. 전체 이관 인증과 월간 신규/미연결 계산을 분리한다. 목록·CSV·회귀의 표시/필터와 동의 설명을 일치시킨다.
- 집합: 단지 속성 및 최신 공시지가의 공통 대장 공급 경로를 정리한다. 회귀 목적별 허용 등급·품질·목록 안내를 일치시킨다. 최신 공시지가 갱신과 기존 연결 보호를 별도 처리한다.
- 주거/비주거: 출처·품질·결측·갱신 계약은 함께 정리하되 원천과 분석 단위의 차이를 유지한다. 자료가 없는 비주거 군집을 주거 단지와 동일하게 채우지 않는다.

완료 조건: 기존 분석을 재현하거나 차이를 근거로 설명할 수 있다. 거래/단지 키 유일성, 품질/시점 조건, 표시/필터 일치, 변경 범위에 필요한 회귀 검증, 갱신 멱등성/복구를 확인한다. 실제 회귀 개선이 없는 변수를 기본식에 자동 승격하지 않는다.

## 6단계 — 검증된 결과의 운영 전환

새 결과를 기존 결과와 병행 비교하고 단계적으로 전환한다. 이전 연결·보강 버전으로 돌아가는 경로를 확보한다. 원본과 로컬 공통 대장은 유지하고 운영에는 필요한 도메인 보강 결과를 전달한다. 배포는 사용자 요청 시 저장소 배포 런북을 따른다.
