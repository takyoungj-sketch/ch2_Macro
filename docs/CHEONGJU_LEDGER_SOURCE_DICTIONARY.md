# 청주 공통 대장 원천·키 사전 v1

작성: 2026-10-04. 현재 구현과 읽기 전용 인벤토리에 근거한 실험용 대응표다. 원천 기관의 전체 코드 명세를 인증하거나 운영 스키마를 변경한 문서가 아니다.

## 식별 단위

- 필지: PNU 19자리. 법정동 10자리·필지구분 1자리·본번/부번 각 4자리. 현재 원천 간 정확한 주소 필지 조회 키이며 분할·합병을 포함한 영구 객체 ID로 가정하지 않는다.
- 건축대장 표제부: `mgmt_pk × snapshot`. PK는 표제부 관리 식별자다. 여러 동·대장 종류·주부속 관계를 포함할 수 있어 거래 자산 1개와 동일하다고 간주하지 않는다.
- 제품 집합: `building_key × asset_type`. 단지/건물 단위 최신 속성 소비 키이며 건축대장 PK와 별도다. 비주거 `cluster_key/resolution_mode`는 도로명 군집 단위다.
- 제품 복합/토지: `transaction_hash`. 거래 입력 판본과 정정·해제 상태를 함께 보존한다.

## 토지특성 AL_D194

확보 범위는 청주 4개 구, 2019~2026년이다. 원본 ZIP/SHP/DBF는 그대로 유지하며 이번 연결 실험은 검사된 `traits_YYYY.csv.gz`를 사용한다. 캐시 해시와 행수는 기존 `cheongju_trait_links_20261004.json`의 인벤토리와 대조했다.

- `A1 → pnu`, `A2 → bjd`, `A6 → lot`: 원문 식별·지번. PNU와 법정동의 앞 10자리 일치를 검사한다.
- `A8 → year`, `A9 → month`: 원문 연도·월. 파일명·입수일과 분리한다.
- `A10/A11 → jimok_code/label`: 지목 코드·원문 명칭.
- `A12 → area`: 원문 필지면적(㎡). 거래 귀속 면적이나 건축대장 대지면적과 별도다.
- `A13/A14`, `A15/A16 → zone1/zone2_code/label`: 토지특성의 용도지역 1·2. AL_D155 전체 복수 지정과 동일 범위로 해석하지 않는다.
- `A17 → use_code`, `A19 → height_code`, `A21 → shape_code`, `A23 → road_code`: 이용상황·고저·형상·도로접면 코드. 원코드 보존, 빈칸/0은 미상 처리, 범주 코드를 수치로 평균하지 않는다.
- `A25 → price`: 공시지가 단가(원/㎡). 공시지가 기준연도·정정 판본을 함께 보존한다. 공시지가 양수 여부는 회귀 적격 여부와 다르다.
- `A26 → trait_asof`: 원천 관측 기준일. 효력일·공급일·입수일을 대신하지 않는다.

명칭이 비어 있더라도 코드가 남을 수 있다. 기존 관측 코드-명칭 사전은 경험적 대응이며 미확인 코드에 다른 의미를 자동 부여하지 않는다.

## 건축대장 표제부

기존 `parcel_master.building`의 2024-09·2025-07·2026-07 판본을 재사용한다. 적재 코드 `paths.TITLE_COLS`의 원본 열 위치는 0부터 시작한다.

- `[0] → mgmt_pk`, `[2] → ledger_kind`.
- `[8] 시군구 + [9] 법정동 + [10] 필지구분 + [11]/[12] 본번/부번 → pnu`, `beopjungri_code`.
- `[7]/[22] → building_name/dong_name`, `[32] → structure_name`, `[35]/[36] → main_purpose/purpose_detail`.
- `[25]/[26]/[28]/[29] → title_land_area/arch_area/gross_area/plat_area`: 서로 다른 원본 면적 항목을 분리한다. 필지면적·거래면적과 자동 치환하지 않는다.
- `[40] → households`, `[66] → ho_cnt`, `[43]/[44] → floors_above/below`, `[60] → approve_date`.
- 주차 `[50]+[52]+[54]+[56]` 대수 합. 면적 열은 합하지 않는다.

현재 DB의 숫자는 기존 적재기에서 일부 결측/비양수 처리된 파생값이다. 이번 추출 파일은 건축HUB 원본 자체가 아니라 로컬 DB 상태의 고정 입력이다. 원본 문자·누락/가공 사유까지 복원하려면 다음 정규화 실험에서 원천 적재 경로를 보완해야 한다.

현재 building.pnu는 대표 주소 필지 연결이다. 추가 대지 목록·주부속 관계·총괄 연결을 완전히 보존한 스키마가 아니다. 표제부 관리 PK별 같은 주소가 있다고 전체 대지·거래 대상을 확정하지 않는다.

2026-10-05 원본 확인 보완: TXT 공통 [16] 외필지수, [23]/[24] 주부속 구분, [47]/[48] 부속건축물수/면적을 원문으로 보존할 필요가 있다. 개수는 식별 목록이 아니다. 기존 PNU 생성기는 대지구분 코드 2도 토지로 처리하지만 원천 기반 정규화에서는 의미 미확인 상태로 분리한다. 대상 2024년 원본은 76열, 이후는 77열이며 샘플 CSV 첫 부분은 TXT와 열 순서가 달라 별도 대응이 필요하다. 근거: `CHEONGJU_RELATION_SOURCE_EVIDENCE_RESULT.md`.

## 이번 연결 정책과 시점

정확한 PNU 및 법정동 일치만 사용한다. 주소 유사도·가격·면적 근사로 누락을 메우지 않는다. 비교는 같은 연도이며 동일 관측일의 비교가 아니다.

- 2024: 건축물 2024-09 ↔ 토지특성 기준일 2024-07-31.
- 2025: 건축물 2025-07 ↔ 토지특성 기준일 2025-08-08.
- 2026: 건축물 2026-07 ↔ 토지특성 기준일 2026-05-13.

건축물 판본월은 정확한 효력일이 아니다. 2019~2022년 토지자료만으로 그 당시 건물 속성을 확보한 것으로 표시하지 않는다. 2024~2026 다른 연도에서 누락 PNU가 보이면 '다른 판본에서 관측됨'으로만 기록한다. 삭제·분할·합병 근거로 자동 전환하지 않는다.

## 정규화에서 분리할 관계

원천 판본, 원본/표준 값, 관측 기록, 필지 속성 버전, 공시지가 기준연도/정정, 건축물 속성 버전, 건물↔필지 관측 관계를 구분한다. 동일 관리 PK의 PNU가 바뀌어도 과거 관계를 덮지 않는다. 서로 다른 관리 PK의 승계나 동일 PNU의 전체 건물 집합도 근거 없이 추정하지 않는다.

복합은 이 관계 위에 거래 대상 필지/건물 연결을 별도로 만든다. 집합은 기존 단지 속성과 최신 대표필지 공시지가 공급 경로를 유지하며 이번 사전에서 과거 거래별 보강을 추가하지 않는다.
