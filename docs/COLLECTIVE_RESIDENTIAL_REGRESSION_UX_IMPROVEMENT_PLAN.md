## 1. 목적과 범위

후속 유형별 통일 작업에는 [토지 회귀 개선안](LAND_REGRESSION_UX_IMPROVEMENT_PLAN.md)도 함께 적용한다. 단가/금액·거래/단지 표본·지분거래 정책 차이는 보존한다.

주거형 집합의 회귀 결과를 복합과 같은 통계 언어·문체·표시 방식으로 읽을 수 있게 한다. 결과 표시와 설명을 통일하되, 분석 단위와 실제 계산 방법의 차이는 명확히 드러낸다.

- 대상은 `BuildingDetailModal` 안의 회귀 분석과 인근단지 추가 기능이다.
- 지역회귀, 층·동·면적 효용지수, 전월세, 비주거 화면 자체를 이번에 직접 검토한 것은 아니다.
- 현재 동작을 기록한 **관찰**, 코드로 확인한 **오류**, 구현할 **개선 제안**을 구분한다. 수치는 사례이며 제품 상수가 아니다.
- 이 문서는 구현·배포 완료 기록이 아니다. 모형추천2를 집합에 도입하거나 복합의 기존 Macro 탐색을 대체하는 계획도 아니다.
- [집합 주거·비주거 패리티](../.cursor/rules/collective-residential-commercial-parity.mdc)에 따라 구현 시 공통 결과·예측·추천 UI는 비주거에도 함께 적용한다. 비주거에 없는 단지 특성을 억지로 추가하지 않고 분석 단위에 맞게 매핑한다.

## 2. 검토 사례와 고급 변수 실험

### 2.1 공통 조건

- 서울 강남구 삼성동, 아파트, 분석 기간 2021-10-01~2026-09-30, 실험 모드.
- 분석 대상: 삼성동중앙하이츠빌리지 26건.
- 추가 단지: 롯데캐슬프레미어 63건. 통합 적합 표본 89건.
- 기본 변수: 전용면적·연식·층·동·거래시점(반기).
- 선형 금액 모형, 상대층 구간, IQR 제외 끔, 범주 결측 미상 유지.
- 최초 결과의 화면 표시: R² 0.90355, Adj R² 0.86311, ‘학습 MAPE 5.43%’.
- 원래 시나리오: 면적 85㎡, 연식 10년, 10층, 중앙하이츠빌리지 102동. 추정값 179,246만원, 평균 추정범위 105,142~253,351만원, 개별 거래 예측범위 94,411~264,082만원.

‘학습 MAPE’는 당시 화면 라벨을 인용한 것이다. 코드 확인 결과 실제로는 교차검증 가능 시 CV 오차를 사용하는 필드였다. §4 R-01의 정정 사항을 적용해야 한다.

### 2.2 직접 실행한 6가지 조합

1. **세대수만 추가:** 89건 유지. 단지 고정효과 대신 세대수를 포함했다. 회귀식에 약 +105만원/세대가 표시됐다.
2. **세대당 주차만 추가:** 89건 유지. 단지 고정효과 대신 주차를 포함했다. 회귀식에 약 +232,322만원/대가 표시됐다.
3. **개별공시지가만 추가:** 89건 유지. 단지 고정효과 대신 공시지가를 포함했다. 회귀식에 약 −0.059만원/(원/㎡)가 표시됐다.
4. **구조만 추가:** 단지 간 차이가 없어 생략됐다. 결과에는 단지 고정효과가 유지됐지만 상단 설명은 ‘FE 생략’으로 표시됐다.
5. **유형만 추가:** 단지 간 차이가 없어 생략됐다. 구조 실험과 동일하게 상단 설명과 실제 결과가 달랐다.
6. **고급 변수 5개 모두 선택:** 구조·유형은 생략되고 세대수·주차·공시지가가 포함됐다. 설계 열 29개, 독립 계수 27개라는 식별 경고가 표시됐다. 계수는 각각 단독 추가 때와 달라졌다.

이 실험들의 R²·Adj R²는 화면 표시 정밀도에서 같았다. 이를 고급 특성의 독립적 설명력 향상으로 해석하지 않는다. 두 단지의 차이를 다른 변수 조합으로 표현한 결과일 수 있으며, 여러 단지 특성을 구분하기에 단지 간 변이가 부족하다.

실험 후 고급 변수를 모두 해제하고 원래 회귀를 다시 실행했다. 시나리오 입력과 대상 단지·동을 복원해 추정값과 두 범위가 최초 표시와 같은지 확인했다. 재실행 때 오차·추천이 조금씩 달라진 현상은 거래 행 순서와 CV 분할 재현성을 추가 점검할 항목이며, 원인을 확정한 것은 아니다.

### 2.3 확인하지 않은 범위

로그 고급 변수 조합 전체, 누락 특성이 많은 다른 단지, 다른 유형 혼합의 실제 적합, 비주거 화면, 밝은 테마·글자 확대는 구현 후 검증 대상이다. 현재 관찰만으로 이 범위까지 정상·오류라고 단정하지 않는다.

## 3. 복합과 통일할 결과 표시·문체

### 3.1 같은 용어와 정보 순서

기본 순서를 **분석 대상·조건 → 모형 상태·제한 → 표본 → 주요 지표 → 회귀식·계수 → 통계적 추정 → 후보 비교**로 맞춘다. 식별 불가·외삽·이전 결과 잔존은 해당 숫자보다 먼저 알린다.

- 제목: **회귀 분석**. 부제에 대상 단지·통합 여부·종속변수·단위·척도를 표시한다.
- 표본: **적합 표본 {n}건**. 통합 분석에서는 **분석 단위 {b}곳**을 함께 표시한다.
- 학습 오차: **학습 오차(MAPE)**. 실제 같은 거래로 적합·평가한 값에만 사용한다.
- 검증 오차: **검증 오차(CV-MAPE)**. 옆에 **무작위 5분할 / 시계열 검증** 등 실제 방법을 표시한다.
- 복합 Macro의 탐색·마지막 연도 확인 단계는 해당 기능이 있을 때만 사용한다. 집합 무작위 5분할 CV를 복합의 다음 연도 예측 성능과 같은 이름으로 부르지 않는다.
- 계수: **계수 상세 보기 / 계수 상세 접기 / 크게 보기**를 공통 동작으로 사용한다.
- 추정 영역: **조건별 통계적 추정**. 버튼은 **추정값 계산**으로 통일한다.
- 구간: **95% 평균 추정범위 / 95% 개별 거래 예측범위**. 현재 구간 산식을 확인해 이름과 도움말을 맞춘다.
- 후보: **예측 목적 / 설명 목적**, **현재 확인 중인 후보 / 현재 결과에 적용된 후보**를 구분한다.

R²의 종속 척도와 금액으로 환산한 R²를 구분한다. 주거형 추천의 ‘원척도 Adj R²’와 기본 결과의 Adj R²가 다른 정의라면 같은 라벨로 합치지 않는다. 로그에서 금액으로 되돌린 예측값에 계산한 지표는 정의를 `?`에 명시하고, 통상적인 회귀 Adj R²와의 구별도 검토한다.

### 3.2 같은 문체

- 설명은 `~입니다 / ~합니다`, 안내는 `~을 확인하세요 / ~할 수 있습니다`로 쓴다.
- ‘작용한다’ 대신 ‘관계가 관찰된다’, ‘차이가 있다’를 쓴다. 관찰 관계를 인과 효과나 개별 적정가로 확대하지 않는다.
- ‘값·식·행·FE·코호트’만으로 대상이 불명확하면 쉬운 이름을 앞에 둔다. 고급 도움말에서 기술 용어를 병기한다.
- 한 문장에 한 가지를 설명한다. 핵심 제한은 본문에 남기고 세부 정의·예외는 해당 `?`에 둔다.
- ‘아닙니다’라는 부정 안내를 반복하기보다 사용자가 무엇을 확인할 수 있는지 먼저 설명한다. 감정평가 대체 금지 안내는 영역당 한 번 유지한다.
- 숫자의 부호와 ‘높음·낮음’을 중복하지 않는다. `−46% 낮음` 대신 `46% 낮음`으로 쓴다.
- 생략·참고용·식별 문제·외삽을 모두 같은 노란 문장으로 뭉치지 않는다. 실제 상태별 제목을 붙인다.

### 3.3 같은 계수·숫자·색상 규격

- 표는 **변수 / β / 효과 해석 / SE / t / p**로 맞춘다. 원계수와 긴 문장을 같은 열로 대체하지 않는다.
- 연속변수, 층, 동, 거래시점, 단지 고정효과, 단지 특성을 묶고 각 그룹에 기준을 표시한다.
- 작은 계수·SE는 유효숫자나 지수 표기로 보존하고 작은 p는 임계치 미만으로 표시한다. `−0만원`, `SE 0.00`, `p 0.00000`으로 의미를 지우지 않는다.
- 회귀식의 표시 기준과 유의 계수 집계 기준을 각각 명시한다. 회귀식에서 숨긴 변수가 계산에서 제외됐다고 읽히지 않게 한다.
- 유의성은 색 외에 텍스트로 표시한다. 식별 문제가 있는 모형에서 초록색 행을 ‘효과 확인’처럼 강조하지 않는다.
- 본문·표는 기본 13~14px 수준을 목표로 한다. 다크·밝은 테마, 표 크게 보기, 숫자 정렬, 글자 확대 대응은 복합과 맞춘다.
- 공통 모달 셸·탭·버튼 변경은 [5앱 형식 패리티](../.cursor/rules/five-app-format-parity.mdc)를 따른다. 같은 위젯이 없는 기능까지 확장하지 않는다.

### 3.4 통일하지 않을 분석 방식

- 복합의 지역 확장과 집합의 인근단지 통합은 같은 명칭으로 뭉치지 않는다.
- 집합의 단지별 수준 차이·동·상대층·반기 기준은 결과 해석에 필요하므로 유지한다.
- 집합 설명 목적 후보를 복합의 AIC 선택으로 자동 변경하지 않는다. 실제 선정 지표를 표시한다.
- 집합의 후보 적용은 현재 변수 체크를 바꾸고 회귀 재실행이 필요한 동작이다. 복합 Macro가 기본회귀를 대체하지 않는다는 규칙과 혼동하지 않는다.
- 엔진·표본·검증 정의를 통일하는 별도 결정 없이 UI 통일을 이유로 산식을 변경하지 않는다.

## 4. 지표·모형 상태의 정확성

### R-01. MAPE 계산 기준 분리 [P0]

재검토 상태: 학습/CV 필드 분리·공통 UI 표시·유효 행 기준 CV·부분 검증 차단은 선행 적용됐다. 아래의 원래 오류 관찰은 이력이며, 검증 방법·fold·평가 거래 수·미제공 사유와 단지 회귀 자체의 재현성 점검은 남아 있다. 전체 완료로 취급하지 않는다.

검토 당시: `fit_model_price_metrics`는 교차검증 가능 시 `mape`에 CV 오차를 넣고, 불가능하면 학습 오차를 반환했다. UI는 이를 항상 ‘학습 MAPE’와 ‘교차검증이 아님’이라는 설명으로 표시했다. 혼합 `mape` 필드는 호환용으로 유지하며 신규 화면은 분리 필드를 사용한다.

개선:

- 응답에 학습 MAPE, CV-MAPE, CV 방법, fold 수, 검증 거래 수, 계산 불가 사유를 구분한다. 필드명은 설계안이며 기존 API 소비자를 확인해 호환성을 유지한다.
- 검증 불가 시 같은 위치에 학습값을 조용히 대체하지 않는다. `검증 오차 계산 불가 — {사유}`로 표시하고 학습 오차는 별도 제공한다.
- 인근단지 추가 전후 점수는 전체 적합 표본의 지표와 분리하고 평가 거래·방법을 같이 표시한다.
- 무작위 5분할 결과가 미래 거래·새 단지에 대한 검증인 것처럼 설명하지 않는다. 추천에도 같은 검증 정의를 사용한다.
- 동일 조건 재실행의 결과 차이는 행 집합·정렬·분할 ID를 대조해 확인한다. 재현성 확보 전 미세한 오차 차이를 정밀한 순위 근거처럼 강조하지 않는다.

카피:

> 검증 오차(CV-MAPE) {x}% · 무작위 5분할. 거래를 나누어 적합에 사용하지 않은 거래의 오차를 계산했습니다. 미래 시점이나 새 단지로의 적용 성능을 직접 검증한 값은 아닙니다.

### R-02. 권장 표본·식별·유의성 구분 [P0]

## 5. 인근단지 선택·추가 전후 비교

### R-03. 대상·비교 기준·실제 포함 단지 구분 [P1]

현재 ‘기준 단지’는 원래 단지를 뜻하지만 ‘FE 기준’은 거래가 많은 추가 단지를 뜻한다. 추가 단지만 칩으로 보여 원래 단지가 무엇인지도 놓치기 쉽다.

- 입력 선택지의 `FE 제외`는 기준 범주 생략인지 표본 부족에 따른 효과 미추정인지 구분한다. 거래가 제외됐다는 의미와 혼용하지 않는다.

카피:

## 6. 고급 분석 · 단지 특성

### R-05. 체크 상태와 실제 모형 구성 분리 [P0]

구조·유형을 각각 켰을 때 상단은 ‘FE 생략’으로 바뀌었지만, 실제로는 차이가 없어 해당 변수를 생략하고 고정효과 모형을 유지했다.

- 실행 전에는 **요청한 분석 방식**, 실행 후에는 **실제로 적합한 분석 방식**을 구분한다.
- 변수마다 `선택 / 포함 / 차이 없어 생략 / 데이터 없음 / 결측 제외 후 생략` 상태를 표시한다.
- 모형 설명은 체크 상태 추론보다 서버가 반환한 실제 포함 변수·기준 범주·고정효과 상태를 우선한다.
- 가능한 상태는 실행 전에도 안내하되, 최종 포함 여부를 미리 확정하지 않는다.

카피:

> 구조는 두 단지에서 같아 제외했습니다. 단지별 가격 차이를 통제하는 모형을 유지했습니다.

> 단지 특성 변수가 실제로 포함되면 단지 고정효과 대신 해당 특성으로 단지 간 차이를 설명합니다.

### R-06. 단지 수·변수 중복·스냅샷 제한 [P0]

- 89건이라는 거래 수만으로 특성 효과를 평가하지 않는다. 서로 다른 단지 수와 각 특성의 서로 다른 값 개수를 함께 표시한다.
- 두 단지에 각각 하나의 값만 있는 특성 여러 개를 함께 넣으면 효과를 독립적으로 구분하기 어렵다. 선택 시 경고하고 결과에서도 식별 제한을 유지한다.

- ‘같은 층에 두 유형이 있으면 순수 유형 효과’처럼 조건 하나만으로 인과 분리가 보장되는 문구는 사용하지 않는다.

카피:

## 7. 계수 상세·시나리오·추천

### R-07. 효과 해석과 작은 계수 표시 [P0/P1]

- 반기 계수를 `1단위 증가`로 설명하지 않는다. `2023년 상반기 / 기준 2025년 상반기 대비`로 표시한다.
- 층·동·단지 효과는 실제 기준 범주를 각 그룹에서 확인할 수 있게 한다. 긴 단지명을 매번 반복하는 대신 그룹명과 동 번호를 조합한다.
- 선형 연속변수는 1단위 변화의 금액, 로그 금액은 `(exp(β×변화량)-1)×100`%로 해석한다. 전용면적을 로그로 바꾸지 않은 모형에 탄력성 문구를 쓰지 않는다.
- 공시지가는 예를 들어 **100만원/㎡ 증가 시**, 주차는 **세대당 0.1대 증가 시**처럼 읽기 좋은 변화량을 쓰되 원계수·입력 단위와 환산을 명시한다.
- 전체 선택 사례의 `공시지가 −0만원 / 주차 +0만원`을 실제 0으로 보이지 않게 한다.
- 연식의 양의 계수를 노후화의 인과적 프리미엄으로 해설하지 않는다. 단지·시점과의 관계 및 모형 한계를 알린다.
- 사용하지 않은 용도지역 주의문은 숨기고 실제 포함 변수의 주의사항만 표시한다.

### R-08. 이전 결과 무효화와 모형 스냅샷 [P0]

관찰: 고급 변수 추가 후 새 회귀가 완료돼 입력이 초기화되고 단지 선택이 바뀌어도, 기존 추정값 179,246만원과 예측범위가 그대로 남았다.

- 회귀를 다시 적합하면 이전 추정 결과를 제거하거나 이전 결과로 명확히 구분한다. 현재 결과의 자리에서 최신처럼 표시하지 않는다.
- 결과에는 모형 ID·실행 조건·척도·단지 구성·계산 당시 입력을 보존한다.
- 변수·층 형식·IQR·결측 처리·분석 기간·단지 구성 중 하나가 바뀌면 이전 결과 상태를 갱신한다. 변경 감지는 변수 체크·로그만으로 제한하지 않는다.
- 회귀 결과와 시나리오 계산이 다른 변수 구성을 사용하지 않도록 실제 적합 스냅샷을 참조한다.
- 오래 걸린 이전 요청이 늦게 도착해 새 결과를 덮지 않도록 요청·모형 식별자를 검증한다.
- 후보 적용은 `변수 선택에 반영됨 / 회귀 재실행 필요 / 현재 결과에 적용됨`으로 나눈다.

카피:

> 분석 조건이 변경되었습니다. 아래는 이전 조건의 결과입니다. 회귀를 다시 실행하세요.

> 회귀모형이 변경되어 이전 추정 결과를 지웠습니다. 입력 조건을 확인한 뒤 다시 계산하세요.

### R-09. 시나리오 초기값·외삽·단지 연동 [P1]

- 고급 특성 기본값에 단지 최솟값·최댓값의 중간값을 자동 사용하지 않는다. 관찰된 505.5세대는 실제 선택 단지와 무관한 가상 값이다.
- 선택 단지의 확인된 특성을 우선 채우고 변경하면 ‘가상 조건’으로 표시한다. 자료가 없으면 임의로 추정하지 않고 입력 필요 상태로 둔다.
- 면적·연식·층 같은 사용자 입력은 모형이 바뀌어도 호환되는 경우 보존하고 변경·제외된 항목을 설명한다. 예측 결과는 별도로 무효화한다.
- 단지를 바꾸면 동·최고층·단지 특성을 해당 단지와 일치시키고 적용 반기를 표시한다.
- 현재 연식 10년은 표본 하한 14년 미만이다. `building_age=10.0` 대신 필드 옆과 결과 상단에 외삽을 설명한다.
- 단일 추정값만 강조하지 않고 구간과 조건을 함께 보인다. 반복되는 면책 문구는 하나로 정리하되 핵심 제한을 숨기지 않는다.

카피:

> 입력한 연식 10년은 분석 표본 범위 밖입니다. 표본의 최소 연식은 14년입니다. 이 추정값은 외삽에 해당합니다.

> 선택 조건에서 관찰된 가격 관계를 이용한 통계적 추정값입니다. 개별 물건의 감정평가액이나 적정가격을 뜻하지 않습니다.

### R-10. 추천 후보의 선정 기준·차이 [P1]

- 예측 목적은 실제 CV 기준, 설명 목적은 실제 설명력 지표를 표시한다. AIC 등 다른 기준을 있는 것처럼 소개하지 않는다.
- `깊이: 표준+` 대신 실제 탐색한 변수군·척도·후보 수를 요약한다. 현재 체크와 탐색 풀의 관계, 고급 변수가 후보 풀에 들어가는 조건도 설명한다.
- 후보 번호·선택 표시·현재 적용 상태와 후보별 다른 변수만 강조한다. 오차 차이가 작으면 반올림 수치만으로 확정적인 우열을 말하지 않는다.
- 공통 표본 수뿐 아니라 검증 거래·분할 조건도 같아야 직접 비교할 수 있다.
- 표본 2곳의 무작위 거래 검증을 새로운 단지의 특성 효과 검증으로 읽히게 하지 않는다.

카피:

> 선택한 단지의 거래에서 변수 조합과 선형·로그 모형을 비교했습니다. 이 후보는 해당 검증 조건에서 오차가 낮았습니다.

> 후보 선택은 변수 체크에 반영됩니다. 결과에 적용하려면 회귀를 다시 실행하세요.

## 8. 모달 공간과 조작 편의 [P1]

- 현재 관찰된 제목·닫기 도구 가림을 수정한다. 모달 이동·크기 복원 후 화면 안에 도구가 남아야 한다.
- 탭·단지 추가 영역이 높이를 과도하게 차지하지 않도록 `2개 단지 · 89건` 요약과 접기 기능을 제공한다.
- 설정, 결과 요약, 계수, 통계적 추정, 모형 추천 구역으로 빠르게 이동할 수 있게 한다.
- 로그 옵션의 짧은 글자가 세로로 잘리지 않도록 레이아웃을 정리한다.
- 계수 표 내부 스크롤과 본문 스크롤 중첩을 줄이고 크게 보기를 제공한다. 키보드로 계수·기준 범주·버튼에 접근할 수 있어야 한다.
- 복합의 공통 표·버튼·도움말 크기를 사용한다. 흰 배경 칩의 어두운 글자가 다크 모드 배경과 섞이지 않도록 점검한다.
