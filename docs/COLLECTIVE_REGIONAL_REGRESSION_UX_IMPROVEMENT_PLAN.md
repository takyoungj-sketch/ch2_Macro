## 1. 범위와 적용 원칙

유형별 통일 작업 시 [토지 회귀 개선안](LAND_REGRESSION_UX_IMPROVEMENT_PLAN.md)도 함께 검토한다. 거래 단위와 단지 단위의 표본·검증 정의는 구분한다.

지역회귀는 **단지별 기간 중앙단가를 단지 특성으로 설명하는 분석**이다. 개별 거래를 행으로 쓰는 단지 내 회귀와 분석 단위가 다르다. UI의 용어·문체·지표 형식·상태 표현은 통일하되, 표본 단위와 검증 방법은 실제 계산에 맞게 표시한다.

- 이번 코드 변경은 RG-01의 동일 조건 재현성 수정과 관련 테스트에 한정한다. 나머지 항목은 유형별 회귀 개선을 한 번에 진행할 때 구현한다.
- 복합의 기존 Macro 모형 탐색을 기준으로 역할·표시 계약을 맞춘다. 모형추천2로 교체하지 않는다.
- 공통 결과·추천·추정 UI 개선은 주거와 비주거에 함께 반영한다. 현재 이 지역회귀 엔진은 단지 속성 기반의 주거 전용이며, 비주거에 대응 지역회귀를 이번에 신설하지 않는다. 향후 도로명 cluster 기반 분석에는 해상도에 맞게 같은 표시·재현성 원칙을 적용한다.
- 다른 유형·앱에도 같은 순서 의존 문제가 없다는 의미가 아니다. 각 엔진의 행 식별자·정렬·검증 분할은 일괄 작업 시 별도 점검한다.
- 아래 수치는 검토 사례다. 화면 고정값이나 성능 보장 문구로 사용하지 않는다.

## 2. 직접 실행한 조건과 관찰

### 2.1 기본 조건

서울특별시 강남구 삼성동, 아파트 + 오피스텔, 5년 창. 세대수·최고층·연식·유형 더미, 로그 모형, 동일 가중, 최소 거래수 5건, 범주 결측 유지로 실행했다. 기준 월은 2026-09-01, 속성 스냅샷은 202607이었다.

- 원천 102곳 → 속성 연결 101곳 → 거래수 미달 51곳 제외 → 최종 50곳.
- 최종 50곳은 학습 38곳과 검증 12곳으로 나뉜다. 검증 12곳은 제외된 단지가 아니다.
- 주차를 추가하면 숫자 결측·품질 문제로 13곳이 추가 제외돼 37곳이 남고, Holdout 검증을 수행하지 않았다.
- 주차 경고의 53곳은 원천 범위의 결측 수이며, 최종 단계에서 실제 추가 제외된 13곳과 분모가 달랐다.

### 2.2 쌍둥이 확장

후보 잠원동을 추가해 실행했다. 확장 표본은 최종 95곳, 학습 71곳·검증 24곳이었다. 지역 더미를 끈 실행의 검증 MAPE는 28.2%, 켠 실행은 29.4%로 표시됐다. 당시에는 RG-01의 순서 의존 문제가 있었으므로 이 차이를 지역 더미의 효과로 확정할 수 없다.

- 후보 목록의 단지 수는 아파트 재고·후보 선정 기준의 수치이며, 현재 5년·혼합 유형·변수 조건에서 적합 가능한 수와 다르다.
- 지역 더미를 켠 결과에서도 기본 변수 블록 표는 더미를 끈 식의 지표를 표시했다. 코드의 `_block_contrib`가 지역 더미 정보를 설계행렬에 전달하지 않는 것을 확인했다.
- 잠원동은 서초구인데 화면 범위 설명만으로는 강남구 밖까지 포함됐다는 사실을 즉시 알기 어려웠다.
- 실제 단지 중앙하이츠를 선택해 추정 입력과 결과·범위를 확인했다. 추정 영역 제목은 ‘평균단가’, 단지 관측값은 ‘중앙값’으로 표현돼 대상 통계가 혼재했다.

### 2.3 검토 한계

다른 지역 전수, 모든 변수 조합, 비주거 화면, 글자 확대·밝은 테마·키보드 접근성 전체는 검증하지 않았다. 이 문서는 확인된 사례와 코드 확인 사실, 후속 설계 제안을 구분한다.

## 3. 동일 조건 재현성 수정 [RG-01 · P0 · 적용]

### 원인과 수정

원천 SQL의 반환 순서가 고정되지 않았고, `_split_hold`는 seed=42로 **행 위치**를 섞었다. 데이터와 표본 수가 같아도 단지 순서가 달라지면 학습·검증 단지가 바뀌었다.

`load_danji_frame`에서 유형 값을 정규화한 후 `(asset_type, building_key)`로 안정 정렬하고 인덱스를 초기화했다. 기본회귀·추천·예측 재적합이 이 공통 로더를 사용한다. 난수 시드·검증 비율·최소 표본 기준·모형 산식은 유지한다.

### 확인한 근거

- 수정 전 같은 API 요청 5회에서 검증 MAPE가 38.88%, 38.88%, 38.88%, 26.18%, 29.52%였다. 표본은 모두 학습 38곳·검증 12곳이었다.
- 별도 조회 6회의 데이터 내용은 동일했지만 반환 순서 및 학습·검증 구성이 4종류였다.
- 같은 데이터를 원순서·역순·셔플 2가지로 넣는 실험에서 단지 키 정렬 후 검증 대상·계수·지표가 모두 같아졌다.
- 자동 테스트는 빈 표본·검증 없는 소표본·유형 간 동일 building_key·선형/로그·동일/거래수 가중을 포함한다. 서로 다른 조회 순서를 제공하면서 회귀·추천·예측 응답 전체가 같은지 비교한다.
- 새 테스트 5개와 기존 지역회귀·추천 테스트를 합쳐 36개가 통과했다. 로컬 API 재시작 후 회귀 요청 5회의 전체 응답이 같았고(R² 0.67737, 학습 MAPE 22.33%, 검증 MAPE 18.64%), 같은 입력의 예측 요청 3회도 전체 응답이 같았다.

정렬 후 처음 계산되는 결과는 이전 화면의 결과와 달라질 수 있다. 이는 평가 표본을 고정하는 수정이며, 오차 감소나 모형 성능 향상을 의미하지 않는다. 데이터·기간·변수·지역 자체가 바뀌었을 때 검증 대상까지 고정하는 설계는 RG-05의 별도 과제다.

재현 스크립트·상세 응답은 `logs/local-collective/regional_repro*`, 수정 후 API 검증은 `regional_verify_fix*`에 있다. 로그는 Git·배포에 포함되지 않을 수 있으므로 핵심 근거는 이 문서에 남긴다.

## 4. 결과 정합성과 비교 기준 개선

### RG-02. 분석 대상·척도·지표 정의 [P0]

- 제목과 설명을 ‘단지 중앙단가’로 통일한다. 단위는 `만원/㎡`, 표본 단위는 `단지`로 명시한다. 추정값은 해당 특성에서 모형이 추정한 단지 중앙단가이며, 개별 거래 가격이나 개별 주택 감정가로 설명하지 않는다.
- 현재 로그 모형의 R²와 가격 척도에서 다시 계산한 Adj R²가 같은 줄에 표시된다. 각각의 계산 척도와 표본을 응답에 담고, 동일 척도 지표끼리 묶는다. 로그 R²와 원단가 Adj R²를 한 쌍처럼 읽히게 하지 않는다.
- 학습 오차·검증 오차를 분리하고 검증 방법과 학습/검증 단지 수를 표시한다. 검증하지 않은 경우 `— · 검증 표본 부족`으로 표시한다.
- 상세 도움말은 단지별 기간 중앙값을 계산한 뒤 단지를 학습·검증으로 나누는 과정을 설명한다. 시간에 따른 미래 예측 검증으로 표현하지 않는다.
- 거래수 가중을 사용하면 지표의 가중 여부와 유효 표본 수 의미도 도움말에서 설명한다.

### RG-03. 표본 흐름과 결측 내역 [P1]

- 원천 → 속성 연결 → 거래수 조건 → 변수 결측·품질 제외 → 최종 분석 → 학습/검증으로 보여준다. `최종`에 학습 수만 쓰지 않는다.
- 단계별 제외 수와 전체 결측 현황을 구분한다. 예: `주차 사용 시 현재 적합 후보 중 13곳이 추가 제외됩니다.` 원천 결측 53곳은 별도 참고로 표시한다.
- 결측 상세 창에 변수별 결측·품질 이상 수, 해당 단지 목록, 제외 사유를 제공한다. 한 단지가 여러 사유를 가질 때 합계가 중복될 수 있음을 명시한다.
- 결과에서 ‘주차 제외 후 실행’, ‘최소 거래수 변경’, ‘지역 추가’로 연결하되 변경된 설정을 보여준 다음 실행한다. 변수 자동 해제 후 기존 결과를 최신처럼 남기지 않는다.
- 37곳에서 검증이 사라지는 경우처럼 조건 변경의 영향을 실행 전 또는 실행 직후 요약한다.

### RG-04. 추천 후보의 표본·선정 오차 [P0]

- 후보에 적용 변수·척도·적합 가능 단지 수·학습/검증 수·검증 방법을 표시한다. 현재 식과 표본이 다르면 `표본 다름`을 표시한다.
- 후보 선정에 사용한 Holdout 오차를 독립적인 최종 성능 검증처럼 표현하지 않는다. 우선 `후보 비교용 검증 오차`로 명시하고, 후속 설계에서 공통 평가 표본 또는 별도 최종 검증을 결정한다.
- 변수별 결측으로 비교 대상이 달라졌을 때 단순히 낮은 오차만으로 우수 판정을 내리지 않는다. 공통 표본 평가와 사용 가능 표본 수를 함께 검토한다.
- 적용 버튼은 `이 변수 조합으로 실행`으로 표현하고 변경될 변수·척도를 요약한다. 적용 후 이전 추정 결과는 재계산 전 상태로 전환한다.

### RG-05. 기본회귀와 쌍둥이 확장의 평가 대상 [P0]

- 기본회귀는 기준지역, 확장회귀는 혼합 지역에서 별도 검증 표본을 만들고 있다. 서로 다른 대상에서 구한 MAPE 차이로 ‘확장으로 개선’을 판단하지 않는다.
- 기준지역의 검증 단지를 먼저 고정하고, 그 단지를 양쪽 학습에서 제외한다. 기본은 기준지역 학습 단지, 확장은 같은 단지에 추가지역 학습 단지를 더해 **같은 기준지역 검증 단지**에서 비교한다.
- 추가지역 표본에서도 별도 진단을 제공할 수 있지만 기준지역 성능과 구분한다. 표본이 부족하면 개선 판정을 보류한다.
- UI는 `기준지역 검증 오차`, `추가 학습 단지`, `평가 대상 동일 여부`를 함께 표시한다. 동일 조건 재현성 수정만으로 이 비교 설계까지 완료된 것은 아니다.

### RG-06. 지역 더미와 변수 블록 정합성 [P0]

- 기본 블록·추가 블록 비교에도 현재 식과 같은 지역 더미·표본·가중·범주 처리를 전달한다.
- 지역 더미 포함 여부와 기준지역을 회귀식·계수·블록 표·추정 입력에 일관되게 표시한다.
- 선택했지만 변이가 없어 생략된 변수, 실제 포함 변수, 기준 범주를 구분한다. 체크박스 선택과 식에 포함된 상태를 동일시하지 않는다.

## 5. 조작 편의성과 가시성 개선

### RG-07. 쌍둥이 선택과 범위 확인 [P1]

- 기준지역과 추가지역을 각각 표시한다. 예: `기준: 강남구 삼성동 / 추가: 서초구 잠원동`.
- 순위 산출에 쓰는 기준 읍면동과 실제 회귀에 포함되는 기존 선택지역 전체를 구분한다.
- 후보 수치에 `후보 선정 기준: 아파트 재고·3년`처럼 기준을 붙인다. 실행 후에는 현재 조건으로 남은 단지 수를 따로 표시한다.
- 지역 더미 도움말은 `지역별 평균적인 수준 차이를 반영합니다. 기준지역 대비 차이로 표시합니다.`로 설명한다. 성능 향상을 보장하는 옵션처럼 표현하지 않는다.
- 선택지역 수·최종 분석 단지 수를 요약하고, 긴 후보 설명은 도움말로 이동한다. 기본회귀와 확장 결과는 각각의 실행 조건을 보존한다.

### RG-08. 계수·추정·결과 상태 [P1]

- 계수 표는 복합·집합 단지 회귀와 같은 열 순서·유의성 표시·단위·기준 범주 형식을 쓴다. p값은 `0` 대신 `<0.001`, 작은 계수는 `+0.0` 대신 유효숫자나 적절한 단위로 표시한다.
- 로그 계수의 단위 변화·범주 대비 해석을 분리한다. 지역계수는 기준지역 대비로, 유형계수는 기준유형 대비로 설명한다.
- 추정 제목은 `단지 중앙단가 추정 (만원/㎡)`로 변경한다. `관측 중앙단가`, `모형 추정값`, `차이`를 구분한다. 학습에 사용한 단지의 차이를 독립 검증 오차로 부르지 않는다.
- 평균 추정범위와 개별 관측값의 예측범위는 공통 용어를 사용하되, 여기서 관측 단위는 개별 거래가 아니라 **단지의 기간 중앙단가**임을 밝힌다. 통계 담당 검토 후 최종 라벨을 확정한다.
- 실제 단지 선택값·직접 입력값을 구분하고, 지역 더미 사용 시 해당 지역도 입력·결과에 포함한다.
- 조건 변경 후 `설정이 변경되었습니다. 다시 실행하면 결과에 반영됩니다.`를 표시한다. 추정 결과는 사용한 모형·입력·데이터 기준일을 함께 보존한다.
- 결측 상세 창 제목·닫기 버튼 잘림, 중첩 스크롤, 로그 옵션 줄바꿈을 점검한다. 모달 크롬 등 형식 변경은 5앱 공통 패리티 작업에서 함께 적용한다.

## 6. 문체와 화면 설명문구

문장은 ‘~합니다/~하세요’로 통일하고, 내부 구현 용어는 본문에서 쉬운 말로 바꾼다. 한 문구는 상태·이유·다음 행동 중 필요한 내용을 짧게 전달한다. 내부 변수명은 상세 도움말에 둔다.

- `단지 평균단가 예측` → `단지 중앙단가 추정`.
- `창 중앙값을 단지 시세로 보기 어려운 단지를 제외합니다` → `선택한 기간의 거래가 5건 이상인 단지를 분석합니다. 거래가 적은 단지는 대표 단가가 불안정할 수 있습니다.` 숫자는 현재 설정에 맞춘다.
- `숫자 결측으로 빠집니다` → `선택한 변수의 값이 없거나 품질 기준을 충족하지 못하면 분석에서 제외합니다.`
- `표제부 단지에는 주차 값이 없어 켜면 빠집니다` → `주차 정보가 없는 단지는 주차 변수를 사용할 때 분석에서 제외됩니다.` 출처 설명은 도움말로 보낸다.
- `Holdout은 탈락이 아닙니다` → `검증 단지는 모형 학습에서 따로 남겨 두고 오차 평가에 사용합니다.`
- `표본이 적어 Holdout 검증을 수행하지 않았습니다` → `분석 단지가 40곳 미만이어서 별도 검증을 수행하지 않았습니다. 표시된 학습 오차만으로 예측 성능을 판단하기 어렵습니다.` 현재 정책 변경 시 수치도 함께 갱신한다.
- `고른 읍면동과 체크한 쌍둥이 지역의 단지를 사용합니다` → `선택지역과 추가지역의 단지를 함께 학습합니다. 포함 지역은 위의 분석 범위에서 확인할 수 있습니다.`
- `구조는 실측에서 예측 개선 없음` → `기존 실험에서는 구조 변수의 예측 개선이 확인되지 않았습니다. 현재 지역의 효과는 검증 결과로 확인하세요.` 실험 범위·시점은 도움말에 제공한다.
- `원본 / 풀 / 최종 n` → `전체 단지 / 분석 후보 단지 / 최종 분석 단지`로 역할에 맞게 표시한다. 최종·학습·검증 수를 혼용하지 않는다.

이 표현들은 구현 시 확정할 문구 초안이다. 공통 지표명·범위 라벨·용어는 복합 문서 §3 및 집합 단지 회귀 문서와 함께 최종 결정한다. AI 설명과 물음표 도움말도 같은 단위·표본·상태를 사용한다.

## 7. 일괄 구현 순서와 완료 기준

1. **공통 표시 계약 확정:** 지표 척도·검증 방법·표본 단위·실제 포함 변수·모형/입력 스냅샷을 복합·집합 주거/비주거 기준으로 정리한다.
2. **정합성 수정:** RG-02·04·05·06의 계산/응답 계약을 먼저 수정하고, 학습·검증·추천·추정이 같은 모형 정보를 참조하게 한다.
3. **UI·문체 통일:** RG-03·07·08과 §6을 공통 컴포넌트·용어 기준에 맞춰 반영한다. 데이터 단위 차이는 명시한다.
4. **도움말·AI 동기화:** 실제 계산 기준·제외 이유·기준 범주·검증 상태를 함께 전달한다.

후속 완료 기준:

- [ ] 동일 데이터·동일 설정의 반복 실행에서 단지 구성·계수·추천·추정 응답이 같다. RG-01 자동 테스트를 유지한다.
- [ ] 최종 분석 수 = 학습 수 + 검증 수이며, 제외 단계의 분모와 중복 처리 기준이 명확하다.
- [ ] 주차 켜기/끄기·최소 거래수 변경·범주 결측 처리의 영향을 확인한다.
- [ ] 로그/선형의 지표 계산 척도와 단위가 명확하다.

- [ ] 지역 더미 전후 회귀식·블록·기준지역·추정 입력이 일치한다.

- [ ] 비주거 공통 UI와 복합의 표기·문체를 함께 검토한다. 현재 없는 주거 전용 기능을 비주거에 형식적으로 복제하지 않는다.
- [ ] 좁은 창·글자 125%/150%·밝은/다크 테마·키보드에서 제목·닫기·핵심 지표·실행 버튼이 보인다.
