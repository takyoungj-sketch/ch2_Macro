## 2. 변경 식별 → 영향 대상 → 재보강 → 통계 재계산

원장이 바뀌었다고 해서 연결된 거래를 전부 다시 계산하지 않는다. 바뀐 원천 행에서 출발해 영향을 받는 필지·건물·거래·통계 칸만 다시 계산한다.

```text
원천 변경분(change set) → 영향 필지·관리번호 → 영향 거래(역색인) → 재보강 → 영향 통계 칸
```

역색인은 판본마다 만든다. 거래→필지(복원 지번·PNU), 거래→관리번호, 거래→사용한 대장 판, 거래→사용한 slim 기준일이다. 이 색인을 뒤집어 "이 필지·이 관리번호를 쓰는 거래"를 찾는다.

### 2.1 원천별 영향 범위

**거래 원장**
- 새 해시: 미상 거래로 처음부터 연결한다.
- 사라진 해시: 고아 처리(§4).
- 그 밖의 거래는 다시 계산하지 않는다.

**대장 새 판(분기)**
- 판 선택 규칙(`snapshot_policy.pick_snapshot`)은 "계약년월 이하 판 중 가장 늦은 것, 없으면 이후 판 중 가장 이른 것"이다. 이 규칙에서는 더 늦은 판이 추가돼도, 계약년월이 새 판보다 앞선 거래는 고르는 판이 바뀌지 않는다.
- 영향 거래 ① 계약년월이 새 판 이상인 거래: 판을 다시 골라 재연결한다.
- 영향 거래 ② 위 ①의 거래 중 관리번호 사용 필드(구조·주용도·층수·사용승인·연면적·대지위치)가 바뀐 경우는 값만 다시 쓴다.
- 과거 판을 사이에 끼워 넣는 경우는 판 선택이 넓게 바뀌므로 전체 재구축으로 본다.
- 예전 미상 거래를 새 판으로 다시 시도하는 일(`--retry-unmatched`)은 판 선택 규칙을 바꾸는 일이다. 증분이 아니라 규칙 판 변경으로 다룬다.

**토지 새 기준일**
- 영향 거래 ① 관측값(지목·면적·용도지역1·2·공시지가)이 직전 관측과 달라진 필지의 거래.
  - 최신 용도지역과 다음 기준일 위험 표시가 바뀐다.
  - D-047 실측으로 용도지역 연 잔차는 0.3~0.4%다.
- 영향 거래 ② 시점 판정이 최신 기준일에 기대는 거래(`adjacent_before`, `undetermined`, 계약연도가 직전 최신 기준연도 이상).
  - 새 기준일로 `contract_year`가 되거나 위험 표시가 정해질 수 있다.
- 값과 판정이 같은 필지는 새 관측이 와도 다시 쓰지 않는다.

**행정구역 코드 이력**
- 새 코드 쌍에 걸리는 거래만 코드 해석(`code_resolution`)과 연결을 다시 한다.

**통계 칸**
- 재보강된 거래가 속한 (시군구·유형·계약연도) 칸만 다시 계산한다.
- 통계 마트 갱신은 제품 반영 단계에서만 하고, 지금은 영향 칸 목록만 만든다.

### 2.2 영향 범위의 크기(추정)

| 분기 변경 | 영향 거래(추정) | 근거 |
|---|---|---|
| 실거래 12개월 창 | 창 안 신규·정정 해시 수천~1만여 건 | 월 신규 약 1만 건 수준 |
| 대장 새 판 | 계약년월이 새 판 이상인 거래(분기 몫 약 2~3만) | 판 선택 규칙 |

## 3. 판본과 저장

판본 디렉터리 하나에 아래를 함께 둔다(저장소 밖, `C:\CH2\parcel_master\versions\<domain>\<version_id>\`).

| 파일 | 내용 |
|---|---|
| `contract.sqlite` | 머리·값 표(계약 v1) + 고아 보관 표 + 변경 기록 표(§4) |
| `manifest.json` | 규칙 판, 원천 입력 목록과 SHA-256, 직전 판본 ID |
| `change_set.json` | 원천별 변경 건수, 영향 거래 수, 영향 통계 칸 수(건수만) |
| `gate.json` | 품질검사 결과 |
| `approval.json` | 승인 기록(있을 때만). 저장소 `docs/lab/approvals/`에도 사본 |

- 판본 ID 예: `built-2026Q4-r1`(분기·규칙 판).
- 활성 판본은 레지스트리 포인터 하나로 가리킨다. 청주 운영 경로(`ledger_operations_cli`)의 방식을 쓴다: 후보는 별도 디렉터리, 게시 시 포인터·revision·이벤트를 한 트랜잭션으로 바꾼다.
- 보관: 최근 3개 판본은 전체 SQLite(판본당 약 1.5GB), 그 이전은 manifest·change_set·gate·approval과 변경 기록만 남긴다. 원천 원본과 manifest가 있으면 어느 판본이든 다시 만들 수 있다.

## 4. 거래 해제·정정 처리

원칙: **과거 기록은 지우지 않는다. 현재 공급 대상에서만 뺀다.**

1. **감지:** 새 판본을 만들 때 직전 판본의 키 중 지금 원장에 없는 해시를 고아로 잡는다.
2. **분류(보고용):**
   - 같은 법정동·도로, 대장 판 창 안 계약, 같은 필지로 연결된 새 해시가 있으면 `rehashed_candidate`(정정 추정)로 둔다.
   - 같은 도로에 다른 필지 거래만 있으면 `relocated_or_removed`로 둔다.
   - 같은 도로에 거래가 없으면 `removed`(해제·삭제 추정)로 둔다.
   - 원천 해제 표시(정제 전 해제 열)를 얻을 수 있으면 그 근거를 같이 적는다.
3. **공급표 처리:**
   - 고아 행을 현재 머리·값 표에서 빼고, 같은 판본 SQLite의 `ledger_link_orphan_v1`로 옮긴다.
   - 옮길 때 보존하는 것: 직전 머리·값 전부, 고아가 된 판본 ID, 분류, 원천 지문.
   - 제품 조회는 현재 표만 읽으므로 고아는 자동으로 빠진다.
4. **새 해시:** 정정 추정이라도 옛 결과를 옮겨 붙이지 않는다. 미상 거래처럼 처음부터 연결한다. 정정으로 가격·면적·용도가 바뀌면 연결 근거도 바뀔 수 있기 때문이다.
5. **변경 근거:**
   - 판본마다 `ledger_link_change_v1`에 키별 변경을 남긴다.
   - 남기는 값: 종류(added / orphaned / relinked / value_changed / state_changed), 원인(tx_new / tx_removed / register_snapshot / land_base / code_change / rule), 직전·새 행 지문.
6. **정리:**
   - 연속 두 판본에서 고아인 행만 정리 후보가 된다. 정리는 승인 뒤에만 한다.
   - 정리 뒤에도 그 판본 디렉터리(보관 기간 안)와 변경 기록에는 남는다.
7. **동결 보강표(`built_transaction_enrichment`):** 이 규칙은 새 공급 계층에만 적용한다. 동결 보강표의 고아 285건은 지금처럼 보고만 하고 지우지 않는다. 동결 보강표에 손대는 일은 별도 승인 사항이다.
8. **해시 손실 점검:**
   - 해시에는 계약월·일이 없다. 같은 주소·연도·가격·연면적·용도의 거래 둘은 원장에서 하나로 합쳐진다.
   - 적재마다 정제 CSV에서 해시 필드는 같고 계약월·일만 다른 행 수를 센다.
   - 손실이 의미 있게 크면 해시 v2(계약월 포함)를 별도 결정으로 올린다. 해시 v2는 모든 키를 바꾸므로 전체 재구축과 연결 이관 계획이 같이 필요하다.

계약 v1 DDL은 고아 보관 표와 변경 기록 표를 아직 갖고 있지 않다. 구현하기로 하면 DDL 초안 v1.1에 두 표를 더하고, 이것도 적용 금지 초안으로 둔다.

## 5. 재현성 — 증분 결과와 전체 재구축 결과가 같아야 한다

### 5.1 비교 항목

같은 판본 정의(규칙 판 + 입력 목록)로 증분본과 전체본을 만든 뒤 아래를 비교한다. 하나라도 다르면 실패다.

| 수준 | 비교 |
|---|---|
| 건수 | 머리 행, 값 행, 고아 행, 변경 기록 행 |
| 키 | 머리 키 집합(누락·추가·중복), 값 키(대상×변수) 집합 |
| 연결 상태 | `link_state`, `link_level`, `building_id_state`, `bldrgst_pk`, `code_resolution`, `hold_flags`, `register_snapshot`, `register_after_contract`, `source_digest` |
| 속성값 | `value_num`, `value_text`, `value_level`, `source`, `basis_date`, `timing`, `change_risk`, `use_approved` |
| 결측 상태 | 값이 빈 행의 `value_state`(충돌 결측·원천 결측·미정·미연결 구분까지 같아야 함) |
| 전체 | 정렬된 전체 내용 지문 |

열마다 불일치 건수를 따로 낸다. 전체 지문만 보면 무엇이 다른지 알 수 없기 때문이다. 실행 시각·실행 ID 같은 값은 비교 열에 두지 않는다. 지금 공급표에도 이런 열은 없다.

### 5.2 추가 검사(증분 전용)

- **변경 회계:** 직전 현재 행 + 추가 − 고아 = 지금 현재 행. 바뀐 키에는 모두 변경 기록과 원인이 있어야 한다.
- **영향 밖 불변:** 영향 대상이 아닌 키는 직전 판본과 행 내용이 바이트 단위로 같아야 한다. 증분의 가장 강한 안전장치다.
- **순서 무관:** 같은 분기에 대장 판과 토지 기준일이 같이 오면 적용 순서를 바꿔도 결과 지문이 같아야 한다.

### 5.3 시험 계획 (새 원천 없이 지금 자료로)

| 시험 | 방법 | 통과 조건 |
|---|---|---|
| R1 같은 입력 재생성 | 이미 함: 두 번 만든 공급표 비교 | 지문 동일 — **통과(9단계)** |
| R2 대장 판 추가 재연 | 판본 A = 대장 판 {2024-09, 2025-07}. A에 2026-07을 증분 적용한 것과, 세 판으로 전체 구성한 것을 비교 | §5.1 전 항목 불일치 0, 영향 밖 불변 |
| R3 토지 기준일 추가 재연 | 판본 A = slim 기준연도 ≤ 2025(조회 필터). 2026 기준일 증분 적용 대 전체 구성 | 같음 |
| R4 거래 추가·삭제·정정 재연 | 실제 키 집합에서 표본을 빼거나 넣어 A·B를 만든다. 추가 = A에 없던 1% 표본. 삭제 = B에서 뺀 1% 표본. 정정 = 같은 필지 쌍을 한쪽은 삭제·한쪽은 추가 | 고아 분류 건수가 설계대로, 현재 표는 전체 구성과 같음 |
| R5 순서 무관 | R2와 R3를 두 순서로 적용 | 지문 동일 |
| R6 실패 주입 | 적재·영향 계산·재연결·품질검사·포인터 전환 단계마다 강제 실패 | 활성 판본·제품 표 변화 0, 후보만 남음 |
| R7 복구 | 게시 뒤 직전 판본으로 포인터 복구 | 복구 뒤 공급 출력 지문이 원래와 같음 |
| R8 품질 미달 차단 | 일부러 연결률을 떨어뜨린 후보(예: 한 시도 매칭 입력 제거) | 판정 blocked, 게시 명령이 승인 기록 없음으로 거절 |

- 원장·거래 DB는 읽기만 한다. A·B 키 집합은 빌더 입력 필터로 흉내 낸다.
- 필요한 빌더 변경: 대장 판 목록 인자, slim 기준연도 상한 인자, 키 부분집합 인자.
- 공간: 시험 SQLite 약 8개 × 1.5GB ≈ 12GB(C: 여유 552GB).
- 시간: 전국 매칭 한 구성 약 35분 + 공급표 수 분 기준으로, 전체 시험 약 반나절로 추정한다.

## 6. 실패와 복구

```text
접수(manifest·SHA-256) → 후보 생성(별도 디렉터리) → 품질검사 → 승인 기록 확인 → 게시(포인터 전환) → [제품 반영: 별도 승인]
```

- 후보 생성·품질검사는 활성 판본을 복사한 후보 안에서만 쓴다. 어느 단계에서 멈춰도 활성 포인터와 제품 표는 그대로다.
- 품질검사 판정이 blocked면 게시 명령이 거절한다. needs_waiver면 경고마다 면제 사유가 승인 기록에 있어야 한다.
- 게시 명령은 승인 기록의 판본 SQLite SHA-256과 품질검사 결과 SHA-256이 지금 후보와 같을 때만 실행한다. 다르면(후보가 바뀜) 거절한다.
- 원장 지문 검사(9단계 `integrity_ledger_digest`)가 후보 생성 뒤 원장이 바뀐 것을 잡는다. 낡은 후보는 다시 만든다.
- 복구는 포인터만 직전 판본으로 되돌린다. 판본 SQLite의 SHA-256을 확인한 뒤 바꾼다. 최신 판본과 이력은 지우지 않는다. 과거 판본으로 복구된 동안에는 새 적재를 막는다(청주 운영 경로와 같음).
- 제품 표(Postgres·VPS) 반영은 게시와 별개다. 승인 범위가 `product_switch`일 때만 하고, 기존 SOP의 백업 → 승격 → 롤백 절차를 따른다. 지금은 표본 정확도 미검증이라 열지 않는다.

## 7. 품질검사 보강

### 7.1 데이터 악화와 불확실 값 제거를 나눈다 (구현·재실행함)

`run_link_quality_gate_v1.py`에 `coverage_transitions`를 더했다. 대상 거래·변수마다 이전 확정값이 지금 어떻게 됐는지 나눈다.

| 분류 | 뜻 | 판정 |
|---|---|---|
| kept | 그대로 확정 | — |
| gain | 이전엔 없고 지금 확정 | 보고 |
| reclassified_uncertain | 후보 동일로 내림 | 불확실 값 제거 |
| removed_uncertain | 후보 충돌·미정으로 비움 | 불확실 값 제거 |
| source_loss | 원천 결측이 됨 | **실제 손실** |
| link_loss | 미연결이 됨 | **실제 손실** |

- `coverage_change`: 실제 손실만 센다. 전국 −1%p면 실패, 범위 −3%p면 경고다. 순변화가 크게 떨어졌지만 실제 손실이 아닌 범위는 `scopes_net_drop_explained`로 내역과 함께 보고한다.
- `coverage_uncertainty`(신규): 불확실 값 제거를 따로 센다. 전국에서 −1%p를 넘으면 경고한다. 식별 규칙이 퇴행한 신호로 보기 때문이다. 범위별 값은 보고만 한다.
- 재실행 결과: 확보율 통과(전국 실제 손실 0.01%p 이하), 불확실 값 통과(전국 −0.44~−0.45%p). 제주 구조·층수·사용승인은 "순변화 −6.55~−6.66%p, 실제 손실 0, 불확실 −7.57%p"로 보고된다. 판정은 여전히 **needs_waiver**(고아·용도지역 일치 경고 2개)다.

### 7.2 분기 자동 보고

품질검사 JSON에 이미 전국·시도·유형·계약연도별 연결률·확보율·충돌률·시점 적합률과 직전 판본 대비 변화(%p·건수), 확보율 변화 내역이 있다. 구현 시에는 여기서 사람이 읽는 분기 요약을 만든다.
- 판정
- 경고·실패 범위 표
- 연결률·확보율 변화 상위·하위 10개 범위
- 고아 분류
- 해시 손실 수
- 영향 거래 수

요약은 `docs/lab/quarterly/<version_id>.md`에 둔다. 범위 대상 1,000건 미만은 값만 내고 경보에서 뺀다(9단계와 같음).

### 7.3 증분용 검사 추가

§5.2의 변경 회계·영향 밖 불변·순서 무관에 해시 손실 수와 고아 분류 건수를 더한다. 증분본과 전체본 비교(§5.1)는 연 1회 정기로 돌리고, 규칙 판이 바뀔 때는 반드시 돌린다.

## 8. 대표 용도지역 원칙 (제안, 결정 필요)

한 필지에 용도지역이 둘 이상이면, 면적 비율 없이 하나를 임의로 고르지 않고 복수라는 사실을 보존한다.

- **원천이 정한 순서는 따른다.** slim(토지특성)에는 용도지역1·2 두 칸이 있고, 시험 공급표는 용도지역1을 쓴다. 토지특성 조사 지침상 용도지역1이 주된(면적이 큰) 용도지역인지는 지침 원문으로 **확인이 필요하다**. 확인되면 용도지역1을 대표값으로 둔다.
- **용도지역2가 있으면 버리지 않는다.** 변수 `zone_secondary`와 표시 `multi_zone`을 더한다. 계약연도 라벨이 있는 거래 중 용도지역2가 있는 것은 9,659건이다(4-D 집계).
- **AL_D155처럼 순서·면적이 없는 복수 라벨은 대표값을 만들지 않는다.** 라벨 집합 전체를 `zone_labels_all`로 두고 상태를 `multi_unranked`로 둔다. 기존 보강표가 "첫 세부 라벨"을 고른 것이 차이 88%의 원인이었다.
- **면적 비율을 얻게 되면**(용도지역 도형과 지적 도형 중첩) 면적 가중 대표값을 새 규칙 판으로 만든다. 이것은 증분이 아니라 전체 재구축이다.
- **표시:** 복수면 "제1종일반주거 외 1"처럼 보이고, 통계 묶음은 대표값 기준에 복수 여부 필터를 둔다. 가격 형성에 무엇을 쓸지는 통계적 효용 실험에서 정한다.
- 기본 표시 전환(D-050·D-051)은 여전히 회귀 비교 뒤 별도 결정이다.

## 10. 제품 공급 승인 조건

다음이 모두 맞아야 제품 공급 전환을 검토한다. 하나라도 빠지면 섀도 공급만 한다.

1. 품질검사 판정이 `eligible_for_approval`이거나, `needs_waiver`이고 경고마다 승인된 면제 사유가 있다.
2. 승인 기록이 판본·품질검사 결과의 SHA-256과 맞고, 승인 범위가 `product_switch`다.
3. **독립 표본 연결 정확도(4-C, KAIS 219건 등)가 판정됐고**, 기준을 넘는다. 기준값은 판정 전에 사용자가 정한다. 그때까지 품질검사의 `sample_accuracy`는 `unverified`이고 이 조건은 닫혀 있다.
4. 재현성 시험 R2~R8을 통과했다.
5. 대표 용도지역 원칙과 기본 표시가 결정됐다.

5. 토지·집합 시험 공급표와 같은 틀 적용
