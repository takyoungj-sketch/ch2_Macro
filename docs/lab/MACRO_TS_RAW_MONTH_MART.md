## 0. 한 줄

Insight #1·G3 월 실험은 **정제 원장 GROUP BY를 쓰지 않는다.**  
국토부 CSV(`raw long term` 2010~2020 + `raw base` 2021~)에서 **전국·달력월·8유형 건수·액만** 쌓은 실험 DB를 쓴다.  
같은 마트의 **연 합**은 Insight #5(연 규모·구성, 실험 전) 분자로 재사용한다. G3 연 r 표와 5번의 비율은 다른 질문이다.

---

## 1. 왜 고치나

2026-09-16 실측. 공개 거래규모 그래프가 2010년대 월 10조 미만 → 2020년 월 80조 근처로 뛰었다.

원인은 단위가 아니라 **원장 커버리지**다.

| | 2018 | 2019 |
|--|------|------|
| 아파트 연 건수(원장) | 7.3만 | 51만 |
| 아파트 연 액(원장) | 16조 | 186조 |
| 합계에서 토지 액 비중 | 69% | 17% |

토지 원장은 2010부터 있다. 집합·복합은 **2010~2018을 건별 원장에 넣지 않기로** 되어 있다 ([`ROLLING_WINDOW_7Y_PLAN.md`](../ROLLING_WINDOW_7Y_PLAN.md) §2.4). 2019·2020만 7년 창용으로 붙였다.

그래서 2010년대 「8유형 합계」는 토지 + 일부이고, 2019년 전년동월은 시장 급증이 아니라 원장이 붙은 해다. 그 변화율이 상관계수에 섞인다.

제품 원장은 주소·building_key·해제·용도·지분 등 **정제 게이트**를 지난다. 거시 실험이 보려는 것은 그 정제 결과가 아니라 **국토부가 그달 그 유형으로 공개한 거래의 전국 월 합**에 가깝다. 같은 CSV라도 원장과 실험 마트의 숫자가 달라도 된다. 실험은 raw 쪽을 SSOT로 한다.

## 3. 하는 일

전용 DB에 **전국 월 1행 유형**만 넣는다. 건별 원장이 아니다.

```
raw/raw long term/{유형}_2010_2020/*.csv     → 2010-01 … 2020-12
raw/raw base/{유형}_2021_2026/*.csv          → 2021-01 … 열린 달 직전
        ↓  계약년월 GROUP BY, 해제 행 제외
macro_ts_stats.national_month
        ↓
G3 compute_macro_ts (grain=calendar_month) · GET /api/insight/01
```

같은 연도를 long term과 base에서 동시에 읽지 않는다. **2020까지 long term, 2021부터 base.**

## 5. 단독다가구 재수집 (사용자)

국토부 수집기. 방어 규칙 [`MOLIT_CSV_COLLECTOR_WARNINGS.md`](../MOLIT_CSV_COLLECTOR_WARNINGS.md). **2019·2020 파일은 다시 받지 않는다** (이미 32 CSV = 16시도×2년).

### 5.1 받을 것

- 유형: **단독다가구 · 매매만** (전월세 아님)
- 기간: **2010-01 ~ 2018-12**
- 저장: `E:\ch2\ch2_Macro\raw\raw long term\단독다가구_2010_2020\`
- 기대: 시도×9년. 현재 수집기 16시도 기준 **144 CSV**. 1회 상한 100이라 **두 번** 돌린다.

### 5.2 CLI 예

저장 폴더는 기존 2019·2020과 **같은 폴더**. `max-new-downloads`가 기존 파일을 건너뛴다.

```powershell
cd E:\ch2\ch2_Macro\deploy\molit_csv_collector
py -m molit_csv_collector --cli --property-type detached --deal-type sale --start-year 2010 --start-month 1 --end-year 2018 --end-month 12 --output-dir "E:\ch2\ch2_Macro\raw\raw long term\단독다가구_2010_2020" --max-new-downloads 100
```

끝나면 같은 명령을 한 번 더 돌려 나머지를 채운다.

GUI면 유형은 단독다가구만, 매매, 2010-01~2018-12, 출력 폴더 위와 동일.

### 5.3 게이트 (수집 끝)

| 확인 | 기준 |
|------|------|
| 폴더 CSV 수 | 2019–2020 32 + 2010–2018 신규. 16시도×9년이면 합 **176** |
| 파일명 연도 | `*_단독다가구_매매_YYYY.csv` 의 YYYY가 메타 `계약일자`와 같음 |
| 실패 | `.download_failures.jsonl` · `failed/` 비우기 |
| 2010·2015·2018 | 서울·경기 파일이 0바이트가 아님 |

시도 목록이 예전에 광주·전남 분리(17)였으면 파일 수가 176을 넘을 수 있다. 수는 로그에 적고, **연도 2010–2018이 비면** 그 시도만 재실행.

### 5.4 같이 받으면 좋은 것

토지 long term 폴더가 비어 있다. 실험 결을 raw로 통일하려면:

```powershell
py -m molit_csv_collector --cli --property-type land --deal-type sale --start-year 2010 --start-month 1 --end-year 2020 --end-month 12 --output-dir "E:\ch2\ch2_Macro\raw\raw long term\토지_2010_2020" --max-new-downloads 100
```

토지 2010–2020은 용량이 크다. 단독을 먼저 채워도 마트 뼈는 만들 수 있다. 다만 **합계 선을 2010부터 공개하려면 토지 raw가 있어야** 한다. 그 전에는 합계를 2010부터 그리지 않는다.

## 6. 실험 DB

제품 `land_stats` / `built_stats` / `collective_stats`와 **분리**한다.

| | 값 |
|--|-----|
| DB (가칭) | `macro_ts_stats` |
| 테이블 | `national_month` |
| grain | `calendar_year` × `calendar_month` × `mix_type` |
| 값 | `n` (건), `amount_10k` (만원 합) |
| 출처 열 | `source` = `long_term` \| `base`, `built_at` |
| 유형 | D-027과 같음. 상가 = 상업업무 일반+집합, 공장 = 공장창고 일반+집합 |

`mix_type`: 토지, 상가, 공장, 단독다가구, 아파트, 오피스텔, 연립다세대, 분양권. 합계는 조회 시 8개를 더한다. 합계 행을 저장해도 된다.

열린 달(이번 달)은 넣지 않는다. G3와 같다.

## 7. 행을 셀 때 (최소 정제)

원장 파이프라인을 돌리지 않는다. CSV에서 전국 합만.

| 적용 | 적용하지 않음 |
|------|----------------|
| 면책 상단 skiprows (국토부 15행) | building_key, 주소 복원, 용도지역·지목 필수 |
| 해제사유발생일이 있으면 제외 | `is_valid`, 단가 NOT NULL |
| 계약년월 파싱 실패·금액≤0 제외 | 지분 거래 제외 여부 — **1차는 포함**(국토부 행 그대로). 빼면 메모 |
| 상업업무·공장창고: `유형=일반` → 복합 쪽, `유형=집합` → 집합 쪽, 둘을 상가/공장에 합침 | 시군구 코드 매핑 |

금액 단위는 CSV **거래금액(만원)**. 차트 축은 기존처럼 조원/월.

스키마 iloc는 기존 SSOT를 재사용한다. 집합 [`pipeline/collective/molit_schemas.py`](../../pipeline/collective/molit_schemas.py), 복합 [`pipeline/built/molit_schemas.py`](../../pipeline/built/molit_schemas.py), 토지는 수집기·land refine의 계약년월·금액 열.

## 8. 게이트 (마트 적재 후)

숫자 게이트. 통과 전에 Insight 표를 갈아끼우지 않는다.

1. **이음**  
   각 유형 월 시계열이 2010-01(수집된 유형)부터 열린 달 직전까지 빈 달이 없다. 단독은 수집 전에 2019-01부터만 있어도 된다.
2. **2018→2019 아파트**  
   원장처럼 연 건수가 7만→51만으로 뛰면 **실패**. raw가 붙으면 2010년대 아파트 연 건수는 수십만 규모여야 한다.
3. **2020 vs 2021**  
   long term 마지막 해와 base 첫 해의 월평균 건수가 유형별로 한 자릿수 배로 갈라지지 않는다. (시장 변동은 허용, 원장 단절 수준의 10배는 실패)
4. **파일 공백**  
   오피스텔·토지 base 결번을 `coverage_notes`에 남긴다. 합계 공개 문장에 숨기지 않는다.
5. **진단용(SSOT 아님)**  
   2019–2020 아파트 월 합을 지금 원장과 비교해 표를 남긴다. 달라도 실험은 raw를 따른다.

## 9. G3·Insight 연결

| 지금 | 이후 |
|------|------|
| `compute_macro_ts` 월 = `national_month`. 연 = 같은 표의 달력연 합(12개월 미만 제외) | 단가. Insight 본문은 월 |
| Insight `GET /api/insight/01` · G3 `?tool=g3` 월 | 같은 compute. 공개 본문은 2026-09-16 r에 맞춤 |
| 공개 기간 | 8유형 2010-01~열린 달 직전 |

ECOS 금리·M2는 그대로 `data/한은 월간/`.

공개 창은 마트가 붙기 전까지 **2010년대 합계 선을 관계처럼 읽게 두지 않는다.** 선택:

- A. 수준·상관을 게이트 통과 전엔 올리지 않거나
- B. 임시로 **2021-01~** (base만, 전년동월은 2022부터)만 보여 준다

A를 기본으로 한다. 지금 올려 둔 2010~ 합계·2019 YoY r는 실험 기록이 아니라 원장 공백 기록이다.

카피: 합계는 여전히 「모든 부동산」이 아니다. 다만 「2010년대는 토지만」이라는 오해 설명은 마트 이후에 바꾼다.
