이 단계는 **데이터 품질 검증**(거래와 대장 속성이 제대로 이어졌나)이다. **통계적 효용 검증**(대장 속성이 회귀 설명력·예측력을 높이나)은 공급 체계가 안정된 뒤 별도 실험으로 한다.

## 1. 지표 — 서로 섞지 않는다

| 지표 | 뜻 | 분모 | 지금 |
|---|---|---|---|
| 연결 성공률 | 대상 중 대장 필지·건물에 이어진 비율 | 대상(연결+미연결) | 76.42% |
| 연결 정확도 | 이어진 건물이 실제 거래 건물인 비율 | 독립 표본 | **미검증**(판정 0건) |
| 속성 확보율 | 변수별 확정값 비율 | 대상, 연결 각각 | 구조 75.9% / 99.4% |
| 시점 적합률 | 값이 계약 시점에 맞는 비율 | 연결 | 계약연도 용도지역 97.73%, 계약 뒤 대장 판 80.8% |
| 속성 충돌률 | 후보끼리 값이 달라 비운 비율 | 연결 | 변수별 0.01~0.04% |

"확정"은 **현재 연결 규칙상 식별이 하나로 정해졌다**는 뜻이다. 실제 거래 건물과 맞는지는 독립 표본 판정 전까지 말하지 않는다.

모든 지표는 전국, 시도, 거래 유형, 계약연도별로 낸다. 각 범위에 전체·대상·연결·미연결·해당 없음 건수를 붙이고, 이전 판본 대비 변화(%p와 건수)를 같이 둔다. 범위의 대상이 1,000건 미만이면 경보에서 뺀다(값은 낸다).

## 2. 검사 항목

검사 결과마다 **전체 분모, 검사 대상 분모, 미검증 건수, 불일치 건수**를 적는다.

| 검사 | 내용 | 실패 | 경고 |
|---|---|---|---|
| 키 정합 | 원장 키 대비 누락·추가·중복 | 1건 이상 | — |
| 원장 지문 | 판본을 만든 뒤 원장 행이 바뀌었나 | 1건 이상(판본이 낡음) | — |
| 이전 결과 고아 | 이전 결과 중 원장에서 사라진 거래 | 이전 결과의 0.1% 초과 | 1건 이상 |
| 계약 규칙 | 상태 밖 값, 승인 없는 후보 동일 사용, 확정 아닌 관리번호 | 1건 이상 | — |
| 연결률 변화 | 전국·범위별 연결률 하락 | 전국 −1%p, 범위 −3%p | 범위 −1.5%p |
| 확보율 변화 | 이전 확정값이 원천 결측·미연결이 된 **실제 손실**만 센다(10-18 개정) | 전국 −1%p | 범위 −3%p |
| 불확실 값 제거 | 이전 확정값을 식별이 안 돼 후보 동일·충돌로 내린 몫. 범위별 값은 보고만 | — | 전국 −1%p |
| 충돌률 | 변수별 충돌 비율 상승 | — | 전국 +0.2%p |
| 시점 적합 | 계약연도 용도지역 비율 하락 | — | 전국 −1%p |
| 이전 결과 일치 | 같은 거래의 변수 값이 이전 판본과 같은 비율 | — | 건물 변수 99%, 용도지역 95% 미만 |
| 재생성 안정성 | 같은 입력으로 다시 만든 판본과 내용 지문 비교 | 다르면 | 재생성본 없음 |
| 표본 정확도 | 독립 표본 판정 | — | 항상 "미검증" 표시. 제품 전환 판단을 막음 |

문턱값은 초안이다. 문턱값 자체의 승인은 별도 결정이다.

## 3. 판정과 승인 절차

```text
판본 생성 → 품질검사 → 판정
  실패 1개 이상      → blocked: 제품 반영 불가. 원인 수정 후 새 판본
  경고만             → needs_waiver: 경고마다 사유를 적은 면제 기록이 있어야 다음으로
  통과               → eligible_for_approval: 승인 대상일 뿐, 자동 반영 아님
승인 기록(판본·검사 결과 지문·면제 사유·승인자·날짜) → 그때만 제품 반영 작업 시작
```

- 품질검사 스크립트는 제품 표에 쓰지 않는다. 반영 스크립트는 승인 기록 파일이 있고, 그 기록의 판본·검사 결과가 지금 검사 결과와 같을 때만 실행하게 만든다(8단계 구현).
- 표본 정확도가 "미검증"인 동안은 판정이 통과여도 **제품 공급 전환**(D-050·D-051 개정)은 열지 않는다. 시험·섀도 공급만 가능하다.
- 승인 기록은 저장소 `docs/lab/approvals/`에 판본마다 한 파일로 둔다. 양식은 `quality_gate_approval_template_v1.json`.

### 경고에 대한 면제 사유 (제안)

1. **고아 285건** — 원인 조사 결과(§6) 정정·해제로 원장에서 사라진 거래다. 새 판본은 이 거래를 담지 않으므로 새 공급에는 영향이 없다. 8단계 고아 처리 규칙으로 넘긴다.
2. **제주 확보율 하락** — 제주는 같은 필지 같은 연면적 동이 많아 관리번호 미정 941건(후보 동일 880·충돌 61)이다. 기존 표는 첫 동 값을 채웠고, 새 공급은 동이 정해지지 않으면 확정값으로 세지 않는다. 의도된 변화다. 행 단위 추적 결과 실제 손실은 0이고, 확보율 검사가 실제 손실과 불확실 값 제거를 나눠 보게 바꿔 이 경고는 없어졌다.
3. **용도지역 일치 93.34%** — 원인 분석 결과(§5) 88%가 대표 라벨 선택 규칙 차이이고, 상가·공장 거래 원천과는 새 값이 더 잘 맞는다. 기본 표시 전환은 별도 결정으로 남긴다.

- 기존 표가 복수 라벨을 가진 거래가 차이의 89%(28,776 / 32,404)다. 차이 대부분은 "어느 라벨을 대표로 고르나"의 문제다.
- 상가·공장 거래 원천 용도지역이 있는 131,767건에서 원천과 같은 비율: 기존 표시값 86.4%, 기존 라벨 목록 중 하나 93.4%, 새 최신값 97.6%, 새 계약연도 값 96.6%.
- 상위 쌍은 보전관리→계획관리 4,154, 농림→계획관리 2,721, 자연녹지→개발제한구역 2,670, 생산관리→계획관리 2,502 등 관리지역·녹지 경계 필지다.
- 연결 오류가 원인일 수 있는 차이는 최대 약 200건(비교 대상의 0.04%)이다. 표본 판정 때 이 묶음을 우선 본다.
- 기존 결측 11,525건 중 7,438건은 AL_D155 값이 없었고 4,087건은 대분류 라벨뿐이었다. 새 값은 그중 10,608건을 채웠다.

## 6. 고아 285건 원인

거래 해시는 유형, 주소(addr1~5), 지번, 계약연도, 가격, 연면적, 건물용도로 만든다(`pipeline/built/import_refined.py`). 정정으로 가격·면적·용도가 바뀌면 같은 거래가 새 해시로 들어오고, 해제된 거래는 정제 단계에서 빠진다(`refine_built.py` 해제 열). 동결 보강 행은 FK가 없어(069) 남는다.

| 확인 | 결과 |
|---|---|
| 생성 시점 | 285건 모두 2026-08-23 동결 적재 |
| 사용한 대장 판 | 2025-07 218, 2026-07 67 — 모두 최근 계약으로, 월간 재적재 창(9·10월)에 든다 |
| 같은 법정동·도로, 판 창 안 계약, 같은 필지로 연결된 새 해시가 있음 | 100 — **정정으로 해시가 바뀐 것으로 추정** |
| 같은 도로에 다른 필지 거래만 있음 | 73 — 해제·삭제 또는 정정으로 필지가 달라짐 |
| 같은 도로에 지금 거래 없음 | 112 — **해제·삭제로 추정** |

원천 해제 기록과 대조하지 않았으므로 정정·해제 구분은 추정이다. 계약월은 해시에 들어가지 않아 같은 주소·연도·가격·면적·용도의 거래가 둘이면 하나로 합쳐진다(`ON CONFLICT DO NOTHING`) — 8단계 해시 안정성 점검 대상.

## 7. 8단계로 넘기는 규칙 (초안)

1. **고아 감지:** 월간·분기 적재마다 기존 결과(보강표·공급표) 중 원장에 없는 해시를 센다. 품질검사 "이전 결과 고아"가 이 일을 한다.
2. **분류:** 같은 필지·도로·계약 창에 새 해시가 있으면 `rehashed_candidate`, 없으면 `removed`(해제·삭제 추정).
3. **처리:** 고아 행은 자동 삭제하지 않는다. 공급표에서는 상태 `orphaned`로 내리고 제품 조회에서 빠지게 한다. 새 해시는 미상 거래처럼 새로 연결한다(옛 결과를 옮겨 붙이지 않음).
4. **보관:** 고아 행은 판본과 함께 보관하고, 연속 두 판본에서 고아이면 정리 후보로 올린다. 정리는 승인 뒤.
5. **해시 점검:** 해시 필드에 없는 값(계약월·일)이 다른 중복 거래의 손실 건수를 적재마다 센다.
