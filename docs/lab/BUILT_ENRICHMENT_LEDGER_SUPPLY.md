# 복합 보강 — 대장 공급 재현·전환 (계획 4단계)

계획: [`docs/LEDGER_NEXT_PHASE_PLAN.md`](../LEDGER_NEXT_PHASE_PLAN.md) 4단계 · 2026-10-17
보강 본문: [`docs/BUILT_DATA_ENRICHMENT.md`](../BUILT_DATA_ENRICHMENT.md) · 원장: [`BUILDING_LEDGER_V1_DESIGN.md`](BUILDING_LEDGER_V1_DESIGN.md)

대상은 계약 2019+ 거래 663,596건(16시도), 규칙은 A1/A2 + `time_fallback`(기준 판 2026-07) 그대로다. DB는 읽기만 했다.

## 1. 건물 공급 — 원장에서 그대로 재현된다

| 확인 | 결과 |
|---|---|
| 원장 → 시도별 캐시 96개(16시도 × 3판 × 표제부·총괄) | 원본 캐시와 **행 순서까지 96/96 동일** |
| 같은 캐시로 매칭 | 확정 결과 동일(시도 12·30 재실행 53,717 / 14,067건 전부 일치) |
| 파이프라인 경로(`--register-source ledger`) | 세종 2026-07 표제부 파일이 원본 캐시와 바이트 동일 |

- **원문 줄 순서가 규칙의 입력이다.** 같은 필지에 대지면적·동이 여럿이면 먼저 나온 값을 쓰므로, 원장 v1을 관리번호 순으로 읽으면 시도마다 0.1~0.5%가 달라졌다(전국 확정 505,151건 중 755건, `built_enrichment_ledger_replay_20261017.json`). 동결 원장은 건드리지 않고 원본 줄 번호만 담은 별도 파일 `C:\CH2\parcel_master\building_ledger_v1_line_order.sqlite`를 만들었다(6개 원본 행 수·sha256 일치, 줄마다 원장 원문 해시와 대조해 불일치 0). 이 순서로 읽으면 위 표처럼 완전히 같다.
- 비용: 원장 → 캐시 96개 약 12분. 원본 재스캔과 비슷하다. 이득은 시간이 아니라 원본 TXT 없이 같은 입력을 재현할 수 있다는 점과 관리번호다.

## 2. 동결 행 재현

지금 코드로 다시 돌린 결과 vs `built_transaction_enrichment` 동결 498,283행:

- 같음 **498,210 (99.985%)**, 다름 67, 재현 안 됨 6. 다른 67건 중 필지가 다른 것은 2건이고 나머지는 사용 판·후보 수 기록 차이.
- 동결 이후 새로 확정되는 거래 6,874건(동결 정책상 기존 행은 다시 매칭하지 않는다).
- 73건의 원인은 아직 분해하지 않았다(동결 당시 캐시·코드 판 차이로 추정).

## 3. 표제부 관리번호(`bldrgst_pk`)

- 동결 행은 0건 채워져 있다.
- 확정 행 중 **99.4%(502,029 / 505,077)는 관리번호가 하나로 정해진다.** 0.6%(3,048)는 같은 필지에 같은 연면적 동이 여럿이라 비운다(구조 등은 기존대로 첫 동).
- 코드 반영: 새로 확정되는 행부터 채운다. 기존 동결 행에 채우려면 enrichment 표 UPDATE가 필요해 따로 결정한다.

## 4. 토지 공급 — 대지면적 (A2 셋째 대체값)

토지대장(AL_D003, 최신판, 지목 대) 대신 토지특성 slim(가장 최근 기준일, 지목 08=대)으로 바꿔 같은 규칙을 돌렸다(`built_enrichment_land_supply_20261017.json`).

| | AL_D003 | slim |
|---|---:|---:|
| 확정(시도 12 제외) | 451,434 | 451,601 (+167) |
| 시도 12 확정 | 53,717 | 51,934 (−1,783) |

- 시도 12 제외 시 99.97% 동일, 새 확정 221 · 풀림 54 · 필지/등급 변경 58.
- 시도 12는 slim에 새 코드가 없어 A2 1,855건이 빠진다 → 코드 이력 연결 전에는 전환 불가.
- 두 사전이 모두 값을 가진 필지에서 면적 동일 99.0%(4,147,818 / 4,187,539).
- 판단: 정확도 영향은 거의 없다. 전환 이유는 AL_D003 시도별 수집을 없애는 것이고, 시도 12 연결이 선행 조건이다.

## 5. 토지 공급 — 용도지역

동결 행의 AL_D155(최신판) 라벨 vs slim의 계약연도 용도지역(`built_enrichment_zone_supply_20261017.json`).
상가·공장은 거래 원천에 용도지역이 있어 두 공급을 같은 기준으로 대조할 수 있다.

| 상가·공장, 거래 원천 용도지역과 일치 | 일치율 |
|---|---:|
| slim 계약연도 용도지역 | **98.7%** (110,795 / 112,252) |
| AL_D155 최신판 대표 라벨 | 80.5% (103,048 / 127,966) |

- slim이 값을 못 주는 행 16.3%: 필지 없음 10.8%(대부분 시도 12, 53,020행), 계약연도 자료 없음 5.5%.
- 두 공급이 모두 있는 행에서 slim이 AL_D155 라벨 중 하나와 같은 비율 97.1%, 대표 라벨과 같은 비율 84.6%.
- 주의: 거래 원천 용도지역이 토지특성에서 왔을 수 있어 98.7%는 "정답률"이 아니라 "사용자가 원천에서 보는 값과의 정합"이다.
- 판단: 표시 용도지역은 slim 계약연도 값이 원천과 훨씬 잘 맞는다. 다만 D-050(대표 1개)·D-051(동의 문구)과 회귀 비교가 걸려 있어 바꾸려면 결정이 필요하다.
