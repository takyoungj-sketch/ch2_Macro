# 집합 단지 속성 — 다중후보(D·F)

> **상태:** 적용. 세대수=후보 합산, 시공사=첫 단지 + `외`, 지역회귀 hard 표본에 D·F 포함.  
> **기준:** `collective_building_attributes` snapshot `202607` · 아파트만  
> **데이터:** [`collective_danji_unmatched_backlog.json`](collective_danji_unmatched_backlog.json) (거래수 상위 25 필지)  
> **백필:** `python -m parcel_master.apply_multi_kapt`

## 범위

축약대장·PNU가 **못 푸는** 구멍이었다. K-apt가 같은 지번에 단지를 둘 이상으로 쪼갠 경우(D `lot_multi`)와, 단지명 부분일치 후보가 여럿인 경우(F `contains_multi`).

| tier | 규칙 | 단지 | 거래 |
|------|------|------|------|
| D | lot_multi | 249 | 77,866 |
| F | contains_multi | 126 | 7,692 |
| **합** | | **375** | **85,558** |

Z(미매칭)는 다른 문제다. K-apt 의무관리 밖·이름 불일치이며 표제부 「집합」이 메울 칸이다. 다만 **PNU는 유일한데도 목록을 안 채우는** 구멍은 아래에 따로 적는다.

## 적용 규칙 (2026-08-22)

1. **목록:** 세대수 = 후보 **합산**, 시공사 = 단지명순 첫 단지 시공사 + `외`. **첫째 행을 대표값으로 쓰지 않는다.**
2. **모달:** 후보 행을 모두 보여 준다. 합산은 목록·규모 칸 요약이다.
3. **지역회귀:** D·F를 hard 표본에 넣는다. 시공사 더미는 목록과 같은 `{첫 시공사} 외`. F는 실거래명 6글자 이상·후보 4곳 이하만 합산한다(「부평」이 동 전체 단지를 삼키지 않게).
4. 후보는 `match_danji_codes`(쉼표 구분). `danji_code`는 정렬 후 첫 코드.
5. 재건축·묶음 Z(경성맨션2·계룡맨션, 남산주공3 등)는 채우지 않는다.

## PNU 유일인데 안 채움 (재건축 2 · 묶음 6)

대전·충북 `pnu_new` 22단지 이름 확인. 약칭 14곳은 tier `P` / `pnu_unique` 로 세대수·시공사를 목록에 넣는다. 아래 8곳은 넣지 않는다. P·T는 지역회귀에 넣지 않는다.

**재건축 — 같은 필지, 다른 건물. 옛 거래에 새 단지 정보를 붙이지 않는다.**

## 재집계

```sql
SELECT match_tier, match_rule, COUNT(*) AS n, SUM(n_tx) AS tx,
       COUNT(households) AS hh_filled
FROM collective_building_attributes
WHERE snapshot_ym = (SELECT MAX(snapshot_ym) FROM collective_building_attributes)
  AND asset_type = 'apartment'
  AND match_tier IN ('D', 'F')
GROUP BY 1, 2;
```
