# 복합 거래 당시 용도지역 v1 (계획 4-D)

계획: [`LEDGER_NEXT_PHASE_PLAN.md`](../LEDGER_NEXT_PHASE_PLAN.md) 4단계 · 2026-10-18 · 앞 단계: [`BUILT_LINK_QUALITY_V1.md`](BUILT_LINK_QUALITY_V1.md)

대상: 4-C 제안 구성에서 연결된 계약 2019+ 복합 거래 507,116건. 용도지역은 토지 slim의 용도지역1(기준연도별)에서 읽었다. 원장·거래 DB·`built_transaction_enrichment`는 읽기만 했다. 행 단위 결과는 `C:\CH2\parcel_master\verification\built_zone_asof_v1_rows.pkl`, 랩 JSON(`built_zone_asof_v1_20261018.json`)에는 건수만 있다.

## 상태 구분

토지특성은 기준일(기준연도 1월 1일, 일부 7월 1일)마다 값이 있다. 계약 (연, 월)에 대해:

| 상태 | 뜻 | 보존하는 연도 |
|---|---|---|
| **관측** | 계약연도 기준일 중 계약월 이전 것이 있다 | 그 기준연도 |
| **추정** | 계약연도 값이 없고, 앞(전년)과 뒤(같은 해 하반기 또는 다음 해) 기준일 값이 같다 | 앞·뒤 기준연도 |
| **인접(이전)** | 전년 값만 있다. 계약 시점까지 바뀌었을 수 있다 | 전년 |
| **인접(이후)** | 계약 뒤 기준일 값만 있다. 계약 후 관측이다 | 다음 기준연도 |
| **확인 불가** | 1년 안에 기준일이 없음, 앞뒤 값이 다름, 한 기준일에 값이 둘, 필지 없음, 필지 코드가 계약보다 늦게 생김 | — |

기준연도는 토지특성 조사 기준일이지 **용도지역이 실제로 바뀐 날이 아니다.** "관측"은 계약연도 기준일 값이 있다는 뜻이고, 그해 중간에 바뀐 것까지 보장하지 않는다.

코드 연결: 시도 12는 4-A 대응표, 전북 52←45·강원 51←42는 토지 코드 이력 층 V1의 앞자리 교체 규칙을 썼다. 승인된 대응이 없는 시군구 개편(부천·화성 일반구, 인천 2026-07 개편, 군위 편입)은 연결하지 않고 확인 불가로 남겼다.

- 최신값을 거래에 붙이면 약 1.9%(9,476건)가 거래 당시와 다른 용도지역으로 보이게 된다.

## 3. 원천 대조 (상가·공장)

상가·공장은 거래 원천에 용도지역이 있다. 다만 원천 값이 토지특성에서 왔을 수 있어 정답률이 아니라 정합이다.

| slim 값 | 원천과 같음 |
|---|---:|
| 거래 당시(전체) | **98.7%** (129,835 / 131,553) |
| — 관측 | 98.7% (128,732 / 130,378) |
| — 인접(이후) | 93.1% (925 / 994) |
| 최신 | 97.7% (128,513 / 131,553) |

거래 당시 값이 최신값보다 원천과 1.0%p 더 맞는다. 계약 후 관측(인접 이후)은 93.1%로 떨어져, 이후 관측을 계약 당시 값처럼 쓰면 안 된다는 원칙이 숫자로 확인된다.

AL_D155(현재 보강 표시값, 최신판 대표 라벨)와는 대표 라벨이 같은 비율 83.7%, 거래 당시 값이 AL_D155 라벨 중 하나에 들어가는 비율 97.4%다. 대표 라벨 차이 대부분은 한 필지의 복수 용도지역 중 무엇을 대표로 골랐는지의 차이다(기존 진단과 같음).

## 4. 결정 초안 (미적용)

D-050(제품 용도지역은 대표 1개)·D-051(원장 `zone_type` 미덮기, 표시=필터)에 걸리므로 결정 전에는 바꾸지 않는다.

1. 보강 용도지역의 기본 표시값을 AL_D155 최신판 대표 라벨에서 **토지 slim 거래 당시 값**으로 바꾼다. 상태가 관측·추정·인접(이전)일 때만 쓴다.
2. 인접(이후)·확인 불가는 거래 당시 값을 비우고, 최신 값은 "현재 용도지역"으로 따로 보인다. 계약 후 관측을 거래 당시 값으로 쓰지 않는다.
3. 행마다 상태와 기준연도를 함께 저장한다(예: `zone_asof_status`, `zone_asof_year`). 표시 문구는 "용도지역(YYYY년 기준)"처럼 기준연도를 드러낸다.
4. 거래 원천 `zone_type`은 그대로 두고 덮지 않는다(D-051 유지).
5. 승인 대응이 없는 시군구 개편 지역(약 7천 건)은 코드 이력 대응을 따로 만든 뒤 다시 잰다.

적용하려면 enrichment 표에 열 추가와 기존 행 값 채움이 필요하다. 기존 결과를 바꾸는 일이므로 별도 승인 대상이다.
