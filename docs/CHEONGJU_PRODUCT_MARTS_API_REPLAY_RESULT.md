# 청주 가격 마트·제품 응답 함수 병행 검증

후속 [실제 SQL·FastAPI 요청 검증](CHEONGJU_PRODUCT_HTTP_SQL_RESULT.md)에서 실제 PostgreSQL 임시 입력과 앱 라우터에 각 경로 122개 요청을 실행하여 상태·본문 일치를 확인했다. 기존 한 명령에 추가했으며 TCP/nginx/브라우저 검증은 별도다. 아래는 앞서 수행한 응답 함수 단계의 기록이다.

2026-10-05. [숫자 공급·회귀 재현](CHEONGJU_PRODUCT_NUMERIC_SUPPLY_RESULT.md)의 다음 단계로 기존 집계 함수와 제품 응답 변환 함수를 동결 자료에 실행했다. 고정 입력의 가격 집계와 응답 호환성을 확인했다. 운영 DB·backend 코드는 이번 작업에서 수정하지 않았다.

## 실제 검증 범위와 결과

주거 거래 108,077건을 기존 `build_collective_building_stats._records_from_row`에, 비주거 3,987건을 기존 `build_collective_commercial_cluster_stats._record_from_row`에 다시 공급했다. 주거 1,471개·비주거 306개 마트의 거래 수·평균·표준편차·신뢰구간·최솟값·25분위·중앙값·75분위·최댓값은 기존 저장값과 모두 같았다. 두 자산군 모두 차이 0개다. 거래의 유효성·양수 단가·기간·키 집합도 확인했다.

마트의 주소·군집 설명 등 메타데이터는 동결값을 유지했다. 이번 범위는 7년 창의 가격 열 재계산이며 SQL MAX 메타데이터 집계, 연간 마트, 다른 창, 전체 PostgreSQL 마트 재생성은 아니다. 가격 집계 자체는 대장 속성을 사용하지 않는다. 대장 공급 효과는 가격 집계 뒤 붙는 속성·가격·품질 표시에서 검증했다.

주거는 실제 `_stats_row_from_parts`, 분석 게이트 함수, `attach_danji_list_fields`와 Pydantic 응답 검증을 실행했다. 기존 값과 통합 공급 값의 세대수·이상값 표시·시공사·매칭 등급/규칙·공시지가/연도·주소·분석 게이트가 모두 같았다. 속성 조회에는 동결 행을 반환하는 제한된 SELECT 어댑터를 사용했다. 허용한 네 조회 형태 이외에는 실패하며 임의의 빈 결과를 반환하지 않는다. 스냅샷 최댓값은 동결 범위의 값이다.

비주거는 기존 도로명 군집 응답 함수 `_cluster_row_from_parts`로 306개 응답을 검증했다. 주거 속성 합산을 적용하지 않았다. 복합은 실제 `_serialize_tx_row`와 응답 스키마로 거래 13,293건을 원장 표시·보강 표시 각각 비교했고 모두 같았다. 용도지역과 복구 지번 표시는 기존 함수의 규칙을 사용했다. 거래 해시·키를 새로 바꾸거나 관리 PK를 부여하지 않았다.

이는 **실제 제품 응답 함수의 오프라인 검증**이다. HTTP 라우팅·인증·필터·정렬·페이지·SQL 조인 실행·전체 응답 envelope의 종단 검증을 완료했다는 뜻은 아니다. 분석 게이트도 동결 거래 연도를 사용하며 실제 연간 테이블 조회는 하지 않았다.

## 공급 소비와 실패 처리

새 소비 검증기는 성공 공급 manifest의 정확한 보고서·스크립트 목록, 모든 성공 체크, SHA, gzip 및 내용 SHA, 기준 입력·선택 판본의 일치를 확인한 뒤 자료를 연다. 비교가 끝날 때 manifest를 다시 확인하여 실행 중 다른 공급 세대가 게시되면 중단한다. 새 보강·합산·회귀 사용 권한이 false인지도 확인한다.

한 명령 실행은 원천 공급 → 실제 회귀 → 가격 마트 재계산 → 응답 변환 → 코드/산출물 해시 검증 → 최종 성공 manifest 순이다. 실패 시 새 성공 manifest를 쓰지 않는다. 이전 manifest가 남아 있더라도 현재 공급 및 보고서 해시가 같아야 유효하므로 파일 존재만으로 성공을 판단하면 안 된다. 원본·거래·상세 응답은 연구 폴더의 gzip으로 보존하고 커밋하지 않는다.

실제 전체 실행은 약 54초에 통과했다. 이는 로컬 고정 자료의 배치 실행 시간이며 제품 API 지연 시간이 아니다.

```powershell
pipeline\.venv\Scripts\python.exe pipeline/parcel_master/run_cheongju_product_acceptance.py
```

가격·응답 검증만 재실행하려면 완료된 공급 manifest가 필요하다.

```powershell
backend\.venv\Scripts\python.exe pipeline/parcel_master/replay_cheongju_supply_marts_api.py
```

관련 테스트는 **151개**가 통과했다. 추가 검사는 혼합된 보고서 세대·변경된 실행 코드·실패/누락 성공 체크의 차단, 미지원 SELECT 차단, 자산 유형별 최신 가격 구분을 검증한다. 기존 dirty 제품 파일은 보존했고 실제 실행한 작업폴더 코드의 SHA를 보고서에 기록했다. 재현할 때 해당 코드 판본이 맞아야 한다.
