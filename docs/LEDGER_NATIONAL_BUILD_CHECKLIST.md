# 전국 공통 대장 구축 전 체크리스트

2026-10-05. 청주 파일럿은 [성공 범위로 종료](CHEONGJU_LEDGER_PILOT_CLOSURE.md)했다. 아래는 전국 구축의 준비·인계 항목이며 청주 파일럿에 추가하는 완료 조건이 아니다. 신규 적재·실험은 실행하지 않았다. 지역·담당·날짜는 후속 착수 시 정한다.

2026-10-07. 다음 구축의 범위는 [대장 속성 DB 계획](LEDGER_ATTRIBUTE_DB_PLAN.md)이다. 토지특성 전국 필지와 기존 건축대장 세 판을 먼저 만들고, 용도지구·갱신 주기·제품 전환은 그 계획의 뒤 단계다.

## 1단계 — 청주 파일럿 종료

- [x] 성공 범위·증거·미해결 항목·종료 규칙 기록.
- [x] 기존 구현 커밋과 로컬 연구 자산 위치 인계.
- [x] 관리자 계획일지에 완료와 후속 구축 순서 기록.

## 2단계 — 전국 공통 대장 구조 확정 (다음 구축 단계, 미착수)

- [ ] 청주 구조를 기본으로 원천/관측/버전/식별자/주소 관계/가격과 분석 투영의 책임을 고정한다. 새 원천 탐색을 기본 경로 완성의 선행 조건으로 늘리지 않는다.
- [ ] 지역 범위·PK namespace·규칙/스키마 버전·완전 스냅샷/부분 입력의 처리 계약을 명시한다. 범위 변경과 규칙 변경은 같은 월 추가 적재로 숨기지 않는다.
- [ ] current·last_seen·보류·출처·기준시점·사용 권한의 소비 계약을 유지하고 제품별 허용 범위를 정한다.
- [ ] 후보/공개/복구의 책임, 파일·registry 보관 위치, 로그·백업·보관 기간과 담당을 정한다.
- [ ] 구현 범위와 완료 산출물을 문서 한 곳에 확정한다. 모든 객체 소속 인증·회귀 채택은 이 단계의 기본 요건으로 넣지 않는다.

## 3단계 — 지역 단위 확장 (미착수)

- [ ] 다음 적용 지역과 확보 자료의 기준월·원본 파일 목록을 선택한다.
- [ ] 확정 구조를 그대로 사용해 지역별 배치를 구성한다. 변경이 필요하면 명시적 변경 기록을 남긴다.
- [ ] 지역별 처리 시간·저장량·누락/중복/보류 수를 운영 기록으로 남기고 현실적인 자원 예산을 정한다.
- [ ] 다음 지역으로 넘길 결과·복구 기준을 정한다. 정밀 전국 비용 추정을 시작 전 무한 선행 과제로 두지 않는다.

## 4단계 — 실제 월 갱신 운영 (미착수)

- [ ] 실제 새 원본의 스키마·기준월·범위·해시를 접수 계약에 연결한다.
- [ ] 신규/변경/미관측·정정판 처리와 공개 판정, 실행 담당·주기·장애 대응을 SOP로 정한다.
- [ ] 원천 복구 시 제품 소비 차단·재인계·재공개의 운영 책임을 정한다.
- [ ] 첫 실제 갱신 결과와 복구 기록을 보존한다. 자료 미확보는 이 단계의 대기 사유이며 종료한 청주 파일럿을 재개하는 사유가 아니다.

## 5단계 — 제품 전환 (미착수)

- [ ] 기존 제품 키/값의 승계 범위와 새 사용 권한을 목적별로 확정한다. 보류 객체와 미인증 소속을 자동 반영하지 않는다.
- [ ] 제품별 공급 어댑터를 운영 입력에 연결하고 값·시점·신뢰상태·마지막 관측을 함께 전달한다.
- [ ] 실제 서버·프록시·브라우저에서 제품 사용 범위를 확인한다. 주거/비주거는 통계·표시 계약을 공유하되 단지/도로명 군집 단위는 유지한다.
- [ ] 병행 생성·전환·복구 절차와 운영 반영 범위를 정한다. 실제 배포는 사용자 배포 요청과 저장소 런북을 따른다.

85개 객체·복합 PK의 관계 판정은 데이터 품질, 회귀 채택은 모형 연구의 독립 목록에서 관리한다. 위 단계 일정에 합의되지 않은 실행 날짜·완료율을 적지 않는다. 후속 작업마다 범위·담당·완료 산출물·중지 지점을 먼저 고정한다.
