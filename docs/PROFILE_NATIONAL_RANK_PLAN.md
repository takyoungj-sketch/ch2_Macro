## 0. 한 줄

프로필 화면 **왼쪽**에 세로형 **「전국 지역 순위」** 카드를 두고, 오른쪽 **3개년 8대시장 표**와 높이를 맞춘다.  
순위 유니버스는 **지금 연 프로필과 같은 grain의 전국 전부**다. 시군구만이 아니라 **읍면동·리도 전국**이다.

Macro Insight 문장·한 지역 시계열 상관은 **이후**. 전국 산점도는 §8.

## 1. 가능 여부 — 읍면동·리 전국 순위

**가능하다.** 새 원장을 긁지 않는다. 이미 `regional_profile` (`v2.1-national`, `window_years=3`)에 grain별 3년 총액·총건수·인구가 있다.

로컬 `collective_stats` 실측 (`as_of_month=2026-07-01`):

| grain | 행 수 | 3년 거래액 > 0 | 인구 > 0 |
|-------|------:|---------------:|---------:|
| 시군구 `sigungu` | 304 | 304 | 269 |
| 읍면동 `eupmyeondong` | 5,669 | 5,655 | 4,934 |
| 법정리 `beopjungri` | 20,590 | 20,572 | 17,132 |
| 시도 `sido` | 17 | 17 | 16 |
| city | 14 | 14 | 14 |

PostgreSQL에서 2만 행 `ORDER BY`는 재빌드 한 번에 충분하다. **막히는 지점은 DB가 아니라 브라우저와 매 요청 JSONB 스캔이다.**

| 하면 됨 | 하면 안 됨 |
|---------|------------|
| 프로필 재빌드 때 **순위 마트**를 같이 쌓는다 | 요청마다 `features` JSONB를 풀어 전국 `ORDER BY` |
| API는 **얇은 튜플**(코드·이름·값·순위·인구) | 프로필 전체 JSONB 2만 건을 내려 보내기 |
| 읍·리는 **가상 스크롤** (보이는 ~12행만 DOM) | React로 2만 `<tr>` 렌더 |
| gzip + `(version, as_of, window, level)` 캐시 | 탭 바꿀 때마다 재조회 |

대략 페이로드: 리 2만 행 × (코드·짧은이름·액·건수·인구·순위 3종) → JSON 원문 ~1MB 전후, gzip 후 **수백 KB**. 세션당 grain 하나면 운영상 허용. DOM 2만 행은 허용하지 않는다.

**시·도 / city:** 같은 규칙(같은 grain 전국)을 적용하면 행이 20개 미만이라 부담 없다. Twin은 계속 제외(D-029). 제품 초점은 시군구·읍면동·리.

## 2. 1단계 화면 (확정)

현재 `/profile/`은 `max-w-5xl` **단일 열**이다. 「왼쪽 빈 공간」은 기존 사이드바가 아니라, **이번 단계에서 만드는 2열**이다.

```
[ 헤더 · 지역 검색(프로필 전환) ]

[ 전국 지역 순위 카드     ]  [ 3개년 부동산 거래 현황 ]
[ (세로, 높이 ≈ 오른쪽 표) ]  [ YearlyMixTable          ]

[ 주거 전월세 3개년 … ]
[ 지역 시장 구성 + 특화도 배지 ]
[ 대표시장 · 토지 · 아파트 · Twin … ]
```

좁은 화면에서는 순위 카드가 위, 연도표가 아래.

### 2.1 왼쪽 카드 — 「전국 지역 순위」

**상단**

- 제목: 전국 지역 순위 ⓘ
- 부제: `최근 3년 · {시군구|읍면동|리} 기준`  
  (하드코딩 「시군구」 금지. 연 grain을 따른다.)

**탭** (지표 3개만)

| 탭 | 정렬 키 | 표 열 |
|----|---------|--------|
| 시장 규모 | 3년 총거래액 | 순위 · 지역 · 최근 인구 · 3년 거래액 |
| 거래 활동 | 3년 총거래건수 | 순위 · 지역 · 최근 인구 · 3년 거래건수 |
| 인구 대비 | 3년 총거래액 ÷ 최근 인구 | 순위 · 지역 · 최근 인구 · 인구당 거래액 |

**넣지 않음:** 인구 대비 거래건수. 처음부터 지표를 늘리지 않는다.

**현재 지역 고정 행**

스크롤 영역은 전국 리스트(가상 스크롤)다. **현재 지역은 리스트에서 사라져도 항상 보인다.**

관악구가 100위면:

```
1위 …
2위 …
…
10위
─────────
100위 서울 관악구   ← 카드 하단 고정(pin)
```

상위 N(기본 **10**)은 스크롤과 별개로 「머리」가 아니다. 사용자는 1위부터 끝까지 스크롤한다. pin은 **뷰포트 하단 고정**이라 100위가 화면 밖이어도 관악구 행이 남는다.

**검색 (카드 안)**

페이지 상단 지역 검색(프로필 전환)과 별개다.

- 결과를 **필터해서 목록을 줄이지 않는다.**
- 해당 순위로 **자동 스크롤 + 강조**.
- 동명이면 기존 picker와 같이 상위 행정명으로 구분.

**하단 한 줄** (탭과 무관, 항상)

```
{지역명}의 전국 위치
거래액 ○위 · 거래건수 ○위 · 인구 대비 거래액 ○위
```

표를 안 읽어도 세 위치가 보이게 한다. 인구 없음이면 세 번째만 `—`.

### 2.2 특화도 — 별도 Insight 블록 없음

「지역 시장 구성」막대에 **작은 배지**만 붙인다.

예:

- 아파트 53% · 전국 평균 대비 **+13%p**
- 연립다세대 17% · 전국 평균 대비 **+4%p**

건수 막대 / 금액 막대 각각, **같은 grain 전국** 대비.

인과 문장·Macro Insight 생성은 하지 않는다.

### 2.3 명시적 비범위 (1단계 당시 · Insight는 유지)

- Macro Insight 카드, 자동 해설 문장
- 한 지역 3개년으로 인구↔거래액 상관 r
- Twin V1/V2 점수를 순위 카드에 섞기
- 인구 대비 건수 탭
- 읍면동을 「소속 시군 안 순위」로 축소 (사용자 확정: **전국**)

전국 산점도는 §8.

## 3. 산식 · 유니버스

### 3.1 Grain = 유니버스

연 프로필이 `eupmyeondong`이면 순위 분모는 **전국 읍면동**.  
`beopjungri`이면 **전국 리(법정동 포함 10자리)** — 마트 정의는 그대로다.  
**화면 선택 (D-057):** 리가 없는 법정동(`…00`)은 프로필에서 **읍면동 grain**으로 연다. 가능동 검색 → 읍면동 순위(남이면과 동급). 실제 리만 `beopjungri`.  
시군구끼리, 리끼리. **레벨 혼합 없음** (D-029와 동일).

코드는 **canonical만** (D-028). 폐지·역사 코드가 순위를 쪼개지 않게 빌더의 canonical 입력을 그대로 쓴다.

> **조회 (저비용):** `beopjungri` 순위 API는 `…00` 동을 빼고 위를 다시 매긴다. 마트 행은 그대로다. 특화도 전국 비중(mix)은 아직 동 포함 — 재적재는 §9.

### 3.2 값

| 지표 | 소스 (이미 Profile feature) |
|------|------------------------------|
| 3년 총거래액 | `yearly_mix.total_amount_3y` (만원) |
| 3년 총거래건수 | `yearly_mix.total_count_3y` |
| 최근 인구 | `features.population` |
| 인구 대비 | `total_amount_3y / population` (인구 > 0일 때만) |

단위 표시: 거래액은 기존 프로필과 같이 조/억 축약. 인구는 만 명 축약.

### 3.3 동점 · 0 · 결측

- 순위: SQL `RANK()` (1, 2, 2, 4). 같은 값이면 같은 위, 다음 위는 건너뛴다.
- 거래액·건수 **0**: 유니버스에 **포함**, 맨 아래 동점.
- **인구 없음·0:** 규모·활동 순위에는 남긴다. **인구 대비 순위만 분모에서 제외**, 칸·하단 요약은 `—`. 인구를 추정·대체하지 않는다.

실측 공백(2026-07): 시군구 ~11%, 읍 ~13%, 리 ~17%가 인구 없음. 리 전국 「인구 대비」는 약 1.7만 행만 순위가 난다. 이 사실을 ⓘ에 적는다.

### 3.4 특화도 (%p)

같은 `(profile_version, as_of, window, region_level)` 전국에서:

```
national_share_type = Σ(해당 유형 3년 금액) / Σ(전체 3년 금액)
delta_pp = (local_share − national_share) × 100
```

건수 막대는 건수 합으로 같은 식.  
**지역 비중을 산술평균하지 않는다** (거래 없는 리가 100% 아파트를 들고 있으면 왜곡).

배지: `전국 평균 대비 +13%p` / `−4%p`. 0.5%p 미만은 `평균 수준` 정도로 줄여도 된다 (구현 시 라운딩만 문서에 고정).

## 4. 데이터 · API · 운영

### 4.1 마트 (권장)

`regional_profile` JSONB를 라이브 스캔하지 말고, 프로필 빌드 끝에 예:

`regional_profile_rank`  
`(profile_version, as_of_month, window_years, region_level, region_code)`  
컬럼: 짧은 이름, amount_3y, count_3y, population, rank_amount, rank_count, rank_per_capita(nullable), 특화도용 유형별 전국 share는 **grain당 1행 메타**로 두거나 API가 한 번 계산해 캐시.

행 수 ≈ 시군+읍+리 ≈ 2.7만. 디스크·인덱스는 무시할 수준.

### 4.2 API 스케치 (구현 시 OpenAPI 확정)

```
GET /api/regional-profile/national-ranks
  ?profile_version=v2.1-national
  &window_years=3
  &region_level=beopjungri
  &as_of_month=2026-07-01
```

응답 한 번에 세 지표 값+순위를 내려 **탭 전환은 클라이언트만**.  
포커스 코드는 클라이언트가 리스트에서 찾아 pin 한다.

`as_of`가 없거나, 그 달 스냅샷 행 수가 같은 grain 최대치의 80% 미만이면 **행이 더 많은 전국 스냅샷**으로 폴백한다. (부분 `--sido-code` 재빌드가 최신 월을 덮어 순위를 시·군만으로 줄이지 않게.)

특화도 전국 share는 같은 응답의 `national_share_by_type` (count/amount).

### 4.3 프론트

- 리스트: 가상 스크롤 (`@tanstack/react-virtual` 등). 카드 높이 ≈ `YearlyMixTable`.
- pin 행 + 구분선.
- 검색 → `scrollToIndex(rank-1)` + highlight.
- 무료/유료 동일 숫자 (D-043). 전국 목록 CSV 다운로드는 넣지 않음.

### 4.4 갱신 주기 (D-054)

순위 마트는 프로필과 **같은 연간 스냅샷**이다. **월간 토지/복합/집합 사이클에서 돌리지 않는다.**

매년 초 1회:

1. `rebuild_regional_profile_national.py` (프로필 빌더가 rank까지)
2. Promote `collective_stats`

창 = 완결 달력 연도 3년. 빼먹으면 한 해 동안 지난 프로필·순위가 남는다. 절차: [`MONTHLY_UPDATE_CHECKLIST.md`](MONTHLY_UPDATE_CHECKLIST.md) §7.

## 9. 차후 — 리 grain = 법정리만 (근본, 미착수)

저비용(D-057)은 **프로필 지역선택**만 고친다. 토지 법정동·리 칩은 유지한다.

근본을 넣을 때:

1. **판별:** 리 = 10자리이면서 리코드 ≠ `00`. 리가 없는 법정동은 읍면동(8자리)에만 존재.
2. **프로필 빌드:** `…00`은 `beopjungri` 행을 만들지 않는다 (8자리만). Twin·아파트 분위는 같은 지리의 읍면동 행을 쓴다.
3. **순위 마트:** `beopjungri` 유니버스에서 `…00` 제외 후 재순위. 글로서리 「리끼리」= 법정리만. (조회 필터는 이미 목록에서 동을 뺀다. mix 특화도 비중은 여기.)
4. **검색:** 공유 picker를 토지와 같이 바꿀지는 별 결정. 기본은 토지 Enter 유지, 프로필 진입만 승격(이미 D-057).
5. **금지:** `region_codes`에서 10자리 법정동 삭제, 리 이름 NULL. 원장·PNU 키.

시점: 연초 프로필 재빌드(D-054). D-030 P1-a의 예외를 빌드 규칙으로 고정한다.
