## 1. 목적과 구현 범위

후속 일괄 구현에는 [토지 회귀 개선안](LAND_REGRESSION_UX_IMPROVEMENT_PLAN.md)도 함께 적용한다. 종속변수와 지분거래 처리의 도메인 차이를 보존하면서 결과 상태·지표·문체를 통일한다.

복합·주거·비주거의 회귀 결과를 같은 통계 언어와 문체로 읽을 수 있게 한다. 이번에는 결과 해석을 왜곡하는 오류를 먼저 수정했다. 모달 구조·색상·배치·표본 흐름·잔차 진단 등은 다른 유형의 회귀 개선안과 함께 구현한다.

비주거 도로명 회귀의 한 행은 **도로 범위에 속한 개별 거래**다. 도로별 요약 단가를 한 행으로 쓰는 지역회귀가 아니다. 주거 단지 내 회귀와는 표본 단위가 같지만, 주거 지역회귀의 단지 단위 분석과는 다르다. 집합상가·공장은 같은 엔진·패널을 사용하며 층 구간과 일부 도로 변수만 대상에 맞게 구분한다.

- 공통 지표·계수 해석 수정은 주거·비주거에 함께 반영했다.
- 비주거의 날짜 필터·거래시점 선택·결과 상태 수정은 단일 도로와 도로 추가 경로를 함께 대상으로 삼았다.
- 복합의 기존 Macro 탐색을 추천2로 교체하지 않는다.
- 아래 수치는 검토 시점의 관찰값이다. UI 상수·성능 보장으로 사용하지 않는다.

## 2. 직접 검토한 사례

서울특별시 강남구 개포동의 개포로, 집합상가, 5년 선택 상태에서 회귀 결과·계수 상세·층 고급설정·가정 시나리오·예측형/설명형 추천을 확인했다.

수정 전 화면:

- 모달 제목의 요약 n=324, 회귀 적합 n=150.
- 기본 변수는 연면적·연식·층·용도지역·건축물용도·도로폭·거래시점(반기), 선형, IQR 제외 끔.
- R² 0.82529, Adj R² 0.78125, ‘학습 MAPE’ 48.12%.
- 기준 반기는 2019H2로 표시됐다. 왼쪽의 5년 선택과 회귀 표본 기간을 혼동할 수 있었다.
- 같은 변수 조합의 설명형 추천 후보에는 CV-MAPE 64.7%가 표시됐다.
- 계수 상세의 반기·상가 층 구간에도 ‘1단위 증가 시’라는 설명이 붙었다.
- 시나리오에 85㎡·10년·1층을 입력하면 109,124만원을 표시했지만 적용 반기를 입력하거나 결과에서 확인할 수 없었다.
- 도로폭을 해제하면 변경 안내는 있었으나 숫자 입력이 비워지고 이전 추정 결과는 남았다.

집합공장·도로 추가는 자동 테스트로 검증했고, 실제 집합공장 화면을 전수 검토한 것은 아니다. 다른 지역·글자 확대·밝은 테마·키보드 접근성 전체는 후속 검증 범위다.

## 3. 이번에 적용한 정합성 수정

### C-01. 기간 필터 누락 [P0 · 적용]

단일 도로 API 클라이언트가 날짜 범위를 요청 본문에 넣지 않았고, 백엔드 회귀 요청 스키마에도 날짜 필드가 없었다. 회귀 실행·예측의 조회 함수도 날짜 경계를 전달하지 않았다.

- 프런트 요청 → 요청 스키마 → SQL 필터에 `contract_date_from/to`를 연결했다.
- 도로 추가 경로는 기존 날짜 조회를 유지하고, 내부 회귀 요청에도 날짜 기준을 전달한다.
- 실제 2021-10-01~2026-09-30 조건으로 재실행하면 적합 표본은 96건이었다.
- 제목의 목록 요약 건수와 회귀 적합 건수의 관계를 설명하는 UI는 C-08의 후속 과제다. 날짜 전달 수정만으로 원천·제외·최종 표본 흐름이 모두 설명되는 것은 아니다.

### C-02. 학습·검증 오차 혼용과 부분 검증 [P0 · 적용]

공유 엔진의 `mape`는 CV가 가능하면 CV 오차, 아니면 학습 오차였다. 화면은 이를 항상 ‘학습 MAPE’로 설명했다. 또한 결측이 섞인 행 전체를 먼저 분할해 일부 fold가 실패하고 남은 거래의 예측만으로 CV 오차를 계산할 수 있었다. 후보 탐색은 결측을 제거한 뒤 분할해 현재 모형과 평가 대상도 달라질 수 있었다.

- 공통 응답에 `in_sample_mape`, `cv_mape`, `metric_basis`를 추가했다. 기존 `mape`는 호환을 위해 기존 의미로 유지한다.
- 주거·비주거 공통 결과에 학습 MAPE와 5겹 교차검증 MAPE를 별도로 표시한다. CV 불가 시 학습 오차로 대체 표시하지 않는다.
- CV 분할 전에 y와 설계행렬의 유효 행을 맞춘다. 유효 표본 전체의 검증 예측이 완료되지 않으면 CV 지표를 제공하지 않는다.
- 로그 R²·Adj R²는 로그 척도임을 표시한다. MAPE는 금액 원척도다.
- 실제 수정 후 학습 MAPE는 45.85%, CV-MAPE는 82.61%였다. 같은 변수의 설명형 후보도 CV-MAPE 82.61%로 일치했다.

수정 후의 오차 상승·하락은 계산 기준과 표본 변화의 결과다. 이전 값과 직접 성능 개선 비교를 하지 않는다. 무작위 5겹 검증은 미래 시점 성능 검증이나 후보 선택 후 독립 최종 검증을 뜻하지 않는다.

### C-03. 거래 순서와 반복 실행 [P0 · 적용]

단일·추가 도로 조회에 거래 ID와 정렬을 추가하고, 공통 전처리에서 거래 ID로 순서를 고정한다. 같은 데이터·설정이면 모형과 추천의 CV 분할이 반복 실행마다 달라지지 않게 한다.

실제 개포로 API 3회 전체 응답이 일치했다. 테스트에서는 거래 행을 섞은 단일·통합 도로 데이터에서도 결과·추천이 같은지 확인한다. 데이터·조건 자체를 바꿨을 때 같은 검증 거래를 고정하는 비교 설계는 후속 과제다.

### C-04. 시나리오 적용 반기 누락 [P0 · 적용]

모형에 반기 더미가 있어도 시나리오에서 이를 설정하지 않아 항상 기준 반기 값으로 계산했다.

- 모형에 포함된 반기와 기준 반기를 예측 옵션으로 전달한다.
- 시나리오에서 반기를 선택하고, 선택한 반기 더미를 실제 계산에 반영한다.
- 결과에는 `적용 거래시점`을 표시한다. 미지정 API 요청은 기준 반기를 사용하되 응답에 이를 명시한다.
- 모형에 없는 반기 선택은 오류로 처리한다. 시나리오의 필수 연속값 누락·0 이하 면적도 거부한다.
- 실제 API에서 2021H2는 131,245.0만원, 2022H1은 139,777.5만원으로 계산됐고 응답에 각각의 반기가 명시됐다. 이는 시점 반영 여부를 확인한 사례이며 가격 판단 자료가 아니다.

### C-05. 설정·입력 변경 후 이전 결과 잔존 [P0 · 적용]

- 회귀 결과가 사용한 요청 조건과 현재 조건을 비교한다. 변수·척도뿐 아니라 기간·지역·층 형식·IQR 조건도 비교에 포함한다.
- 조건이 달라졌거나 재적합 중이면 시나리오 계산을 막고 이전 추정값을 표시하지 않는다.
- 숫자 입력은 변수 체크 변경만으로 지우지 않는다. 시나리오 입력 변경 후에도 기존 추정값을 현재 입력의 결과처럼 남기지 않는다.
- 재적합 후 예측 응답을 초기화한다. 늦게 도착한 예측 응답도 해당 요청·입력과 일치할 때만 표시한다.

현재 구현은 비주거 패널에 우선 적용했다. 주거 패널의 같은 상태 문제는 주거 개선안의 후속 통일 작업에서 적용한다. 공통 표시 계약은 동일하게 유지한다.

### C-06. 범주 계수의 잘못된 해석 [P1 · 적용]

공유 계수 해석에서 반기·상가 층·공장 층·도로 고정효과를 연속변수처럼 처리하던 경로를 수정했다. 이제 해당 더미는 ‘기준 대비’로 설명한다. 구체적인 기준 범주를 계수 행 옆에 붙이는 UI는 후속 과제다.

## 4. 후속 UI 개선안 — 유형별 일괄 구현

### C-07. 분석 범위와 정보 구조 [P1]

- 상단에 유형·기준 도로·추가 도로·실제 분석 기간을 표시한다.
- 설정 → 결과 요약 → 계수 → 잔차 진단 → 통계적 추정 → 모형 추천 순서로 공통 구조를 맞춘다.
- `분석 코호트 / 단일 cluster / + cluster 추가` 대신 `분석 도로 1곳 / 도로 추가`처럼 사용자가 다루는 대상을 표현한다. 내부 cluster 정의는 도움말로 보낸다.
- 통합회귀에서는 포함 도로와 기준 도로, 도로 고정효과의 적용·생략 상태를 표시한다. 시나리오가 어느 도로를 기준으로 하는지도 명시한다.
- 상단 고정 영역을 축소하고 추가 도로 선택은 접을 수 있게 한다. 결과를 읽을 수 있는 본문 높이를 확보한다.

### C-08. 표본과 경고 [P1]

- 목록 요약 건수와 회귀 적합 건수에 각각의 기간·필터·집계 기준을 붙인다.
- 원천 거래 → 지역·기간·유형 조건 → 결측·품질 제외 → IQR 제외 → 적합 거래로 표본 흐름을 보여준다.
- 현재 실제 DB 날짜 조건의 유효·양수 단가 거래는 192건, 적합은 96건이었다. 단계별 제외 사유·건수는 후속 응답 계약으로 제공한다. 목록 요약 324건과 같은 분모라고 가정하지 않는다.
- ‘30건, 계수당 5건에 못 미쳐 참고용’ 대신 미달 항목별 실제 값과 기준을 표시한다. 30건은 충족했지만 계수당 거래가 부족한 경우를 구분한다.
- 계수 수·설계행렬 순위·계수당 거래 수·검증 가능 여부를 확인할 수 있게 한다. 변수 줄이기 등 다음 행동을 연결한다.

### C-09. 계수와 잔차 진단 [P1]

- 복합·주거와 같은 열 순서·숫자 형식·유의성 표시를 사용한다. p값은 `<0.001` 등으로 표시하고 통계량 소수 자릿수를 줄인다.
- 면적은 `1㎡ 증가`, 연식은 `1년 증가`, 범주는 `기준 범주 대비`로 구분한다. 반기는 실제 기준 반기, 층은 기준 층 구간을 직접 명시한다.
- 층 구간별 거래 수·구간 정의를 표시하고 사용자가 선택한 옵션과 실제 적용 형식을 함께 보여준다.
- 계수 표 내부와 모달 본문의 중첩 스크롤을 줄이고 표 확대를 제공한다.
- 복합과 같은 잔차 진단 진입점을 제공한다. 관측-적합·잔차-적합·이상 영향 거래를 검토하되 어떤 표본의 잔차인지 명시한다.

### C-10. 통계적 추정과 모형 추천 [P1]

- 입력 옆에 학습 범위와 선택한 기준 범주·도로·반기를 보여준다. 범위 밖 입력은 해당 필드에서 알린다.
- 금액(만원)과 단가(만원/㎡)를 시각적으로 구분하고, 평균 추정범위·개별 거래 예측범위의 의미는 유형 공통 설명을 사용한다.
- 추천 후보에 현재 모형과의 변수·척도 차이, 표본 동일 여부, 평가 방법을 표시한다.
- 현재 추천이 후보 선정에 사용한 CV를 별도 최종 검증처럼 표현하지 않는다. 동일 거래 표본인지뿐 아니라 유효 행·검증 분할이 같은지도 확인한다.
- `이 후보 적용`은 설정 변경인지 즉시 실행인지 명확하게 한다. 설정만 바꾼 경우 변경 표시와 재실행 경로를 연결한다.
- 설명형은 설명력, 예측형은 검증 오차를 먼저 보여주되 두 목적 모두 표본·불확실성을 함께 읽게 한다.

### C-11. 문체·색상·모달 형식 [P1]

- 코호트 영역의 밝은 배경과 옅은 글자 조합을 수정해 다크 테마 대비를 확보한다.
- 로그 옵션을 한 줄 또는 명확한 두 줄로 정리한다. `금액만 로그. 연면적은 그대로.`는 보조 설명으로 둔다.
- 경고·한계 설명의 반복을 줄인다. 핵심 한 문장, 조건별 주의, 자세히 보기로 나눈다.
- 모달 제목·닫기·확대·글자 배율, 표·버튼·도움말 크기는 5앱 형식 패리티 작업과 함께 맞춘다.

문구 초안:

- `변수가 시세에 어떤 방향·크기로 작용하는지 탐색합니다` → `다른 조건을 함께 고려했을 때 변수와 거래금액의 관계를 살펴봅니다.` 인과 효과로 단정하지 않는다.
- `도로(cluster) 내 거래만 사용합니다` → `선택한 도로 범위의 거래를 분석합니다.` 추가 도로가 있으면 포함 범위를 반영한다.
- `가정 시나리오 (참고)` → `조건별 거래금액 추정`.
- `아래 조건에서 모형이 가리키는 금액 수준입니다` → `입력한 조건과 거래시점에서 모형이 추정한 거래금액입니다.`
- `깊이: 표준+` → 실제 탐색 범위를 설명하는 도움말로 이동한다. 사용자가 조작할 수 없는 내부 등급을 제목처럼 노출하지 않는다.
- `적용은 위의 변수 체크와 로그 체크를 바꿉니다` → `후보를 적용하면 변수와 모형 설정이 바뀝니다. 회귀를 다시 실행하면 결과에 반영됩니다.`
- 긴 공통 한계 문구는 `관측된 거래관계를 설명하는 통계적 참고값입니다.`를 먼저 두고 상세 한계를 펼쳐 읽게 한다. 한계 자체를 숨기지 않는다.
