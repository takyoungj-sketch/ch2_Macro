# 청주 원천 판본에 묶인 제품 공급 인계

**파일럿 종료(2026-10-05, D-077):** [청주 공통 대장 공급 파일럿 성공 종료](CHEONGJU_LEDGER_PILOT_CLOSURE.md). 아래 ‘남은 단계’는 후속 운영/제품 구축 과제이며 파일럿 필수 조건이 아니다. 이번 종료 기록에서 재연 명령을 다시 실행하지 않는다. 제품 전환 조건과 권한은 유지한다.

2026-10-05. 선택 원천 공개 판본에서 기존 속성·공시지가를 다시 계산하고 제품 공급 산출물을 만들었다. 원천 DB·stage·포인터 revision·소비 계약·기존 공급 검증 세대·산출물·어댑터 코드 해시를 하나의 receipt로 묶었다. 제품 공급 포인터는 연구 registry 안에서만 변경하며 실제 제품 DB는 수정하지 않는다.

## 원천과 실제 공급 범위

`operations_product_v1`에 청주 전체 2026-07 확장 원문 판본을 정규화 전체 스냅샷으로 접수했다. 원본 연구 DB 해시를 유지했다. 별도 DB에는 건물 141,252개·필지 480,633개 관측이 들어 있다. 첫 접수·적재·원천 게시 약 159초, DB 999,714,816바이트였다. 첫 전체 실행은 약 260초이며 공급 생성·실패 주입·검증을 포함한다. 반복 실행 비용은 [실측 보고서](lab/cheongju_product_handoff.json)의 실행 이력에서 구분한다.

이 운영 경로는 최신 판본 하나에서 시작했다. 과거 판본과 최신 미관측 2,995개 이력은 원래 청주 연구 DB에 보존된다. 여기의 `last_seen_only=0`은 단일 판본 시작 결과이며 청주 전체 건물 소멸·누락이 없다는 증거가 아니다. 새 원본 재추출·실제 다음 월 갱신·여러 도시 판본 운영 복구 비용은 이번 측정에 포함하지 않는다.

기존 제품의 키와 보류 근거를 사용해 주거 속성 893개 키·공시지가 1,302개 키를 선택 DB에서 다시 공급했다. 속성은 실제 기존 집합 집계 알고리즘을 사용한다. 새 소속 인증·대표필지 선택·수량 합산 승인으로 해석하지 않는다. 보류 속성·K-apt 등 다른 출처 속성은 기존 입력을 유지한다. 복합 13,293건과 비주거 도로명 군집 306개도 기존 입력을 유지한다. 주거 공급 키는 1,471개이고 실제 최신 목록은 이전 검증과 같이 1,470개다.

값별 원천·기준시점·신뢰상태·last_seen·사용 권한을 반환한다. 원천에서 공급한 속성에는 관리 PK·원문 버전 해시, 가격에는 기존 대표 PNU·가격 연도가 포함된다. 모든 새 제품 사용 권한은 false이고 `legacy_replay_audit`만 허용한다.

## 검증·게시·읽기

수치가 같은지만 확인하지 않고 새 공급을 실제 HTTP/SQL 검증의 `fixture_rows`에 투영해 기존 검증 완료된 연구 공급과 canonical JSON 해시를 비교한다. 열 값·키·숫자 직렬화 타입까지 같아야 게시한다. 기존 SQL/ASGI 검증 코드·참조 자료·결과의 해시도 확인한다. 이 일치 증거는 새 TCP/브라우저 요청 실행을 뜻하지 않는다. 공통 군집 참조 메타데이터는 기존 검증 범위이며 이 비교의 참조 인자는 양쪽 모두 동일하다.

전체 관련 테스트 168개와 실제 재연 검사 11개를 통과했다. 단위 테스트는 공급 포인터 실패·원천 revision 변경·검증 세대 변경·혼합 입력·산출물 변조·보류 속성의 기존 값 유지·생성 중 원천 변경을 확인한다. 첫 실행과 후속 강화 검증의 측정값은 실행 이력에 함께 보존했다.

불변 산출물을 먼저 완성한 뒤 원천 active/revision이 유지됐는지 확인하고 제품 handoff 등록과 선택 포인터를 한 트랜잭션으로 게시한다. 실패 주입에서 기존 선택 handoff가 유지됐다. 실패 산출물은 선택되지 않은 연구 시도로 남으며 파일 존재만으로 게시 완료를 판단하지 않는다.

소비자는 직접 gzip을 열지 않고 `ledger_product_handoff.load()`를 이용한다. 원천 선택이 바뀌거나 과거로 복구됐다가 같은 판본으로 돌아와도 revision이 달라져 기존 인계를 거절한다. 새 인계를 생성·검증해야 한다. 계약·검증 세대·코드·원천 DB·receipt·산출물 변경도 차단한다. 읽기 종료 시 원천과 제품 검증 세대를 다시 확인한다.

```powershell
# 전체 재연: 기존 원천 게시를 재검증하고 새 handoff ID로 공급·실패 검증
pipeline\.venv\Scripts\python.exe pipeline/parcel_master/run_cheongju_product_handoff.py
# 선택 handoff를 읽기 전에 검증
pipeline\.venv\Scripts\python.exe pipeline/parcel_master/ledger_product_handoff_cli.py --root data/research/cheongju_ledger/operations_product_v1 verify
# 이 운영 경로의 제품 전환 조건 확인
pipeline\.venv\Scripts\python.exe pipeline/parcel_master/ledger_product_handoff_cli.py --root data/research/cheongju_ledger/operations_product_v1 gate
```

새 handoff만 만들 때는 같은 CLI의 `build --batch-id <새_ID>`를 사용한다. ID 재사용은 거절하고 실패 시 기존 포인터를 유지한다. 전국 원문·SQLite·gzip은 Git에 넣지 않는다.

## 남은 단계

선택 판본에 묶인 공급 인계 조건을 이 제한된 연구 범위에서 충족했다. 새 제품 사용 권한, 실제 다음 원천 갱신, TCP·프록시·브라우저 검증은 남아 있다. 운영 경로를 지정하지 않은 제품 전환 판정은 인계를 자동 인정하지 않는다. 회귀 모형 채택은 별도 트랙이다.

다음은 청주 전체 여러 판본을 같은 운영 경로에서 접수하고 원천 복구 시 제품 소비 차단·재인계를 함께 재연하는 것이다. 판본별 저장 공간과 갱신·복구 비용도 측정한다. 신규 원천 추출기의 접수 계약 연결과 실제 다음 자료 갱신은 새 자료 확보 시 수행한다.
