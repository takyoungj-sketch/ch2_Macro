## 0. 정체성 (한 줄)

CH2 Macro가 **계산**한다.  
AI가 분석 **목적과 경로**를 잡는다.  
Caveat가 AI를 **제어**한다.  
History가 분석 과정을 **축적**한다.  
AI가 마지막에 그것을 **사람 말로 정리**한다.

역할:

> CH2 Macro의 데이터와 분석 기능을 이해하고, 분석 목적에 맞는 경로를 제안하며, 엔진이 낸 결과를 해석하고, 필요 시 추가 분석과 요약 보고서까지 돕는 **분석 보조 AI**.

금지: 투자·매수·적정가 추천.  
허용: 분석 경로 추천.

## 1. 5층 구조와 파이프라인

층을 바꾸지 않는다. Planner는 **경로만**이 아니라 **지금 실행 가능한지**까지 본다.

```
사용자 질문
    │
    ▼
┌─────────────┐
│   Intent    │  무엇을 알고 싶은가?
└──────┬──────┘
       ▼
┌─────────────┐
│  Playbook   │  어떤 경로가 적합한가? (후보 탐색)
└──────┬──────┘
       ▼
┌─────────────────────┐
│ Active Context      │  현재 데이터·화면으로 가능한가?
└──────────┬──────────┘
           ▼
┌─────────────┐
│   Caveat    │  문제가 있나? 다음 행동은?
└──────┬──────┘
       ▼
사용자에게 경로 제안
       │
       ▼
   [실행 요청]  ← P3 이후. 승인 없이 엔진 호출 금지
       │
       ▼
  CH2 엔진 실행
       │
       ▼
    Bundle
       │
       ▼
 Analysis History   ← 성공 Bundle만 자동 기록
       │
 ┌─────┴──────┐
 ▼            ▼
해석        비교 / 추가 분석
                │
                ▼
            분석 메모 (보고서 = History의 출력)
```

### 층별 계약

| 층 | 입력 | 반환 | 절대 하지 않음 |
|----|------|------|----------------|
| **Product Knowledge** | app·panel·질문 | 기능 카드 (목적 / 적합한 질문 / 장점 / 주의) | 한 단지 실측 n, 계수, 「지금 이 표본」숫자 |
| **Playbook** | Intent | 후보 path 순위 (문서화된 표만) | 없는 기능을 지어내기 |
| **Active Context** | 현재 화면 Bundle | n, 유형별 n, 계수, warnings, 화면에서 실행 가능 여부 | 다른 화면 API를 몰래 호출해 숫자 채우기 |
| **Caveat** | Bundle 경고·n·플래그 | 조건 → 판단 → 다음 행동, `caveat_ids` | **숫자를 만들기** (「신뢰도 23% 증가」금지). 실행 가부는 Gate |
| **Analysis History** | 성공 Bundle | 실행된 분석 슬롯 | 채팅 전문을 통계 근거로 쓰기. 실패한 Gate를 슬롯으로 남기기 |

숫자에만 Screen-bound. Product/Playbook은 화면이 없어도 말한다.

## 2. Planner: 경로 + 실행 가능성

```
Intent
  → 가능한 분석방법 탐색 (Playbook)
  → 현재 데이터/화면으로 실행 가능한지 판단 (Active Context)
  → Caveat로 순위 조정
  → 경로 제안
```

「아파트와 오피스텔 가격격차를 분석해줘」→ Product만 보면 통합회귀가 맞다. Planner는 추가로 본다.

- 현재 지역에 두 유형 표본이 있는가  
- 동일 지번 / 인접 지번인가  
- 주거용인가  
- 기간은 충분한가  
- 필요한 변수가 있는가  
- **현재 화면에서 바로 실행할 수 있는가**

실행할 데이터가 없는데 「통합회귀를 추천합니다」만 말하면 안 된다.  
가능하면 경로 + 실행 가능. 불가면 왜 안 되는지 + 화면에서 무엇을 하면 되는지.

## 3. Product Knowledge = 판단 자료 (매뉴얼이 아님)

각 기능 카드 최소 4칸: **기능 · 목적 · 적합한 질문 · 주의** (+ 장점).

예 — 집합 통합회귀

| | |
|--|--|
| **목적** | 서로 다른 유형의 집합부동산 가격수준 비교 |
| **적합한 질문** | 아파트와 오피스텔 가격차이 · 주거/비주거 유형효과 · 특정 유형의 상대가격 |
| **장점** | 면적·연식 등 개별 특성을 통제 가능 |
| **주의** | 유형별 표본 부족 · 지역 이질성이 큰 경우 · 지나치게 넓은 지역을 하나로 묶는 경우 |

코드: `backend/app/ai/knowledge/product.py` 기능 카드.

## 4. Caveat = 행동 규칙 (경고 문구가 아님)

형식: **조건 → 판단 → 가능한 다음 행동.**

예: n 과소 → 신뢰 주의 → 인접지역 확대.

### Caveat가 숫자를 만들어서는 안 됨

허용: `n < 권장`이면 인접지역 확대를 **검토** (n은 Bundle에서 인용).  
금지: `n=18이므로 인접지역을 포함하면 신뢰도가 23% 증가한다.`

숫자 결과는 무조건 CH2 엔진. Facts First와 동일.

### Gate vs Caveat (D-056)

| | Gate | Caveat |
|--|------|--------|
| 역할 | **계산 가능 여부** | **결과 신뢰 · 다음 행동** |
| 누가 | 엔진/서버 (`analysis_gates`) | 카탈로그 + Planner |
| 예 | `n < engine_min` → 실행 불가 | `engine_min ≤ n < recommended` → 실행됨 · 주의 · 확대 권고 |
| AI | 판단하지 않음 | 엔진이 켠 경고·n을 번역 |

`n=18`이라고 AI가 실행을 막지 않는다. 소표본 자체를 보고 싶을 수 있다.  
「표본이 부족해서 분석할 수 없습니다」로 뭉뚱그리지 말고, 실행됐으면 「안정성에 주의, 인접 비교를 권고」라고 한다.

## 5. 추천의 경계 (유지)

**허용**

- 현재 표본이 적어 인접지역을 포함한 지역회귀를 추가로 검토하는 것이 좋습니다.  
- 아파트와 오피스텔을 동일 조건에서 비교하려면 통합회귀가 적합합니다.

**금지**

- 이 아파트는 저평가되어 있습니다.  
- 이 아파트를 매수하는 것이 좋습니다.  
- 적정가격은 5억 2천만원입니다.

## 6. Analysis History

대화 기록이 아니라 **실행된 분석의 기록**.

### 생성 시점 (D-056, 확정)

**분석 엔진이 유효한 결과 Bundle을 반환한 시점에 자동 생성.**

```
회귀 요청
   ↓
Gate
 ├─ 실패 → 오류/안내 → History 없음
 │
 └─ 통과
      ↓
   CH2 엔진
      ↓
   성공 Bundle
      ↓
   History 자동 생성
```

질문할 때만 만들면, 화면에서 직접 회귀만 돌린 뒤 「아까 회귀와 비교해 줘」가 비어 있다.  
AI가 실행하든 사용자가 직접 실행하든 같은 구조.

**넣지 않음:** 목록·지도·단순 통계·기간 변경·모달 열기.  
**넣음:** 집합/코호트/복합/지역 회귀 **성공**. (이후 같은 규칙으로 확장)

실패한 회귀는 History가 아니다.

### 슬롯

```
id, at
intent_id, path_id
scope                 # 지역, 유형, 기간
n, n_by_type
metrics               # adj_r², mape, …
key_coeffs            # 목적에 해당하는 계수만
warnings, caveat_ids
source                # engine_bundle
```

P2 이후 (P0 필수 아님):

```
recommended_path
executed_path
user_override         # AI가 확대를 권했는데 현재 지역만 본 경우
```

보고서에서 「당초 인접지역 확대를 검토할 수 있었으나 현재 지역만을 대상으로 분석하였다」를 만들 수 있게.

### 비교 예

History #1 청주 ○○동 n=42 오피스텔 효과=−12.3% p=.021  
History #2 인접 포함 n=187 오피스텔 효과=−10.8% p=.004  

→ 「인접 포함 후에도 방향은 동일했고 통계적 유의성은 높아졌습니다.」  
(두 슬롯에 있는 부호·p만. 없는 %를 만들지 않음.)

n 과소 caveat_ids를 슬롯에 남긴다. 「왜 인접까지 갔지?」→ History가 근거.

## 7. 보고서 = History의 출력

별도 AI 모드가 아니다. 「지금까지 정리해 줘」= History를 사람이 읽게 묶는다.  
실행되지 않은 분석의 숫자를 넣지 않는다. 감정평가서·투자 의견이 아니다.

## 8. 단계 (확정)

| ID | 목표 | 완료 조건 |
|----|------|-----------|
| **P0** | 지식: Product 카드 + Caveat 카탈로그 + Playbook | Planner가 CH2를 기능/목적/질문/주의로 말할 수 있음 |
| **P1** | Intent → Path → Context 실행 가능 비교 → 추천 | 화면 없어도 격차 질문에 경로를 말하고, 데이터 없으면 실행 불가를 말함 |
| **P2** | History 자동 (성공 Bundle) + 이전 슬롯 비교 | 화면 직접 회귀 성공 후 「아까와 비교」가능 |
| **P3** | 실행 보조 (승인·딥링크, 엔진 대리 계산 없음) | 아래 P3-1… |
| **P4** | 분석 메모 | History만으로 메모 |
| **P5** | 복합 / 지역 / 토지 실행 보조 | P3와 같은 사다리 |

### P3를 집합부터 쪼갠다

처음부터 AI가 코호트 조건을 임의로 조작해 실행하지 않는다. v1: **추천 → 버튼 → 기존 기능**.

| 단계 | AI | 실행 |
|------|-----|------|
| **P3-1** | 집합 코호트 경로 안내 | 기존 화면으로 이동 |
| **P3-2** | 집합 통합회귀 실행 요청 | 사용자 승인 → CH2 엔진 |
| **P3-3** | 결과 해석 + Caveat | AI (숫자=Bundle) |
| **P3-4** | 이전 History와 비교 | AI |
| **P3-5** | 분석 메모 | AI = P4 |

P3-1이 먼저인 이유: 사용자 질문이 단지 가격·동/평형·최근 변화·유형 격차에 몰리고, 집합회귀·코호트가 이미 제품에 있다.

## 9. UI

`[? 도움]` + `[AI 어시스턴트]` 유지. 토지·복합·집합·임대·프로필 **같은 헤더 슬롯**. 카드 안 중복 버튼은 제거.

모달 세 갈래:

| | 사용자 | 층 |
|--|--------|-----|
| **지금 결과가 궁금해** | 이 회귀를 설명해 줘 | Context + Caveat |
| **이런 분석을 하고 싶어** | 아파트·오피스텔 격차 | Product + Planner (+ Context면 실행 가능 판단) |
| **결과를 정리하고 싶어** | 지금까지를 보고서로 | History (+ 없으면 실행을 안내) |

---

## 10. 하지 말 것

- LLM이 만든 계수·격차%·예측 금액·「신뢰도 N% 증가」  
- History에 없는 1차/2차 비교  
- Twin 지역 이름을 프로필 Bundle 없이 나열  
- 백그라운드 회귀로 숫자를 채워 경로를 「검증」  
- 분석 메모를 감정평가·투자 의견으로 확장  
- 한 단지 실측 n을 Product Knowledge에 고정  
- 모든 API 호출을 History에 넣기
