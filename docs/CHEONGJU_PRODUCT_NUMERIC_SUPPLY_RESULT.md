# 청주 제품 숫자 공급·실제 회귀 엔진 병행 재현

2026-10-05. 청주 전체 통합 대장에서 제품 숫자를 공급하는 연구 경로를 한 명령으로 묶었다. 기존 제품 DB는 읽기 전용으로 동결했으며 운영 입력 전환은 하지 않았다. [전체 통합 결과](CHEONGJU_INTEGRATED_LEDGER_V2_CITY_RESULT.md)의 후속 검증이다.

## 실제로 공급한 범위

주거 기존 이름 키 1,471개·거래 108,077건을 유지했다. 기존 표제부 PNU 속성 키 934개 중 905개는 숫자가 같고, 15개는 다르며, 14개는 최신 원천 후보가 없다. 차이 15개는 모두 기존 검토 보류 85개 키에 속한다. 가구수 15개·동수 7개·승인연도 9개·최고층 6개·구조군 3개의 차이가 있으며 항목별 수는 중복된다.

같은 숫자·같은 기존 승인연도·보류 제외 조건을 충족한 **893개 키의 숫자 속성**을 통합 원문에서 실제로 공급했다. 기존 대표 PNU의 **2026년 가격 1,302개**도 통합 원천에서 공급하여 기존 값과 일치했다. 가격이 없던 169개는 유지했다. K-apt 등 다른 출처 속성 413개는 기존 값을 승계하고 무속성 124개는 유지했다. 이는 K-apt의 통합 원천 이관을 뜻하지 않는다. 보류·불일치·미관측에 대한 새 속성 교체는 하지 않았다.

복합 거래 13,293건 중 기존 보강 10,799건에는 관리 PK가 전부 없었다. 현재 주소 후보는 단일 표제부 8,370건·복수 1,979건·최신 미관측 450건이고 주소 미복구는 2,494건이다. 기존 보강은 보존했고 관리 PK를 자동 부여하지 않았다. 후보 속성 비교 12,820개는 거래 정확도 지표가 아니다. 비주거 306개 도로명 군집·3,987건은 기존 분석 단위를 유지했다.

## 원문 판본과 소비 계약

기존 청주 SQLite 약 2.03GB를 보존하고 연구용 복제본에 2026-07 표제부의 원래 31개 열을 문자열로 추가했다. `cheongju-city-2026-07-product-fields-v1` 판본의 건물 관측은 141,252개이며 토지특성 480,633개를 함께 보존한다. 연구 DB는 2,724,536,320바이트, 최초 확장은 약 578초였다. 원본 파일 SHA·PK·식별 필드를 검증했고 기존 세 판본과 복구 이력은 유지했다. 본번 0000은 제품 투영에서도 보류한다.

각 공급값은 원천·기준시점·신뢰상태·마지막 관측·사용 허용을 갖는다. 원천 기준일 미상은 null이며 판본 월로 대체하지 않는다. 기존 값 승계와 통합 원문 재공급 출처를 구분한다. `legacy_replay_audit=true`는 고정 입력 비교 권한이다. 원천 계약의 `product_enrichment`, `quantity_aggregation`, `regression`은 계속 false다. 이번 실제 엔진 재적합은 연구 비교이며 새 소속·합산·회귀 채택의 승인 근거가 아니다.

## 실제 제품 엔진 비교

동결 입력과 통합 공급 입력을 실제 backend 함수로 재적합했다. 고정 사양 안에서 표본·계수·지표가 모두 일치했다.

- 주거 지역 회귀: 693개 키. 로그 모형, 거래 수 가중, 가구수·층수·나이·공시지가·자산 더미. 로그 R² 0.7563, 원가격 척도의 조정 지표 0.759, MAPE 21.06%, RMSE 64만원/㎡. 단순 키 평균 예측 222.5902만원/㎡, 관측 220.4433만원/㎡. 두 R²의 척도를 혼동하지 않는다.
- 복합: 12,946건. 기존 구조 보강을 유지한 log-log 모형. R² 0.7282609781, MAPE 47.71%.
- 비주거 상가: 3,792건. 기존 군집 고정효과 모형. R² 0.5424973665, MAPE 90.73%.
- 비주거 공장: 114건. 같은 기존 분석 방식. R² 0.2105129065, MAPE 110.34%.

숫자 차이 15개는 모두 보류되어 후보 교체 수도 0이었다. 따라서 일치는 **공급 경로의 호환성**을 보여주며 새 원천의 정확도 개선이나 새 회귀 모형의 성능 개선을 뜻하지 않는다. 전체 API 요청 조합·집계 마트 재생성·시간외 검증은 이번 범위에 포함되지 않는다. 두 제품 DB의 동결은 각각 읽기 전용 트랜잭션이며 서로 동일 시각의 운영 스냅샷은 아니다.

## 재실행·복구

저장소 루트에서 실행한다. 기존 backend 가상환경은 실제 엔진 비교에 사용한다.

```powershell
pipeline\.venv\Scripts\python.exe pipeline/parcel_master/run_cheongju_product_supply.py
```

동결 입력을 재사용하고 알려진 원문 확장 판본을 확인한 뒤 숫자 공급·실제 엔진 비교·성공 manifest를 생성한다. 정상 재실행은 약 33초, 이전 공개 판본에서 최신 연구 판본으로 복구 후 재실행은 약 42초였다. 원본 확장 추출을 매번 반복하지 않는다. 알 수 없는 후속 판본이나 원본 청주 DB 해시 변경은 중단한다. 원문 조회·검증은 약 1~2초, 숫자 비교와 산출물 생성은 약 12초였으며 운영 API 응답 시간은 아니다.

산출물은 같은 디렉터리의 임시 파일을 완성한 후 교체하여 실패 시 기존 파일을 보존한다. 성공 manifest는 보고서·스크립트 SHA와 복구 실행 이력을 기록한다. 여러 파일 전체의 단일 트랜잭션은 아니므로 소비자는 성공 manifest의 해시 일치를 확인해야 한다. 관련 테스트 **147개**가 통과했다.
