## 0. 한 줄

**본체는 AI가 아니다.** 지정·랜덤 표본 지역에 대해 원장·정제 흔적·마트 빌더를 다시 돌려 대조하는 **결정적 QA 엔진**이 숫자를 만들고, AI는 그 결과만 해석한다.

전국 빌드가 **완료**된 것과 전국 빌드가 **정확한** 것은 다른 문제다. 이 엔진은 후자를 표본으로 확인한다.

---

## 1. 문제

생산 파이프라인은 전국 단위로 다음을 수행한다.

```
원데이터 수집 → 정제 → 원장 DB → 통계 마트
```

같은 생산 경로(또는 같은 AI 세션)가 “내가 만든 통계가 맞다”고 선언하면 QA가 아니다.

지금 있는 검증은 **배치가 깨지지 않았는가**에 가깝다.

| 기존 | 하는 일 | 하지 않는 일 |
|------|---------|--------------|
| `verify_monthly_integrity.py` | UNIQUE grain, 골든 건수, Promote 게이트 | 특정 동의 원장↔마트 역추적 |
| 월간 count snapshot | 전국·시도 급변 | 나성동 아파트 2025년 중위가 |
| CSV validate / 매핑 점검 | 수집·코드 품질 | 통계 재계산 |
| Twin Validation | 회귀 pool이 Local보다 나은가 | 원장·마트 수치 |

빠진 고리: **한 지역 × 한 기간 × 한 유형**을 원데이터부터 마트까지 내려가, 왜 맞거나 다른지를 남기는 것.

## 2. 제품 이름과 내부 이름

| 표기 | 의미 |
|------|------|
| **AI 검증 로봇** | 관리자 UI·대화에서 쓰는 통칭 |
| **QA 엔진** | 숫자를 만드는 본체 (SQL·빌더 재실행·대조) |
| **AI 해석기** | QA JSON만 읽고 원인 후보·보고서를 씀 |

구현 모듈·테이블·CLI는 `qa_audit` / `qa_region_audit` 계열을 쓴다. `ai_verify`처럼 AI가 집계하는 이름은 쓰지 않는다.

## 3. 불변 원칙

1. **생산과 검사를 분리한다.**  
   수집·정제·마트 빌더는 생산이다. QA는 그 결과를 의심하고 재계산·대조한다. 같은 에이전트 세션에서 “만들고 맞다”고 하지 않는다.

2. **숫자는 LLM이 만들지 않는다.**  
   [AI 헌법](./CH2_AI_CONSTITUTION.md) **Facts First · No Recalculation**과 같다. 건수·합·평균·중위는 파이썬/SQL이 만든다. LLM은 diff를 해설만 한다.

3. **운영자만, 눌렀을 때만.**  
   공개 앱·헤더·일반 AI 어시스턴트에 넣지 않는다. V1에서 자동 스케줄·월간 cycle 연동 금지. 전국 작업과 동시에 돌리지 않는다.

4. **전국 한 방 검증이 아니다.**  
   대상은 지정 지역 또는 층화 랜덤 표본이다. UI의 「○ 전국」은 V1에 두지 않는다.

5. **QA는 원장·마트를 UPDATE하지 않는다.**  
   발견 → 판정 → 보고만. 수정은 운영자가 확인한 뒤 **생산 파이프라인**에서 한다.

6. **L3만으로 “일치”를 선언하지 않는다.**  
   빌더를 다시 부르면 저장 마트와 항상 같을 수 있다. **L1(독립 원장 SQL) · L3(생산 빌더) · 저장 마트** 세 칸을 비교한다.

## 4. 역할 분리

```
원천데이터
    │
    ├─ 생산 파이프라인 ──► 정제 ──► 원장 ──► Mart ──► 통계 API
    │
    └─ (운영자가 실행할 때만)
         QA 엔진
           L1 원장 재집계
           L2 정제 추적
           L3 생산 빌더를 해당 지역만 재실행
           저장 Mart와 대조
           PASS / REVIEW / ERROR / BLOCK
         AI 해석기 ──► 원인 후보 · 확인 목록 · 보고서
```

| 역할 | 해도 됨 | 하면 안 됨 |
|------|---------|------------|
| 생산 AI / 파이프라인 | 수집·정제·마트 구축 | 자기 결과를 PASS로 확정 |
| QA 엔진 | 읽기, 재집계, 대조, 판정 enum | 원장/마트 WRITE, 통계값 덮어쓰기 |
| AI 해석기 | QA JSON 인용, 원인 가설, 사람이 볼 항목 | 건수·금액 재발명, “맞습니다”만 출력 |

해석기 기본 태도: **저장된 수치가 틀렸을 가능성을 먼저 찾는다.** 일치는 “세 칸이 같다”는 사실이지, 파이프라인이 완벽하다는 선언이 아니다.

## 5. 검증 레벨

| 레벨 | 이름 | 하는 일 | V1 |
|------|------|---------|-----|
| **L1** | 원장 재집계 | 대상 지역·기간·유형만 원장에서 n / 금액합 / 평균 / 중위 등을 **독립 SQL**로 다시 냄 | 필수 |
| **L2** | 정제 추적 | 전체 → 유효(`is_valid`) → 검토(`needs_review`) → 제외. **왜 빠졌는지** 사유 버킷 | 필수 (얇게) |
| **L3** | Mart 재실행 | 전국 구축에 쓰는 **동일 빌더 함수**를 해당 지역에 한정해 다시 돌림. 결과 ↔ 저장 마트 | 필수 |
| **L4** | 화면 체인 | API JSON ↔ 화면 캡션(반올림·창·라벨) | **보류** |

V1의 질문은 “원장 → 정제 → Mart가 맞는가”이다.  
원장·마트가 맞는데 화면만 다르면 그때 L4(UI/API)를 연다.

### 5.1 세 칸 대조 (핵심)

| 비교 | 의미 |
|------|------|
| L3 = 저장 마트, L1 ≠ 마트 | 필터·매핑·`is_valid` 드리프트 후보 |
| L3 ≠ 저장 마트 | as_of 불일치, 부분 빌드, 캐시, 빌더 버전 |
| L1 = L3 = 마트 | 그 표본에서는 통과 (전국 보증이 아님) |

L2는 세 칸의 **제외 사유**를 채운다. “1건 적다”만 남기지 않는다.

### 5.2 L2가 V1에서 할 수 있는 것 / 없는 것

지역별 “원자료 1,247 → 중복 13 → 오류 7” 같은 **ingest 단계 로그는 아직 없다.**  
V1 L2는 원장 플래그로 추적한다.

- 대상 필터 전 행 수
- `is_valid` / `needs_review` / 해제·취소 등 도메인 제외
- 지역코드 결측·비정규 길이
- `transaction_hash` 중복 그룹
- (가능하면) raw 테이블 또는 CSV 해당 지역 행 수

상세한 단계별 drop 다이어그램은 ingest가 지역 단위 카운터를 남긴 뒤 V2에서 붙인다.

## 6. 판정 등급

이분(정상/오류) 금지. 런마다 하나의 **최악 등급**을 남기고, 지표별로도 등급을 둔다.

| 등급 | 의미 | 예 |
|------|------|-----|
| **PASS** | 세 칸이 허용 오차 안 | 건수 0 차이, 금액 ε 안 |
| **REVIEW** | 차이는 있으나 원인 미확정 또는 설명 가능한 경계 | 평균 0.4%인데 제외 1건 미추적 |
| **ERROR** | 구축 오류로 보는 불일치 | 원장에 있는 유효 건이 마트에서 빠짐 |
| **BLOCK** | 그 표본의 통계를 신뢰하기 어려움 | 건수 괴리 큼, 코드 매핑 대량 실패, 빌더 예외 |

허용 오차 (V1 기본, 도메인 주석으로 고정):

| 지표 | 규칙 |
|------|------|
| 거래건수 | **0건만 PASS.** 1건도 REVIEW 이상 |
| 금액 합 | 만원 단위 반올림 ε (도메인별 1단위) |
| 평균·중위 | 건수·합이 PASS여도 평균만 어긋나면 REVIEW. 이유를 L2가 못 쓰면 REVIEW 유지 |
| 빈 표본 | 거래 0건 지역은 PASS가 아니라 **SKIP** (랜덤이 빈 면을 골랐으면 재추출) |

등급은 이후 “어떤 오류가 반복되는가”를 보기 위한 QA 자산이다. 런을 버리면 안 된다.

## 7. 대상 선정

두 모드는 역할이 다르다. 둘 다 V1에 넣는다.

| 모드 | 역할 |
|------|------|
| **지정 검증** | 의심 지역·업데이트 직후 확인. 예: 세종 나성동 / 아파트 / 2025년 |
| **랜덤 검증** | 개발자가 예상하지 못한 오류. 전국을 “정상”이라고 선언하지 않음 |

### 7.1 지정

운영자가 고른다.

- 지역: 시도 / 시군구 / 읍면동 (V1은 읍면동 또는 시군구 하나)
- 기간: 달력 연도 **또는** `as_of_month` + `window_years` (한 런에 하나만. 혼용 금지)
- 시장·유형: 도메인이 정한 enum (V1: 아래 §10)
- 레벨: L1+L2+L3 고정 (레벨 축소 옵션은 V1에 없어도 됨)

### 7.2 랜덤 — 층화 (균등 추출 금지)

순수 균등은 거래 없는 면·리를 반복해서 뽑는다.

권고 층화 (V1):

```
시도 균등(또는 가중) 1곳
  → 해당 시도 내 시군구 (거래 존재 집합에서)
    → 읍면동 (최근 창 또는 지정 연도에 n>0)
      → 유형 (해당 도메인에서 거래 있는 유형)
```

한 번에 1~3 표본. 각 표본은 독립 런(행)으로 저장한다.

재추출: 대상 기간 n=0 이면 SKIP 후 같은 시도에서 다시 뽑는다. 최대 재시도 횟수를 둔다.

「17개 시도 전부」는 랜덤이 아니라 전수에 가깝다. V1 기본은 **1회 실행에 1~3 표본**이다.

## 8. 검증 단위 (grain)

한 런의 키:

```
domain × region_level × region_code × period_kind × period_key × asset_type
```

| 필드 | 예 |
|------|-----|
| `domain` | `collective_apt` (V1) |
| `region_level` | `eupmyeondong` |
| `region_code` | 나성동 canonical |
| `period_kind` | `calendar_year` \| `as_of_window` |
| `period_key` | `2025` 또는 `2026-07-01|3` |
| `asset_type` | `아파트` |

지역 필터는 핫패스와 같이 **`=` / expanding `IN`**. `ANY` 금지 ([LAND_LEDGER_QUERY_PERF.md](./LAND_LEDGER_QUERY_PERF.md) — 토지 확장 시 동일).

상권 폴리곤(임대 368)은 행정구역 grain이 아니다. 본 QA 대상에 넣지 않는다.

## 9. 산출 지표 (V1 최소)

L1·L3·저장 마트가 **같은 정의**로 맞춰야 하는 값:

| 지표 | 비고 |
|------|------|
| `n` | 유효 거래 건수 |
| `sum_price` | 거래금액 합 (원장 단위 그대로, 표시 환산은 보고서에서) |
| `mean_price` | 산술평균 |
| `median_price` | 중위 |
| (선택) `sum_area` / `mean_unit_price` | 도메인에 단가가 있으면 |

보고서에 원천 필드 샘플(일자, 코드, 유형, 면적, 가격)을 **소수 건** 첨부할 수 있다. 전량 덤프는 V1 기본이 아니다.

## 10. V1 범위

한 도메인만. 예시는 **집합 아파트 × 읍면동 × 달력 연도**.

| 포함 | 제외 |
|------|------|
| L1 + L2(원장 플래그) + L3 | L4 화면 |
| 지정 + 층화 랜덤 1~3 | 「전국」 한 방 |
| CLI 우선, 이어서 관리자 전용 화면 | 공개 UI, 게이트웨이 카드, 제품 AI 「검증해줘」 |
| 런 기록 테이블 | 원장/마트 WRITE |
| AI 해석은 QA JSON 이후 (꺼도 엔진은 동작) | LLM이 원장을 읽고 건수를 말함 |
| 로컬 DB | VPS 자동 실행, 월간 SOP 강제 편입 |

토지·복합·임대·비주거 집합은 **같은 계약(레벨·등급·세 칸)** 으로 나중에 복제한다. 토지는 용도×지목·창(3/5/7)·지목군이 달라 별 어댑터다.

월간 `verify_monthly_integrity`는 유지한다. 본 엔진이 Promote 게이트를 **대체하지 않는다.** 나중에 운영자가 원할 때만 “랜덤 1표본”을 SOP 선택 칸으로 넣을 수 있다. V1에서는 넣지 않는다.

## 11. 운영 · 인증

- 일반 사용자 UI에 메뉴·버튼·딥링크 없음.
- 진입: `py scripts/qa/audit_region.py` 및/또는 `/api/admin/qa/*`.
- 인증: 로컬 `.env` 전용 토큰 (예: `QA_AUDIT_TOKEN`). 커밋 금지. 공개 `API_TOKEN`과 분리하는 것을 권고.
- 실행 주체: 운영자(당신)만. 자동 cron 없음.
- 동시성: 생산 전국 빌드 중에는 돌리지 않는다 (문서 주의. 락은 V2 후보).

## 13. AI 해석기 계약

입력: `qa_audit_run` JSON (L1/L2/L3/마트/diff/등급).  
출력: 짧은 보고서.

포함해야 할 것:

- 종합 등급 (엔진 `verdict`를 그대로 인용)
- 불일치 지표와 **엔진이 준 수치**
- 원인 후보 (L2 버킷: 지역코드, `is_valid`, 창 경계, 유형 분류 등)
- 사람이 원장에서 열어볼 것 (코드, 기간, 제외 사유)

금지:

- JSON에 없는 건수·금액 생성
- “통계가 맞습니다”만 있는 결론
- 원장 수정 제안의 자동 실행 (문구로 “생산 파이프라인에서 확인”만)

제품 화면의 통계 어시스턴트와 **라우터를 공유하지 않는 것**을 권고한다. 관리자 QA 전용 호출.

## 14. 구현 순서

코드에 들어가기 전 본 문서가 SSOT다.

| 단계 | 산출 | 완료 조건 |
|------|------|-----------|
| **P0** | 본 문서 | 원칙·레벨·등급·V1 grain 합의 (본 절) |
| **P1** | 집합 아파트 L1 SQL + 저장 마트 조회 + CLI 지정 1지역 | ✅ `scripts/qa/audit_region.py` |
| **P2** | L2 플래그 버킷 + L3 빌더 지역 한정 재실행 | ✅ `compute_annual_records` (마트 WRITE 없음) |
| **P3** | 층화 랜덤 1~3 + `qa_audit_run` 저장 | ✅ `--random` · `--save` · `logs/qa_audit/` |
| **P4** | 관리자 화면 (지정/랜덤/결과 표/등급) | 공개 앱에 링크 없음 |
| **P5** | AI 해석기 (선택 · 엔진 독립) | 토큰 없어도 CLI 표는 동작 |
| **P6+** | 토지·복합·임대 어댑터, L4, SOP 선택 칸 | V1 런이 쌓인 뒤 |

P1에서 쓰는 대조 대상 마트는 **그 화면이 실제로 읽는 테이블/API**와 같아야 한다. 다른 집계를 “정답”으로 두면 QA가 거짓 경보만 만든다.

## 17. 성공 기준 (V1)

1. 운영자가 지정한 읍면동·아파트·연도에 대해 L1 / L2 / L3 / 저장 마트 표가 나온다.  
2. 건수 1건 차이면 PASS가 될 수 없고, L2에 제외 후보가 붙는다.  
3. 랜덤 실행이 거래 있는 표본을 고르거나 SKIP 후 재추출한다.  
4. 엔진이 DB를 변경하지 않는다 (런 로그 테이블 INSERT만 허용).  
5. 공개 프론트에 진입점이 없다.  
6. AI를 꺼도 판정과 표는 동일하다.

이 조건이 되면, 이후 실제 런을 보고 어떤 검사를 자동화할 가치가 있는지 정한다. 자동화는 그다음 결정이다.
