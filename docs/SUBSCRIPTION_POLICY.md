# CH2 구독 정책 (방향 확정)

> **상태:** 방향 SSOT (구현 전)  
> **일자:** 2026-08-27  
> **결정:** D-052  
> **기능 게이트(무료/유료 화면):** [`CH2_ENTITLEMENT.md`](./CH2_ENTITLEMENT.md) (D-043)  
> **공개 요금 페이지** (`/subscription`)는 토스 심사·구현 시 이 문서에 맞춰 갱신한다. 지금 허브 숫자는 **구 요금표**다.

지금 단계에서는 장기 할인으로 묶는 것보다 **상품 구조와 결제 흐름을 단순하게** 유지한다. 결제 코드를 넓히기 전에 이 규칙을 따른다.

---

## 1. 가격 (월 구독만)

| 구독 상태 | 월 금액 | 의미 |
|-----------|---------|------|
| 제품 1개 (Macro **또는** FieldNote) | 10,000원 | 단독 |
| 제품 2개 (Macro **and** FieldNote) | 13,000원 | 둘째 +3,000원 |
| Viewer · FieldNote PC GUI | 0원 | 구독 대상 아님 |

- **연간 구독 없음.** 유지율 데이터를 본 뒤에만 재논의.
- 세 번째 제품 가격은 정하지 않는다.
- 토스가 “할인 쿠폰”을 붙이지 않는다. 청구 금액이 1만 또는 1.3만이다.

---

## 2. 구독 모델 — CH2 계정 하나

사용자는 제품을 켜고 끄고, **결제는 구독 한 줄**이다.

```
CH2 계정
  └── 구독 (최대 1개)
        ├── Macro on/off
        ├── FieldNote on/off
        ├── 금액 10,000 | 13,000
        └── source  play | web | bank_transfer
```

금지: Play FieldNote와 웹 Macro를 **동시에 과금**. 합치면 1만+1만이 되어 1.3만 정책과 모순이다.

---

## 3. 결제 채널

### 3.1 웹 (복수 제품의 중심)

`ch2data.com` 구독 관리. 한 결제 수단, 금액은 체크된 제품 수에 따라 1만 또는 1.3만.

| 수단 | 역할 |
|------|------|
| **토스페이먼츠** | 웹 기본 PG. 카드·간편결제. **카카오페이는 토스 상점의 결제 수단**으로 켠다 (별도 카카오 상점 과금 아님). |
| **카카오페이 단독 PG** | 토스 심사가 거절되거나 카카오페이를 토스에서 못 켤 때만 검토. |
| **계좌이체** | 운영자가 지정한 **CH2 계좌**로 입금. 자동 CMS가 아님. 입금 확인 후 권한. 법인·세금계산서용 예외 채널로 우선. |

토스 심사는 2026-08 신청, 승인 후 키 연동.

### 3.2 앱 (FieldNote 단독만)

FieldNote Android **만** 쓰는 사람은 Google Play 월 10,000원.

둘 다 쓰려면 웹 통합 구독(13,000원)으로 옮긴다. 앱 설정에서 Play 구매와 웹 구독이 **동시에 켜지지 않게** 막는다.

Play로 FieldNote를 쓰는 사람이 Macro를 추가하려 하면: 웹 1.3만으로 전환할지 묻고, Play 구독은 **사용자가 해지**. **이번 달 만료 후** 웹 구독을 시작한다. 그 사이에 웹 Macro 1만만 열지 않는다.

> Play 정책: 앱 안 FieldNote Pro를 웹 결제만으로 켜면 심사 리스크가 있다. 심사가 막히면 **앱은 로그인만, 결제는 전부 웹(W안)** 으로 접는다. 지금은 **P안**(단독=Play, 둘 다=웹)을 방향으로 둔다.

### 3.3 계좌이체 운영 (방향)

- 구독 화면에 계좌·입금 금액·입금 메모(예: `CH2-{user_id}-{YYYYMM}`)를 보여 준다.
- 운영자가 입금 확인 후 해당 월 권한을 켠다 (Admin 또는 게시판 접수).
- 다음 달 미입금이면 만료일에 권한 종료. 일할 환불 없음.
- 월마다 이체해야 하므로 자동 카드/페이보다 CS가 많다. **기본 경로는 토스(+카카오페이 수단)** 이고, 이체는 요청 시에 연다.

## 4. 상태와 전이

| 상태 | Macro | FieldNote | 금액 | source |
|------|-------|-----------|------|--------|
| none | off | off | 0 | — |
| fn_play | off | on | 10,000 | play |
| web_one | 둘 중 하나만 on | | 10,000 | web 또는 bank_transfer |
| web_both | on | on | 13,000 | web 또는 bank_transfer |

| 지금 | 하려는 일 | 결과 |
|------|-----------|------|
| none | 웹에서 Macro 또는 FieldNote | web_one, 이번 달 1만 |
| none | 앱에서 FieldNote | fn_play |
| web_one | 다른 제품 체크 | web_both. 추가는 즉시 사용, 다음 청구 1.3만 (일할 없음) |
| web_both | 하나 해제 | 다음 결제일부터 1만. 이번 달은 이미 낸 달 |
| fn_play | Macro 추가 | 차단 → Play 해지 → 만료 후 web_both |
| any | 해지 | 만료일까지 사용, **부분 환불 없음** |

---

## 5. 환불

- 월 구독만 있으므로 “이번 달분은 사용, 다음 결제일부터 해지”.
- Play 환불은 Google 절차. 웹(토스·카카오페이)은 PG·전자상거래법. 계좌이체는 입금월 기준으로 운영자가 처리.
- 연간·교차 채널 일할 정산은 만들지 않는다.

---

## 6. 구현 시 스키마 방향 (아직 적용하지 않음)

계정당 구독 **1행**. `items(macro, fieldnote)` + `amount_krw` + `source(play|web_toss|bank_transfer)`.  
지금 DB의 `product=bundle`·연간 SKU는 이 정책과 맞지 않으니 구현 때 정리한다.
