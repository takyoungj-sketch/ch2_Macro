# AI 출시 한도 구현 및 활성화 안내

2026-11-07. [출시 계획](AI_SUBSCRIPTION_LAUNCH_PLAN.md)의 후속 구현이다.

## 확정 정책

- Macro 단독: 월 10,000원, AI 질문 200회.
- 동시 구독: 월 15,000원, Macro AI 250회, 사진 분석 500장, 별도 문구 작성 100회, 주소표 보정 100회.
- 사용자 후속 지시에 따라 문구 작성·주소표는 추가 비용 실측 없이 100회로 확정했다. 이번 구현·검증에서 유료 API를 추가 호출하지 않았다.
- 계정의 정상 완료 작업을 차감한다. 내부 검증·재작성 호출, 네트워크 중복 요청, 결과 재열람은 추가 차감하지 않는다.
- 사진 단문·장문 분석은 모두 사진 장수를 사용한다. 별도 메모 문구 작성만 작성 1회로 계산한다. 사진 분석에 포함된 설명을 문구 작성으로 중복 차감하지 않는다.
- 기존 Fieldnote 단독·무료 이용자의 기기별 정책은 유지한다. 기존 경로의 공급자 실패·잘못된 응답에는 사전 차감량을 반환하도록 보완했다.

## 구현

### 계정별 저장·정산

`backend/app/ai/allowances.py`, `db/077_platform_ai_allowances.sql`:

- 계정 잠금, 기능별 이용 기간·한도·사용·예약, 요청 상태, 별도 결과 저장, 공급자 호출 원가, 운영 복원 이력의 6개 테이블.
- PostgreSQL 계정 행 잠금으로 잔여량 검사·예약·정산을 직렬화한다. 외부 호출 중에는 DB 잠금을 유지하지 않는다.
- 사용자·멱등 키 유일 제약으로 중복 작업을 막는다. 같은 키에 다른 입력은 409, 완료된 동일 요청은 저장 결과를 반환한다.
- 결과 영속 저장과 이용량 정산은 하나의 트랜잭션이다. 최종 실패에는 예약량을 반환하고, 이미 발생한 모델 비용은 별도로 남긴다.
- 작업은 예약한 기간에 정산한다. 구독의 실제 만료 시각을 사용하며 기존 31일 결제 코드를 바꾸지 않았다. 기존 진행 중인 AI 기간이 있으면 상향으로 초기화하지 않는다.
- 연간 상품의 월별 하위 기간은 생성일을 기준으로 월말을 보정한다. 여러 제품 권한이 있다는 이유로 동시 구독으로 간주하지 않는다.
- 관리자 계정은 유료 고객 한도에서 제외한다. 기존 개발·시험 원가 장부와 접근 경계를 유지한다.

### Macro

- `/api/ai/chat`, 모델 호출이 가능한 `/api/ai/explain`에 동일한 계정 한도를 적용한다.
- `/api/ai/allowance`: 본인의 한도·사용량·예약량·잔여량·다음 초기화 날짜.
- `/api/ai/requests/{요청ID 또는 클라이언트 작업키}`: 본인 작업 상태 및 완료 결과만 조회.
- `AiChatRequest`와 `AiExplainRequest`에 `request_id`를 추가했다. 활성화된 유료 요청에는 작업 ID가 필요하다.
- 공통 UI에 실제 사용량·80% 안내·한도 소진 안내를 표시한다. 중단 또는 연결 오류 뒤 서버에서 완료된 답변은 재접속 시 회수한다.
- 기존 네거티브 원칙·자유로운 답변 형식·근거 검증은 유지한다. 한 질문의 생성·검증·재작성 원가는 같은 요청에 연결한다.

### Fieldnote

- `/api/platform/fieldnote/ai/vision`: 서버가 실제 첨부 이미지를 세고 중복 첨부를 제거한다. 단문·장문 모두 사진 장수 차감.
- `/sheet`: 경로 자체로 주소표 기능을 결정한다. 클라이언트의 `X-Ai-Kind`를 바꿔 다른 기능 한도로 우회하지 못한다. 빈 주소 결과는 차감하지 않는다.
- `/write`: 별도 텍스트 문구 작성 1회. 제공된 메모에 없는 사실·수치·가격 판단을 추가하지 않도록 서버 안내를 사용한다.
- `/allowance`: 계정별 기능 한도를 조회한다. 동시 구독 계정은 기기별 선차단 대신 서버 사용량을 표시하고, 로컬 카운터를 다시 증가시키지 않는다.
- 별도 저장소 `D:/ch2/ch2_FieldNote`에 프록시 작업 ID, 서버 한도 캐시, 로그인 전환 시 캐시 초기화, 기존 훅의 사전 조회·표시를 연결했다.
- 메모 화면에 별도 문구 작성 → 미리보기 → 메모 적용 동작을 추가했다. 기존 해외 전송 동의가 있어야 실행하며 기존 메모를 자동 덮어쓰지 않는다.
- 사진 촬영·저장·기존 결과 표시 경로는 AI 차감에 연결하지 않았다. 사진 보관 용량 자체를 무제한으로 바꾸지는 않았다.

### 원가·운영

- 계정별 공급자 기록은 생성/검증/재작성 단계, 실제 모델, 입력·캐시·출력 토큰, 추정 USD, 완료·오류·미확정 상태를 구분한다.
- 알려지지 않은 모델은 mini 원가로 조용히 계산하지 않고 `cost_unknown`으로 남긴다. 캐시 입력 단가를 반영한다.
- 계정 요청은 기존 서버 전체 200회·1만원 실험 제한을 소모하는 사용자 한도로 판단하지 않는다. 기존 JSONL 장부는 개발·기존 경로의 기록으로 남는다.
- `AI_PAID_EMERGENCY_STOP=true`는 유료 AI의 새 예약만 서비스 점검 상태로 중지한다. 완료 결과 재조회·이미 수락한 작업은 유지한다.
- `/api/admin/ai-usage/accounts`는 로그인한 관리자만 계정별 잔여량·원가 단계·정산 대기를 읽을 수 있다. 관리자 화면에 새 집계를 추가했다.
- 작업당 기본 상한: 사진 12장, 인라인 이미지 문자열 합계 20,000,000자, Fieldnote 텍스트 40,000자, Macro 요청 JSON 120,000자. 원격 이미지 URL은 받지 않는다.
- 모델 출력은 `AI_MAX_OUTPUT_TOKENS`(기본 8,000)로 제한한다. 클라이언트가 큰 값을 보내도 서버 상한을 넘지 않는다.

## 운영 반영 전 순서

**이번 작업은 코드 구현이며 운영 배포·DB 변경·환경 설정 활성화를 수행하지 않았다.** 기본 플래그는 기존 이용자와 구버전 앱을 보호하기 위해 꺼져 있다. 활성화 전에는 확정 정책이 운영에 적용됐다고 안내하지 않는다.

1. 관련 코드와 Fieldnote 앱 변경을 각각 검토·백업한다. 이미 있던 다른 변경과 섞어 전체 스테이징하지 않는다.
2. 실제 대상이 `ch2_platform`인지 확인한 뒤 `db/077_platform_ai_allowances.sql`을 적용한다. 통계 DB에 적용하지 않는다. 신규 테이블만 추가하며 기존 구독·기기 원장을 삭제하거나 소급 차감하지 않는다.
3. Fieldnote 새 앱 버전을 준비한다. 구버전 앱에는 유료 요청 작업 ID가 없으므로 서버 플래그를 먼저 켜면 해당 요청이 거절될 수 있다. 앱 전환·안내를 먼저 준비한다.
4. 실제 월/연 구독·해지 예약·갱신·상품 전환 사례를 PostgreSQL 검증 계정에서 대조한다. 결제 검증 stub이나 관리자 계정만으로 유료 동작 검증을 대신하지 않는다.
5. 서버에 `AI_SUBSCRIPTION_QUOTA_ENABLED=true`를 설정하고 프로세스를 재시작한다. `DATABASE_URL_PLATFORM`은 기존 서버 설정을 사용한다. 키·접속 문자열을 문서나 저장소에 복사하지 않는다.
6. 사용자 한도 조회, 마지막 잔여량 동시 요청, 실패 반환, 계정 교차 접근 차단, Fieldnote 사진·작성·주소표 단위, 관리자 원가 합계를 확인한다.
7. 운영 비용·미확정 호출·정산 대기 상태를 관찰한다. 사용자별 숨겨진 원가 상한 대신 운영 경고와 명시적 장애 대응을 사용한다.

배포는 별도 사용자 배포 요청 시 [런북](../deploy/AGENT_DEPLOY_RUNBOOK.md)을 따른다. 현재 구현만으로 자동 커밋·푸시·배포하지 않는다.

## 장애 복구

완료 결과는 본인 작업 조회 API로 재열람할 수 있다. 예약 상태에서 서버가 중단됐다면 자동으로 예약을 풀지 않는다. 실행 중인 작업이 없고 결과도 제공되지 않았는지 확인한 뒤, 30분 이상 된 예약만 복원한다.

백엔드 작업 디렉터리에서:

```text
python -m scripts.reconcile_ai_allowance REQUEST_ID --operator OPERATOR --reason REASON --worker-stopped
```

이 도구는 예약 반환과 보정 이력을 원자적으로 기록한다. 실행 중인 작업에 쓰면 안 된다. 결과가 이미 완료된 작업·새 예약·중복 복원은 거절한다.

운영 중 중지가 필요하면 먼저 `AI_PAID_EMERGENCY_STOP=true`로 새 작업을 막고 진행 작업과 장부를 대조한다. 플래그를 단순히 꺼서 기존 장부와 기기 카운터 사이를 오가는 것을 일반 복구 절차로 삼지 않는다. DB의 요청·결과·예약 기록은 보존한다.

## 검증과 남은 운영 확인

- 백엔드: 관련 **186개 테스트 통과**. 한도 경계, 동시 마지막 1회, 중복 요청, 실패 반환, 결과 저장 트랜잭션, 내부 호출 비용, 구독 기반 기간·상향 유지, 미확정 모델 및 방치 예약 복구를 테스트했다. 사진 분석·별도 작성의 정상 차감과 빈 주소표의 미차감도 모의 공급자 응답으로 확인했다.
- Windows 샌드박스에서 asyncio의 로컬 소켓 초기화가 멈추는 것을 스택으로 확인했다. 최종 테스트는 로컬 소켓을 허용한 환경에서 모의 공급자 응답으로 실행했다. 유료 호출은 하지 않았다.
- Macro 6앱·관리자 화면: TypeScript 및 Vite 빌드 통과. Fieldnote: TypeScript 검사 통과. 기존 번들 크기·브라우저 호환 데이터 경고는 있었고 빌드는 성공했다.
- 미수행: 운영 PostgreSQL에서의 마이그레이션·다중 프로세스 경합 시험, 실제 구독 결제 전환 E2E, Android/iOS 실기기 UI 및 새 앱 배포. 실제 공급자 호출을 이용한 추가 실측도 사용자 지시에 따라 수행하지 않았다.
- 공급자 단가 변경, 연간 상품의 기존 약정·사용자 전환, 계정 삭제 시 별도 결과 보관 정책은 운영 반영 시 기존 정책과 함께 확인한다.

정책은 모두 확정됐지만, 위 운영 활성화 검증이 끝나기 전에는 운영 적용 완료로 보고하지 않는다.
